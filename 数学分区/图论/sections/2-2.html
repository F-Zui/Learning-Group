二分图最大匹配：Kuhn 算法

把“找增广路”写成一个递归函数：左边点逐个尝试，右边点被占了就让它原来的搭档去别处试试。学完能默写 Kuhn 模板、分析 $O(VE)$ 复杂度，并把问题改写成匹配。

第 2 章 · 匹配与网络流 难度 ●●○ 前置：§2.1 匹配与 Hall 定理 关键词：Kuhn · 增广路 · 二分图

一从“存在”到“算出来”

Hall 定理能回答“完美匹配存不存在”，但它是一个存在性判据：要检查全部 $2^{|X|}$ 个子集，根本没法直接跑。真正要写进程序的，是构造——给定一张二分图，输出最多能配多少对，以及具体怎么配。

暴力贪心不行：2.1 的例子已经说明，先来先得会卡在次优解。出路是 Berge 定理——只要还能找到增广路，就说明当前匹配不是最大；把增广路翻过来，匹配就变大。于是问题变成：给定一个左点，如何找一条从它出发的增广路？

二让位：增广路的递归写法

从左边未匹配的点 $u$ 出发，沿一条非匹配边走到右边的 $v$。如果 $v$ 还空着，太好了，直接配上；如果 $v$ 已经被 $u'$ 占了，就试着让 $u'$ 去别处——这等价于从 $u'$ 继续找增广路。如果 $u'$ 找到了新位置，$v$ 就腾出来给 $u$；如果找不到，$u$ 换下一条边再试。

读法

递归函数 dfs(u) 的含义可以一句话概括：“请给 $u$ 找个位置，必要时让别人挪一挪。”它的返回值是“找到了没有”。每个右点在一次 dfs 中只访问一次（用 used 标记），保证不会绕圈，所以单次 dfs 是 $O(E)$ 的。

三代码与逻辑图

代码 1 · Kuhn 求二分图最大匹配C++17
vector<int> g[N];          // 只存「左点 → 右点」的边
int matchR[N];           // matchR[v] = 与右点 v 配对的左点，0 表示空
bool used[N];            // 本轮 dfs 中右点 v 是否已访问

bool dfs(int u) {
    for (int v : g[u]) {
        if (used[v]) continue;   // 同一轮不走回头路
        used[v] = true;
        if (matchR[v] == 0 || dfs(matchR[v])) {
            matchR[v] = u;          // v 空着，或原搭档成功让位
            return true;
        }
    }
    return false;              // 所有邻居都试过，u 配不上
}

int maxMatching(int n) {
    int ans = 0;
    for (int u = 1; u <= n; ++u) {
        memset(used, 0, sizeof used);   // 每个左点重新开始
        if (dfs(u)) ++ans;
    }
    return ans;
}
易错

三个坑：第一，used 必须在每个左点开始前清空，而不是每次 dfs 清空，否则递归会让位失败；第二，matchR 只记录右点的搭档，左点不需要单独记录；第三，无向边要按二分图定向，存成“左→右”单向边，否则会把右侧点当左侧点搜索，逻辑全乱。

四正确性与复杂度

定理（Kuhn 的正确性）

按任意顺序处理左侧点，每次调用 dfs 尽可能匹配它，最终得到的匹配是最大匹配。

证明

对内层做归纳：设处理完前 $k$ 个左点后，当前匹配 $M$ 是“只允许这 $k$ 个左点”的子图上的最大匹配。加入第 $k+1$ 个左点 $u$ 时，若 dfs(u) 成功，匹配数增加 1，且 $u$ 已被匹配，故仍最大。

若失败，假设新图存在比 $M$ 更大的匹配，由 Berge 定理存在 $M$-增广路 $P$。$P$ 的两个端点都未被饱和；右侧端点一定空闲，左侧端点只能是 $u$（前 $k$ 个左点在 $M$ 中都被饱和，而增广路翻转不会让已饱和的点变空）。于是 $P$ 是从 $u$ 出发的增广路，但 dfs(u) 已经穷尽了从 $u$ 出发的所有交替路径，矛盾。故 $M$ 仍最大。∎

外层循环 $n$ 次，每次 dfs 至多访问每条边一次，所以总复杂度 $O(VE)$，即 $O(nm)$。对 $n,m\le 10^4$ 的题已经够用；若规模再大，要换 Hopcroft–Karp（$O(E\sqrt V)$）。

算法复杂度适用
Kuhn（匈牙利）$O(VE)$模板短，$10^4$ 量级
Hopcroft–Karp$O(E\sqrt V)$$10^5$ 量级，按层同时增广
Dinic 建流$O(E\sqrt V)$需要带权/多源时统一处理

五例题

例 1 手跑一遍 Kuhn

左侧 $u_1,u_2,u_3$，右侧 $v_1,v_2,v_3$，边为 $u_1v_1,u_1v_2,u_2v_1,u_2v_3,u_3v_2$。按 $u_1,u_2,u_3$ 顺序执行，最大匹配是多少？

解　$u_1$：$v_1$ 空闲，配 $u_1v_1$。$u_2$：$v_1$ 被占，问 $u_1$ 能否换位——$u_1$ 换到 $v_2$，于是 $u_2v_1$，现在 $\lbrace u_1v_2,u_2v_1\rbrace$。$u_3$：只有 $v_2$，被 $u_1$ 占；$u_1$ 试 $v_1$ 被 $u_2$ 占，$u_2$ 试 $v_3$ 空闲 → $u_2$ 换到 $v_3$，$v_1$ 空出；$u_1$ 换到 $v_1$，$v_2$ 空出给 $u_3$。最终 $\lbrace u_3v_2,u_1v_1,u_2v_3\rbrace$，大小为 3。

注意最后一步连续让位了两次：$u_3\to v_2\to u_1\to v_1\to u_2\to v_3$，正是递归在深度上展开。

例 2 棋盘骨牌的最大覆盖

一个 $n\times m$ 棋盘，用 $1\times2$ 骨牌不重叠地覆盖格子，最多能盖住多少格？

解　按行列奇偶染黑白，相邻格异色，把黑格放左侧、白格放右侧，相邻格连边。一张骨牌恰好覆盖一对相邻格，所以骨牌铺法就是匹配；最多覆盖格数等于 $2\nu(G)$。

当 $nm$ 为偶数且没有挖洞时，棋盘存在完美匹配，能盖满；若挖去若干格，只需求出最大匹配。这就是“棋盘覆盖”类题目的标准建模。

六习题

  1. 为什么 used 数组要在每个左点的 dfs 之前清空，而不是在 dfs 内部清空？
    思路　used 的作用范围是“一次增广搜索”。
    答案　一次 dfs(u) 的整个递归过程共享同一张“已访问”表，才能保证每个右点最多被让位一次、搜索不绕圈，复杂度才是 $O(E)$。若每次递归都清空，就会在同一层反复访问，甚至死循环。
  2. 如果只给出了一个无向图，没告诉你哪边是 $X$、哪边是 $Y$，怎么求最大匹配？
    思路　先判断二分图，再定向。
    答案　先 BFS 染色（1.2 节），把颜色 0 的点作为左侧、颜色 1 的点作为右侧；若染色失败说明图不是二分图，Kuhn 不能直接用。定向后对所有左侧点跑 Kuhn。
  3. Kuhn 算法能否直接求一般图（非二分图）的最大匹配？
    思路　一般图里，交替路可能遇到奇圈。
    答案　不能。奇圈会让“让位”出现两条分支，必须用带花树（Blossom）算法把奇圈缩成一个点。Kuhn 依赖二分图“奇圈不存在”这一结构。
  4. 怎样从最大匹配构造出最小点覆盖？
    思路　用 2.1 节 König 定理的证明：从所有未饱和的左侧点做交替搜索。
    答案　令 $U$ 为搜索到的左侧点、$W$ 为搜索到的右侧点，则 $(X\setminus U)\cup W$ 是最小点覆盖，大小为 $\nu$。实现时在 Kuhn 结束后再跑一次交替 BFS 即可。
  5. 有 5 个任务和 5 个工人，每个任务只能由特定工人完成。如何判断能否全部完成？
    思路　建二分图，判断是否存在大小为 5 的匹配。
    答案　左点为任务、右点为工人，能完成则连边；跑 Kuhn，若答案等于 5 则能全部完成，否则由 Hall 定理可以找到一个“任务多、可做工人少”的子集作为不可行的证据。
如果把“最大匹配”改成“最大权匹配”（每条边带权，求总权最大的匹配），Kuhn 还够用吗？
引导　不够。增广路只保证边数最大，不保证权值最大。带权情形要用 KM 算法（求完美匹配的最小/最大权）或最小费用最大流；核心仍然是沿增广路调整，但每次要找“权值和最小/最大”的增广路，通常用势函数（顶标）配合 Dijkstra 实现。
进阶 · Hopcroft–Karp 与 Dinic 的同一性（Bondy & Murty Ch. 16）

Hopcroft–Karp 先 BFS 分层，再沿最短增广路一次推多条，复杂度 $O(E\sqrt V)$。把匹配建成单位容量流网络后，它恰好就是 Dinic 在单位容量图上的特例：Dinic 的“分层图 + 阻塞流”与 HK 的“最短增广路集合”一一对应。理解了这一点，第 2.3 节的 Dinic 代码可以直接当匹配算法用。

一页纸
  • Kuhn = 对每个左点找一条增广路，找到就翻转，匹配数 +1。
  • used 标记右点，一次搜索内有效；matchR 记录右点的搭档。
  • 复杂度 $O(VE)$；规模大时换 Hopcroft–Karp / Dinic。
  • 棋盘、任务分配、最大独立集都能化成匹配；最大独立集 $=n-\nu$。
