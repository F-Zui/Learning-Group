网络流：Dinic 与最大流最小割

把“最多能运多少”写成带容量的有向图，用残量网络上的增广路求解，用 Dinic 的分层图把复杂度压下来。学完能默写 Dinic 模板，并把匹配、最小割、点覆盖都建模成流。

第 2 章 · 匹配与网络流 难度 ●●● 前置：§2.2 Kuhn 算法 关键词：最大流 · 最小割 · Dinic

一最多能运多少

工厂在一端，仓库在另一端，中间是容量有限的公路网。每条路每小时最多通过多少辆车是已知的，问：从工厂到仓库，每小时最多能运多少货？

这就是最大流问题。它比最短路更难：最短路只关心一条路径，最大流要让许多条路径同时工作，还要在瓶颈处重新分配。二战时苏联铁路网、今天的网络带宽、任务调度，都是同一个模型。

二流、割与对偶

定义（流网络与流）

一个流网络是带两个特殊顶点的有向图：源点 $s$、汇点 $t$，每条边 $e=uv$ 有容量 $c(e)\ge0$。流 $f$ 给每条边一个实数 $f(e)$，满足：（1）容量约束 $0\le f(e)\le c(e)$；（2）守恒：对除 $s,t$ 外的每个点，流入等于流出。流的值 $|f|$ 是 $s$ 的净流出量。

定义（割）

把 $V$ 分成 $S,T$ 两部分，$s\in S$、$t\in T$，称为一个$s$-$t$ 割。它的容量 $c(S,T)$ 是所有从 $S$ 指向 $T$ 的边的容量之和。容量最小的割称为最小割。

下面这张图的边标着“流量/容量”。源点送出 10 单位，汇点收到 10 单位，中间每条边都不超容量且流量守恒——这是一个合法流，而且它就是最大流。

易错

流量守恒必须对每个中间点逐点检查，不能只看源点和汇点：图上 $a$ 点的 $4+2=6$ 与流入的 6 相等，才算平衡。写建模程序时最常见的错误是漏掉某条边的方向，导致某个点凭空多出流量。

定理（最大流最小割）

对任意流网络，最大流的值等于最小割的容量。

证明

先证“流不大于割”。对任意流 $f$ 与割 $(S,T)$，把 $S$ 中所有点的守恒式相加：$s$ 的净流出 $|f|$ 等于跨越割的净流量 $f(S,T)-f(T,S)$，而后者不超过 $c(S,T)$（正向边不超过容量，反向边贡献非正）。故 $|f|\le c(S,T)$。

再证“存在流等于某个割”。取最大流 $f$，在残量网络（见下节）中从 $s$ 出发做搜索，令 $S$ 为可达点集。$t\notin S$（否则还能增广，与最大性矛盾）。对 $S\to T$ 的每条边，必有 $f(e)=c(e)$，否则这条边的残量大于 0，$T$ 中的端点应可达；对 $T\to S$ 的每条边，必有 $f(e)=0$。于是 $|f|=f(S,T)-f(T,S)=c(S,T)$，这个割就是最小割。∎

读法

这条定理的意义远超算法：它说“最大”与“最小”是一对对偶问题。求最大流时，你同时得到最小割；任何一个“最多能……”的问题，往往都有一个“最少要……”的对偶答案。匹配里的 König 定理（$\nu=\tau$）就是它在二分图上的特例。

三残量网络与 Dinic

要改进一个流，就要找“还能再挤进去一点”的路径。做法是构造残量网络：每条边 $uv$ 保留剩余容量 $c-f$ 作为正向边，同时加一条容量为 $f$ 的反向边 $vu$。反向边的作用是“反悔”——把已经送过去的水退回来，改走别的路线。

Ford–Fulkerson 的思路是：不断在残量网络里找 $s\to t$ 路，沿路推 $\min$ 剩余容量，直到找不到路。它一定终止，但复杂度可能很差（每次只推 1 单位）。Dinic 加了两条改进：分层（只沿层数递增的边走）与当前弧优化（每条边在同一轮只试一次），把复杂度降到 $O(V^2E)$。

代码 1 · Dinic 最大流C++17
struct Edge { int to, cap, flow; };
vector<Edge> e;
vector<int> g[N];
int level[N], it[N];      // it[u]：当前弧，避免重复扫已废弃的边

void addEdge(int u, int v, int c) {
    g[u].push_back(e.size()); e.push_back({v, c, 0});
    g[v].push_back(e.size()); e.push_back({u, 0, 0}); // 反向边，容量 0
}

bool bfs(int s, int t) {          // 在残量网络上分层
    fill(level, level + n, -1);
    queue<int> q; level[s] = 0; q.push(s);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int id : g[u]) {
            const Edge& ed = e[id];
            if (ed.cap > ed.flow && level[ed.to] == -1) {
                level[ed.to] = level[u] + 1;
                q.push(ed.to);
            }
        }
    }
    return level[t] != -1;         // 汇点不可达：已经没有增广路
}

int dfs(int u, int t, int f) {    // 沿层次图推流，返回推过去的量
    if (u == t) return f;
    for (int& i = it[u]; i < (int)g[u].size(); ++i) {
        int id = g[u][i];
        Edge& ed = e[id];
        if (ed.cap > ed.flow && level[ed.to] == level[u] + 1) {
            int ret = dfs(ed.to, t, min(f, ed.cap - ed.flow));
            if (ret > 0) {
                ed.flow += ret;
                e[id ^ 1].flow -= ret;  // 反向边退流
                return ret;
            }
        }
    }
    return 0;
}

int dinic(int s, int t) {
    int flow = 0;
    while (bfs(s, t)) {
        fill(it, it + n, 0);
        while (int f = dfs(s, t, INT_MAX)) flow += f;
    }
    return flow;
}
易错

三个高频错误：第一，反向边容量必须初始为 0，并在推流时同步退流 e[id^1].flow -= ret；第二，it[] 必须用引用 int& i，否则当前弧优化失效、复杂度退化；第三，dfs 的 i 不回溯，导致同一条废弃边被反复扫描。还有一个隐蔽的坑：边数要开两倍（正反各一条）。

四建模：把题目变成流

网络流真正难的不是模板，而是建模。下面三种套路覆盖了大多数题目：

题型建图答案
二分图最大匹配$s\to$ 左部容量 1，左$\to$右容量 1，右部$\to t$ 容量 1最大流 = $\nu(G)$
最小割（删边最少）原图边容量 1，求 $s$-$t$ 最小割最少删几条边使断开
点有容量限制把点拆成 $v_{in}\to v_{out}$，容量为点容量经过该点的流量受限
例 1 匹配就是流

证明二分图最大匹配可以化归为最大流。

解　加源点 $s$ 与汇点 $t$：$s$ 向每个左点连容量 1 的边，每个右点向 $t$ 连容量 1 的边，原来的边从左指向右、容量 1。任何大小为 $k$ 的匹配给出流量 $k$ 的流（沿匹配边各送 1 单位）；反过来，整数流在每条边上取 $0/1$，取那些流量为 1 的中间边就得到一个匹配。由整数性，最大流等于最大匹配。

例 2 用最小割回答“最少删几条边”

给一张无向图与两点 $s,t$，每次可以删一条边，最少删几条能让 $s$ 与 $t$ 不连通？

解　把每条无向边拆成两条方向相反、容量 1 的有向边，求 $s$-$t$ 最小割。删掉的边正是割中容量为 1 的边，删完后 $S$ 与 $T$ 之间没有边，$s,t$ 不连通；而任何使 $s,t$ 不连通的删边集合都对应一个割，所以最小值就是最小割容量。

这个量称为 $s$-$t$ 边连通度。若要求“删最少的点”，把点拆成 $v_{in}\to v_{out}$、容量 1 即可。

五习题

  1. 证明：对任意流 $f$ 与任意割 $(S,T)$，都有 $|f|\le c(S,T)$。
    思路　把 $S$ 中所有点的守恒式相加，注意内部边两两抵消。
    答案　$\sum_{v\in S}(\text{流出}-\text{流入})=f(S,T)-f(T,S)$；内部边一正一负抵消，只剩跨割的边。$s$ 的净流出为 $|f|$，其余 $S$ 中点净流出为 0，故 $|f|=f(S,T)-f(T,S)\le c(S,T)$。
  2. 为什么残量网络要加反向边？只用正向剩余容量会怎样？
    思路　想一个“先走错路、后来需要退回”的例子。
    答案　反向边允许把已经送出的流撤回，从而修正早期的错误选择。没有反向边，Ford–Fulkerson 可能停在非最大流上；Dinic 的分层图也会因此不完整。
  3. 在二分图匹配的流网络中，若所有容量都是整数，最大流一定是整数吗？为什么？
    思路　看每次增广推的量。
    答案　是。每次增广推的是 $\min$ 剩余容量，起点为整数容量，归纳可知残量始终是整数，故最终流是整数。这条“整数性”是匹配、点覆盖等组合结论能从流推出的关键。
  4. 一张网络有 $n=500$ 个点、$m=5000$ 条边，Dinic 的 $O(V^2E)$ 上界是 $1.25\times10^9$，实际会跑这么慢吗？
    思路　上界是理论最坏情况，分层数通常远小于 $n$。
    答案　通常不会。Dinic 的层数一般很小，单位容量网络还有 $O(E\sqrt V)$ 的更强上界；实测在 $10^4$ 点、$10^5$ 边的随机图上很快。但网格状、层数多的构造图仍可能逼近上界，需要更快的算法或建图优化。
  5. 怎样用最小割求“最大权闭合子图”？（提示：正权连源、负权连汇）
    思路　把“选了一个点就必须选它的后继”变成割的约束。
    答案　$s$ 向正权点连容量为权的边，负权点向 $t$ 连容量为 $|\text{权}|$ 的边，原依赖边容量 $+\infty$。最小割把点分成“选”与“不选”两半，答案 $=$ 正权总和 $-$ 最小割。
最大流的值是否可能大于任何一条边的容量之和？小于最小割？
引导　取割 $S=\lbrace s\rbrace$，容量就是从 $s$ 出发的边容量和，所以最大流不超过它。最大流只会等于最小割，不会小于——这是定理的直接结论。反过来，如果所有边容量都是整数，最大流也必是整数（整数性）。
进阶 · 最小费用最大流与对偶（Bondy & Murty Ch. 7）

给每条边再加单位费用，要求“在流量最大的前提下费用最小”，就是最小费用最大流（MCMF）。做法是在残量网络上用 SPFA 或势函数 + Dijkstra 找单位费用最小的增广路，反复增广。它与线性规划的对偶理论直接相关：最大流是原问题，最小割是对偶问题，而 MCMF 的对偶是“势函数”与“顶标”，这也是 KM 算法能求最大权匹配的原因。

一页纸
  • 流要满足容量约束与中间点守恒；流的值 = 源点净流出。
  • 最大流 = 最小割（对偶）；割只数 $S\to T$ 方向的边。
  • 残量网络 = 剩余容量 + 反向退流边；增广路在其中找。
  • Dinic：BFS 分层 + 当前弧 + 阻塞流，$O(V^2E)$，单位容量 $O(E\sqrt V)$。
