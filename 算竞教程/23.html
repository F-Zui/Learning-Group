23 · DFS 枚举：子集、组合与排列

把“枚举所有方案”写成递归：一副骨架四块内容，一套回溯三行；再用 vis、start、“选或不选”三种手段分别处理排列、组合、子集的不重不漏，并学会先估方案数再写代码。
⭐ 已学范围普及-预计 65 分钟DFS回溯字典序
本节出现的新函数 / 新语法（先看懂再用）
  • 回溯三行（标记 → 递进 → 还原） —— 本节核心：标记、递进、还原，三行必须在循环体内成对出现
  • start 参数（组合的去重手段） —— 下一层只能从 i+1 开始，这是组合与排列的唯一代码区别
  • printf 定宽输出 —— 一句话控制空格、换行与定宽输出

第 14 节用 for 和二进制数过搜索空间，第 21 节把递归拆成“出口 + 递推”。DFS 枚举 = 递归 + 枚举：把“从一堆东西里挑若干个”摊成 n 层决策，每层选一个，选完往下走，走完退回来换下一个。这个“退回来换下一个”的动作叫回溯，代码里只有一行。

DFS 枚举不保证快，只保证不重不漏。三种题型的所有技巧都在处理“不重”：排列用 vis，组合用 start，子集用“选或不选”。

先把骨架拆成四块。任何一道 DFS 枚举题，都能填进这张表里，填不进去就说明还没想清状态。

骨架部件它回答的问题全排列（n! 种）组合（C(n,k) 种）
层（step）现在在做第几层决策正在填第 step 个位置已经选了 step 个数
候选集这一层允许选哪些1..n 里所有没被用过的数start..n
出口什么状态算一个完整方案step > nstep > k
还原离开这一层要撤销什么vis[i] = 0不用撤销：start 天生递增

本节没有新关键字，只有一种必须背下来的固定顺序。把它当一个不可拆的整体记住，比理解之后再写要快。

新函数拆解 · 回溯三行（标记 → 递进 → 还原）
vis[i] = 1; dfs(step + 1); vis[i] = 0;
组成含义 / 格式要求
① vis[i] = 1标记：把 i 从候选集里划掉。下一层看到的 vis 就是“占位之后”的现场。
② dfs(step + 1)递进：带着新状态进入下一层。这句话返回时，它内部的所有标记都已经撤干净了。
③ vis[i] = 0还原：撤销 ①。不写这一行，i 会一直被认为占着，后面所有分支都选不到它。
为什么必须还原所有层共用同一份全局数组。dfs 只是“借用”它，离开时必须物归原主，否则兄弟分支看到的是上一条路径留下的脏状态。
顺序不能换先标再递进、先递进再还原。把还原写在递归前面，等于下一层拿到的是“没占位”的状态，同一个数会被重复填进不同位置。
位置在循环体内三行必须一起写在 for 的循环体里。写到循环外面就只还原了最后一次的 i，这是最典型的手误：代码看起来完全正常，答案少一半。
成对检查法调不出来时先数一遍：每个 = 1 是否都配了一个 = 0，两者是否在同一个循环体、同一个下标变量上。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int n = 3, a[10];
bool vis[10];

void dfs(int step) {                       // step：正在填第几个位置
    if (step > n) {                        // 出口：n 个位置都填满了
        for (int i = 1; i <= n; ++i) cout << a[i] << ' ';
        cout << '\n';
        return;
    }
    for (int i = 1; i <= n; ++i) {         // 这一层的候选集：1..n
        if (vis[i]) continue;              // 已被前面某层占用的数不能再用
        a[step] = i;
        vis[i] = 1;                        // ① 占位
        dfs(step + 1);                     // ② 递进
        vis[i] = 0;                        // ③ 还原
    }
}

int main() { dfs(1); }                     // 输出 6 行，正好是 3! 个排列
注意

注意 a[step] = i 不需要还原：同一层的下一次循环会直接覆盖它。要还原的是占用关系（vis），不是答案数组。

忘记还原的症状很隐蔽：不 RE、不崩，只是方案数远少于预期（常常只剩一条）；如果只在某个分支上漏写，就变成“答案小一点”，最难查。

还原写在 dfs 之前，症状相反：同一个数被反复填，输出大量非法排列，n 稍大直接 TLE。

新函数拆解 · start 参数（组合的去重手段）
void dfs(int step, int start)
组成含义 / 格式要求
step已经选了几个数，等于递归层数。step == k 时到达出口。
start这一层允许使用的最小下标。它把“下标严格递增”变成一条硬约束，于是每个集合只有一种生成顺序。
为什么就够去重从 {1,2,3} 里选 2 个，排列会给出 (1,2) 和 (2,1) 两份；先选小的、后选大的，就只留 (1,2)。
传 i + 1 还是 i当前数用过就不能再用 → 传 i + 1；如果允许重复使用同一个数（如整数拆分）→ 传 i。
和 vis 的分工vis 管“哪些用过了”，start 管“只能往更大的方向选”。组合用 start 就够，不需要 vis。
出口写法step > k 与 step == k 都能用，但必须和传参起点对齐。两种风格混着改，是 off-by-one 的主要来源。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int n = 5, k = 3, a[25];

// 从 1..n 中选 k 个，按字典序输出每一种组合
void dfs(int step, int start) {            // step：已选个数；start：本层最小可选值
    if (step > k) {                        // 选够了，输出一种组合
        for (int i = 1; i <= k; ++i) printf("%3d", a[i]);
        printf("\n");
        return;
    }
    for (int i = start; i <= n; ++i) {     // 只从 start 往后选
        a[step] = i;
        dfs(step + 1, i + 1);              // ★ 下一层起点是 i+1，不是 start+1
    }
}

int main() { dfs(1, 1); }                  // C(5,3) = 10 行
注意

写成 dfs(step + 1, start + 1) 是经典错误：那样只会生成 {(1,2,3),(2,3,4),…} 这类连续区间，方案数少一大截，而且小数据很难发现。

把 i + 1 改成 i，同一个数可以被重复选，输出就变成“可重复组合”，第 32 节完全背包的枚举就长这样。

新函数拆解 · printf 定宽输出
printf("%5d", x);
组成含义 / 格式要求
%5d十进制整数，右对齐，至少占 5 个字符位，不够的在左边补空格。
%-5d负号 = 左对齐，空格补在右边。
宽度小于实际位数有宽度的格式符不截断。x = 123456 时 %5d 照旧输出 6 位，整行就错位了。
一行的分隔printf("%d%c", x, i == n ? '\n' : ' '); 用三元表达式让行末换行、其余打空格，省掉 if。
和 cout 混用两者都能用，但一个程序里最好只用一种。混用时不要写 ios::sync_with_stdio(false)，否则输出顺序可能乱。
最小可运行示例
示例
#include <bits/stdc++.h>
using namespace std;

int main() {
    for (int i = 1; i <= 3; ++i) printf("%5d", i);   // "    1    2    3"
    printf("\n");
    printf("[%5d][%-5d]\n", 42, 42);                 // "[   42][42   ]"
    printf("%5d\n", 123456);                        // 宽度不够时不截断，输出 123456
    return 0;
}
注意

本节的挑战题 P1088 要求“N 个数、相邻两数之间一个空格、行末不能多空格”，用 cout 得在循环里写 if；用 printf 的 %d%c 组合一个格式符就够了，更不容易漏。有的题还要求每个数占固定宽度（例如 P1706 要求 %5d），也是同一个格式符的事。

对 long long 要用 %5lld，用 %5d 会把高 32 位丢掉，输出一个随机数。

下面的例题是本节所有内容的最小检验：它的搜索树有 2²⁰ 个叶子，却因为一个剪枝在 1 秒内跑完；而它把“枚举所有方案”和“取最优”两件事同时装进了一副 DFS 骨架里。

例题 · kkksc03 考前临时抱佛脚洛谷 P2392普及-去洛谷做这题 ↗

kkksc03 要考 4 科，每科各有一本习题集，第 k 科有 s_k 道题，做完第 i 道要花 t 时间。

他的左右两个大脑可以同时各做一道题，但仅限于同一科；所以他必须一科一科地复习，同一科内的题可以任意分配给左脑或右脑并行做。

问复习完全部 4 科最少要多久。

输入格式：共 5 行。第 1 行 4 个正整数 s₁ s₂ s₃ s₄；第 2~5 行各给出该科每道题所需的时间。

输出格式：一行一个整数，表示最短总时间。

数据范围：1 ≤ s_k ≤ 20，每道题的时间 ≤ 60。

输入： 2 1 1 1 3 4 5 6 1 输出： 16
例题怎么想：每科独立，把“选不选”变成“给谁做”

先切开。4 科必须一科一科复习，总时间 = 4 科用时之和；“同一科内两脑并行”只影响单科用时。所以 4 科是 4 个完全独立的子问题，分别求最小再相加——这一步判断省掉了任何跨科的组合。

单科模型。把这一科的题分成两堆 A、B，分别给左脑、右脑并行做，这一科用时就等于 max(sum A, sum B)：两堆同时开始，谁先做完都要等另一堆。所以问题变成“把 s 个数分成两堆，让较大那堆的和尽量小”。

枚举什么。每道题只有两种归属（左或右），所以一共 2^s 种分法，s ≤ 20 时最多 2²⁰ ≈ 10⁶ 种。这正好是“选/不选”模板：层数是题数，每层两个分支。

状态怎么记。dfs(k, idx, sum)：第 k 科、正要决定第 idx 道题、左脑已经用了 sum。右脑的用时不用单独存——它是 tot[k] − sum，用到时再算，少一个参数就少一处错。

出口与更新。idx > s[k] 时这一科分完了，代价 = max(sum, tot[k] − sum)，用它更新这一科的 best。注意 best 在每科开始前要重置成无穷大。

剪枝。代价 max(sum, tot−sum) ≥ sum，所以当 sum ≥ best 时，再往下分配只会让 sum 更大，不可能更优 → 直接 return。这一句把实际访问的节点数砍掉一大截。

规模。最坏 4 × 2²⁰ ≈ 4.2×10⁶ 个叶子，每个叶子一次比较；加剪枝后通常只走几万到几十万个节点，1 秒内轻松跑完。

完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

int s[5];                // 每科的题数
int t[5][25];            // 每道题所需时间
int tot[5];              // 每科的总时间
int best;                // 当前这一科的最小用时

// 第 k 科，正在决定第 idx 道题，左脑已用 sum
void dfs(int k, int idx, int sum) {
    if (sum >= best) return;              // 最优性剪枝：左脑已经不比已知答案好
    if (idx > s[k]) {                     // 这一科分完了
        best = min(best, max(sum, tot[k] - sum));   // 两脑并行，慢的那个决定用时
        return;
    }
    dfs(k, idx + 1, sum);                 // 这道题交给右脑
    dfs(k, idx + 1, sum + t[k][idx]);     // 这道题交给左脑
}

int main() {
    for (int k = 1; k <= 4; ++k) cin >> s[k];
    for (int k = 1; k <= 4; ++k)
        for (int i = 1; i <= s[k]; ++i) {
            cin >> t[k][i];
            tot[k] += t[k][i];
        }

    int ans = 0;
    for (int k = 1; k <= 4; ++k) {
        best = INT_MAX;                   // 每科单独求，必须重置
        dfs(k, 1, 0);
        ans += best;                      // 4 科串行，用时相加
    }
    cout << ans << "\n";
    return 0;
}
逐行拆解
代码片段含义与理由
int s[5]; int t[5][25];4 科，每科最多 20 题，开 25 格够用。下标从 1 开始，和题号对齐，少一次减一。
int best;只有这一个全局变量会跨调用变化，所以回溯时要小心：它不是“答案数组”，而是“当前最优”，不需要还原，但每科开始前必须重置成 INT_MAX。
void dfs(int k, int idx, int sum)三个参数分别回答“哪一科、第几道题、左脑用了多久”。右脑用时由 tot[k] − sum 推出，不用再传一个参数。
if (sum >= best) return;最优性剪枝。因为 max(sum, tot−sum) ≥ sum，所以 sum 一旦追平 best，这条分支就不可能更优。注意条件是 >=，写成 > 只是少剪一点，不影响正确性。
if (idx > s[k])出口写成“第 s[k]+1 道”，表示这一科全部定完了。写成 idx == s[k] 会漏掉最后一题的归属。
best = min(best, max(sum, tot[k] - sum));单科用时是两脑用时的较大值。写成 min 或 + 都是逻辑错误——两脑是并行的，不是相加。
dfs(k, idx + 1, sum);先走“交给右脑”这一支：sum 不变，所以更容易较早凑出较小的 max，让 best 尽快变小，后面的剪枝更狠。
best = INT_MAX;每科开始前重置。忘了这一句，第 2~4 科会直接沿用上一科的最优值，答案偏小且样例都可能对不上。
三个模板：只差“候选集”那一行

把子集、组合、排列写成同一副骨头，差别只在循环怎么写。这三段建议直接背下来，之后所有搜索题都是往里面填东西。

子集：选或不选
#include <bits/stdc++.h>
using namespace std;

int n = 3, a[25], top = 0;

void dfs(int i) {
    if (i > n) {                          // 每个元素的去留都定了
        for (int k = 1; k <= top; ++k) cout << a[k] << ' ';
        cout << '\n';
        return;
    }
    dfs(i + 1);                           // 分支一：不选 i
    a[++top] = i;                         // 分支二：选 i，先占位
    dfs(i + 1);                           //        再往下
    --top;                                //        回来时弹出（这就是还原）
}

int main() { dfs(1); }                    // 2^3 = 8 行，第一行是空集
组合：start 递增
#include <bits/stdc++.h>
using namespace std;

int n = 5, k = 3, a[25];

void dfs(int step, int start) {
    if (step > k) {
        for (int i = 1; i <= k; ++i) cout << a[i] << ' ';
        cout << '\n';
        return;
    }
    for (int i = start; i <= n; ++i) {    // 起点是 start，不是 1
        a[step] = i;
        dfs(step + 1, i + 1);             // 下一层起点右移一格
    }
}

int main() { dfs(1, 1); }                 // C(5,3) = 10 行

③ 排列：候选集固定为 1..n，用 vis[] 排除已经用过的数（第 14 节的 P1706 就属于这一种）。三者对照一下：子集的分支数固定为 2，不需要循环；组合的循环起点是变的；排列的循环起点固定、靠 vis 排除。

还有一条容易忽略：子集模板里 --top 就是“回溯三行”的第三行，只不过这里占位的是一个栈指针而不是 vis。还原的对象永远是“你刚才改动的那份状态”，把它找出来，回溯就不会写错。

这一节的 6 个坑，每个都有具体症状

WA，答案偏小且样例就可能对不上：best 没有在每科开始前重置成 INT_MAX，第 2~4 科直接沿用了第 1 科的最优值。

WA，答案明显偏小：单科用时写成 min(sum, tot−sum)。两脑是并行不是串行，慢的那个才决定用时。

WA，最后一题的归属丢了：出口写成 idx == s[k]。正确出口是“第 s[k]+1 道”，即 idx > s[k]。

WA，答案偏大：剪枝条件写反成 if (sum <= best) return;，把还能变优的分支整片砍掉。剪枝的边界写完后一定手算一组小数据验一遍。

WA，只有某一科错：tot[k] 累加时忘了先清零，或者在读入循环里把题加到了别的科上。

WA，输出只有一位数：只 cout << best，忘了 4 科是串行的，要把每科的 best 累加到 ans。

数学补给 · 方案数估算：n! 和 2ⁿ 的失控点

DFS 枚举的时间 = 搜索树节点数 × 每个节点的工作量。节点数是可以提前算出来的，这就是“能不能做”的唯一判据。

排列：A(n,k) = n!/(n−k)! 组合：C(n,k) = n!/(k!(n−k)!) 子集：2ⁿ = Σ C(n,k)

nn!2ⁿC(n, n/2)能不能枚举

25—33554432—子集已吃力

判据：一般评测机 1 秒约做 10⁸ 次简单操作，但搜索的每个节点还要输出或判断，所以节点数控制在 10⁷ 以内才稳。于是 n! 的失控点在 n = 11~12，2ⁿ 的失控点在 n = 24~25，C(n, n/2) 在 n = 30 附近（1.5×10⁸）。

输出也会失控。本节挑战题 P1088 只输出一行 10⁴ 个数，约 60 KB；但如果题目要求“输出全部排列”，n = 9 就是 362880 行、约 16 MB，n = 12 更是 4.8×10⁸ 个排列、约 28 GB——哪怕搜索一秒跑完，输出也要跑几分钟。看到“输出所有方案”先估输出量，这一条比估复杂度更早生效。

递归深度不用担心：深度等于层数，排列是 n 层、组合是 k 层，每层栈帧几十字节，n ≤ 10⁴ 都不会爆栈。下一节的网格搜索才会遇到“深度 = 状态数”导致的爆栈。

挑战题 · 火星人
洛谷 P1088普及-去洛谷做这题 ↗

火星人用一排手指表示数：N 根手指编号 1..N，一种排列就是一个 N 位数。把所有能形成的排列按字典序从小到大排好，第 k 小的排列就表示数 k。例如 N = 3 时：123 = 1、132 = 2、213 = 3、231 = 4、312 = 5、321 = 6。

现在给你火星人当前的排列和一个小整数 M，要求输出“比它大 M 的排列”，即把它往后数 M 个。数据保证结果不会超出 N! 的范围。

输入格式：三行。第一行一个正整数 N（1 ≤ N ≤ 10000）；第二行一个正整数 M（1 ≤ M ≤ 100）；第三行是 1..N 的一个排列，用空格隔开。

输出格式：一行 N 个整数，即答案排列，相邻两数之间一个空格，行末不能有多余空格。

引导性提示（先只看这里）

M 很小（≤ 100），但 N 很大（≤ 10000），N! 更是天文数字——所以不能“把全部排列排出来再往后找”。

只问“下一个”的话，能不能只改动排列末尾的一小段？想想一个排列什么时候已经是末尾的最后一个。

从右往左找第一个“下降点” a[i] < a[i+1]：它右边全是递减的，说明这一段已经排到尽头了。把这个点换成一个更大的数，再把右边重新排成最小——这就是“下一个排列”的全部动作。

想看思路了？点开完整思路

思路。答案就是把当前排列做 M 次“求下一个排列”。M ≤ 100，每次 O(N)，总计 O(NM) ≤ 10⁶。关键是 O(N) 求出“字典序的下一个排列”，这就是 next_permutation 的原理。

第一步：找下降点。从右往左扫，找到最靠右的 i 使 a[i] < a[i+1]。i 右边这段一定是递减的（否则右边还有下降点，i 就不是最靠右的）。如果找不到这样的 i，说明整个排列递减，它已经是最后一个排列。

第二步：换一个更大的数上来。在 i 的右边从右往左找第一个 a[j] > a[i]（右边递减，所以从右往左扫到的就是“大于 a[i] 的数里最小的那个”），交换 a[i] 与 a[j]。这一步保证新排列比原排列大、但只大最少的一点点。

第三步：把后缀变成最小。交换之后 i 右边仍然是递减的，反转它就变成递增，也就是后缀能排成的最小顺序。先换数、再反转，顺序不能颠倒。

为什么这是“下一个”。新排列的前 i−1 位与原排列相同（最长公共前缀）；第 i 位变大了一点点；后缀取到了最小。任何比原排列大、又比新排列小的排列，都必须在前 i−1 位相同的前提下第 i 位不变大，但那样它就不比原排列大——矛盾。所以新排列正好是紧邻的下一个。

输出。用 printf("%d%c", a[i], i == n ? '\n' : ' ') 一次搞定空格与换行，避免行末多一个空格。也可以直接用 std::next_permutation，但手写一遍才真正掌握“排列枚举”。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int a[10005], n;

bool nxt() {                          // 求字典序的下一个排列
    int i = n - 1;
    while (i >= 1 && a[i] >= a[i + 1]) --i;   // 从右往左找最靠右的下降点
    if (i < 1) return false;                  // 整体递减：已经是最后一个排列
    int j = n;
    while (a[j] <= a[i]) --j;                 // 右边递减，从右往左找第一个 > a[i] 的
    swap(a[i], a[j]);
    reverse(a + i + 1, a + n + 1);            // 后缀反转成最小顺序
    return true;
}

int main() {
    int m;
    cin >> n >> m;
    for (int i = 1; i <= n; ++i) cin >> a[i];

    for (int k = 0; k < m; ++k) nxt();        // 往后数 m 个

    for (int i = 1; i <= n; ++i)
        printf("%d%c", a[i], i == n ? '\n' : ' ');   // 行内空格、行末换行
    return 0;
}
关键片段拆解
片段作用
while (i >= 1 && a[i] >= a[i + 1]) --i;从右往左找最靠右的下降点。用 >= 而不是 >：相邻两数相等时（本题是排列，不会出现，但换成多重集就需要），这一段仍算“递减”。
if (i < 1) return false;整个数组递减，说明它是最后一个排列。本题保证不会越过 N!，但写上它才是一个完整函数。
while (a[j] <= a[i]) --j;i 右边递减，所以从右往左第一个比 a[i] 大的数，正是“比 a[i] 大的数里最小的”。换成从左往右扫，交换后第 i 位会变得过大，得到的就不是下一个排列。
swap(a[i], a[j]);把最小的“更大的数”换到第 i 位，保证新排列只比原排列大最少的一点点。
reverse(a + i + 1, a + n + 1);交换后后缀仍然递减，反转成递增就是后缀的最小排列。注意区间是 [i+1, n]，左闭右开所以右端写 a + n + 1。
for (int k = 0; k < m; ++k) nxt();M ≤ 100、N ≤ 10000，所以最多 10⁶ 次操作。若 M 很大，就得用康托展开直接定位，那是另一个话题。
printf("%d%c", a[i], i == n ? '\n' : ' ');题目要求相邻两数一个空格、行末不多空格。用 cout << a[i] << " " 会多出末尾空格。
这题最容易错的地方
  • 找下降点时用 a[i] > a[i+1]（多写了一个等号）：遇到相邻相等就停错位置，后续全乱。
  • 只交换 a[i] 与 a[j] 而忘了反转后缀：输出的是一个合法的排列，但不是紧邻的下一个。
  • 反转写成 reverse(a + i, a + n + 1)：把刚换好的第 i 位也反转了，答案完全错。
  • 输出用 cout << a[i] << ' '：行末多一个空格，逐字比对会被判 WA。

挑战 2 · 数的划分
洛谷 P1025普及/提高-去洛谷做这题 ↗

把整数 n 分成 k 份，每份都不能为空，且不考虑顺序。例如 n = 7、k = 3 时，(1,1,5)、(1,5,1)、(5,1,1) 被认为是同一种分法。

输入格式：一行两个整数 n、k（6 ≤ n ≤ 200，2 ≤ k ≤ 6）。

输出格式：一行一个整数，即不同的分法数。

样例对应的 4 种分法是 (1,1,5)、(1,2,4)、(1,3,3)、(2,2,3)。

样例
输入： 7 3 输出： 4
引导性提示（先只看这里）

“不考虑顺序”这一条必须变成代码里的约束，否则同一个方案会被数 k! 次。想想怎样规定一个统一的书写顺序。

把一份方案写成 a₁ ≤ a₂ ≤ … ≤ a_k，它就唯一了——每种分法恰好对应一个不降序列。于是问题变成“枚举长度为 k 的不降正整数序列，和为 n”。

枚举到第 step 份时，用“剩下的和 rest”和“这一份的最小值 last”就能描述全部进度；还要提前判断剩下的份能不能分完。

想看思路了？点开完整思路

去重手段。强制方案按不降序书写：a₁ ≤ a₂ ≤ … ≤ a_k。任何一个无序分法排序后唯一，所以“不降序列”与“分法”一一对应，不重不漏。这和第 23 节组合枚举里“下标递增”是同一个思想。

状态。dfs(rest, step, last)：还要分的总和 rest、还要分成 step 份、下一份最小能取 last。三个参数把“已经分了多少、还剩多少、下一个至少多大”全说清了。

转移。第 step 份取 v，v 从 last 开始往上试，然后递归 dfs(rest − v, step − 1, v)。把 v 当作新的 last，不降序自动成立。

循环上界就是可行性剪枝。剩下的 step 份每份至少 v，所以必须 step · v ≤ rest，即 v ≤ rest / step。写成 for (int v = last; v * step <= rest; ++v) 一步到位，不用另外判。

出口。step == 1 时只剩一份，它必须等于 rest；只要 rest ≥ last（不降序成立）就计一种方案。不必再循环——最后一份是被前面的选择唯一确定的。

为什么停。每递归一次 step 减一，且 rest 严格减小（v ≥ 1），所以最多 k 层、每层有限，一定走到 step == 1。

复杂度。枚举的是“不降序列”的个数，也就是分法数本身（n = 200、k = 6 时不超过几万），加上剪枝后实际访问的节点只有几万级，远小于排列数 k!。

答案量级。n = 200、k = 6 时答案在 10⁵ 量级，int 足够；但计数类题目养成用 long long 的习惯更稳。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int n, k, ans = 0;

// rest：还要分的和；step：还要分成几份；last：这一份最小能取多少
void dfs(int rest, int step, int last) {
    if (step == 1) {                 // 只剩一份：由前面已选的数唯一确定
        if (rest >= last) ++ans;     // 还要满足不降序
        return;
    }
    for (int v = last; v * step <= rest; ++v)   // v*step <= rest：剩下的每份都 ≥ v
        dfs(rest - v, step - 1, v);             // 下一份的下界抬到 v，保证不降
}

int main() {
    cin >> n >> k;
    dfs(n, k, 1);                    // 和为 n，分 k 份，第一份至少是 1
    cout << ans << "\n";
    return 0;
}
关键片段拆解
片段作用
dfs(int rest, int step, int last)三个参数正好对应“还剩多少、还要几份、下一份至少多大”。last 是不降序的唯一开关。
if (step == 1)只剩一份时不用循环——剩下的 rest 全给它，方案唯一确定。这一步把最后一个 for 循环省掉了。
if (rest >= last)最后一份也必须 ≥ last，否则不满足不降序，这种写法会和前面已经数过的方案重复。
for (int v = last; v * step <= rest; ++v)上界 rest / step 就是可行性剪枝：剩下的 step 份每份至少 v，装不下就停。写成 v <= rest 也能出正确答案，但会多试很多无用分支。
dfs(rest - v, step - 1, v)第二、三个实参分别是“扣掉这一份”和“把下界抬到 v”。传 last 而不是 v 会允许重复计数；传 v+1 则强制严格递增，会漏掉 (1,1,5) 这类有相等项的方案。
dfs(n, k, 1);从“和为 n、还要 k 份、第一份至少 1”出发。下界写 0 也行，但 0 会让 step 永远减不完。
cout << ans答案是方案数，不是某条路径。注意这里没有输出具体分法，所以不需要存 a[] 数组。
这题最容易错的地方
  • 去重手段用错：last 传 last 允许相等项重复计数，传 v + 1 又漏掉相等项。本题要求不降（允许相等），所以传 v。
  • 循环上界写成 v <= rest：答案对但慢；写成 v < rest 则会漏掉“最后一份就是 rest”的情况。
  • 出口漏了 rest >= last 的判断，会把 (5,1,1) 这类倒序写法也算进来，方案数偏大。
  • 把“不考虑顺序”理解成“去掉重复的方案”，在最后用 set 去重：既慢又容易写错，正解是在枚举时就规定顺序。
