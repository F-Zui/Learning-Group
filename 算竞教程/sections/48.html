48 · 单调栈与单调队列

一句话概括这一节：把不可能成为答案的元素当场删掉。四个用法串起来——单调栈求下一个更大元素、左右边界定柱状图最大矩形、单调队列求滑动窗口最值、单调队列把 DP 的 O(nR) 转移压成 O(1)。
提高-预计 65 分钟单调栈滑动窗口最值贡献法

单调栈和单调队列解决同一类问题：在滑动窗口里随时拿到最值。手法只有一句——把“永远不可能成为答案”的元素当场删掉。删得干净，每个元素只进一次、出一次，均摊 O(n)。

单调栈维护“还没等到答案的下标”；单调队列维护“当前窗口里还可能成为最值的下标”。两者都只做两件事：入队前弹掉比自己差的，入队后弹掉过期的。
任务结构弹出条件均摊代价
右边第一个更大元素单调栈，栈内值不增栈顶值 < 当前值就弹O(n)
柱状图中最大矩形单调栈，左右各跑一遍栈顶值 ≥ 当前值就弹O(n)
长度 k 的窗口最值单调队列，队内值单调队尾更差就弹 + 队头过期就弹O(n)
f[i] = a[i] + max f[j]单调队列，窗口 [i−R, i−L]队尾 f 更小就弹 + 队头出窗O(n)

四段代码是同一份骨架：while 弹队尾 → push 当前 → while 弹队头 → 用队头更新答案。真正的差别只有两处：弹队尾用 < 还是 ≤，以及队头什么时候算过期。这两处写错，样例照样过，随机数据一片 WA。

推导deque（双端队列）覆盖：deque / push_back / push_front / 存下标需求 → 尝试 → 验证 → 定理
问题

普通 queue 只能队尾进、队头出；stack 只能一端进出。而滑动窗口要同时做两件事：队尾弹掉更差的元素（像栈），队头弹掉过期元素（像队列）。

一个容器要在两端都能增删，朴素想法是数组 + 两个指针，但那样删除中间元素要搬数据。C++ 的 deque 正是为这件事设计的：双端队列。

1尝试①：把两端的接口列出来

deque 提供 push/pop × front/back 四个组合，外加两端的取值。单调队列用的就是这四件事。

签名：全部接口
deque<int> q;
q.push_back(x);  q.pop_back();
q.push_front(x); q.pop_front();
q.front();  q.back();  q.empty();  q.size();
验证 / 关键

注意它和 stack 的唯一区别：两端都能动，所以能弹掉过期元素。stack 只有一端，弹不掉队头 —— 这就是单调队列必须用 deque 的原因。

2尝试②：逐项确认
组成部分含义 / 格式要求
<deque><bits/stdc++.h> 已包含。声明写成 deque<int> q; 或 deque<pair<int,int>> q;。
push_back / pop_back队尾进、队尾出。单调队列用它们维护“值单调”这一侧。
push_front / pop_front队头进出。这是它和 stack 的唯一区别：两端都能动，所以能弹掉过期元素。
front() / back()O(1) 取两端。单调队列的队头永远是当前窗口的最值下标。
必须存下标存值就无法回答“这个元素还在不在窗口里”。窗口滑动时只靠下标判断过期。
q[i] 随机访问deque 支持 O(1) 下标访问，但单调队列只用两端，用 q[i] 遍历反而慢。
底层结构分段连续存储，每段定长；两端增删都是 O(1)，比 vector 多一层指针，常数略大。
什么时候用手写数组窗口长度和值域都固定时，用 int q[N], head, tail 更快（无函数调用、无内存分配）。
验证 / 关键

“必须存下标”这条最容易忽视：窗口滑动时判过期靠的是“这个下标还在不在 [i−k+1, i] 里”，存值根本没有这个信息。

3尝试③：跑一段，看队头一直是窗口最小值
示例：队头即最小值
#include <bits/stdc++.h>
using namespace std;

int main() {
    int a[] = {5, 3, 8, 1};        // 下标 0..3
    deque<int> q;                  // 只存下标，值从队头到队尾单调递增

    for (int i = 0; i < 4; ++i) {
        while (!q.empty() && a[q.back()] >= a[i]) q.pop_back();  // 队尾更差的永久退休
        q.push_back(i);
        cout << a[q.front()] << " ";   // 队头就是当前最小值：5 3 3 1
    }
    cout << "\n";
    return 0;
}
验证 / 关键

输出 5 3 3 1。三行代码就是单调队列的全部骨架：弹队尾 → 入队 → 读队头。滑动窗口只是在这三行之间再插一句“弹过期队头”。

4尝试④：三条记下来
  • 在空的 deque 上调用 front() / back() 是未定义行为，通常读到垃圾值。每一处 front() 之前都要想清楚“它会不会是空的”。
  • deque 虽然支持 q[i]，但它的迭代器比 vector 重；频繁按下标遍历时用 vector。
  • 本节所有题目都可以用 deque 实现，熟练后再换成手写数组压常数。
于是我们得到：

双端队列：两端都能进出、能 O(1) 取两端。它是单调队列的容器，队列里存的是下标，不是值。

一句话记住：两端都能进出的队列，单调队列的容器。

追问 · 把这一步想透
  1. 滑动窗口求最值时，如果 k 接近 n，单调队列还是 O(n) 吗？它省下的到底是哪部分工作？
    想好了？点开核对思路与解析
    还是 O(n)。复杂度与 k 无关：每个下标入队 1 次、出队至多 1 次，总操作 ≤ 2n，k 是 10 还是 106 都一样。但它省下的是“同一个元素被相邻的多个窗口重复比较”那部分：k 接近 n 时窗口只有 n−k+1 个，暴力总共才 (n−k+1)·k ≈ n 次，单调队列反而显不出优势；优势最大的是 k ≈ n/2，那时暴力约 n²/4，队列仍是 2n。常见错路是以为“k 大时队列会退化”或“队列长度是 k 所以复杂度带 k”——队列里最多 k 个元素，但每个元素一生只进出一次；反过来也有人以为 k 接近 n 时必须换 ST 表，其实没有必要。
  2. 把 dpi = min{ dpj + (sumi − sumj)² } 的转移也交给单调队列，为什么不行？这类式子需要什么额外条件（决策单调性 / 凸性）才能用队列维护？
    想好了？点开核对思路与解析
    不行。先把式子展开：dpj + (si − sj)² = si² + (dpj + sj²) − 2·si·sj，对固定的 j 它是 si 的一次函数，斜率 −2sj、截距 dpj + sj²。单调队列能用的前提是“谁更优只看元素自身的值”，可这里两个 j 谁更优取决于当前查询的 si——而且候选集合是 [1, i−1] 只增不减，根本不是定长滑动窗口。这类式子要用斜率优化：维护一个下凸包，队头按“两条直线的交点是否已越过 si”弹，队尾按叉积弹，si 不单调时还要在凸包上二分。常见错路是把“min + 平方”直接当滑动窗口最值套单调队列，队头弹出的元素过几步可能又变回最优，答案偏大；另一条是老老实实写 O(n²)，n = 105 时 1010 次转移直接 TLE。
  3. 窗口里如果要同时维护“最大值”和“最大值出现的次数”，单调队列还够用吗？为什么？
    想好了？点开核对思路与解析
    够用，但必须改一处：弹队尾时只弹严格更小的（把 >= 换成 >），让等大的元素全部留在队列里。这样队列仍然非增，队头是最大值，而从队头开始连续的那一段等值元素，个数就是最大值出现的次数——过期只可能发生在队头，弹掉最左边那个就自然少一次。如果照本节求最值的习惯用 >= 把等号弹掉，旧的最大值出现位置被删，计数一定偏小，而且只在有重复最大值的数据上错。常见错路是硬扛：要么用 multiset 每窗口 O(log k)（能过但慢一个 log），要么想靠“记录最大值和它第一次出现的位置”蒙过去，窗口里有多个并列最大值时立刻错。
推导数组模拟栈：stk[++top]覆盖：数组模拟栈 / top 指针 / 全局数组需求 → 尝试 → 验证 → 定理
问题

deque 能用了，但 P5788 的 n 到 3×10⁶。这时 std::stack 的三个操作 top() / push() / pop() 是三次函数调用，还带着内存分配和迭代器封装 —— 常数大到能决定过不过。

而且栈的数组大小是编译期就知道的（n + 5），根本不需要动态结构。能不能只要一个数组加一个指针？

1尝试①：一个数组 + 一个下标

元素存在 stk[1..top]，top 同时就是栈的大小。stk[0] 永远空着，可以当值为 0 的哨兵。

签名：五个动作
int stk[N], top = 0;
stk[++top] = i;        // 入栈
int t = stk[top];      // 取栈顶
--top;                 // 出栈
if (top == 0) { /* 空 */ }
验证 / 关键

没有任何函数调用、没有内存分配 —— 这就是手写数组栈比 std::stack 快 2~3 倍的原因，而且能按下标回溯（stk[k] 直接读第 k 层）。

2尝试②：逐项确认
组成部分含义 / 格式要求
top = 0 表示空栈元素存在 stk[1..top]，top 同时就是栈的大小。stk[0] 永远空着，可以当值为 0 的哨兵。
stk[++top] = i先加后写：第一个元素落在 stk[1]。写成 stk[top++] 会让下标从 0 开始，后续判空要小心。
a[stk[top]]栈里存下标，随时能取回原值、原位置。存值就丢了位置信息，答案要求下标时直接报废。
--top出栈只减指针，O(1)，不动任何内存。
比 std::stack 快 2~3 倍std::stack 的 top()、push()、pop() 是三次函数调用，且无法按下标回溯；3×106 的题手写数组明显更快。
栈必须是全局或 staticn = 3×106 时栈数组 12 MB，开在 main 里会让栈帧过大直接爆栈；开成全局变量（在 BSS 段）最稳。
验证 / 关键

“全局或 static”不是习惯问题，是生死的区别：局部数组 12 MB，评测机栈限制通常 8 MB，直接 RE —— 而数组本身完全没越界。

3尝试③：跑一遍，观察栈内值始终不增
示例：单调栈的标准写法
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 3000005;
int stk[MAXN], top = 0;              // 全局：3e6 个 int 进静态区，不占调用栈

int main() {
    int a[] = {0, 5, 3, 8, 1};       // 1 基下标，a[0] 空着不用
    int n = 4;
    for (int i = 1; i <= n; ++i) {
        while (top > 0 && a[stk[top]] < a[i]) --top;   // 弹掉挡不住当前元素的
        stk[++top] = i;                                // 自己进栈
        cout << "i=" << i << "  栈内值：";
        for (int k = 1; k <= top; ++k) cout << a[stk[k]] << " ";
        cout << "\n";
    }
    return 0;
}

/* 输出（栈内值始终不增）：
i=1  栈内值：5
i=2  栈内值：5 3
i=3  栈内值：8
i=4  栈内值：8 1            */
验证 / 关键

输出里能直接看出“栈内值始终不增”：5 / 5 3 / 8 / 8 1。这就是“单调栈”这个名字的由来 —— 弹掉挡不住当前元素的，剩下的自然单调。

4尝试④：两条记下来
  • 判空必须写 top > 0。少了它，空栈时读 stk[0]（值恒为 0）可能侥幸不崩，但逻辑已经错了——这类“不崩的错”最难查。
  • 数组大小按题目上限 +5 开，n ≤ 3×106 就开 3000005。开小一个数量级只会得到 RE，不会给你提示。
于是我们得到：

手写栈：stk[++top] = i 入栈，--top 出栈，top == 0 判空，数组放全局。这是单调栈在 n = 3×10⁶ 时唯一能过 TLE 的写法。

一句话记住：手写栈：top 指针 + 全局数组，单调栈的标准写法。

  1. 柱状图结论里“最大矩形一定以某根柱子的高度为高”这句话为什么成立？如果矩形上方悬空，能不能往上抬？抬的过程中宽度会变吗？
    想好了？点开核对思路与解析
    因为矩形的高度只能是它覆盖的那些柱子的最小高度：如果矩形的上边界 y 严格低于覆盖区间内的最小柱高，就把上边界一路抬到那根最矮的柱子顶端——覆盖的列一根都没变，宽度不动、高度变大，面积只会变大。所以最优矩形的上边界一定正好卡在某根柱子的高度上，枚举“以 hi 为高”就够了，宽度自然被左右第一个更矮的柱子夹住。常见错路是把结论记成“一定以最高的柱子为高”——最优矩形完全可能是“很矮但很宽”的那个，高度由区间最矮的柱子决定；另一条是担心用 ≥ 弹掉等高的柱子会漏解，其实等高的那几根由最靠左的一根算全宽就够了，最大值不会漏。
算法落地例题 · 【模板】单调栈 · 右边第一个更大的元素覆盖：洛谷 P5788 / 单调栈（下一个更大元素）
需求

例题 · 【模板】单调栈 · 洛谷 P5788 普及/提高-

给出项数为 n 的整数数列 a1, a2, …, an。定义 f(i) 为数列中第 i 个元素之后第一个大于 ai 的元素的下标；若不存在这样的元素，则 f(i) = 0。

输入：第一行一个整数 n（1 ≤ n ≤ 3×106）；第二行 n 个整数 a1..n（1 ≤ ai ≤ 109）。

输出：一行 n 个整数 f(1), f(2), …, f(n)，相邻两数之间用一个空格隔开。

样例
输入：
5
1 4 2 3 5
输出：
2 5 4 5 0
1① 朴素做法为什么死：重复扫描

朴素做法：对每个 i 向后扫，找到第一个更大的位置。n = 3×106 时最坏 9×1012 次比较，按每秒 108 次算要二十多个小时。瓶颈不是“找得慢”，而是重复扫描。

关键是一条支配关系：若 i < j 且 ai ≤ aj，那么对任何 k < i，j 都比 i 更近、且不小于 ai，所以 i 永远不可能是 k 的答案——i 可以从候选集合里删掉。

按这条规则删下去，剩下的候选永远是一串“下标递增、值不增”的位置。新元素 ai 一到，值比它小的候选全部当场确定答案 i（i 确实是它们右边第一个更大的位置），然后 i 自己进候选集合。

“只在一端增删、还要保持单调”——这就是栈。新元素从栈顶开始弹，弹干净再压入，栈里值自然不增。

朴素做法：重复扫描是瓶颈
// 朴素：对每个 i 向后扫（O(n^2)，n = 3e6 时必 TLE）
for (int i = 1; i <= n; ++i)
    for (int j = i + 1; j <= n; ++j)
        if (a[j] > a[i]) { ans[i] = j; break; }
为什么

这一段是整节的灵魂：单调性不是假设，是被“支配关系”逼出来的。删掉永远用不上的候选之后，剩下的集合只能是一串单调的位置 —— 否则中间那个早该被弹掉了。

2② 核心四行：弹、记答案、进栈
核心 4 行
for (int i = 1; i <= n; ++i) {
    while (top > 0 && a[stk[top]] < a[i]) { ans[stk[top]] = i; --top; }
    stk[++top] = i;
}
为什么

为什么总复杂度是 O(n)：每个下标进栈恰好 1 次、出栈至多 1 次，while 里的比较总次数 ≤ 2n。单次 while 最坏能弹 n 次，但那是把别人先前存下的“入栈次数”一次花掉；摊到全部 n 个元素上就是常数。

两处细节决定对错：弹的条件用 < 还是 ≤——题目要“严格大于”，值相等的候选必须留着，所以用 <；栈里存下标而不是值——答案要位置，且重复值无法区分。

3③ 主循环：把四行展开
主循环
    for (int i = 1; i <= n; ++i) {
        // 栈里每个下标都还没等到答案，它们的值从栈底到栈顶单调不增
        while (top > 0 && a[stk[top]] < a[i]) {
            ans[stk[top]] = i;   // i 是它右边第一个更大的位置，答案当场定下
            --top;               // 它再也不会被用到，出栈
        }
        stk[++top] = i;          // 自己进栈，继续等右边
    }
    // 结束时栈里剩下的下标右边没有更大的数，ans 保持 0
为什么

弹的边界是“严格小于”：等于 a[i] 的候选不能弹，因为等于不算“大于”。前半句 top > 0 是判空，少了它会读 stk[0]（值恒为 0），看起来不崩、答案却可能全错。

ans[stk[top]] = i; 要先记答案再 --top，顺序反了就记错了人。stk[++top] = i; 是先 ++ 后赋值，保证元素落在 stk[1..top]。

结束时栈里剩下的下标右边没有更大的数，ans 保持全局数组的初值 0 —— 正好符合题目要求。

4④ 快读：3×10⁶ 个数不能靠 cin
手写快读

为什么

while (c < '0' || c > '9') c = getchar(); 跳过空格与换行。本题 ai ≥ 1，可以不管负号。

x = x * 10 + (c - '0'); 逐位累加。手写快读的本质就是自己解析数字，绕开 cin 的格式检查。输出同理：3×106 次 cout 会慢一截，用 printf 更稳。

5⑤ 完整程序
完整代码
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 3000005;

int n, a[MAXN], ans[MAXN];
int stk[MAXN], top = 0;          // 手写栈：stk[1..top] 存下标，top = 0 是空

inline int readInt() {           // 3×10^6 个数，逐字符读比 cin 快 3 倍以上
    int x = 0; char c = getchar();
    while (c < '0' || c > '9') c = getchar();
    while (c >= '0' && c <= '9') { x = x * 10 + (c - '0'); c = getchar(); }
    return x;
}

int main() {
    n = readInt();
    for (int i = 1; i <= n; ++i) a[i] = readInt();

    for (int i = 1; i <= n; ++i) {
        // 栈里每个下标都还没等到答案，它们的值从栈底到栈顶单调不增
        while (top > 0 && a[stk[top]] < a[i]) {
            ans[stk[top]] = i;   // i 是它右边第一个更大的位置，答案当场定下
            --top;               // 它再也不会被用到，出栈
        }
        stk[++top] = i;          // 自己进栈，继续等右边
    }
    // 结束时栈里剩下的下标右边没有更大的数，ans 保持 0

    for (int i = 1; i <= n; ++i) printf("%d ", ans[i]);
    printf("\n");
    return 0;
}
为什么

const int MAXN = 3000005;：题给 n ≤ 3×106，多开 5 个位置防越界。开成 1e6 只会得到 RE。

int stk[MAXN], top = 0; 放全局：放在静态区，不占 8 MB 的调用栈；top = 0 表示空栈，元素从 stk[1] 开始存。

样例验证：a = 1 4 2 3 5，i=2 时 1 的答案是 2；i=3 时 4 不被弹，2 进栈；i=4 时 2 的答案是 4；i=5 时 3 和 4 的答案都是 5；最后 5 没有答案，输出 0 —— 答案 2 5 4 5 0，与样例一致。

竞赛用法

看到什么想到它：“每个元素右边/左边第一个更大（更小）的元素”、“以某个值为高度的最大矩形”、“所有子数组的最小值之和”—— 只要答案取决于“最近的那个更大/更小”，就是单调栈。

复杂度：均摊 O(n)。每个下标进栈一次、出栈至多一次，while 的总执行次数 ≤ n；空间 O(n)。n = 3×10⁶ 时数组 12 MB，必须放全局。

常见的坑：① 栈里存值而不是下标，重复值或要求输出位置时全错；② 求“严格大于”却写成 <=，相等元素被提前弹掉；③ 判空漏写 top > 0，空栈读 stk[0]；④ 先 --top 再记答案，记错了人；⑤ 数组开 10⁶ 而 n 到 3×10⁶ → RE；⑥ 3×10⁶ 的输入用 cin 且没关同步 → TLE。

模型：单调栈均摊 O(n)坑：弹的条件用 < 不用 <=
追问 · 落到代码上再想一遍
  1. 把“第一个更大”改成“第一个不小于”（允许相等），弹栈条件该怎么变？举一组数据说明两种写法输出不同。
    想好了？点开核对思路与解析
    把弹栈条件从 a[stk[top]] < a[i] 改成 a[stk[top]] <= a[i]，把等号也弹掉——因为“不小于”里“等于”也算，a[i] = a[top] 时 i 就是栈顶的答案，栈顶没有理由再等下去。数据 1 4 4 5：严格大于输出 2 4 4 0，改成不小于输出 2 3 4 0，差别只在第 2 个数——它会认位置 3 那个 4，而不是跳过等号去认位置 4 的 5。常见错路是只改了一半：题面读成“不小于”，代码里还是 <，重复值处答案一律偏右（偏到后面更大的那个）；更糟的是把不等号方向记反，写成 a[stk[top]] > a[i]，那维护的是递增栈，语义整个换了。
  2. “左边第一个更大”和“右边第一个更大”能不能一遍扫完同时求出来？需要几个栈、各自的方向是什么？
    想好了？点开核对思路与解析
    能，一次从左往右的扫描就够，只要把答案改成弹出时结算：p 被 i 弹出时，右边第一个更大就是 i；而弹完后 p 下面的那个元素（也就是新的栈顶）正是 p 左边第一个更大的位置。一个栈同时给出 L 和 R，不用反着再扫一遍。本节柱状图那份代码之所以跑两遍，是因为它把“扫描到 i 时结算 L”和“反向扫描结算 R”分开了，两遍写法更好读。常见错路是以为必须开两个栈（一个从左、一个从右）——方向不同不等于栈要两份；另一条是忘了没被弹出的元素没有右边界，一遍写法里必须在末尾补一个高度 0 的哨兵把它们全部弹出来，否则 L、R 只填了一半。等号放在哪一侧还要跟题目语义对齐：柱状图两边都用 ≥ 也行（面积与归给谁无关），做贡献法时就必须一边严格一边不严格。
  3. 所有子数组最小值之和可以用 L、R 做贡献法。那“所有子数组最大值之和”呢？L、R 该怎么定义？
    想好了？点开核对思路与解析
    完全对称：把每个子数组归给它的最大值，Li 取左边第一个严格大于 hi 的位置，Ri 取右边第一个大于或等于 hi 的位置，答案 = Σ hi × (i − Li) × (Ri − i)。注意等号的方向要跟着换：最小值版本是“左严格小于、右小于等于”，最大值版本就变成“左严格大于、右大于等于”，这样每个子数组只会归给它最靠右的那个最大值，不会重复计数。偷懒的等价做法是把所有数取负，用最小值版本算完再取负。常见错路是把最小值那套 L、R 定义原样照搬（左小右小于等于），相等的最大值会被两个位置各统计一次，答案偏大。

第一件事是把“下一个更大”换成“左右第一个更矮”，问题就从模板题变成一道真正的模型题：柱状图中最大的矩形。

算法落地用法 · 柱状图最大矩形：左右各找第一个更矮的，宽度被夹住覆盖：柱状图最大矩形 / 左右第一个更矮 / 哨兵 / long long
需求

n 根宽 1、高 hi 的柱子并排。结论是：最大矩形总可以“往上抬”到顶住某根柱子的顶端，所以它一定是以某个 hi 为高的矩形。于是枚举 i，求以 hi 为高时能伸多宽——答案是左右两边各自“第一个比 hi 矮”的位置之间。

设 Li、Ri 为左右第一个比 hi 矮的下标（没有就是 0 与 n+1），则面积 = hi × (Ri − Li − 1)。求 L、R 就是把上一题的不等号反过来，各跑一遍单调栈。

需求：给定 h = 2 1 5 6 2 3，求最大矩形面积。能手算：以第 3 根（高 5）为高，宽 5 − 2 − 1 = 2，面积 10。

样例
输入：6
2 1 5 6 2 3
输出：10
1① 结论：最大矩形一定以某根柱子的高度为高
读入 + 哨兵
vector<int> h(n + 2, 0);                 // h[0] 与 h[n+1] 是高度 0 的哨兵
for (int i = 1; i <= n; ++i) cin >> h[i];
为什么

为什么一定以某根柱子的高度为高：矩形的高度只能是它覆盖的那些柱子的最小高度。如果矩形的上边界严格低于覆盖区间内的最小柱高，就把上边界一路抬到那根最矮的柱子顶端——覆盖的列一根都没变，宽度不动、高度变大，面积只会变大。所以枚举“以 hi 为高”就够了。

首尾各留一个高度 0 的哨兵：任何真实柱子都比它高，于是“左边没有更矮的”这种情况由 0 号位兜住，代码里少一个分支。

2② 左边界：弹掉所有不比它高的，栈顶就是第一个更矮的
左边界
vector<int> L(n + 2), R(n + 2), stk;
stk.reserve(n + 2);

// 左边界：i 左边第一个比 h[i] 矮的位置
for (int i = 1; i <= n; ++i) {
    while (!stk.empty() && h[stk.back()] >= h[i]) stk.pop_back();
    L[i] = stk.empty() ? 0 : stk.back();
    stk.push_back(i);
}
为什么

h[stk.back()] >= h[i]：弹掉所有“不比 h[i] 高”的柱子，并保留等号。等高的柱子可以被同一个矩形一起覆盖，让最靠左的那根算全宽度就够了，最大值不会漏。

L[i] = stk.empty() ? 0 : stk.back();：弹干净后栈顶就是左边第一个更矮的位置；栈空说明左边全是高个子，左边界顶到 0。

这就是上一题“右边第一个更大”的镜像：不等号方向反过来、栈内值从“不增”变成“不减”，其余一字不差。

3③ 右边界：方向反过来，中间必须清空栈
右边界
stk.clear();
// 右边界：i 右边第一个比 h[i] 矮的位置
for (int i = n; i >= 1; --i) {
    while (!stk.empty() && h[stk.back()] >= h[i]) stk.pop_back();
    R[i] = stk.empty() ? n + 1 : stk.back();
    stk.push_back(i);
}
为什么

右边界完全对称，只是方向反过来：从右往左扫，栈里留下的是“右边还没遇到更矮者”的柱子，弹干净后的栈顶就是右边第一个更矮的位置；栈空说明右边没有更矮的，右边界顶到 n+1。

两遍共用一个栈，中间必须 stk.clear()，否则上一遍的残留会污染结果——这是本题最容易漏的一行。

4④ 面积：h[i] × (R[i] − L[i] − 1)，注意 long long 与减 1
统计答案
ll best = 0;
for (int i = 1; i <= n; ++i)
    best = max(best, (ll)h[i] * (R[i] - L[i] - 1));
cout << best << "\n";

为什么

R[i] - L[i] - 1：减 1 是因为 L、R 都是“更矮”的位置，本身不参与矩形。写成 R−L 会把矩形撑到矮柱子上，答案偏大。

高度到 109、宽度到 105，乘积到 1014，必须转 long long——这是本题最隐蔽的 WA：不转的话大测试点变成负数。

5⑤ 完整程序：两遍单调栈
完整程序
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

int main() {
    int n;
    cin >> n;
    vector<int> h(n + 2, 0);                 // h[0] 与 h[n+1] 是高度 0 的哨兵
    for (int i = 1; i <= n; ++i) cin >> h[i];

    vector<int> L(n + 2), R(n + 2), stk;
    stk.reserve(n + 2);

    // 左边界：i 左边第一个比 h[i] 矮的位置
    for (int i = 1; i <= n; ++i) {
        while (!stk.empty() && h[stk.back()] >= h[i]) stk.pop_back();
        L[i] = stk.empty() ? 0 : stk.back();
        stk.push_back(i);
    }
    stk.clear();
    // 右边界：i 右边第一个比 h[i] 矮的位置
    for (int i = n; i >= 1; --i) {
        while (!stk.empty() && h[stk.back()] >= h[i]) stk.pop_back();
        R[i] = stk.empty() ? n + 1 : stk.back();
        stk.push_back(i);
    }

    ll best = 0;
    for (int i = 1; i <= n; ++i)
        best = max(best, (ll)h[i] * (R[i] - L[i] - 1));
    cout << best << "\n";
    return 0;
}
为什么

样例输出 10。复杂度 O(n)：每个下标进栈、出栈各一次，两遍合计 ≤ 4n 次操作。

一遍扫完的写法（省掉一个数组）：把 h[0] = h[n+1] = 0 当哨兵，令 i 从 0 扫到 n+1：只要 h[栈顶] > h[i] 就弹出栈顶 p，此时栈顶（弹完后的新栈顶）就是 p 的左边界，i 是右边界，直接算面积 h[p] × (i − 栈顶 − 1)。每个柱子只在被弹出时结算一次，只用一个栈、一个变量就能出答案，常数比两遍扫描小一半。

二维版本是“每行当一次柱状图”：先对每一行求出“以这一行为底、向上连续 1 的个数”，再对每行跑一次上面的算法，总复杂度 O(nm)。洛谷上的玉蟾宫（P4147）就是这个模型。

竞赛用法

看到什么想到它：题目给一排柱子 / 直方图，问最大矩形；“以某个值为高度的最大矩形”；“左右第一个更矮 / 更高”——只要答案取决于最近的那个更矮者，就是单调栈。

复杂度：均摊 O(n)，空间 O(n)；两遍扫描或一遍结算都行。

常见的坑：① 面积不转 long long，1014 溢出成负数；② 忘了减 1，答案偏大；③ 两遍之间忘了 stk.clear()；④ 弹栈条件用 > 而不用 >=，等高的柱子让宽度被切开。

模型：柱状图最大矩形均摊 O(n)坑：面积要转 long long
算法落地用法 · 滑动窗口最值：单调队列三步，代价与窗口长度无关覆盖：单调队列 / 滑动窗口最值 / 弹队尾 / 弹队头 / 求最大值
需求

单调队列 = 单调栈 + 队头能出。窗口 [i−k+1, i] 右移一格，左边出去一个、右边进来一个。队尾负责“进”时弹掉更差的，队头负责“出”时弹掉过期的。

需求：对每个长度 k 的窗口求最小值。以 n = 8、k = 3、a = 1 3 −1 −3 5 3 6 7 为例，能手算：−1、−3、−3、−3、3、3。

样例
输入：8 3
1 3 -1 -3 5 3 6 7
输出：-1 -3 -3 -3 3 3
1① 三步骨架：弹队尾 → 入队 → 弹队头 → 读队头
三步骨架
deque<int> q;                    // 存下标；对应值从队头到队尾单调递增
for (int i = 0; i < n; ++i) {
    while (!q.empty() && a[q.back()] >= a[i]) q.pop_back();  // ① 队尾更差的永久退休
    q.push_back(i);
    while (q.front() <= i - k) q.pop_front();                // ② 滑出窗口的从队头退休
    if (i >= k - 1) cout << a[q.front()] << " ";             // ③ 窗口满 k 个才有答案
}
为什么

三步各管一件事：① 队尾更差的永久退休；② 新下标入队；③ 队头过期的弹掉。顺序不能换——先弹队尾再入队，队列才始终只含“还有用”的下标。

为什么队列里存下标而不是值：窗口滑动时判过期靠的是“这个下标还在不在 [i−k+1, i] 里”，存值根本没有这个信息。

2② 弹队尾：不比新元素小的都退休
弹队尾
while (!q.empty() && a[q.back()] >= a[i]) q.pop_back();  // 队尾更差的永久退休
为什么

a[q.back()] >= a[i]：队尾的值不小于新元素，说明队尾既不更小、又比新元素先过期，永远轮不到它当最小值，直接弹。

弹干净后当前元素一定入队：它可能是后面若干个窗口的答案。

等号也弹：留下最新的那个，窗口右移时它活得更久。这也是“每个下标只进一次、出一次”的来源——队列里最多 k 个元素，但总操作 ≤ 2n。

3③ 弹队头：过期条件差一个等号都不行
弹队头
while (q.front() <= i - k) q.pop_front();                // 滑出窗口的从队头退休
为什么

窗口左端是 i−k+1，下标 ≤ i−k 的都已出窗。写成 q.front() < i - k 就少弹一轮，过期元素会霸占队头，答案偏小。

过期的只可能在队头，因为队列里的下标递增——所以一个 while 就够，不必遍历整个队列。

4④ 输出条件与求最大值：只差一个符号
输出条件
if (i >= k - 1) cout << a[q.front()] << " ";             // 窗口满 k 个才有答案
为什么

if (i >= k - 1)：前 k−1 个位置窗口还没满，不能输出。0 基下标下这是唯一的正确边界，写成 i > k−1 会少一个数。

队头是整个窗口的最小值，因为队内值单调递增且队头没有过期。

求最大值：把 ① 的 >= 改成 <=，其余一个字都不动。两类最值只差一个符号。

5⑤ 完整程序：输出每个长度 k 窗口的最小值
完整程序
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    deque<int> q;
    for (int i = 0; i < n; ++i) {
        while (!q.empty() && a[q.back()] >= a[i]) q.pop_back();
        q.push_back(i);
        while (q.front() <= i - k) q.pop_front();
        if (i >= k - 1) cout << a[q.front()] << " ";
    }
    cout << "\n";
    return 0;
}
为什么

复杂度：每个下标入队 1 次、出队至多 1 次，总操作 ≤ 2n，与窗口长度 k 无关。用 multiset 也能维护窗口最值，但每次 O(log k)，n = 106 时慢 20 倍。

样例逐窗口：k = 3 时依次输出 −1、−3、−3、−3、3、3，与手算一致。

竞赛用法

看到什么想到它：滑动窗口求最值、定长区间的 max/min 随区间右移而更新；DP 转移里出现 max{f_j : i−R ≤ j ≤ i−L} 这类定长窗口最值。

复杂度：均摊 O(n)，与 k 无关；空间 O(k)。

常见的坑：① 忘了弹队头，或过期条件写成 <，答案偏小；② 输出条件写成 i > k−1，少一个数；③ 队列存值不存下标，判不出过期；④ 空队列时 q.front()，未定义行为。

模型：单调队列均摊 O(n)坑：过期条件不能少一个等号
算法落地用法 · 单调队列优化 DP：把 O(nR) 的 max 压成 O(1)覆盖：单调队列优化 DP / 入队时机 i−L / 出队 i−R / NEG
需求

单调队列真正的价值在优化 DP。看一个典型转移：fi = ai + max{ fj : i−R ≤ j ≤ i−L }。题意：一条走廊有 n 个格子，从 0 出发，每次必须向前跳 L 到 R 格，落到格子 i 得 ai 分（可以是负数），求跳到 n 的最大得分。

需求：n = 5、L = 2、R = 3，a = 1 2 3 4 5。能手算：f0 = 0，f2 = 2，f3 = 3，f4 = f2 + 4 = 6，f5 = max(f2, f3) + 5 = 8。

样例
输入：5 2 3
1 2 3 4 5
输出：8
1① 看清窗口：候选集 [i−R, i−L] 随 i 右移，长度固定
初值
f[0] = 0;                            // 起点，得分为 0
deque<int> q;                        // 存下标 j，f 值从队头到队尾单调递减
// 不要把 0 提前塞进队列：j = 0 只有在 i == L 那一轮才合法（一步正好跳 L 格）
为什么

暴力枚举 j 是 O(nR)。但 fj 的取值区间 [i−R, i−L] 随 i 单调右移、长度固定，正是“滑动窗口最值”。把它换成单调队列，转移降到 O(1)，总复杂度 O(n)。

起点 0 不能提前塞进队列：候选 j 要满足 j ≤ i−L 才允许跳到 i。提前塞进去，i < L 时就会用一步跳 L 格的非法转移。

2② 入队：每轮新获得资格的候选恰好一个 i−L
入队
for (int i = 1; i <= n; ++i) {
    // ① j = i - L 从这一步起才允许用来跳到 i，进队
    if (i - L >= 0 && f[i - L] != NEG) {
        while (!q.empty() && f[q.back()] <= f[i - L]) q.pop_back();
        q.push_back(i - L);
    }
为什么

入队时机是本题的关键：j 只有在 j ≤ i−L 时才允许跳到 i，所以每轮新加入的候选恰好是 i−L 一个；起点 0 会在 i = L 那一轮自动进队。

f[i - L] != NEG：不可达状态不能入队，否则 NEG 加几次之后会变成一个大负数，最后判 f[n] == NEG 失效，输出一个天文数字。

f[q.back()] <= f[i - L] 就弹：队尾的 f 值不更大，它既不更优、又比新来的先过期，永远用不上。

3③ 出队：跳得太远、够不到 i 的从队头走
出队
    // ② j < i - R 跳得太远，够不到 i，出队
    while (!q.empty() && q.front() < i - R) q.pop_front();
为什么

过期条件用 q.front() < i - R：j = i−R 这一步跳 R 格，正好合法，不能弹。写成 <= 会把最远的那一步禁掉，答案偏小。

队头弹出的都是下标最小的——队列里下标递增，所以过期的只可能在队头，一个 while 就够。

4④ 转移与收尾：队头就是窗口里 f 最大的那个
转移
    // ③ 队头就是 [i-R, i-L] 里 f 最大的那个
    if (!q.empty()) f[i] = f[q.front()] + a[i];
}
cout << (f[n] == NEG ? -1 : f[n]) << "\n";
return 0;
}
为什么

原来要对 j 扫一遍 max，现在队头 O(1) 给出最大值。转移从 O(R) 降到 O(1)，总复杂度 O(n)。

const ll NEG = LLONG_MIN / 4：用“足够小的数”当不可达标记。直接用 LLONG_MIN，加上 a[i] 会下溢成正数；除以 4 之后累加几次负数也不会溢出。

样例：f = 0, NEG, 2, 3, 6, 8，输出 8。

5⑤ 完整程序：单调队列优化 DP
完整程序
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const ll NEG = LLONG_MIN / 4;            // "不可达"标记，加 a[i] 也不会溢出

int main() {
    int n, L, R;
    cin >> n >> L >> R;
    vector<ll> a(n + 1), f(n + 1, NEG);
    for (int i = 1; i <= n; ++i) cin >> a[i];

    f[0] = 0;                            // 起点，得分为 0
    deque<int> q;                        // 存下标 j，f 值从队头到队尾单调递减
    // 不要把 0 提前塞进队列：j = 0 只有在 i == L 那一轮才合法（一步正好跳 L 格）

    for (int i = 1; i <= n; ++i) {
        // ① j = i - L 从这一步起才允许用来跳到 i，进队
        if (i - L >= 0 && f[i - L] != NEG) {
            while (!q.empty() && f[q.back()] <= f[i - L]) q.pop_back();
            q.push_back(i - L);
        }
        // ② j < i - R 跳得太远，够不到 i，出队
        while (!q.empty() && q.front() < i - R) q.pop_front();
        // ③ 队头就是 [i-R, i-L] 里 f 最大的那个
        if (!q.empty()) f[i] = f[q.front()] + a[i];
    }
    cout << (f[n] == NEG ? -1 : f[n]) << "\n";
    return 0;
}
为什么

样例输出 8，与手算一致。f[n] 仍是 NEG 说明一步也跳不到 n，按题意输出 −1。

复杂度 O(n)：每个下标至多进队一次、出队一次；空间 O(n) 存 a 与 f。

竞赛用法

看到什么想到它：DP 转移里出现 max/min{ f_j : i−R ≤ j ≤ i−L }——候选区间随 i 单调右移、长度固定。

复杂度：O(n)，把每个状态 O(R) 的枚举压成 O(1)。

常见的坑：① 把 0 提前塞进队列，用非法的跳跃；② 入队时机写成 i−L−1 或 i−L+1，步长范围整体偏移；③ 出队用 <=，把正好跳 R 格的那一步禁掉；④ 不可达状态入队，NEG 被累加成大负数；⑤ NEG 直接用 LLONG_MIN，加 a[i] 下溢成正数。

模型：单调队列优化 DPO(n)坑：入队时机与 NEG
这一节的 8 种典型错法（含症状）

WA，答案整体错位一格。—— 单调栈里存了值而不是下标。一旦出现重复值，或者题目要求输出位置，就彻底失效。

WA，只在有重复值的数据上错。—— 求“第一个严格大于”却写成 while (a[stk[top]] <= a[i])。相等的候选被提前弹掉，答案会记成一个“不大于它”的位置。样例通常没有重复值，看不出来。

WA，窗口答案偶尔偏小。—— 滑动窗口忘了弹队头，或者过期条件写成 q.front() < i - k。过期的元素还霸着队头，后面几个窗口全部被一个“幽灵”污染。用 n=2, k=1, a=3 5 一试就知道。

WA，第一行少输出一个数。—— 输出条件写成 i > k - 1，应该是 i >= k - 1。

TLE，明明复杂度是 O(n)。—— 3×106 的输入用 cin 却没关同步；或者把“弹队尾”写成了每次扫一遍窗口找最小值（那就退回 O(nk)）。

RE（数组越界）。—— MAXN 开成 106 而 n 到 3×106；或者空队列时调用 q.front()（deque 空时取值是未定义行为，多数时候读到垃圾值）。

WA，第二组数据开始全错。—— 多测没有清空栈 / 队列 / top 指针。上组数据的残留让第一组之后的答案全歪。

WA，大测试点变成负数。—— 柱状图面积写成 h[i] * (R[i] - L[i] - 1) 而没转 long long，109 乘 105 直接溢出成负数。

数学补给 · 均摊、笛卡尔树与贡献法

均摊 O(n) 怎么证。用会计法：给元素 i 进栈时预存 2 次操作额度，一次用于将来出栈、一次用于本次比较。while 循环每弹一个元素就消耗掉它进栈时存下的额度，所以 n 次扫描中 while 体执行总次数 ≤ n。单次 while 最坏 O(n)，但 n 次合计 O(n)——这就是“均摊”与“最坏”的区别。

滑动窗口同理。n 个下标各入队 1 次、出队至多 1 次，总代价 ≤ 2n，与 k 无关。对比 multiset 的 O(n log k)：k = 106 时 log k ≈ 20，等于凭空多 20 倍常数。

笛卡尔树。把 Li、Ri（左右第一个更矮）当作父子关系，单调栈恰好建出一棵二叉树：节点 i 的子树区间正好是 (Li, Ri)，子树大小 = Ri − Li − 1。于是“以 hi 为高的最大矩形” = hi × 子树大小——柱状图问题就是笛卡尔树上的“高度 × 子树大小”。等高柱子怎么挂都不影响面积。

贡献法（本节 tag 里的第三件事）。要求“所有子数组的最小值之和”，必须让每个子数组只归属一个最小值，否则等高元素会被重复计数。规则：Li 取左边第一个严格小于 hi 的位置，Ri 取右边第一个小于或等于 hi 的位置——于是每个子数组归给它最靠右的最小值。

按这个规则，以 hi 为最小值的子数组个数 = (i − Li) × (Ri − i)：左端点可选 Li+1 … i 共 i − Li 种，右端点可选 i … Ri−1 共 Ri − i 种。答案 = Σ hi × (i − Li) × (Ri − i)。注意这里是“左小于、右小于等于”的不对称写法；柱状图求面积时两边都用 ≥ 也对，因为面积与“归给谁”无关。

量级感受。n = 3×106 时，O(n²) 是 9×1012 次比较，1 GHz 也要两小时；O(n) 是 3×106 次。同一道题，两个复杂度之间差的是“能不能交”。

式子含义典型用途
Ri − Li − 1以 hi 为高的矩形宽度柱状图最大矩形
(i − Li) × (Ri − i)以 hi 为最小值的子数组个数所有子数组最小值之和
Σ (i − Li)(Ri − i)应等于子数组总数 n(n+1)/2贡献法写完后的自检

挑战题 · 发射站
洛谷 P1901普及/提高-去洛谷做这题 ↗

某地有 N 个能量发射站排成一行，第 i 个发射站的高度是 hi、能量值是 vi，所有 hi 互不相同。每个发射站同时向左右两边发射能量，能量只被两边最近的、且比它高的发射站接收；如果那边不存在更高的发射站，这份能量就损失掉。

一个发射站收到的能量，是所有能到达它的发射站发出的能量之和。求收到的能量最多的那个发射站收到了多少。

输入：第一行一个整数 N（1 ≤ N ≤ 106）；接下来 N 行，每行两个整数 hi、vi（1 ≤ hi, vi ≤ 109），数据保证所有 hi 互不相同。

输出：一行一个整数，表示最大的接收能量。

引导性提示（先只看这里）

每个发射站只关心两件事：左边第一个比它高的、右边第一个比它高的。不用管能量会不会传到第三个人。

“左边第一个比它高的”，和本节例题“右边第一个比它大的”，是同一个模板把方向反过来。

从左往右跑一遍、从右往左跑一遍，两次都往一个累加数组里加。接收的能量总和可能到 1015。

想看思路了？点开完整思路

把任务拆成两半：对每个 i，找到 左边第一个 h 比自己大的位置 p，让 rec[p] += vi；再找右边第一个比自己大的位置 q，让 rec[q] += vi。两遍互不干扰。

求“左边第一个更大”用单调栈：从左往右扫，维护一个高度递减的下标栈。遇到 i 时，把栈里所有高度小于 hi 的弹掉——它们挡不住 i，而且已经被 i 截住了，以后不可能再成为任何人的“最近的更高者”。

弹干净之后，栈顶就是左边第一个比 hi 高的位置，把 vi 记在它头上。

为什么栈顶一定对：设 j 是 i 左边第一个比 i 高的位置。若 j 被弹出，只能是被某个 k（j < k < i）以 hk > hj > hi 弹掉的，那 k 比 j 更靠右且也比 i 高，与 j 的“第一个”矛盾。所以 j 一定还在栈里，且栈里没有比它更靠右的合法候选，它就是栈顶。

右边同理，从右往左再跑一遍同一个模板，栈清空后重新用。

复杂度 O(N)：每个下标进栈一次、出栈至多一次，两遍合计 4N 次操作，N = 106 轻松通过。

using namespace std;
typedef long long ll;
const int MAXN = 1000005;

int n, h[MAXN], v[MAXN];
int stk[MAXN], top = 0;             // 单调栈：存下标，高度从栈底到栈顶递减
ll rec[MAXN];                       // rec[i] = 第 i 个发射站收到的总能量

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; ++i) scanf("%d%d", &h[i], &v[i]);

    // 第一遍：每个站把能量交给左边最近的更高者

        while (top > 0 && h[stk[top]] < h[i]) --top;   // 更矮的挡不住我，弹掉
        if (top > 0) rec[stk[top]] += v[i];            // 栈顶就是左边第一个更高的
        stk[++top] = i;                                // 自己进栈
    }

    // 第二遍：反方向再来一次，处理右边
    top = 0;
    for (int i = n; i >= 1; --i) {
        while (top > 0 && h[stk[top]] < h[i]) --top;
        if (top > 0) rec[stk[top]] += v[i];
        stk[++top] = i;
    }

    ll best = 0;
    for (int i = 1; i <= n; ++i) best = max(best, rec[i]);   // 注意用 ll 接
    printf("%lld\n", best);

挑战 2 · 理想的正方形

给定一个 a × b 的非负整数矩阵，请找出一个 n × n 的正方形区域，使这个区域内最大值与最小值的差尽可能小。输出这个最小差值。

输入格式：第一行三个整数 a、b、n（2 ≤ a, b ≤ 1000，n ≤ a，n ≤ b，n ≤ 100）；接下来 a 行，每行 b 个非负整数，相邻两数之间一个空格。矩阵中所有数都不超过 10⁹。

输出格式：一行一个整数，表示所有 n × n 正方形区域中「最大值 − 最小值」的最小值。

5 4 2
1 2 5 6

16 17 2 1
2 10 2 1
1 2 2 2

样例
输入： 5 4 2 1 2 5 6 0 17 16 0 16 17 2 1 2 10 2 1 1 2 2 2 输出： 1
引导性提示（先只看这里）

先降到一维想：一条长度为 b 的数列，滑一个长度 n 的窗口，求每个窗口的最大值和最小值——这是本节刚学的单调队列，O(b)。

二维怎么办？先只在每一行内滑一次，得到 rowmax[i][j] = 第 i 行第 j−n+1..j 列的最大值。接着把 rowmax 竖着看：每一列再滑一个长度 n 的窗口，拼起来正好是 n × n 方块的最大值。

最大值和最小值要用两套单调队列，弹出方向相反，绝不能共用一个。

想看思路了？点开完整思路

① 暴力为什么不行。共 (a−n+1)(b−n+1) 个方块，每个求最值 O(n²)，最坏 10⁶ × 10⁴ = 10¹⁰。

② 二维最值可以拆成两次一维。关键性质：n × n 方块的最大值 = 「每一行的窗口最大值」再对这 n 个值取最大；最小值同理。因为 max 和 min 都满足结合律，可以分方向做。

③ 第一次（横向）。对每一行做长度 n 的单调队列，得到 rowmax[i][j]、rowmin[i][j]：表示第 i 行以 j 结尾的长度 n 区间的最值。总代价 O(ab)。

④ 第二次（纵向）。固定列 j，把 rowmax[1..a][j] 当成一个序列，再做一次长度 n 的单调队列，就得到以 (i, j) 为右下角的 n × n 方块的最大值；rowmin 同样处理后得到最小值。总代价还是 O(ab)。

⑤ 统计答案。i ≥ n 且 j ≥ n 时（方块才凑得满）用 max − min 更新答案。

⑥ 复杂度。两次 O(ab) 的滑动窗口，a、b ≤ 1000 时约 2×10⁶ 次队列操作，比暴力快 4 个数量级。三个 1005 × 1005 的 int 数组约 12 MB，放全局。

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1005;
int A, B, n;
static int v[MAXN][MAXN];
static int rmin[MAXN][MAXN], rmax[MAXN][MAXN];

int main() {
    scanf("%d%d%d", &A, &B, &n);
    for (int i = 1; i <= A; ++i)
        for (int j = 1; j <= B; ++j) scanf("%d", &v[i][j]);

    // 第一遍：每行内部滑动窗口，rmin/rmax[i][j] 表示第 i 行 [j-n+1, j] 的最值
    for (int i = 1; i <= A; ++i) {
        deque<int> qmin, qmax;
        for (int j = 1; j <= B; ++j) {
            while (!qmin.empty() && v[i][qmin.back()] >= v[i][j]) qmin.pop_back();
            qmin.push_back(j);
            if (qmin.front() <= j - n) qmin.pop_front();
            while (!qmax.empty() && v[i][qmax.back()] <= v[i][j]) qmax.pop_back();
            qmax.push_back(j);
            if (qmax.front() <= j - n) qmax.pop_front();
            rmin[i][j] = v[i][qmin.front()];
            rmax[i][j] = v[i][qmax.front()];
        }
    }

    // 第二遍：每一列上对 rmin/rmax 再做一次长度为 n 的滑动窗口
    int ans = INT_MAX;
    for (int j = n; j <= B; ++j) {
        deque<int> qmin, qmax;
        for (int i = 1; i <= A; ++i) {
            while (!qmin.empty() && rmin[qmin.back()][j] >= rmin[i][j]) qmin.pop_back();
            qmin.push_back(i);
            if (qmin.front() <= i - n) qmin.pop_front();
            while (!qmax.empty() && rmax[qmax.back()][j] <= rmax[i][j]) qmax.pop_back();
            qmax.push_back(i);
            if (qmax.front() <= i - n) qmax.pop_front();
            if (i >= n) ans = min(ans, rmax[qmax.front()][j] - rmin[qmin.front()][j]);
        }
    }

    printf("%d\n", ans);
    return 0;
}

片段作用
while (!qmin.empty() && v[i][qmin.back()] >= v[i][j]) qmin.pop_back();队尾比新元素大（或相等）的全部弹掉：它们既不会更小、又比新元素先过期，永远轮不到当答案。
if (qmin.front() <= j - n) qmin.pop_front();窗口是 [j−n+1, j]。队头 ≤ j−n 就滑出去了。每步最多过期一个，所以用 if 就够。
rmin[i][j] = v[i][qmin.front()];队头是这一段的最小值。第一遍把「行内 n 个数」压成一个值。
for (int j = n; j <= B; ++j) { ... for (int i = 1; i <= A; ++i)第二遍拿 rmin/rmax 当输入，同样的骨架再跑一次，只是把「沿行滑」换成「沿列滑」。
if (i >= n) ans = min(ans, ...);竖直方向凑满 n 行才是一个完整的 n × n 方块，前面几行还不能统计。
deque<int> qmin, qmax;最大值和最小值的弹出方向相反，两个队列必须分开。共用一个立即失去单调性。
这题最容易错的地方
  • 只做一次滑动窗口：行内窗口的最值不是方块的最值，必须横竖各做一次。
  • 最大和最小共用一个队列：弹出条件一正一反，队列立刻不再单调，答案随机错。
  • 窗口左端点写成 j−n 而不是 j−n+1：每个窗口多留一个过期元素，min 偏小、max 偏大。
  • 数组开成 1000：下标能取到 1000，越界 → RE 或异常答案，习惯开 1005。
