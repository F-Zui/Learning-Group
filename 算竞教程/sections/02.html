02 · 循环、累加与整数溢出

把“算一次”升级成“算一百万次”：用 for/while 把重复劳动交给机器，用累加器收集结果，并在动手之前算清这个和会不会超过 2.1×10⁹。
⭐ 已学范围入门预计 50 分钟for/whilelong long溢出

第 1 节的程序只做一次加法，这一节让它做一百万次。循环要想清楚三件事：从哪开始、什么时候停、每轮做什么；累加只想一件事：这个和最大能到多少。前者决定快不快（TLE），后者决定对不对（WA）。

先算最坏情况的上界，再写代码。

两个数先摆着：1+2+…+65536 = 2147516416，比 int 上限 2147483647 大 32769，存进 int 就是负数 -2147450880；而本节的例题要循环 183 万次。循环次数和数值范围是两件事。

推导for：把“重复”压进一行语法覆盖：for / 初始化 / 条件 / 步进 / 循环变量作用域需求 → 尝试 → 验证 → 定理
问题

要算 1 + 2 + … + 100，手写一百行也能对，可题目里的 n 是读进来的——写多少行事先不知道。机器最擅长的正是“同一件事做很多遍”，缺的只是一种把“重复”说清楚的写法。

1先把重复的事拆成三件

任何一次重复都藏着三个问题：从哪开始、什么时候停、每轮做什么；再加上“这一轮和上一轮怎么衔接”，一共四件事。

用 while 可以先把这四件事摆开写：

验证 / 关键

四件事各占一行，缺一件就写不成循环：没有起点变量动不了，没有终止条件永远转，没有步进条件永远不会变假。

2用 while 把四件事摆开

先不加任何语法糖，用最直白的 while 摆一遍：

四件事的直白写法
int i = 1;                 // 起点
while (i <= 100) {         // 什么时候停
    sum += i;              // 每轮做什么
    ++i;                   // 怎么衔接下一轮
}
验证 / 关键

这段能跑，但“初始化、判断、步进”散在三处，改一处要盯三行。更麻烦的是：++i 少写一次就是死循环，而它离判断语句隔了三行。

3把三段搬进固定槽位

C++ 干脆给这三段留了三个固定位置，用两个分号隔开——写错位置编译器直接报错，而不是像 while 那样悄悄死循环。

签名
for (初始化; 条件; 步进) { 循环体 }
组成含义 / 格式要求
for两个分号隔出三段，分号不能省。
初始化进循环前执行一次，i 只在循环内有效。
条件每轮开始前检查。i <= n 配 i 从 1 起是 n 轮。
步进每轮末尾执行，这里 ++i 与 i++ 等价。
循环体只有一句也写花括号，以后加行不会错。
示例
long long sum = 0;
for (int i = 1; i <= 100; ++i) sum += i;        // 5050
for (int i = 0; i < 5; ++i) cout << i << " ";   // 0 1 2 3 4
验证 / 关键

执行顺序是：初始化一次 → 判断 → 循环体 → 步进 → 回到判断。所以 i = 1; i <= 100 恰好 100 轮，退出时 i 停在 101。

4验证：边界与死循环

把上界换成 n 就是 n 轮；把 <= 换成 < 就是 n−1 轮——差一错误全在这一个符号上。

另一种危险写法：条件写 i != n、步进写 i += 2。一旦 i 跨过 n，条件永远为真，循环再也退不出去。

验证 / 关键

“条件必须是能变假的比较”：<、<=、> 都安全，!= 只有在步长能整除区间时才安全。

于是我们得到：

for 就是“把 while 的三段搬进一行固定位置”，语法替我们记住了顺序，也替我们挡住了“忘了步进”这类死循环。

注意

条件别写 i != n 配 i += 2：步进跨过 n 就永远退不出。

推导while：当“走几轮”事先算不出来覆盖：while / break / continue / 死循环需求 → 尝试 → 验证 → 定理
问题

有的循环次数根本写不出来：读到负数为止、读到文件尾为止、部分和超过给定值为止。这时 for 的三个槽位全用不上——你不知道该填什么上界。

1只写“什么时候继续”

既然终点未知，就别管终点，只写一件事：现在这一轮还需不需要转。while (条件) 每轮开始前检查一次，为真就再来一圈。

次数已知（数 1..n）用 for，次数未知用 while——判断标准是“上界能不能在进循环前写出来”。

验证 / 关键

while 不替你决定起点，也不替你衔接下一轮：起点得在循环外初始化，让条件最终变假的那一步得写在循环体里。

2把“怎么退出”写清楚

三种退出方式覆盖了入门阶段的全部场景：条件自己变假、break 提前跳出、continue 跳过本轮剩下的语句。

签名
while (条件) { 循环体 }
组成含义 / 格式要求
while每轮开始前检查条件，为真再转一圈。
何时用次数未知用它，次数已知（数 1..n）用 for。
改变量循环体里必须让条件最终变假，否则死循环 → TLE。
break跳出整个循环，适合“找到就停”。
continue跳过本轮剩余语句，for 会先做步进。
验证 / 关键

continue 在 while 里最容易出事：如果“让条件变假”的那一步写在 continue 后面，它永远不会执行，循环原地打转。

3验证：两个必须亲手跑的例子

第一个：调和级数部分和超过 15 时停，退出时 n = 1835421——次数确实事先算不出来。第二个：边读边处理，读到负数就 break，读到文件尾 cin 为假自然退出。

示例
double s = 0; int n = 0;
while (s <= 15) { ++n; s += 1.0 / n; }     // 退出时 n = 1835421
int x; while (cin >> x) { if (x < 0) break; cout << x << " "; }
验证 / 关键

++n 和 s += 1.0 / n 换个顺序，答案就差 1——这是 while 里最典型的“先定项号、再加项”。

于是我们得到：

while 只要求你写清“什么时候继续”，代价是退出条件要自己维护。

注意

++n 和 s += 1.0 / n 换个顺序，答案就差 1。

追问 · 把这一步想透
  1. 把 while 改写成 for (n = 1; s <= k; ++n) s += 1.0 / n;，输出写 n 还是 n−1？差一从哪来？
    想好了？点开核对思路与解析
    输出 n − 1。for 的步进在循环体之后执行：最后一轮先把第 n 项加进 s，紧接着 ++n 把 n 变成“还没加的下一项”，条件这时才失败，所以退出时 n 比“最后加进去的项号”大 1。
    用 k = 1 验算：n = 1 进循环、s = 1、n 变 2；1 ≤ 1 仍成立，加 1/2、n 变 3；1.5 ≤ 1 失败，输出 n − 1 = 2，与答案一致。

推导累加器：把每轮的结果收集起来覆盖：sum += x / 初值 / 溢出上界 / 计数器与求积需求 → 尝试 → 验证 → 定理
问题

循环能算出“这一轮的值”，可答案是所有轮次的总和。这个“把结果攒起来”的变量，要回答三个问题：初值给多少、类型开多大、放在哪一层。

1先定初值：让第一次运算不改变结果

求和的初值必须让 sum + 第一项 = 第一项，那只有 0；求积的初值同理，只有 1。这就是“单位元”。

忘了初始化更麻烦：局部变量的初值是随机的，小数据可能碰巧对，大数据必错，而且每次跑结果都不一样。

签名
long long sum = 0;
for (...) sum += x;
组成含义 / 格式要求
初值 0加法的单位元。局部变量不初始化是随机值。
类型要装得下最终结果：上界 = 项数 × 单项最大值。
计数器只加 1 的累加器，初值也是 0。
求积初值是 1，写成 0 结果永远为 0。
验证 / 关键

初值选错不会报错：求和写 1，答案整体大 1；求积写 0，整个乘积永远是 0。

2再定类型：上界 = 项数 × 单项最大值

累加器的类型不看“当前值”，看最坏情况下能涨到多少。105 个不超过 109 的数相加是 1014，int 装不下，必须 long long。

估不出来就先算这个乘法，再决定类型——这是写循环前唯一必须做的算术。

验证 / 关键

1 + 2 + … + 65536 = 2147516416，比 int 上限 2147483647 只大 32769，照样溢出成负数：压线就是翻车。

3验证：三种累加器只差初值和一行循环体
示例
long long sum = 0;
for (int i = 1; i <= n; ++i) sum += i;      // n = 1e9 时约 5×10^17
long long prod = 1;
for (int i = 1; i <= 20; ++i) prod *= i;    // 20! = 2432902008176640000
验证 / 关键

计数器是“只加 1”的累加器，初值同样是 0；求最小值不是累加，它的初值要靠第 4 张卡里的边界常量。

于是我们得到：

累加 = 单位元初值 + 装得下的类型 + 一行 += 。

三个固定初值

求和 0、求积 1、求最小值 INT_MAX，都是让第一次运算不改变结果。

追问 · 把这一步想透
  1. 累加模式能套在很多题型上：统计个数、求平均分、边读边比求最大值。各写一句核心语句，并说明累加器初值分别是多少。
    想好了？点开核对思路与解析
    统计个数：int cnt = 0; ... if (条件) ++cnt;；求平均：long long sum = 0; ... double avg = 1.0 * sum / n;；边读边比求最大值：int mx = INT_MIN; ... if (x > mx) mx = x;。三个初值依次是 0、0、INT_MIN（也可以取第一个数），因为 0 是加法的单位元，而 INT_MIN 保证第一个数一定赢。
    常见错路是最大值初值写 0：数据全是负数时 mx 停在 0，输出一个根本不存在的结果；求积则相反，初值必须写 1，写 0 会让整个乘积恒为 0。
  2. 求积的初值为什么必须是 1？算 1! + 2! + … + n! 并用 int 保存，n 最小取到几就出错？
    想好了？点开核对思路与解析
    初值 1 是乘法的单位元：1 × x = x，第一次运算不改变结果；写 0 则每一项都变 0。1!+2!+…+n! 用 int 存，n = 13 就出错：12! = 479001600 还在 int 内（累加到 n = 12 是 522956313），13! = 6227020800 已超过 2147483647，从这一项起就溢出。
    常见错路是只估“答案有多大”就下结论——n = 12 时答案才 5×10⁸，看着很安全，但溢出发生在中间的 13! 那一项，估答案估不出来。
推导求最值时，初值给什么覆盖：INT_MAX / INT_MIN / LLONG_MAX / 哨兵初值需求 → 尝试 → 验证 → 定理
问题

求最大值时随手写 int mx = 0;，样例全过。可输入换成 -5 -9，程序输出 0——数据里根本没有这个数。问题出在：0 凭什么参与比较？

1初值必须是“真实数据”或“一定输不了的值”

求最大值时，初值要么取第一个读进来的数（它一定是真实数据），要么取一个比所有可能数据都小的哨兵。0 两者都不是。

验证 / 关键

取 a[0] 最稳：它来自输入，不可能是“虚构的答案”；代价是必须先读进至少一个数。

2标准库已经把哨兵准备好了

每个整数类型的上下界都是编译期常量，直接拿来用，不用自己数位数。

签名
int INT_MAX;  long long LLONG_MAX;
组成含义 / 格式要求
INT_MAX2147483647，求最小值的初值。
INT_MIN-2147483648，求最大值的初值。
LLONG_MAX9223372036854775807，19 位。
用法编译期常量，可直接输出。
只当边界别做运算：INT_MAX + 1 溢出成 INT_MIN。
验证 / 关键

两个上限都是 2 的幂减一，末位一定是 7。记“19 位”比记数字实用——long long 最多 19 位十进制。

3验证：哨兵只能出现在比较里

哨兵的职责只是“第一轮必输”，所以它只该出现在比较的右边：

示例
int mn = INT_MAX;
for (int i = 1; i <= n; ++i) { int x; cin >> x; if (x < mn) mn = x; }
cout << INT_MAX << " " << LLONG_MAX << "\n";   // 2147483647 9223372036854775807
验证 / 关键

一旦拿哨兵去做加法或乘法，就会越界：INT_MAX + 1 在 32 位里回绕成 INT_MIN，编译器一声不响。

于是我们得到：

求最值的初值取 a[0] 或 INT_MAX / INT_MIN，绝不取 0。

注意

两个上限都是 2 的幂减一，末位一定是 7。记“19 位”比记数字实用。

推导printf：把“值”和“格式”分开写覆盖：printf / %lld / %d / %.2f / 混用限制需求 → 尝试 → 验证 → 定理
问题

想输出 007（补前导零）、FF（十六进制）、保留两位小数——用 cout 要记一堆操纵器，而且一旦把 long long 交给 %d，它会静默输出垃圾：不报错，只 WA。

1先看清楚“格式”本来是一段文字

printf 的思路是把格式写成字符串：% 开头的是占位符，其余字符原样输出。值按顺序填进占位符，格式和值彻底分开。

这带来两个直接好处：宽度、补零、进制都能写进格式串；也能一次输出多个值。

验证 / 关键

printf("%03d", 7) 里的 03 就是“宽度 3、左边补 0”，换成 cout 要写 setw(3) << setfill('0') 两句。

2记住五个最常用的占位符
签名
printf("%lld\n", 变量);
组成含义 / 格式要求
%lldlong long 的格式符，两个 l 表示 64 位。
%dint 的。给 long long 用只取低 32 位，输出垃圾。
%.2fdouble 保留两位小数。
\nprintf 不会自动换行。
别混用关掉 sync_with_stdio 后不要混用 printf 和 cout。
验证 / 关键

占位符和参数的类型必须一一对上：类型错了 printf 不会救你，它按你写的格式去内存里取字节。

3验证：错格式符的静默截断

算法落地级数求和：一项一项加到超过 k覆盖：洛谷 P1035 / 次数未知的 while + 浮点累加
需求

例题 · 级数求和 · 洛谷 P1035 入门

已知 S_n = 1 + 1/2 + … + 1/n。n 足够大时，S_n 能超过任意给定的整数 k。

给定 k（1 ≤ k ≤ 15），求最小的 n，使 S_n > k。

输入格式：一行一个正整数 k。输出格式：一行一个正整数 n。

样例
输入：
1
输出：
2
1读入 k
读入
int k;
cin >> k;                  // 1 <= k <= 15
为什么

k 最大 15，int 足够。这里不需要任何预处理——真正的信息在循环里才产生。

2准备两个累加变量
两个变量
double s = 0.0;            // 累加器：部分和，必须是浮点
int n = 0;                 // 已经加了多少项
为什么

部分和没有公式，只能一项一项加，所以必须有 s；答案要的是“加到第几项”，所以还要一个 n。s 用 double：1/n 是真分数，用 int 会全部截断成 0。

3循环条件写成“还没超过 k”
循环条件
while (s <= k) {           // 还没超过 k，就再补一项
    // 循环体见下一步：先 ++n 定项号，再 s += 1.0 / n
}
为什么

题目要 S_n > k，所以“没达标”就是 s <= k——注意等号：s == k 时还不算超过，必须再加一项。写成 s < k 会让 k = 1 时答案从 2 变成 1。

4先定项号，再加这一项
循环体
++n;                   // 先定下“这一轮加第 n 项”，顺序不能反
s += 1.0 / n;          // 写 1.0 才是浮点除法
为什么

先 ++n 再累加，让“加进去的项”和“当前的 n”始终对应，退出时 n 就是答案；反过来写，输出要改成 n−1。

必须写 1.0 / n：写 1 / n 时 n ≥ 2 恒为 0，s 停在 1.0，条件永远为真——程序不输出任何东西，它在死循环。

5输出 n，收工
输出
cout << n << "\n";         // 此时 s 第一次超过 k，n 就是最小解
return 0;
完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int k;
    cin >> k;                  // 1 <= k <= 15

    double s = 0.0;            // 累加器：部分和，必须是浮点
    int n = 0;                 // 已经加了多少项

    while (s <= k) {           // 还没超过 k，就再补一项
        ++n;                   // 先定下“这一轮加第 n 项”，顺序不能反
        s += 1.0 / n;          // 写 1.0 才是浮点除法；写 1 / n 会永远停不下来
    }

    cout << n << "\n";         // 此时 s 第一次超过 k，n 就是最小解
    return 0;
}
为什么

退出时 s 刚刚第一次严格大于 k，n 是让条件变假的那一轮——所以它恰好是“最小的 n”。整个过程只走一遍，没有分支、没有数组。

竞赛用法

题型特征：出现“最小的 n 使…超过/达到…”“一直加到…为止”“读到负数为止”，都是次数未知的循环，条件就写在 while 里。

复杂度：循环 n 次，n ≈ ek−γ；k = 15 时 n = 1835421，106 级，O(n) 一秒内跑完。

常见坑：1 / n 写成整数除法（死循环 TLE）；<= 写成 <（答案少 1）；先加项后 ++n（答案多 1）；累加器用 int。

自测三组：k = 1 → 2；k = 2 → 4；k = 15 → 1835421。第三组只差 1，几乎一定是顺序问题。

模型：部分和 + whileO(n)，n ≈ 1.8×10⁶坑：整数除法 / 顺序 / 边界等号
追问 · 落到代码上再想一遍
  1. 把条件从 S_n > k 改成 S_n ≥ k，while 里怎么改？k = 1 时答案从 2 变成几？
    想好了？点开核对思路与解析
    条件改成 while (s < k)：还没到 k 就继续，等于 k 就停。k = 1 时答案从 2 变成 1——S₁ = 1 已经 ≥ 1，一项就够；原题要求严格大于，S₁ = 1 不大于 1，所以还得再加 1/2。
    常见错路是条件不动、只把输出改成 n − 1：那是在修“多加了一项”的差一，而这里差的是“等号算不算达标”，改错了地方。
  2. k 的上限放大到 100，按 S_n ≈ ln n + γ 估一下 n 有多大。这时“一项一项加”还现实吗？
    想好了？点开核对思路与解析
    n ≈ e^(100−0.5772) = e^99.42 ≈ 1.5×10⁴³。按每秒 10⁸ 次估，要 10³⁵ 秒，约 3×10²⁷ 年，完全不现实。
    而且更早就已经不行了：k = 15 时 n 才 1.8×10⁶，k ≈ 22 时 n 已经越过 2.1×10⁹，存 n 的 int 先溢出；再往后每项 1/n 小到加进 s（s ≈ 100，double 有效位只到 10⁻¹⁴）等于没加，累加器不再增长，循环永远退不出。
    常见错路是只答“很大”而不给量级——这道题的正确答案是“必须换成公式”，而反解 S_n = ln n + γ 恰好就是那个公式。

这一节最容易犯的 5 个错（附症状）

累加器不初始化。long long s; 后直接 s += x，局部变量是随机值，小数据过、大数据 WA，且每次跑结果都不同。

用 1 / n 代替 1.0 / n：每项都是 0，累加器不涨，循环退不出 → TLE。

求和用 int：1+2+…+65536 得负数 → WA。项数 × 单项最大值 > 2.1×10⁹ 就换 long long。

long long ans = a * b; 两边都是 int，先溢出再赋值 → WA，要写 1LL * a * b。

边界差一次：i = 1; i < n 只有 n−1 轮 → 本节的题直接 WA。

数学补给 · 2³¹ − 1 与“这个循环要跑多久”

第一个数字是 2147483647。int 占 32 位：1 位符号 + 31 位数值，正数上限就是 2³¹ − 1，10 位数。所以十位以内基本装得下，十一位以上一定装不下。long long 用 63 位，上限 2⁶³ − 1，19 位。

第二个是调和级数 S_n = 1 + 1/2 + … + 1/n ≈ ln n + γ，γ ≈ 0.5772。反解 S_n = k 得 n ≈ e^(k−0.5772)：k = 15 时 n ≈ e^14.4228 ≈ 1.84×10⁶，正是答案 1835421。

挑战题 · 质因数分解
洛谷 P1075普及-去洛谷做这题 ↗

已知正整数 n 是两个不同质数的乘积，求较大的那个质数。

输入格式：一行一个整数 n（2 ≤ n ≤ 2×10⁹）。输出格式：一行一个整数，即较大的质因数。

样例：输入 21，输出 7（21 = 3 × 7）。

引导性提示（先只看这里）

别真去分解质因数：n 最大 2×10⁹，从 2 试到 n 要跑十亿次，必 TLE。

若 i 整除 n，则 i 与 n/i 成对出现，这一对里总有一个不超过 √n。

两个质数中较小的那个 ≤ √n。从 2 往上试，第一个命中的约数就是它。

想看思路了？点开完整思路

设 n = p × q，p < q 且都是质数。由 p < q 得 p × p < n，即 p < √n。

从 i = 2 递增，第一个满足 n % i == 0 的 i 必是 p：若 i 是合数，它必有更小的质因子，早就被找到了。

答案就是 n / p，输出后直接 return。循环写 i * i <= n，只需试到 √n ≈ 4.5×10⁴ 次。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long n;
    cin >> n;

    for (long long i = 2; i * i <= n; ++i) {
        if (n % i == 0) {              // 从小到大，第一个约数就是较小的质因数
            cout << n / i << "\n";     // 另一个因子更大，正是答案
            return 0;                  // 找到即停
        }
    }
    return 0;
}
关键片段拆解
片段作用
long long n;n 最大 2×10⁹，int 装得下，用 long long 是为了后面的除法不贴边。
long long i = 2循环变量也取 64 位，否则 i * i 按 32 位算；数据到 10¹⁸ 就会溢出。
i * i <= n试到 √n 为止。写 i <= sqrt(n) 也行，但开方有浮点误差，乘法更可靠。
n % i == 0第一个命中的 i 就是较小的质数 p，n / i 就是较大的 q。
这题最容易错的地方
  • 循环条件写成 i <= n 或 i < n：对 n ≈ 2×10⁹ 要试十亿次，直接 TLE。
  • 想“先把质因数都存起来再比大小”：多写一遍试除，还可能把两个质数搞混。
  • 特判完全平方数：n 是两个不同质数之积，不可能是平方数，这行只会多一条错路。
