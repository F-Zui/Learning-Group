33 · 区间 DP 与树形 DP

两种“没有下标顺序”的 DP：区间 DP 按长度从短到长，树形 DP 靠 DFS 后序自底向上。把石子合并的三层循环、破环成链，和“选/不选”这一维的树形状态设计一次讲透。
提高-/提高预计 70 分钟区间 DP树形 DP自底向上

第 31 节的线性 DP 从左往右扫，第 32 节的背包按容量递增，顺序都由下标决定。这一节的两个结构没有现成的下标顺序可用：区间要从短往长算，树要等儿子算完再算父亲。规矩其实是同一条——递推顺序必须和状态依赖关系一致：依赖谁，就先算谁。

区间 DP 的循环顺序不是风格问题，是正确性问题。len 一旦挪到内层，程序不报错、不崩，答案直接变成错的。
区间 DP树形 DP
状态f[l][r]：把第 l..r 个元素处理完的最优值f[u][…]：以 u 为根的子树内部的最优值
依赖两个更短的区间 [l,k]、[k+1,r]所有儿子 v 的 f[v][…]
顺序区间长度 len 从 2 到 nDFS 后序：先递归儿子，回到 u 再合并
复杂度状态 O(n²) × 转移 O(n) = O(n³)每点算一次、每条边过一次 = O(n)
典型题石子合并、能量项链、最长回文子序列没有上司的舞会、最大子树和、树形背包

先看清三块骨头：区间 DP 的三层循环、树的存法、树的遍历顺序。前两块是写法，第三块是这一节真正的思想。

推导区间 DP：三层循环的顺序为什么不能换覆盖：三层循环 / len 最外层 / k 的含义 / cost(l,r) / 答案位置需求 → 尝试 → 验证 → 定理
问题

石子合并的转移式其实一眼就能写出来：f[l][r] 由两段更短的区间拼成。可真正落到三重循环时，外层写 l、内层写 r，程序不报错、不崩、样例还常常能过，交上去却 WA——因为有些格子在被用到的时候还没算出来。

1先看转移式依赖谁

f[l][r] = min(f[l][k] + f[k+1][r]) + sum(l..r)，k 取遍 l..r−1。等号右边出现的两个区间 [l,k] 与 [k+1,r]，长度都严格小于 r−l+1。

一个区间的答案只依赖比它短的区间——这句话就是整张表的拓扑序。

验证 / 关键

所以“先算短的、后算长的”不是风格问题，是正确性的前提：只要保证所有更短的区间都在本区间之前算完，转移式读到的就一定是最终值。

2按 l 递增、r 递增会读到没算的格子

最直觉的写法是两重循环：l 从 1 到 n，r 从 l 到 n。

// 错：k 依赖的 [k+1, r] 长度可能比当前区间短，但它可能还没被算过
for (int l = 1; l <= n; ++l)
    for (int r = l; r <= n; ++r)
        for (int k = l; k < r; ++k)
            f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + s[r] - s[l - 1]);
验证 / 关键

比如算 f[1][4] 时要用 f[3][4]：它要等 l 走到 3 才被算，此刻仍是初值 0x3f3f3f3f。于是 f[1][4] 直接等于 INF，且程序一声不吭。

小数据时前面的轮次可能恰好把它填上，所以样例经常照样过——这一类 WA 最难查。

3把长度提到最外层

换一个枚举顺序：先固定长度 len，再扫左端点 l，右端点由 r = l + len − 1 推出。这样进入第 len 层时，所有长度 < len 的区间都算完了。

#include <bits/stdc++.h>
using namespace std;

int n = 5, a[105], s[105];
int f[105][105];                 // f[l][r]：把 a[l..r] 合并成一堆的最小代价

int main() {
    for (int i = 1; i <= n; ++i) { a[i] = i; s[i] = s[i - 1] + a[i]; }
    memset(f, 0x3f, sizeof f);
    for (int i = 1; i <= n; ++i) f[i][i] = 0;        // 长度 1：本来就是一堆，不需要合并

    for (int len = 2; len <= n; ++len)               // ① 先短后长
        for (int l = 1, r = len; r <= n; ++l, ++r)   // ② 再扫左端点
            for (int k = l; k < r; ++k)              // ③ 最后枚举断点
                f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + s[r] - s[l - 1]);

    cout << f[1][n] << "\n";                         // 1..5 合并的最小代价
    return 0;
}

r 由 l + len − 1 推出，就别再单独写一层 r 的循环了。

验证 / 关键

进入某个 len 时，f[l][k] 与 f[k+1][r] 的长度都严格小于 len，所以在第 len 层里它们全部已经算好。这正是 len 必须在最外面的唯一理由。

把外层 len 换成“枚举 l，再枚举 r”，仍然是 r − l 递增；写成 l 从小到大、r 从 l 到 n 就用到未算的 f[k+1][r] → WA。

4参数逐个过一遍：三层循环的每一层管什么
for (int len = 2; len <= n; ++len)
    for (int l = 1, r = len; r <= n; ++l, ++r)
        for (int k = l; k < r; ++k)
            f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + cost(l, r));
组成部分含义 / 格式要求
len区间长度。必须是最外层：长度更小的区间先算完，长区间才拿得到子区间的值。
l, r左右端点，r 由 l + len − 1 推出。用一个变量加长度反推，别再单独写一层 r 的循环。
k分割点，范围 l ≤ k < r。它把 [l,r] 切成 [l,k] 与 [k+1,r] 两段，对应“最后一次操作”。
len 从 2 开始长度 1 的区间不用合并，直接 f[i][i] = 0。从 1 开始只是白跑一层，不算错。
f[l][k] 与 f[k+1][r]两者长度都严格小于 len，走到外层 len 时它们一定已经算好——这就是 len 必须在最外面的唯一理由。
cost(l, r)把两段并成一段的额外代价，最常见是区间和 s[r] − s[l−1]，用前缀和 O(1) 取。
答案在哪线性题答 f[1][n]；环形题先把数组复制成 2n，答所有长度 n 的窗口 f[l][l+n−1] 里的最优值。
验证 / 关键

六个参数里只有 len 的位置是硬性的；l、r、k 交换顺序都不会错，只要保证“短区间先算”。

于是我们得到：

区间 DP 的循环顺序 = 区间长度的递增序 = 状态图的拓扑序。

  • 把外层 len 换成“枚举 l，再枚举 r”，仍然是 r − l 递增；写成 l 从小到大、r 从 l 到 n 就用到未算的 f[k+1][r] → WA，而样例常常刚好能过，最难查。
  • 求 min 的 f 必须初始化成大值（0x3f3f3f3f），求 max 初始化成 0 或 −INF。忘初始化 = 白送 WA。
  • n 到 1000 时 O(n³) = 1.7×10⁸ 且常数不小，先看数据范围，别硬刚。
推导树怎么存：n 个 vector，每个装自己的邻居覆盖：vector<int> g[N] / push_back / size / 范围 for / 有向与无向需求 → 尝试 → 验证 → 定理
问题

树形 DP 的第一道坎不是转移式，是“树在内存里长什么样”。用邻接矩阵 a[u][v] 当然能存，可 n = 6000 时矩阵就是 36 MB，而且每遍历一个点都要扫 n 格——绝大多数格子还是空的。

1先算一笔邻接矩阵的账
// 邻接矩阵：n = 6000 时是 6000 × 6000 个 int = 144 MB（按 bool 存也要 36 MB）
bool a[6005][6005];
for (int v = 1; v <= n; ++v) if (a[u][v]) { ... }   // 每个点都扫 n 格
验证 / 关键

树只有 n−1 条边，矩阵里 99.9% 的位置是空的。存得下也不划算：遍历一次是 O(n)，做一遍树形 DP 就变成 O(n²)。

2每个点开一条不定长表

把“第 u 个点的所有邻居”当成一条表。vector<int> g[N] 就是 N 条表：第 u 条装 u 的邻居，长度随度数变化。

#include <bits/stdc++.h>
using namespace std;

const int N = 6005;
vector<int> g[N];                 // 全局：默认全是空表

int main() {
    // 无向树：1-2, 1-3, 3-4，每条边两个方向都要存
    g[1].push_back(2); g[2].push_back(1);
    g[1].push_back(3); g[3].push_back(1);
    g[3].push_back(4); g[4].push_back(3);

    for (int v : g[1]) cout << v << ' ';    // 2 3
    cout << "\n" << g[1].size() << "\n";    // 2
    return 0;
}
验证 / 关键

树有 n−1 条边，无向存两次 → 共 2(n−1) 次追加，总长度和正好是 2(n−1)。遍历一个点只花 O(度数)，全树走一遍是 O(n)，比矩阵快一个量级。

3参数逐个过一遍：这行声明的四个用法
组成部分含义 / 格式要求
vector<int> g[N]开 N 个 vector，第 u 个装 u 的所有邻居。读法：一个数组，每个元素是一条不定长表。
g[u].push_back(v)在 u 的表尾追加 v，O(1) 摊还。树有 n−1 条边，无向存两次 → 共 2(n−1) 次追加。
g[u].size()u 的邻居个数。树里就是度数：根的儿子数 = 度数，其它节点 = 度数 − 1。
for (int v : g[u])范围 for，依次取出邻居。等价于 for (int i = 0; i < (int)g[u].size(); ++i) { int v = g[u][i]; }。
有向还是无向有向树（父→子）只 push 一次；无向树要 push 两次：g[u].push_back(v); g[v].push_back(u);
为什么不用邻接矩阵n = 6000 的矩阵是 36 MB，遍历一个点还要扫 n 格；邻接表遍历一次只花 O(度数)。
验证 / 关键

vector<int> g[N] 放全局才默认全空，且不占栈。放函数里是 n 个局部 vector，n 大时容易爆栈。

范围 for 里写 int v 是拷贝；要改表本身得写 int &v。本节都只读。

于是我们得到：

用 N 条不定长表存树，空间 O(n)、遍历 O(度数)。

vector<int> g[N];
g[u].push_back(v);
for (int v : g[u]) { ... }
  • vector<int> g[N] 放全局才默认全空，且不占栈。放函数里是 n 个局部 vector，n 大时容易爆栈。
  • 范围 for 里写 int v 是拷贝；要改表本身得写 int &v。本节都只读。
  • 边数记牢：树的边是 n−1 条，无向存两次，所以每个 vector 的总长度和是 2(n−1)。
推导自底向上的顺序从哪来：DFS 后序覆盖：dfs(u, fa) / 防回头 / 后序合并 / 叶子边界 / 根的选择 / 递归深度需求 → 尝试 → 验证 → 定理
问题

区间 DP 能按长度枚举，是因为区间有“长短”可比。树没有这种尺子：谁先算？按编号 1..n 顺着推行不行？——不行，儿子编号完全可能比父亲大。没有现成的枚举顺序，顺序只能由遍历过程本身给出。

1按编号递推为什么不行

树是完全由输入随便编号的。若 f[u] 要用到儿子 f[v]，而 v 的编号比 u 大，那么按 1..n 递推时 f[v] 还没算。

// 反例：按编号从小到大处理，父亲可能排在儿子后面
for (int u = 1; u <= n; ++u)
    for (int v : g[u]) f[u] += f[v];    // f[v] 可能还是初始值
验证 / 关键

编号是输入给的，和树的形状没有任何关系。想在编号上做文章，得先排序，而那等价于重新算一遍树的结构——不如直接递归。

2递归进去，再回来合并

所有依赖都是“父亲依赖儿子”。那就让函数先钻到叶子，再一层层往回走：递归调用返回的那一刻，儿子的答案已经算完了。

#include <bits/stdc++.h>
using namespace std;

const int N = 100005;
vector<int> g[N];
int sz[N], dep[N];

void dfs(int u, int fa) {
    sz[u] = 1;                        // 自己算一个点
    dep[u] = dep[fa] + 1;             // 深度可以顺着参数/父亲递推
    for (int v : g[u]) {
        if (v == fa) continue;        // 父亲方向是来的路
        dfs(v, u);                    // ★ 先递归：等 sz[v] 算完
        sz[u] += sz[v];               // ★ 再合并
    }
}

int main() {
    g[1].push_back(2); g[2].push_back(1);
    g[1].push_back(3); g[3].push_back(1);
    g[3].push_back(4); g[4].push_back(3);
    dep[0] = 0;
    dfs(1, 0);                        // 0 是虚点，编号从 1 起，绝不会撞上
    cout << sz[1] << " " << sz[3] << " " << dep[4] << "\n";   // 4 2 3
}
验证 / 关键

两个 ★ 的顺序就是全部秘密：dfs(v, u) 在前、sz[u] += sz[v] 在后。交换一下，sz[v] 还是 0，答案直接少一大截（本节后面有对照图）。

叶子节点没有任何邻居能通过 if (v == fa)，for 循环直接结束、函数返回——不需要单独写递归边界。

3参数逐个过一遍：dfs(u, fa) 的两个参数
组成部分含义 / 格式要求
u当前节点。dfs 的每一层只负责一棵子树，不关心兄弟。
fau 的父亲。树存成无向图后，邻居里有一个是“来的路”，必须跳过，否则两点之间来回横跳。
if (v == fa) continue;这一行就是“不走回头路”。删掉它 → 无限递归 → 爆栈 RE，连输出都没有。
dfs(v, u)传的是 u，不是 fa：v 的父亲是 u。写成 dfs(v, fa) 会让 v 继续往上爬。
①②的顺序所有合并儿子的语句必须写在 dfs(v, u) 之后。写在前面，f[v] 还是初始值，答案偏小且不报错。
叶子节点叶子没有任何邻居能通过 if，for 循环直接结束，函数返回——不需要单独写递归边界。
根怎么选无向树任选一个当根（常写 1）；有向树（父→子）要先找入度为 0 的点。
深度递归深度 = 树高，最坏是一条链、深度 n。n ≤ 2×10⁴ 时安全，到 10⁵ 要考虑手写栈。
验证 / 关键

fa 初值写 0、编号从 1 开始，0 一定不等于任何邻居——无向树靠这一手省掉 vis 数组。

根取哪个不影响 sz[1] 之外的信息量，但答案若是“某个点”，要在 dfs 里顺手更新全局量。

于是我们得到：

树形 DP 的枚举顺序 = DFS 后序 = 每个节点的所有儿子都先算完。

void dfs(int u, int fa) {
    for (int v : g[u]) {
        if (v == fa) continue;   // 不走回头路
        dfs(v, u);               // ① 先把儿子的答案算完
        ...                      // ② 再用 f[v] 更新 f[u]
    }
}
  • fa 初值写 0、编号从 1 开始，0 一定不等于任何邻居——无向树靠这一手省掉 vis 数组。
  • 把两个 ★ 交换顺序：sz[u] += sz[v] 时 sz[v] 还是 0，答案直接少一大截。这是树形 DP 第一大坑。
  • 根取哪个不影响 sz[1] 之外的信息量，但答案若是“某个点”，要在 dfs 里顺手更新全局量。

第一道题是本节的模板：一条链上的合并，加上一个环的处理。先把它彻底做透，第二个例题才有参照物。

算法落地石子合并 P1880：破环成链 + 按长度递推覆盖：洛谷 P1880 / 环形区间 DP / 破环成链
需求

例题 · 石子合并 · 洛谷 P1880 普及/提高-

在圆形操场四周摆了 N 堆石子，现要将石子有次序地合并成一堆。规定每次只能选相邻的两堆合并成新的一堆，并把新堆的石子数记为该次合并的得分。

求将 N 堆合并成 1 堆的最小得分与最大得分。

数据范围：1 ≤ N ≤ 100，0 ≤ aᵢ ≤ 20。

输入格式：第一行 N；第二行 N 个整数，第 i 个表示第 i 堆的石子数。
输出格式：两行，第一行最小得分，第二行最大得分。

样例
输入：
4
4 5 9 4
输出：
43
54
1破环成链：复制一份接在后面，顺便做前缀和
const int INF = 0x3f3f3f3f;
int n, a[205], s[205];              // a 开两倍：破环成链
int f[205][205], g[205][205];      // f 最小得分，g 最大得分

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) { cin >> a[i]; a[i + n] = a[i]; }   // 复制一份接在后面
    for (int i = 1; i <= 2 * n; ++i) s[i] = s[i - 1] + a[i];          // 前缀和：O(1) 取区间和
为什么

环上有 n 种“从哪断开”的选择。暴力枚举断点各做一次 DP 是 O(n⁴)。把数组复制一份接在后面，得到长度 2n 的链——环上任何一种断法，都对应这条链上一个长度为 n 的连续窗口。

前缀和让区间和 s[r]−s[l−1] 变成 O(1)；否则在 k 循环里再求和就多一层 O(n)，直接 O(n⁴)。

2初始化：min 表要给足大值，max 表给 0
    memset(f, 0x3f, sizeof f);     // 求最小：初值要足够大
    memset(g, 0, sizeof g);        // 求最大：得分非负，初值 0 就行
    for (int i = 1; i <= 2 * n; ++i) f[i][i] = g[i][i] = 0;   // 单堆不用合并，得分 0
为什么

求最小值的表必须先铺满一个大数（0x3f3f3f3f ≈ 1.06×10⁹），否则 min 永远取到 0。求最大值的表得分非负，铺 0 就够。

长度 1 的区间（单堆）不需要合并，得分 0——这一行必须写在 memset 之后，顺序反了会被重新铺回 INF。

3三层循环：长度最外层，断点最里层
    for (int len = 2; len <= n; ++len)                 // ① 长度从小到大
        for (int l = 1; l + len - 1 <= 2 * n; ++l) {   // ② 左端点
            int r = l + len - 1;
            for (int k = l; k < r; ++k) {              // ③ 断点：左段 [l,k]，右段 [k+1,r]
                int add = s[r] - s[l - 1];             // 本次合并的得分 = 两段总重
                f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + add);
                g[l][r] = max(g[l][r], g[l][k] + g[k + 1][r] + add);
            }
        }
为什么

最后一个合并动作的得分固定为 sum(l..r)，与 k 无关，所以提到 k 循环外算一次就够。前面两段内部的合并互不干扰，各自独立取最优不会冲突——这就是最优子结构。

长度上限是 n 而不是 2n：只有长度 n 的窗口才对应一个完整的环，更长的区间没有意义。

4答案：n 个窗口里取最优
    int mn = INF, mx = 0;
    for (int l = 1; l <= n; ++l) {                     // 枚举环的断点 = 长度 n 的每个窗口
        mn = min(mn, f[l][l + n - 1]);
        mx = max(mx, g[l][l + n - 1]);
    }
    cout << mn << "\n" << mx << "\n";
    return 0;
}
为什么

l 从 1 到 n 就把 n 种断法全试了一遍；每种断法的答案就是 f[l][l+n-1]。

mn 从 INF 起步，和表里的初值一致；mx 从 0 起步，因为得分非负。

5完整代码：提交版
完整代码
#include <bits/stdc++.h>
using namespace std;

const int INF = 0x3f3f3f3f;
int n, a[205], s[205];              // a 开两倍：破环成链
int f[205][205], g[205][205];      // f 最小得分，g 最大得分

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) { cin >> a[i]; a[i + n] = a[i]; }   // 复制一份接在后面
    for (int i = 1; i <= 2 * n; ++i) s[i] = s[i - 1] + a[i];          // 前缀和：O(1) 取区间和

    memset(f, 0x3f, sizeof f);     // 求最小：初值要足够大
    memset(g, 0, sizeof g);        // 求最大：得分非负，初值 0 就行
    for (int i = 1; i <= 2 * n; ++i) f[i][i] = g[i][i] = 0;   // 单堆不用合并，得分 0

    for (int len = 2; len <= n; ++len)                 // ① 长度从小到大
        for (int l = 1; l + len - 1 <= 2 * n; ++l) {   // ② 左端点
            int r = l + len - 1;
            for (int k = l; k < r; ++k) {              // ③ 断点：左段 [l,k]，右段 [k+1,r]
                int add = s[r] - s[l - 1];             // 本次合并的得分 = 两段总重
                f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + add);
                g[l][r] = max(g[l][r], g[l][k] + g[k + 1][r] + add);
            }
        }

    int mn = INF, mx = 0;
    for (int l = 1; l <= n; ++l) {                     // 枚举环的断点 = 长度 n 的每个窗口
        mn = min(mn, f[l][l + n - 1]);
        mx = max(mx, g[l][l + n - 1]);
    }
    cout << mn << "\n" << mx << "\n";
    return 0;
}
为什么

五段就是这份程序的全部：破环 / 初始化 / 三层循环 / 取窗口 / 输出。最小和最大用同一个转移，只是 min 换成 max，所以两张表一起算，代码只多两行。

竞赛用法

题型特征：答案能由“最后一次操作把序列切成两半”描述；n 大概在 100~500；中间可以插一个断点 k。看到“相邻两堆合并”“删去一个数”“回文子序列”就想到它。

复杂度：状态 O(n²)，转移 O(n)，总 O(n³)。但真实转移次数是 C(n+1,3) = n(n−1)(n+1)/6，n = 100 时约 1.7×10⁵，一瞬间；n = 1000 时 1.7×10⁸，要压常数。

  • 三层循环写成 l、r、k：用到未算的 f[k+1][r]，WA 且不报错。
  • 求 min 忘了初始化（全 0）：输出 0。
  • 环形题忘了复制成 2n：只算了一个断点。
  • 数组只按 n 开：复制成 2n 后访问 f[200][…] 越界。

可扩展：得分规则改成“两堆之差”，转移式照写，因为代价仍只由 (l,r,k) 决定；允许一次合并 3 堆，则 k 变成两个断点，复杂度 O(n⁴)。

模型：区间 DP（环形）O(n³) 但实际 C(n+1,3)坑：len 必须最外层，环形要复制 2n

第二道题把“区间”换成“子树”。注意这一次没有任何“区间长度”可以枚举，顺序完全由递归调用保证。

算法落地没有上司的舞会 P1352：树形 DP 的后序落地覆盖：洛谷 P1352 / 树形 DP / 后序合并
需求

例题 · 没有上司的舞会 · 洛谷 P1352 普及/提高-

某大学有 n 个职员，编号 1..n，他们的从属关系构成一棵以校长为根的树，父节点是子节点的直接上司。宴会每邀请一个职员都会增加快乐指数 rᵢ，但如果某职员的直接上司来了，这个职员就不肯来。

求邀请哪些职员能使快乐指数之和最大。

数据范围：1 ≤ n ≤ 6×10³，−128 ≤ rᵢ ≤ 127（可以为负）。

输入格式：第一行 n；接下来 n 行每行一个整数 rᵢ；再接下来 n−1 行，每行两个整数 l、k，表示 k 是 l 的直接上司。
输出格式：一行一个整数，最大快乐指数。

样例
输入：
7
1 1 1 1 1 1 1
1 3
2 3
6 4
7 4
4 5
3 5
输出：
5
1存边并找根：谁没有上司，谁就是校长
int n, r[6005];
vector<int> g[6005];        // g[u]：u 的所有直接下属（有向，父 → 子）
int f[6005][2];             // f[u][0] u 不来；f[u][1] u 来
bool hasFa[6005];           // 用来找根：没有上司的人就是根

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> r[i];
    for (int i = 1; i < n; ++i) {
        int l, k;                  // k 是 l 的直接上司
        cin >> l >> k;
        g[k].push_back(l);         // 加边 k → l
        hasFa[l] = true;           // l 有上司，不可能是根
    }

    int root = 1;
    for (int i = 1; i <= n; ++i)
        if (!hasFa[i]) { root = i; break; }   // 入度为 0 的点
为什么

输入只告诉你“谁是上司”，不会直接告诉你谁是校长。读边时顺手记一笔 hasFa，省掉一次入度统计。

本题的边是有向的（父→子），所以只 push 一次 g[k].push_back(l)，dfs 里也不会走回头路。

2状态初始化：自己这一份先记上
void dfs(int u) {
    f[u][1] = r[u];         // u 来：先拿到自己的快乐值
    f[u][0] = 0;            // u 不来：自己贡献 0
为什么

状态就是“这个人来不来”：f[u][1] 是 u 来时子树的最大快乐值，f[u][0] 是不来时。约束只发生在直接父子之间，爷爷来不来与 u 无关——这一维就够了。

r[u] 可能是负数，照样加进去，不能“负的就不要”：选了 u 就是选了 u 这个前提。

3后序：先递归儿子，回到 u 再合并
    for (int v : g[u]) {    // 有向树，边只从父指向子，不会走回头路
        dfs(v);             // ★ 先把儿子的两个值算出来
        f[u][0] += max(f[v][0], f[v][1]);   // u 不来 → 儿子来不来都行
        f[u][1] += f[v][0];                 // u 来了 → 儿子一定不能来
    }
}
为什么

u 不来 → 每个儿子 v 来不来都行，取 max(f[v][0], f[v][1])；u 来了 → 儿子一定不能来，只能加 f[v][0]。两句话就是全部转移。

顺序完全由递归结构给出：这里没有“长度为 1、2、3”可枚举，只有“儿子先算完”。合并语句必须写在 dfs(v) 之后，写在前面拿到的是初值。

4答案：根来与不来取大的
    dfs(root);
    cout << max(f[root][0], f[root][1]) << "\n";
    return 0;
}
为什么

根是唯一没有上司的点，从别的点开始 dfs 会漏掉根之上的部分，答案偏小。根来与不来都是合法方案，所以最后取一次 max 收尾。

5完整代码：提交版
完整代码
#include <bits/stdc++.h>
using namespace std;

int n, r[6005];
vector<int> g[6005];        // g[u]：u 的所有直接下属（有向，父 → 子）
int f[6005][2];             // f[u][0] u 不来；f[u][1] u 来
bool hasFa[6005];           // 用来找根：没有上司的人就是根

void dfs(int u) {
    f[u][1] = r[u];         // u 来：先拿到自己的快乐值
    f[u][0] = 0;            // u 不来：自己贡献 0
    for (int v : g[u]) {    // 有向树，边只从父指向子，不会走回头路
        dfs(v);             // ★ 先把儿子的两个值算出来
        f[u][0] += max(f[v][0], f[v][1]);   // u 不来 → 儿子来不来都行
        f[u][1] += f[v][0];                 // u 来了 → 儿子一定不能来
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> r[i];
    for (int i = 1; i < n; ++i) {
        int l, k;                  // k 是 l 的直接上司
        cin >> l >> k;
        g[k].push_back(l);         // 加边 k → l
        hasFa[l] = true;           // l 有上司，不可能是根
    }

    int root = 1;
    for (int i = 1; i <= n; ++i)
        if (!hasFa[i]) { root = i; break; }   // 入度为 0 的点

    dfs(root);
    cout << max(f[root][0], f[root][1]) << "\n";
    return 0;
}
为什么

注意 dfs(int u) 只有一个参数：本题边是有向的，从 u 出发只会往下走，不需要 fa 判回头。无向树才需要 dfs(u, fa)。

竞赛用法

题型特征：答案在树上，子树之间互相独立，约束只在父子之间——“父亲来了儿子不能来”“选了父亲才能选儿子”。这时一定有第二维表示“父/子选没选”。

复杂度：每个节点进一次 dfs、每条出边看一遍，O(n) 时间、O(n) 空间，跟树高无关、跟形状无关。

  • f[u][1] 写成 += max(f[v][0], f[v][1])：把不该来的上司请来了，样例 5 → 7。
  • 合并语句写在 dfs(v) 之前：f[v] 还是初值，答案恒定偏小且不崩。
  • 从 1 号点开始 dfs 而不是找根：漏掉根之上的部分。
  • r[u] 为负就跳过：状态被污染，答案偏大。

可扩展：树形背包（P2014 选课）把 f[u][0/1] 换成 f[u][j]（选 j 门课），合并时对儿子做一次背包；换题通常只改三处：第二维含义、初始化、儿子怎么并进父亲。

模型：树形 DP（父子约束）O(n) 时间 / O(n) 空间坑：先递归后合并，根要自己找
这两个模板还能套在哪

认区间 DP 的信号：答案能由“最后一次操作把序列切成两半”描述；n 大概在 100~500；中间可以插一个断点 k。石子合并、能量项链（环形，同样复制 2n）、最长回文子序列（f[l][r] 看两端是否相等）、括号匹配类，都是这个骨架。

认树形 DP 的信号：答案在树上，子树之间互相独立，约束只在父子之间。这时一定有第二维表示“父/子选没选”，比如选或不选、来或不来、装多少件。没有这一维，父子约束就没法表达。

环形问题的两套写法：①复制成 2n，答案取窗口；②强行分类讨论“第一堆和最后一堆是否合并”，对区间 DP 也能用，但要加一维状态。前者代码短、后者有时更快，初学一律用前者。

树形 DP 的通用写法：先 dfs 儿子，回来再合并，最后更新全局答案。换题时通常只改三处：第二维的含义、初始化（f[u][…] 的起点）、以及儿子那一步怎么并进父亲。

这一节的 6 个坑，按症状记

区间 DP 写成 for (l) for (r = l; r <= n; ++r) for (k)：用到还没算的 f[k+1][r] → WA，样例经常照样过，因为小数据正好被前几轮覆盖。

求最小却没给 f 初始化（全 0）→ 输出 0 或明显偏小的数 → WA。0x3f3f3f3f 是最稳的 INF。

环形题忘了复制成 2n，只在 1..n 上做：只算了一个断点 → WA，n 小的时候甚至可能蒙对。

树 DFS 漏了 if (v == fa) continue;：两个点互相调用 → 无限递归 → RE（爆栈），表现为进程直接退出、无任何输出。

合并儿子的语句写在 dfs(v, u) 之前：f[v] 还是初始值 → WA，答案恒定偏小，且能跑完不崩。

数组只按 n 开：n = 100 却开 f[105][105]，复制成 2n 后访问 f[200][…] → 越界 → RE 或随机 WA。习惯按“题目上界 × 2 再加几格”开。

数学补给 · 区间 DP 的转移次数到底是多少

状态数是 n²，但真跑起来不是 n³ 次，而是少得多。数一数三层循环总共进多少次最内层。

固定长度 len，区间有 n − len + 1 个，每个区间的断点有 len − 1 个。总次数：

T(n) = Σlen=2..n (n − len + 1)(len − 1) = C(n+1, 3) = n(n−1)(n+1)/6

代入验证：n = 3 时 C(4,3) = 4；手算 (2)(1) + (1)(2) = 4 ✓。n = 4 时 C(5,3) = 10；手算 (3)(1)+(2)(2)+(1)(3) = 10 ✓。

所以“区间 DP 能过 n ≤ 500 左右”是个可以直接背的数字。环形题因为数组翻倍、len 只到 n，转移次数约是线性版的两倍，n = 100 时仍是 3×10⁵ 量级。

树形 DP 那边则是另一套账：每个节点进一次 dfs，每次把每条出边看一遍，全部加起来 2(n−1) 次循环体。树的 DP 复杂度永远是 O(n)（或 O(n·状态数)），跟深度无关，跟形状也无关。

举一反三 · 想清楚这些再往下走
先自己写出答案，再点开核对——方向对不对，比答案本身更重要
  1. 把石子合并的得分规则改成“两堆石子数之差”，区间 DP 还成立吗？“最后一步的代价固定为 sum(l,r)”这个性质还在不在？
    想好了？点开核对思路与解析
    还成立，但“代价与 k 无关”这条性质没了：两堆之差是 |(s[k]−s[l−1]) − (s[r]−s[k])|，它随 k 变。好在它只由 (l,r,k) 决定，不依赖两段内部怎么合的，最优子结构还在，转移式照写，代价仍是 O(1)，总复杂度不变。常见错路：发现 add 不能提到 k 循环外，就断定“这题不能用区间 DP”；真正会崩的是得分依赖合并历史形状的规则，那时 f[l][r] 这一个数不够用。
  2. 如果每次允许合并相邻的 3 堆，len 的起点、k 的含义、cost 各要怎么改？复杂度变了吗？
    想好了？点开核对思路与解析
    k 从“一个断点”变成“两个断点”：枚举 l ≤ k1 < k2 < r，把区间切成三段，f[l][r] = min(f[l][k1] + f[k1+1][k2] + f[k2+1][r] + sum(l,r))，len 从 3 开始。复杂度从 O(n³) 涨到 O(n⁴)：状态 O(n²)、转移 O(n²)，n = 100 时约 4×106 次，n = 500 时约 2.6×109 次。常见错路：只把 len 的起点从 2 改成 3，却仍只枚举一个 k——那还是在合并两堆，转移式根本没变，答案必错。
  3. 树形 DP 里“父亲来了儿子就不能来”是硬约束。若改成“父亲来了，儿子的快乐值减半”，状态还需要加维度吗？
    想好了？点开核对思路与解析
    不用加维度。“减半”只作用在儿子自己那一份 r[v] 上，而 r[v] 和 f[v][1] 在父亲合并时都是已知的，u 来不来的信息也已经由 f[u][0]/f[u][1] 这一维区分开了，所以只要把 u 来时的转移改成 f[u][1] += max(f[v][0], f[v][1] − r[v]/2)。常见错路：继续写 += f[v][0]（那是硬约束），把可以来的儿子全排除了；还容易忽略 r 可以是负数——−128 减半是 −64，反而变大，方向别想当然。
  4. 求“树上一条路径的最大点权和（点权可负）”能不能复用 f[u][0/1]？第二维的含义要换成什么？
    想好了？点开核对思路与解析
    不能直接复用“来/不来”。第二维要换成“从 u 往下走一条链的最大点权和”：down[u] = a[u] + max(0, max down[v])，再在 u 处把最大的两条正链和 a[u] 拼起来（答案 = a[u] + 最大的两个 max(0,down[v])），取全树最大值。常见错路：把 f[u][0] 与 f[u][1] 加起来当路径——那只保证“父子不同时选”，跟“连通的一条路径”没关系；只累加最大的一个儿子，得到的是从叶子到 u 的直链，跨两个方向的最优路径被漏掉。
  5. P1880 只要求得分。如果要求输出最优的合并顺序，你要多开一维数组，还是只记断点？空间差多少？
    想好了？点开核对思路与解析
    只记断点就够，不用另开一维存方案。root[l][r] 存最优的 k，一张 int 表，复制成 2n 后是 (2n)² = 4×10⁴ 格，约 160 KB；而存每个区间的完整合并顺序要 O(n³) 个数（n = 100 时约 7×105 个），还要为每个区间单独开 vector。为什么够：合并树被断点唯一确定——从 root[l][r] 递归查两个子区间就能还原整棵树，先序或后序输出就是合并顺序。常见错路：在 k 循环里比较或拼接字符串，复杂度直接多乘一个 len。
  6. 环形问题的“复制成 2n”和“讨论首尾是否合并”两种写法，分别在什么时候更省时间和空间？
    想好了？点开核对思路与解析
    复制成 2n 胜在代码短：不用分类，一次 DP 就把 n 种断点全算完，代价是表变成 (2n)²、有效区间约 2n² 个，转移次数约为线性版的 4 倍（n = 100 时 6.6×105 对 1.7×105）。首尾讨论法在 1..n 上做，只多一维“首尾合不合并”的状态，状态数和转移次数都只有前者的一半左右（约线性版的 2 倍），所以它其实更省时间和空间——代价是分类要想清楚，写错就整题全错，正文因此说“初学一律用前者”。常见错路：以为复制成 2n 只是多花点内存、时间差不多；或者反过来宣称它省空间——它省的是代码，费的是时间和空间。

挑战题 · 最大子树和
洛谷 P1122普及/提高-去洛谷做这题 ↗

一株花上共连有 n 朵花，n−1 条枝干把它们连成一棵树。每朵花有一个“美丽指数”，可能是负数。

一次“修剪”指删掉一条枝干，于是整株花分成两株，扔掉其中一株。可以进行任意次修剪（也可以不剪），使最后剩下的那一株（也可能只剩一朵花）上所有花的美丽指数之和最大，求这个最大值。

输入格式：第一行一个整数 n（1 ≤ n ≤ 16000）；第二行 n 个整数，第 i 个表示第 i 朵花的美丽指数（|aᵢ| ≤ 10⁹）；接下来 n−1 行，每行两个整数 a、b，表示 a 与 b 之间有枝干相连。
输出格式：一行一个整数，表示最大美丽指数之和。

数据保证答案的绝对值不超过 2147483647。

引导性提示（先只看这里）

修剪之后剩下的东西一定是树上“连通的一块”，而且它可以看成某棵子树的一部分。

自己定一个根。对每个点问一句：如果剩下的这一块必须包含它，并且只能往它的子树里取，最多能拿多少？

子树里那些“拖后腿”的部分可以整块剪掉——修剪这个操作正好允许你这么做。

想看思路了？点开完整思路

定根。任取 1 号为根，把无向树变成有向的父子关系。

状态。f[u] = 以 u 为根、必须包含 u、且只在 u 的子树内取点的连通块的最大权值和。

转移。f[u] = a[u] + Σv 是 u 的儿子 max(0, f[v])。儿子那棵子树如果整体是负贡献，就连同这条边一起剪掉（这正是一次合法的修剪）；是正的才接上来。

答案。剩下的那一块总有一个“最靠上的点” u，它就是那一块在根意义下的最高点，所以它一定被某个 f[u] 算到过。取所有 f[u] 的最大值即可。答案允许只留一朵花，所以初始答案不能是 0 —— 必须从 -∞ 起，否则全是负数时会被 0 顶掉。

复杂度。每个点算一次，每条边过一次 → O(n)。n = 16000 时瞬间跑完。

类型。单点权值到 10⁹，n 到 16000，一块的权值和最大可达 1.6×10¹³，必须用 long long。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

const int N = 16005;
int n;
long long w[N], f[N], ans = LLONG_MIN;   // f[u]：必须含 u 的连通块最大权值和
vector<int> g[N];

void dfs(int u, int fa) {
    f[u] = w[u];                         // 自己这一份先算上
    for (int v : g[u]) {
        if (v == fa) continue;           // 父亲方向是来的路，跳过
        dfs(v, u);                       // ★ 先递归：等 f[v] 算完
        if (f[v] > 0) f[u] += f[v];      // ★ 负贡献的子树整块剪掉（就是一次修剪）
    }
    ans = max(ans, f[u]);                // 每个点都可能是那一块的最高点
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    for (int i = 1; i <= n; ++i) cin >> w[i];
    for (int i = 1; i < n; ++i) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);               // 无向树，两个方向都要存
    }

    dfs(1, 0);                           // 0 是虚点，编号从 1 起
    cout << ans << "\n";
    return 0;
}
关键片段拆解
片段作用
long long w[N], f[N], ans = LLONG_MIN权值到 10⁹、点数到 16000，一块的和可达 1.6×10¹³，int 装不下。ans 用 −∞ 起头，保证全是负数时也能取到“最大的那个负数”。
vector<int> g[N]1.6 万个 vector，总边数 3.2 万条，内存不到 1 MB。
dfs(int u, int fa)无向树必须有 fa：否则 u→v→u 来回走，直接爆栈。
f[u] = w[u]初始化就是“只留自己这一朵”，这是一切连通块的起点。
if (f[v] > 0) f[u] += f[v]正贡献接上，负贡献剪掉。这一行同时完成了“取或不取这棵子树”的决策，所以不需要再套一层 0/1 背包式的循环。
ans = max(ans, f[u])答案不是 f[1]：只留一朵花、或最高的那朵在中途时，最高点未必是根。
g[a].push_back(b); g[b].push_back(a);边是双向的。只存一次会有很多点根本走不到 → 答案偏小，且能跑完不报错。
这题最容易错的地方
  • f、w、ans 用 int：n = 16000 且权值都是 10⁹ 时和到 1.6×10¹³，溢出后变成负数 → 大测试点全挂（WA）。
  • ans 初始化为 0：所有花都难看（全负）时正确答案是最大的那个负数，0 会把它顶掉 → WA。
  • 漏写 if (v == fa) continue;：无向树会两点之间来回递归 → RE（爆栈）。
  • 无向边只 push 一次：树被当成有向图，一部分子树永远访问不到 → WA，且不崩不报错。

挑战 2 · 选课
洛谷 P2014提高+/省选-去洛谷做这题 ↗

大学里有 N 门课，第 i 门有 sᵢ 学分，并且最多有一门直接先修课 kᵢ；只有学完先修课才能学这门课，kᵢ = 0 表示没有先修课。

要从这 N 门课里选 M 门学习，求能获得的最大学分。

输入格式：第一行 N、M（1 ≤ N ≤ 300，1 ≤ M ≤ 300）。接下来 N 行，第 i 行两个整数 kᵢ、sᵢ（0 ≤ kᵢ ≤ N，1 ≤ sᵢ ≤ 20）。数据保证至少有一门 kᵢ = 0，且先修关系不冲突。

输出格式：一行一个整数，选 M 门课的最大学分。

样例
输入： 7 4 2 2 0 1 0 4 2 1 7 1 7 6 2 2 输出： 13
引导性提示（先只看这里）

每门课最多一门先修课、先修关系又没有环，所以这是一片森林。“选了儿子就必须选父亲”是关键约束。

森林不好做：加一个 0 号虚拟根，把 kᵢ = 0 的课全挂上去，问题变成“必选根，一共选 M+1 个点”。

在子树 u 里选 j 门，等于把 j−1 个名额分给各个儿子。这是第 32 节的背包，只是“物品”换成了儿子整棵子树。

想看思路了？点开完整思路

先建树：对每门课 i，g[kᵢ].push_back(i)，kᵢ = 0 的课成为虚拟根 0 的儿子。

状态 dp[u][j]：在 u 的子树里选 j 门课、且必选 u 时的最大学分。

转移：把每个儿子 v 看成一件物品——若在 v 的子树里选 t 门，得分是 dp[v][t]。合并是分组背包：dp[u][j] = max(dp[u][j], dp[u][j−t] + dp[v][t])，j 倒序、t 从 1 到 min(sz[v], j−1)。

j 倒序保证同一个儿子只被合并一次；t ≥ 1 是因为选 v 的子树必然包含 v 自己；j−t ≥ 1 是要给 u 留一个名额。

边界：dp[u][1] = s[u]，其余先置 −INF（不可达）。u = 0 时 s[0] = 0。

答案：dfs(0) 后输出 dp[0][M+1]——虚拟根占了 1 个名额，最后减掉。

为什么对：合法方案在树上是一个“含根、向下封闭”的点集。对 u 而言，各儿子方向选多少互相独立，只通过总名额耦合，所以逐个儿子做背包合并不重不漏。

复杂度：单个儿子合并 O(m·sz[v])，全树合计约 O(n·m²/2) = 300×300²/2 ≈ 1.4×10⁷，1 秒内；空间 O(n·m)。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

const int NEG = -1000000000;
int n, m;
vector<int> g[305];            // 先修课 → 后续课，树（多棵树挂在虚拟根 0 上）
int s[305];                    // 学分
int sz[305];                   // 子树大小
int dp[305][305];              // dp[u][j]：在 u 的子树里、必选 u，一共选 j 门课的最大学分

void dfs(int u) {
    sz[u] = 1;
    for (int j = 1; j <= m; ++j) dp[u][j] = NEG;
    dp[u][1] = s[u];                            // 只选 u 自己
    for (int v : g[u]) {
        dfs(v);                                 // 先算完儿子，再合并回 u
        for (int j = min(m, sz[u] + sz[v]); j >= 1; --j)      // 倒序：一个儿子只能合并一次
            for (int t = 1; t <= min(sz[v], j - 1); ++t) {
                if (dp[u][j - t] == NEG || dp[v][t] == NEG) continue;
                dp[u][j] = max(dp[u][j], dp[u][j - t] + dp[v][t]);
            }
        sz[u] += sz[v];
    }
}

int main() {
    scanf("%d %d", &n, &m);
    for (int i = 1; i <= n; ++i) {
        int k;
        scanf("%d %d", &k, &s[i]);
        g[k].push_back(i);                      // k = 0 的课挂在虚拟根 0 上
    }
    if (m > n) m = n;
    ++m;                                        // 虚拟根自己占掉一个名额，最后减掉
    dfs(0);
    printf("%d\n", dp[0][m]);
    return 0;
}
关键片段拆解
片段作用
g[k].push_back(i);k = 0 的课挂到虚拟根 0，森林变一棵树，dfs 只有一个入口。
dp[u][1] = s[u];边界：只选 u 自己。u = 0 时学分 0，正好白占一个名额。
for (int j = 1; j <= m; ++j) dp[u][j] = NEG;先全部设成不可达，再单独写边界。0 会被误当成“合法但很差”。
for (int j = min(m, sz[u] + sz[v]); j >= 1; --j)j 倒序：dp[u][j−t] 必须是没合并 v 之前的旧值。
for (int t = 1; t <= min(sz[v], j - 1); ++t)t 至少 1（选 v 必选自己），至多 j−1（给 u 留一个名额）。
sz[u] += sz[v];合并完再更新子树大小，它决定下一轮 j 的上界。
++m; ... dp[0][m]虚拟根也占一个名额；答案在根上，不是全表最大值。
这题最容易错的地方
  • j 写成正序：同一个儿子被反复合并，答案偏大，且没有任何报错。
  • dp 初值用 0 而不是 −INF：“不存在”的状态带着 0 分参与 max，答案偏大且查不出来。
  • 忘了虚拟根 +1 名额：能选的门数少一，样例输出 7 而不是 13。
  • 把合并语句写在 dfs(v) 之前：儿子的 dp 还没算，全是 −INF，整棵树答案都是 −INF。
