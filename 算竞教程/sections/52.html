52 · KMP 与字符串匹配

用 fail 数组把“失配后从哪重新比”预先算好：f[i] 是前缀 s[1..i] 的最长 border，失配时沿 border 链跳，主串指针永不回退，匹配 O(n+m)。同一套下标还能直接读出最小周期 n − f[n]，Z 函数则用 [l, r] 盒子在 O(n) 内给出每个后缀与前缀的 LCP。
提高预计 70 分钟KMPborderZ 函数

在长串 s1 里找模式串 s2 的所有出现位置，暴力做法是：把 s2 对到每个起点上，逐字符比。最坏 O(|s1|·|s2|)——s1 = s2 = 106 个 a 时是 1012 次比较，必然超时。KMP 把“失配之后从哪一位重新开始比”预先算进一个数组，于是 s1 的指针永不回退，总时间 O(|s1| + |s2|)。

失配时不需要把 s2 挪一格重来：已经匹配上的那一段，既等于 s2 的前一段，也等于 s1 的末尾，所以只要知道“s2 的这段前缀里，最长的、同时也是后缀的前缀有多长”——这个长度就是 fail。

问题

KMP 的全部记号都挂在“前缀长度”上：f[i] 是前 i 个字符的最长 border。如果按 C 语言习惯从 0 开始存，那么“前 i 个字符”对应的是 s[0..i−1]，每一处下标都要减一。border 题里差一位就整题错——这种“到处减一”的写法才是真正的 bug 温床。

于是问题变成：能不能让下标 i 天然等于前缀长度，从此不再做 ±1 的换算？

1第一步：把下标整体右移一位

让第一个字符放在 s[1]，s[0] 空着不用。这样 s[1..i] 恰好是“前 i 个字符”，循环写成 for (int i = 1; i <= n; ++i)，i 就是前缀长度，也是字符个数。

这一步只付出一个字节（s[0]）的代价，换来的是后面所有递推式都不用换算下标。

验证 / 关键

验证：f[i] 的意义是“s[1..i] 的 border 长度”，而下标 i 正好是这段的长度——定义与下标一一对应，f[i] = j 读作“前 i 个字符有长 j 的 border”，读一次就懂。

2第二步：读入与求长度

签名与写法：cin >> (s + 1); 把串读到以 s[1] 开头的位置；int n = strlen(s + 1); 从 s[1] 数到 '\0' 就是串长。

3第三步：把数组放在正确的地方

1e6 个字符的数组必须是全局的：全局数组在静态存储区，不占栈；写在 main 里就是栈上 1 MB，稍深一点的递归或稍大的局部数组就会爆栈。

数组开小了也不一定当场报错：少 1 个字节时 '\0' 写到数组外，属于未定义行为，可能本地没事、交上去 RE。

验证 / 关键

验证：1 基下标要额外留出 s[0] 和结尾的 '\0'，所以 char s[1000005] 只能装 106−2 个字符。开 char s[1000000] 装 106 个字符一定越界。

推导失配之后，从哪一位重新比覆盖：fail / next 数组 / border 递推需求 → 尝试 → 验证 → 定理
问题

在长串 s1 里找 s2，暴力做法是把 s2 对到每个起点上逐字符比。最坏是 s1 = s2 = 106 个 a 的情形，要 1012 次比较，必然超时。

浪费在哪：设已经对上了 j 个字符、第 j+1 个失配。暴力把起点右移一格、j 清零重来，刚刚确认过的那 j 个字符又比了一遍。能不能让“下一次从几位开始比”提前算好、不依赖 s1？

1第一步：看清失配那一刻已经知道什么

失配时我们已知 s1[i−j..i−1] = s2[1..j]。新的对齐方式相当于问：s2 的前缀 s2[1..k] 能不能同时等于 s2[1..j] 的后缀？如果能，就有 k 个字符“自动对上”，从 k+1 继续比。

“既是 s2[1..j] 的前缀、又是它的后缀”有一个名字：border（真前缀且真后缀）。于是问题变成——“s2 的每个前缀，最长 border 有多长”。

验证 / 关键

验证：候选 k 只能是 s2[1..j] 的 border 长度。挑最大的那个最省事，也不会漏——更小的候选都挂在它的 border 链上，后面跳得到。

2第二步：把 f[i] 定义成“前 i 个字符的最长 border”

f[i] 是 s[1..i] 的最长 border 长度。递推只有五行，j 的含义是“进入第 i 轮时 j = f[i−1]，并且 s[1..j] 与 s[i−j..i−1] 已经相等”——这两段相等是“可以直接接着比”的全部依据。

签名：五行的递推
f[1] = 0;
for (int i = 2, j = 0; i <= m; ++i) {
    while (j && s[i] != s[j + 1]) j = f[j];
    if (s[i] == s[j + 1]) ++j;
    f[i] = j;
}
量 / 语句含义 / 格式
f[i] 是什么s 的前 i 个字符（记为 s[1..i]）的最长 border 长度。border = 既是真前缀又是真后缀的子串。
f[1] = 0单个字符没有非本身的 border。这是整条递推的起点，也是所有“回退到底”的终点。
j 的含义进入第 i 轮时 j = f[i−1]，并且 s[1..j] 与 s[i−j..i−1] 已经相等。这两段相等是“可以直接接着比”的全部依据。
if (s[i] == s[j + 1])已经对齐的两段后面再接一个相同字符，border 就延长一位：f[i] = j + 1。
while (j && s[i] != s[j + 1])失配就往短里找下一个候选。候选只能是 f[j]、f[f[j]]……一路跳到 0，跳到底再比 s[1]。
j 必须写在 for 的初始化里写成 for (int i = 2; i <= m; ++i) { int j = 0; ... } 每轮归零，f 全变 0。
j 从哪来循环开始时 j = 0 = f[1]，之后每轮结束 j = f[i]，正好是下一轮需要的值。
示例：buildFail
const int MAXN = 1000005;
int f[MAXN];

// s 从 s[1] 开始，长度 m
void buildFail(const char* s, int m) {
    f[1] = 0;                                  // 单个字符没有 border
    for (int i = 2, j = 0; i <= m; ++i) {      // j 在这里声明：跨轮保留
        while (j && s[i] != s[j + 1]) j = f[j]; // 失配：跳到次长 border
        if (s[i] == s[j + 1]) ++j;              // 匹配：border 延长 1
        f[i] = j;
    }
}

// s = "aabaaab" → f[1..7] = 0 1 0 1 2 2 3
验证 / 关键

验证：f[i] 永远不会超过 f[i−1] + 1——因为 f[i] 的 border 去掉最后一位，就是 s[1..i−1] 的 border，长度必然 ≤ f[i−1]。这条性质决定了 while 里“往短跳”是唯一的出路。

3第三步：为什么跳到 f[j] 就够

设 f[i−1] = j。若 s[i] = s[j+1]，border 直接延长，f[i] = j+1；若不等，f[i] 不可能等于 j+1。设 f[i] = k ≤ j，则 s[1..k] = s[i−k+1..i]，去掉最后一位得 s[1..k−1] = s[i−k+1..i−1]，而这一段是 s[1..j] 的后缀，所以 k−1 是 s[1..j] 的 border，即 k−1 ≤ f[j]。

也就是说：候选 k 恰好落在 border 链上，链是 j, f[j], f[f[j]], …, 0，既不会漏也不会重复。所以 while (j && ...) j = f[j]; 不是“随便往回退一点”，而是沿着这条链从大到小枚举候选。

验证 / 关键

验证：以 aabaaab 为例，f[1..7] = 0 1 0 1 2 2 3。第 6 轮 j 从 2 跳到 1，这一跳是 f[2] = 1，不是“减一”。写成 j-- 就退化成 O(nm)。

于是我们得到：fail 数组——f[i] 是 s[1..i] 的最长 border 长度，用五行递推 O(m) 求出。失配时 j = f[j] 沿着 border 链跳到次长候选，跳的总次数由势能分析控制在 O(m)。

    想好了？点开核对思路与解析
    这句话在一般意义下不成立，只在“q 整除 n”时成立。反例：s = abcdabcdabcd（n = 12，f[12] = 8，p = 4），q = 9 也是周期——因为周期 9 只要求 s[1..3] = s[10..12]，而 abc 确实等于 abc；可 9 不是 4 的倍数。更小的反例是 s = aabaa：p = 5 − 2 = 3，q = 4 也是周期（只需 s[1] = s[5]，都是 a），4 不是 3 的倍数。证明（限 q | n）：q 是周期且 q 整除 n、q < n 时 q ≤ n/2，又 p ≤ q，于是 p + q − gcd(p,q) ≤ p + q − 1 ≤ n − 1 < n，由 Fine–Wilf 知 gcd(p,q) 也是周期；而 p 是最小周期，只能 gcd(p,q) = p，即 p | q。所以完整循环节的长度集合（n 的因数里那些是周期的）必定是 p 的倍数；不完整的“周期”则不受此限。常见错路是把周期和循环节混为一谈，然后拿 q = n−1 之类的数据验证，发现结论崩了却以为是自己算错。

    想好了？点开核对思路与解析
    建 fail 树：把每个 i ≥ 2 的父亲设为 f[i]，根是 0。先给每个点置 cnt[i] = 1（前缀 s[1..i] 自己至少出现一次，就在位置 1），然后按 i 从 n 到 1 倒序执行 cnt[f[i]] += cnt[i]，最后 cnt[i] 就是 s[1..i] 在 s 中作为子串的出现次数（含重叠）。为什么对：某次出现让匹配长度到了 j，沿 fail 链往上跳，j 一定会经过 i 的某个祖先，倒序累加相当于把这个计数沿链推给所有祖先；而每个点只把自己的值推给父亲一次，总代价 O(n)。常见错路是正序累加（从 1 到 n），父节点还没攒齐就往上推，结果系统偏小；另一条是忘了初值 1，只把“子串匹配”的位置算进去，漏掉前缀本身；还有人把它建在 s + '#' + s 上，跨界的匹配被算进来，计数直接翻倍。

问题

fail 数组回答了“s2 自己失配后跳到哪”，可真正要跑的还是在 s1 上做匹配。如果每次失配都把 i 退回到本次匹配的起点加一，那就又回到了 O(nm)。

能不能让 i 一路向前、永不回退，只让 j 上下调整？

1第一步：把两行状态搬过来

已经匹配的长度记作 j。下一个要比的是 s2[j+1]；失配就 j = f[j]，而 i 原地不动——因为退掉的那部分字符，s1 里已经确认过了。

签名：匹配的主循环
for (int i = 1, j = 0; i <= n; ++i) {
    while (j && s1[i] != s2[j + 1]) j = f[j];
    if (s1[i] == s2[j + 1]) ++j;
    if (j == m) { /* 起点 i-m+1 */ j = f[j]; }
}
量 / 语句含义 / 格式
i扫 s1 的指针，从左到右走一遍，永不回退。这是 O(n) 的来源。
j当前已经匹配的字符数。它同时是 s2 的下标：下一个要比的是 s2[j+1]。
while (j && ...)与建 fail 时同一行代码。KMP 匹配就是“用 s2 的 fail 信息驱动 s1 的扫描”。
if (j == m)完整匹配一次，出现位置是 i − m + 1（1 基）。
j = f[j]★ 不能写 j = 0。s2 = aa、s1 = aaa 时，位置 1 和 2 都该输出。
总复杂度i 走 n 步；j 每步最多加 1，故 while 总次数 ≤ n，整体 O(n + m)。
示例：匹配 + 输出
for (int i = 1, j = 0; i <= n; ++i) {
    while (j && s1[i] != s2[j + 1]) j = f[j];   // 失配：沿 fail 后退
    if (s1[i] == s2[j + 1]) ++j;                // 这一位对上了
    if (j == m) {                               // 整串对上
        cout << i - m + 1 << "\n";              // 起点（1 基）
        j = f[j];                               // 允许重叠，继续找
    }
}
验证 / 关键

验证：while 与 if 这两行和建 fail 时一模一样，只是把“自己”换成了 s1。所以 KMP 只要写对一次，另一处照抄即可。

2第二步：命中之后为什么退到 f[m]

完整匹配一次后 j = m。这时若把 j 清零，就要求下一次出现不能与这一次重叠。但题目通常要所有出现位置，包括重叠的——s2 = aa、s1 = aaa 时，位置 1 和位置 2 都算。

正解是 j = f[j]（此时 j = m）：退到 s2 的最长 border，已经对上的那一小段直接当作下一次的开头。

验证 / 关键

验证：s2[j + 1] 在 j = m 时会读到 s2[m+1] = '\0'——只有忘记在匹配后回退 j 才会发生。

3第三步：为什么总共是 O(n + m)

i 走 n 步；j 每轮最多加 1，所以 j 的总增量 ≤ n。而 j ≥ 0，while 里每次 j = f[j] 都让它严格变小，所以总减少量也不会超过总增量。

于是 while 的总执行次数 ≤ n，整段匹配 O(n)——这种“把代价记到未来的增量上”的证明叫势能分析，j 就是势能。

另外，整个算法不需要对 s1 做任何预处理，也不需要 s1 的 fail 数组，流式数据（边读边匹配）也能用。

验证 / 关键

验证：把 while 换成 if (j && ...) --j; 后，“一次只退一格”让每次失配可能退 O(m) 步，总代价回到 O(nm)——势能分析里“总减少量 ≤ 总增量”的前提被破坏了。

两条铁律：失配写 j = f[j] 而不是 --j；命中后写 j = f[j] 而不是 j = 0。前者保证复杂度，后者保证不漏重叠。

问题

KMP 用“长度”做轴：f[i] 说的是前 i 个字符里前缀与后缀重合多少。可有些题问的是位置：从第 i 个字符开始的后缀，和整个串的开头最长能对上几位？

按定义暴力算：对每个 i 逐字符往后比，最坏 O(n2)——106 的串是 1012。能不能把已经比过的信息复用起来？

1第一步：维护一个“已经验证过的区间”

记 [l, r] 是当前“最靠右”的已知匹配段：t[l..r] 与 t[1..r−l+1] 相同。这个盒子里的字符全都验证过，盒外的还没验证。

当 i 落在盒子里（i ≤ r）时，t[i..r] 与 t[i−l+1..r−l+1] 逐位相同，所以“从 i 开始能对上多少位”可以直接抄“从 i−l+1 开始能对上多少位”，也就是 z[i−l+1]。

验证 / 关键

验证：这一步是抄不是猜——盒子内两段字符串完全相同，它们的 LCP 当然也相同，只要不越过盒子右端。

2第二步：抄的时候别抄出盒子

z[1] = n;

    z[i] = 0;
    if (i <= r) z[i] = min(z[i - l + 1], r - i + 1);
    while (i + z[i] <= n && t[1 + z[i]] == t[i + z[i]]) ++z[i];

}

using namespace std;

const int MAXN = 1000005;
char s1[MAXN], s2[MAXN];
int f[MAXN];                       // f[i]：s2 前 i 个字符的最长 border 长度

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> (s1 + 1) >> (s2 + 1);   // 1 基下标

    // ① 预处理：s2 匹配自己，求出 f[1..m]
    f[1] = 0;                                  // 单字符没有非本身的 border

        f[i] = j;
    }

    for (int i = 1, j = 0; i <= n; ++i) {
        while (j && s1[i] != s2[j + 1]) j = f[j];
        if (s1[i] == s2[j + 1]) ++j;

        cout << f[i];
        cout << (i == m ? "\n" : " ");
    }
    return 0;

为什么

总复杂度 O(|s1| + |s2|)：i 走 n 步；j 每步最多加 1，故 while 总次数 ≤ n。

整段只有三个数组：s1、s2 各 1 MB，f 4 MB，106 量级刚好放得下。

把 while 换成 if (j && ...) --j;、或把 j = f[j] 写成 j = 0，样例都可能蒙对，但大数据一定挂——这两处才是本题的考点。

fail 的递推为什么这么写

这是全节唯一需要动脑的地方。设 f[i−1] = j，含义是 s[1..j] = s[i−j..i−1]。要算 f[i]，只有三种情况。

  • 情况 1：s[i] = s[j+1]。把已经对齐的两段各延长一格，得到 s[1..j+1] = s[i−j..i]，于是 f[i] ≥ j+1。又 f[i] ≤ f[i−1] + 1 = j+1（理由见下），所以 f[i] = j+1。
  • 情况 2：s[i] ≠ s[j+1]。这时 f[i] 不可能等于 j+1。设 f[i] = k ≤ j。因为 s[1..k] = s[i−k+1..i]，去掉最后一位得 s[1..k−1] = s[i−k+1..i−1]，而 s[i−k+1..i−1] 是 s[i−j..i−1] = s[1..j] 的一段后缀，所以 k−1 是 s[1..j] 的 border，即 k−1 ≤ f[j]。于是候选 k 恰好落在 border 链上，最大的那个就是 f[j]+1。
  • 情况 3：j 退到 0 仍不匹配。此时没有任何非空 border，f[i] = 0。

“f[i] ≤ f[i−1] + 1”的理由：若 s[1..k] 是 s[1..i] 的 border，去掉最后一位，s[1..k−1] 就是 s[1..i−1] 的 border，所以 k−1 ≤ f[i−1]，即 k ≤ f[i−1] + 1。这条性质说明“长度每轮最多加 1”，也说明失配时只可能往短里找。

所以 while (j && ...) j = f[j]; 不是“随便往回退一点”，而是沿着 all-border 链按从大到小枚举候选。链上的值恰好是 j, f[j], f[f[j]], …, 0，既不会漏，也不会重复。

n % p == 0 ? n / p : 0整除才是“若干个完整块”。如 abababa 的 p = 2，但 7 % 2 ≠ 0，它只是“不完整周期”——末尾被截断了。
for (int k = f[n]; k > 0; k = f[k])border 链。f[k] < k 恒成立，所以循环一定终止；但链长最坏是 n−1（全是同一字符时），别在每个位置都遍历整条链。
为什么对应若 p 是周期，则 s[1..n−p] = s[p+1..n]，即长度 n−p 的前缀等于同长度后缀——正是 border。反之亦然。

Z 函数是 KMP 的“兄弟”：它直接给出“每个后缀与整个串前缀的最长公共前缀”。把模式串拼在主串前面、中间加一个不在字符集里的分隔符，一次 Z 就能得到所有匹配位置。

Z 函数做匹配
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 2000005;              // |s1| + |s2| + 1 再留余量
char t[MAXN];
int z[MAXN];

void getZ(int n) {                     // t 从 t[1] 开始
    z[1] = n;
    int l = 1, r = 0;
    for (int i = 2; i <= n; ++i) {
        z[i] = 0;
        if (i <= r) z[i] = min(z[i - l + 1], r - i + 1);   // 盒子内先抄
        while (i + z[i] <= n && t[1 + z[i]] == t[i + z[i]]) ++z[i];
        if (i + z[i] - 1 > r) { l = i; r = i + z[i] - 1; }
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string a, b;
    cin >> a >> b;                     // a 主串，b 模式串
    int n = a.size(), m = b.size();

    for (int i = 1; i <= m; ++i) t[i] = b[i - 1];
    t[m + 1] = '#';                    // 分隔符：不在字符集里，跨界的匹配立刻失败
    for (int i = 1; i <= n; ++i) t[m + 1 + i] = a[i - 1];

    int N = m + 1 + n;
    getZ(N);
    for (int i = m + 2; i <= N; ++i)
        if (z[i] >= m) cout << i - m - 1 << "\n";   // 起点 = i - (m + 1)
    return 0;
}

盒子 [l, r] 里先抄再扩

代码片段含义与理由
t = b + '#' + a分隔符保证“跨过分隔符的 LCP”不会虚增。于是 z[i] ≥ m 恰好等价于“b 在 a 的位置 i−(m+1) 出现”。
z[i] = min(z[i - l + 1], r - i + 1)盒子内 t[i−l+1..] 与 t[i..] 已经对齐，能抄 z[i−l+1] 这么多；但抄不能越过盒子右端，所以再取 r−i+1。
while (i + z[i] <= n && ...)从抄来的长度继续往外扩。边界条件 i + z[i] ≤ n 防越界。
if (i + z[i] - 1 > r)只有右端被推远才换盒子。r 单调不减，所以总扩大次数 ≤ n，整体 O(n)。
i - m - 11 基下 a 的第 pos 个字符在 t 中的下标是 m+1+pos，反过来 pos = i − (m+1)。
为什么还学 Z求“每个后缀与前缀的 LCP”Z 一步到位；求 border 链 fail 更直接。两个都写熟，按题目挑。
KMP 的 6 种错法（带症状）

WA，样例就错、fail 全为 0。—— j 声明在循环体内（for (int i = 2; ...) { int j = 0; ... }），每轮归零，f 永远算不出非零值。

RE / 越界。—— 数组按 |s1| 开。1 基下标要额外留出 s[0] 和结尾 '\0'，必须开 |s1| + 2 以上；写 char s1[1000000] 装 106 个字符一定爆。

WA，漏掉重叠的出现。—— 匹配成功后写 j = 0。s2 = aa、s1 = aaa 时应输出 1 和 2 两个位置，写 0 只出 1 个。正确写法是 j = f[j]。

TLE。—— 失配时写成 --j 或 j = f[j-1] 之类的“退一格”版本，退化成 O(nm)。106 的对 a 串能跑出 1012 次比较。

WA，答案整体差 1。—— 0 基写法与 1 基写法混用。网上有 nxt[i] 表示 s[0..i] 的 border 的版本，含义与本节 f[i] 差一位，两套不能混。

WA，格式错。—— P3375 要求每个位置单独一行，最后一行才是 fail 数组；不少模板题是位置空格分隔在一行。先读输出格式再写输出。

数学补给 · 均摊 O(n) 与 border 链

两个循环形状相同：j 每轮最多 +1，while 里每次至少 −1。设 j 的总增量 Δ+、总减少量 Δ−。因为 j ≥ 0 恒成立，有 Δ− ≤ Δ+；而 ++j 每轮至多执行一次，故 Δ+ ≤ n。于是 while 的总次数 ≤ n，整个匹配 O(n)。这种“把代价记到未来的增量上”的证明叫势能分析，j 就是势能。

两个恒等式，所有 border 题都从它们出发：

  • p 是 s 的周期 ⟺ s 有长度 n − p 的 border。所以最小周期 = n − f[n]。
  • s[1..i] 的全部 border 长度恰好是 f[i]、f[f[i]]、f[f[f[i]]]……一直到 0。这条链叫 border 链。

border 链没有对数界：s = an 时链就是 n−1, n−2, …, 1，长度 n−1。所以不能靠“链短”来保证复杂度。KMP 的 O(n) 来自势能分析：整场扫描里 +1 至多 n 次，因此 −1 至多 n 次，与某一次跳多远无关。这也解释了为什么“沿链跳”本身很便宜，而在每个位置都重新遍历整条链（例如求所有前缀的全部 border）会变成 O(n2)。

完整周期与不完整周期：n % (n − f[n]) == 0 时 s 由 n/(n−f[n]) 个相同的块拼成；不整除时只是“不完整周期”，如 abababa 的最小周期是 2，但 7 不是 2 的倍数。题目问“循环节个数”还是“周期长度”，答案完全不同。

Fine–Wilf 定理：若 p、q 都是 s 的周期且 p + q − gcd(p, q) ≤ |s|，则 gcd(p, q) 也是 s 的周期。它说明“两个周期会互相挤压出更小的周期”，是很多周期结论的来源。

Z 与 fail 的分工：z[i] 回答“从 i 开始的后缀，与整串开头能对上多少位”；f[i] 回答“前 i 个字符这一段里，前缀与后缀最长能重合多少”。一个以“位置”为轴，一个以“长度”为轴。要“每个位置与前缀的匹配长度”用 Z 更直接；要“前缀的 border 链、周期”用 fail 更直接。

挑战题 · Radio Transmission 无线传输
洛谷 P4391提高-去洛谷做这题 ↗

电台把一条信息 S′ 反复拼接后循环播放：S′S′S′……。你收到的是其中一段连续的字符序列 S，长度 L 保证不小于 |S′|。求 S′ 的最小可能长度。

形式化地说：求 S 的最短子串 S′，使得 S 本身是无限串 S′S′S′…… 的一个子串。

输入：第一行一个整数 L（1 ≤ L ≤ 106）；第二行恰好 L 个小写字母，即序列 S。

输出：一行一个整数，表示 S′ 的最小长度。

引导性提示（先只看这里）

“S 是 S′ 无限重复的一段”等价于：存在 p，使得对每个满足 i + p ≤ L 的 i 都有 S[i] = S[i+p]。这个 p 有个名字，叫周期。

周期的“补集”是 border：p 是周期，当且仅当 S 有长度 L − p 的 border。想让 p 最小，就要让 border 最长。

先手算样例 cabcabca：最长的、既是前缀又是后缀的真前缀有多长？把它从 L 里减掉，得到什么？再想想为什么不需要判断整除。

想看思路了？点开完整思路

记 p 为 S 的一个周期：S[i] = S[i+p] 对所有合法 i 成立。那么 S 去掉最后 p 个字符得到的前缀，与去掉最前 p 个字符得到的后缀完全相同，即 S 有长度 L−p 的 border。反过来，有长度 b 的 border 就等价于有周期 L−b。

所以“最小周期” ⟺ “最长 border”。最长 border 就是 fail 数组的最后一项 f[L]。答案 = L − f[L]。

为什么不需要整除判断：题目允许最后一段 S′ 被截断。样例 cabcabca 的 p = 3，8 不是 3 的倍数，但它确实是 abcabcabcabc 的一段子串。若要求“完整循环节个数”，才需要额外判 L % p == 0。

复杂度：只需求一次 f[1..L]，O(L) 时间、O(L) 空间，L = 106 轻松通过。

边界：L = 1 时 f[1] = 0，答案 1；S 全为同一字符时 f[L] = L−1，答案 1。两端都对。

挑战 2 · Censoring S
洛谷 P4824提高-/提高去洛谷做这题 ↗

给两个由小写字母组成的字符串 S 与 T（|T| ≤ |S| ≤ 106）。反复执行下面的操作：在当前 S 中找到 T 的第一次出现，把这一段删掉；删除后左右两边拼接起来，可能拼出新的 T。直到 S 中不再含有 T 为止。输出处理完的 S。

输入：第一行 S，第二行 T。保证两串都只含小写字母，且 |T| ≤ |S|。题目保证删除过程中 S 不会变成空串。

输出：一行，处理完成的字符串 S。

样例：S = whatthemomooofun，T = moo。先删掉中间那个 moo，拼出 whatthemoofun；此时又出现 moo，再删，剩下 whatthefun。

样例
输入： whatthemomooofun moo 输出： whatthefun
引导性提示（先只看这里）

先估暴力：每次删完都从头重新找一遍 T，最坏要扫多少次字符？|T| = 1 时这个数字是多少？

一次删除只影响被删位置附近的那几个字符，前面已经确认过的匹配不该重算。第 29 节有个结构天生适合「把最近加进来的东西拿掉」。

KMP 里那个「当前已匹配 T 的多长前缀」的指针，在字符被删之后应该退到多少？你需要在 O(1) 内查到「删之前那个位置」的匹配长度——把它和字符一起存起来。

想看思路了？点开完整思路

暴力：反复 find 出 T、erase 掉，再从头找。string::erase 单次 O(|S|)，最坏删 106 次 → 1012 次字符搬动。

换存储：用栈保存「当前还活着的字符」，栈里的内容就是答案的前缀。删除一段 = 弹出最近压入的若干个字符。

压入字符 c 时，KMP 的匹配长度 j 不能从 0 开始，而要从「栈中前一个位置存下来的值」开始——栈里前几个字符正是 c 左边紧邻的内容，匹配必须接着它算。

然后照抄 KMP 的两行：沿 fail 链跳，再看能否 +1，把结果存进 len[栈顶]。

当 j 达到 |T| 时，栈顶 |T| 个字符恰好是 T：整段弹出。弹完之后，下一个字符要继承的匹配长度就是新栈顶存的值——这就是「删完从哪继续」的 O(1) 答案。

为什么正确：栈里的字符序列与被删改后的字符串完全相同，len[] 记录的正是「在原串上跑到这一步时」的匹配长度。被删掉的那些字符不会再影响后续匹配，所以直接丢弃它们的 len 是对的。

复杂度：对 T 求 fail O(|T|)；主过程每个字符压一次、弹一次，j 的推进总量 O(|S|)。总 O(|S|+|T|)。

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1000005;
int fail_[MAXN];              // fail_[i] = T[0..i] 的最长 border 长度
char stk[MAXN];               // 栈 = 当前还没被删掉的字符
int len[MAXN];                // len[k] = 栈的前 k 个字符里，结尾能与 T 匹配上的长度
int top = 0;

int main() {
    string s, t;
    cin >> s >> t;
    int n = s.size(), m = t.size();

    // 1) 只对模式串自身求 fail，O(m)
    fail_[0] = 0;
    for (int i = 1; i < m; ++i) {
        int j = fail_[i - 1];
        while (j && t[i] != t[j]) j = fail_[j - 1];
        if (t[i] == t[j]) ++j;
        fail_[i] = j;
    }

    // 2) 主串逐字符压栈，失配沿 fail 跳，凑满 |T| 就弹栈
    for (int i = 0; i < n; ++i) {
        stk[++top] = s[i];
        int j = (top > 1) ? len[top - 1] : 0;   // 继承栈里前一个位置的匹配长度
        while (j && s[i] != t[j]) j = fail_[j - 1];
        if (s[i] == t[j]) ++j;
        len[top] = j;
        if (j == m) top -= m;                   // 整段 T 弹出，指针自动回到删除前的位置
    }

    stk[top + 1] = '\0';
    cout << (stk + 1) << '\n';
    return 0;
}
