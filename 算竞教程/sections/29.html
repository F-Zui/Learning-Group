29 · 栈与队列的应用

把 LIFO/FIFO 从“系统自动帮你维护”变成“自己调度”：后缀表达式求值（栈顶即最近的两个操作数）、括号匹配（栈顶即最近未匹配的左括号）、递归改显式栈、队列模拟约瑟夫环。
普及/提高-预计 60 分钟栈括号匹配后缀表达式

栈和队列不是两个新容器，是两种顺序约定：栈规定“最后进来的第一个出去”（LIFO），队列规定“最先进来的第一个出去”（FIFO）。前面几节其实一直在用它们 ——BFS 用队列按层扩散，递归用系统栈保存现场 —— 但都是自动的。这一节把它们拿到手里，用一行 st.push(x) 自己决定什么时候存、什么时候取。

具体做三件事：①后缀表达式求值，看清“栈顶就是最近的两个操作数”；②括号匹配，看清“最近未匹配的左括号就是栈顶”；③把递归改写成显式栈，把队列当成一个循环的圈。

栈的语义只有一句：最近的东西最相关。凡是“最近的还没处理完”能刻画问题的地方，都能用栈。
容器从哪进 / 从哪出看一眼拿到谁典型场景
stack<int>都从栈顶最近压入的括号匹配、后缀表达式、递归改迭代、单调栈
queue<int>队尾进、队头出最早进来的BFS 按层扩散、约瑟夫环、任务排队
deque<int>两端都能进出最早或最近的0-1 BFS、滑动窗口最值（第 28 节）

三种容器的接口几乎一样（push / pop / empty / size），区别只在 pop() 删的是哪一个。

推导stack：把“最近还没处理完的东西”存起来覆盖：stack / push·top·pop / LIFO / size_t / 清空需求 → 尝试 → 验证 → 定理
问题

写递归时，函数返回要回到上一层、恢复现场——这件事编译器用系统栈自动做了，我们从来不用管。可有些问题没有“函数调用”这个外壳：比如给一行括号，遇到右括号时要找回最近的那个还没配对的左括号。

用数组存？那得自己记“现在存到第几个”，还要在配对成功后把它抹掉。用队列？队列给你的是最早进来的那个，正好相反。

这里需要的语义只有一句：最近进来的，最先出去。有没有一个容器，天生只认这一条？

1只有一个出入口：push 进去，top 看一眼，pop 拿出来

stack 只有栈顶一个出入口。push(x) 压栈，x 成为新的栈顶；top() 读栈顶；pop() 删栈顶。后进先出（LIFO）。

压栈、看栈顶、弹栈
stack<int> st;
st.push(1);                         // 栈底 → [1]
st.push(2);                         //        [1, 2]
st.push(3);                         //        [1, 2, 3] ← 栈顶
cout << st.top();                   // 3
st.pop();                           // 弹出 3，剩下 [1, 2]
cout << st.top() << st.size();      // 22

底层默认用 deque 装，所以不用预先开大小。push / top / pop 都是 O(1)。

验证 / 关键

“只有一个出入口”不是限制，而是语义：它逼着你只能用“最近的那个”。括号匹配、后缀表达式、递归改迭代、单调栈，全都是这个语义的直接应用。

2两个坑：pop 不返回值，top 返回引用

pop() 删除栈顶但返回 void。想用被删的值，必须先 top() 存下来——这是初学者最高频的一行错。

先取再删
int x = st.pop();     // ✗ 编译不过：pop() 返回 void
int x = st.top(); st.pop();   // ✓ 先取再删

top() 返回的是引用，所以 st.top() += 3 是合法的，而且 char c = st.top(); st.pop(); 的顺序不能反——先 pop 再 top 拿到的是下一个元素。

验证 / 关键

size() 的返回类型是 size_t（无符号），空栈时算 size() - 1 会得到 18446744073709551615。判断空栈用 empty()，不要用 size() == 0 之外的花样。

栈空时调用 top() / pop() 是未定义行为，通常 RE。

stack 故意不给你遍历和下标——只能看栈顶。清空只能循环 pop，或者整个重新赋值。

清空

// 或者：st = stack<int>();

追问 · 把这一步想透
  1. 括号匹配如果要求输出“最长的合法括号子串长度”，栈还够用吗？提示：栈里存下标而不是字符，未匹配的位置就是分割点。
    想好了？点开核对思路与解析
    够用，但栈里要存“下标”而不是字符，并且要有“分割点”的概念。做法：初始把 −1 压栈当哨兵；遇左括号压它的下标；遇右括号先弹出栈顶，若此时栈空说明这个右括号没配上，把当前下标压栈当新的分割点，否则当前合法段的长度就是 i 减去栈顶下标，取最大值。多种括号同理，只是弹出的左括号类型必须对得上，对不上同样把当前位置当分割点。常见错路：只统计“匹配成功的对数”或“栈的最大深度”——[][] 的深度只有 1，但最长合法子串是 4，两者数值相近纯属巧合。
  2. 递归改显式栈时，哪些问题可以随便换、哪些不行？以“求连通块大小”和“输出字典序最小的路径”为例各说一句。
    想好了？点开核对思路与解析
    只关心“访问过哪些点、不关心顺序”的问题可以随便换：连通性、连通块大小、flood fill、可达性、拓扑排序（顺序不唯一但都合法）。不能换的是“顺序本身就是答案”的问题：输出字典序最小的路径、输出所有路径、题面规定了扩展顺序的搜索（比如走迷宫要求左上右下）。原因如正文所说：递归和显式栈是后进先出、队列是先进先出，遍历次序不同但访问集合相同——集合对、顺序不一定对。常见错路：以为“答案数对了就行”，竞赛题逐字比对，顺序是题目的一部分。
  3. 单调栈为什么能在线性时间里求出“每个元素右边第一个比它大的数”？它保证的栈内不变式是什么？先想想：为什么被弹出元素的那个“右边第一个更大”就是当前这个新元素。
    想好了？点开核对思路与解析
    不变式是：从栈底到栈顶，元素的值单调递减，栈里存的是“还没找到右边第一个更大元素”的那些下标。新元素 a[i] 进来时，栈顶所有比它小的元素，它们的“右边第一个更大”正是 a[i]（中间被 a[i] 挡住，且 a[i] 是最近的那个），于是弹栈并同时记录答案；弹到栈顶 ≥ a[i] 或栈空，再把 i 压栈。每个下标进出栈各一次，所以 O(n)；被弹出的元素也不必再考虑，因为 a[i] 比它们大、又比它们活得久。常见错路：只弹栈不填答案（那等于什么都没做），或者弹完忘了 push 当前下标。
推导queue：和 stack 只差“取哪一端”覆盖：queue / front·back / FIFO / 与 stack 对照 / 轮转需求 → 尝试 → 验证 → 定理
问题

queue 前面已经用过（BFS 按层扩散）。可它的接口和 stack 太像了：都叫 push、pop、empty、size，取元素却一个叫 top、一个叫 front。混着记，写的时候就会取错端。

更麻烦的是“什么时候该用哪个”说不清：同样是“存起来等会儿处理”，凭什么 BFS 用队列、括号匹配用栈？这一节把两者摆在一起对照一次。

1先进先出：push 进队尾，front 取队头

queue 从队尾进、从队头出，先进先出（FIFO），所以最早进来的最先被处理。front() 读队头，back() 读队尾，两个都是 O(1)，都不删除。

队头与队尾
queue<int> q;
for (int i = 1; i <= 5; ++i) q.push(i);   // [1, 2, 3, 4, 5]
cout << q.front() << q.back();            // 15

同一时刻你能看到两个元素：最旧的和最新的。stack 只能看到最新的那一个——这是两个容器最直观的区别。

验证 / 关键

取元素时 stack 用 top()、queue 用 front()，这是最容易写混的一处。记住：栈只有“顶”，队列有“头”和“尾”。

2和 stack 的对照：pop 删的都是“下一个该处理的”，但处理方向相反

两个容器的 pop 都是“删掉下一个该被处理的元素”，区别在于“下一个”是谁：stack 处理最新的，queue 处理最旧的。这一句就是 LIFO 与 FIFO 的全部差别。

轮转：push(front) + pop
// 把队头搬到队尾：整圈轮转一格
q.push(q.front());
q.pop();
cout << q.front();                        // 2

这两行是队列特有的动作：先复制队头、压到队尾，再删掉原来的队头——整队元素向前挪一格、队头绕回队尾。约瑟夫环就是它。

验证 / 关键

顺序不能反：先 pop() 再 push(q.front())，取到的就是下一个元素，整圈错位。

3接口细节与适用场景

queue 不能随机访问，也不能倒着走。需要两端都能动时用 deque（第 28 节）。

组成含义 / 格式要求
queue<int>头文件 <queue>。队尾进、队头出；先进先出，所以最早进来的最先被处理。
q.push(x)入队，O(1)。只能从队尾进。
q.front()读队头，O(1)，不删除。相当于 stack 的 top()，但拿到的是最旧的元素。
q.back()读队尾，O(1)。拿到的是最新入队的元素。
q.pop()删除队头，O(1)，同样返回 void。
与 stack 的对照取元素：stack 用 top()，queue 用 front()。pop() 删的都是“下一个该被处理的”，但 stack 处理最新的，queue 处理最旧的 —— 这一句就是 LIFO 与 FIFO 的全部差别。

cout << q.front() << q.back();            // 15

// 把队头搬到队尾：整圈轮转一格

q.pop();

第 26 节已经用 queue 写过 BFS，这里只做对照：把 top 和 front、把“最新”和“最旧”彻底分清。

queue 不能随机访问，也不能倒着走。需要两端都能动时用 deque（第 28 节）。

验证 / 关键

选容器的问句只有一个：下一次该取谁？取最新的用 stack，取最旧的用 queue，两端都可能取的用 deque，取最大/最小的用 priority_queue。

  1. 约瑟夫问题用队列模拟是 O(nm)。如果 n = 10⁵、m = 10⁵，而只需要最后的胜者，用数学补给的递推能到多快？如果既要胜者又要中途某个时刻的剩余人数呢？
    想好了？点开核对思路与解析
    递推 O(n)、O(1) 空间（正文数学补给：J(1) = 0，J(n) = (J(n−1) + m) mod n，输出 J(n) + 1），n = 10⁵ 时是 10⁵ 次取模，微秒级，比模拟的 10¹⁰ 快五个数量级。但它只能求最后的胜者：递推每一步都在“重新编号”，谁已经出列、此刻还剩哪些人这些信息全丢了。要中途的剩余人数只能真模拟，或者换数据结构——用树状数组 / 线段树维护“还活着的人”，每次在 O(log n) 内定位第 k 个活人，总 O(n log n)。常见错路：以为递推能顺带输出完整出列顺序；以及 0 起与 1 起换算错（忘了最后 +1），差一个人。
  2. 用两个栈能不能实现一个队列？反过来，用两个队列能不能实现一个栈？各自需要几次搬移，均摊复杂度是多少？
    想好了？点开核对思路与解析
    两个栈实现队列：设 in 和 out 两个栈，入队 push 到 in；出队时若 out 为空就把 in 全部倒入 out（顺序反转），再弹 out 顶，out 不空就直接弹。每个元素最多被搬两次（进 in 一次、倒 out 一次），n 次操作总搬移 ≤ 2n，均摊 O(1)。反过来两个队列实现栈：入栈 push 到 q1，出栈时把 q1 前 size−1 个搬到 q2、弹出剩下的那个、再交换角色，单次 O(n)、总 O(n²)，均摊仍是每次 O(n)——所以“队列实现栈”做不到均摊 O(1)（用一个队列自身轮转同样要 O(n)）。常见错路：出队时每次都把 in 倒进 out（不判 out 为空），倒一次 O(n)，每次都倒就退化成 O(n²)；以及交换角色时忘了清空 q2。
算法落地后缀表达式：一个栈，一遍扫完覆盖：洛谷 P1449 / 后缀表达式求值 + 栈
需求

例题 · 后缀表达式 · 洛谷 P1449 普及-

后缀表达式（逆波兰式）把运算符写在两个操作数之后。例如 3.5.2.-*7.+@ 对应中缀写法 3×(5−2)+7，值为 16。

输入一行后缀表达式：操作数是十进制非负整数，每个数后面跟一个 '.' 表示这个数结束；运算符只有 +、−、×、÷；整行以 '@' 结尾。输出格式：一行一个整数，即表达式的值。

题目保证表达式合法；除法按 C++ 的整数除法计算（向零取整）。

样例
输入：
3.5.2.-*7.+@
输出：
16
1第 1 步：为什么一遍能算完

中缀表达式难算，是因为读到 + 的时候你还不知道后面有没有 ×：优先级和括号都要“往后看”。后缀表达式把这些决定提前做完了，读到运算符时，它要的两个操作数一定刚好是最近的两个。

“最近的”就是栈顶。于是算法只有三行：数字入栈；运算符弹出两个算一次再压回去；扫完栈里剩一个数。

一个栈 + 一个正在攒的数
stack<long long> st;          // 中间结果可能很大，用 long long 不用 int
long long num = 0;            // 正在读的那个数
char c;
为什么

为什么这样是对的：用归纳看不变量——扫过某个前缀之后，栈里从底到顶正好是“这个前缀算出的、还没被合并的中间结果”，并且它们的相对顺序与表达式剩余部分一致。读到一个数：压栈，不变量成立。读到一个运算符：它作用在最近的两个中间结果上，弹两个压一个正好是它们的合并。扫完只剩一个中间结果，就是答案。

2第 2 步：读数字——多位数要一位一位攒

输入是按字符来的，一个数可能有多位。逐字符读，用 num = num * 10 + (c - '0') 拼装。

拼多位数
    while (cin >> c) {            // 逐字符读，cin >> char 会自动跳过空白
        if (c >= '0' && c <= '9') {
            num = num * 10 + (c - '0');      // 多位数：每来一位，前面的整体左移一位
        }
为什么

342 是 3 → 34 → 342：每次先把已有的数乘 10 进位，再加上新的一位。(c - '0') 把字符 '7' 转成整数 7，靠的是 ASCII 码连续。

cin >> char 会自动跳过空格和换行，所以表达式里有没有空格都不影响。另一种写法是 getline 整行再遍历，那样要自己处理 '\r'。

3第 3 步：'.' 是数字结束符，'@' 是整行结束符

本题的 '.' 是数字结束符，不是小数点。看到它就说明前面攒的 num 是一个完整的操作数。

两个特殊符号
        } else if (c == '.') {
            st.push(num);         // '.' 是这个数的结束符
            num = 0;              // 清零，准备读下一个数
        } else if (c == '@') {
            break;                // 表达式结束
        }
为什么

清零这一步不能漏：不清零，下一个数会拼在上一个数后面。

'@' 直接 break，循环结束后栈里应该只剩一个数——如果还剩两个，说明表达式不合法或漏算了。

4第 4 步：运算符——先弹的是右操作数

先弹出的是右操作数 b，后弹出的是左操作数 a，计算的是 a op b。对 + 和 × 无所谓，对 − 和 ÷ 写反就得到相反数或倒数——这是本节最高频的 WA。

弹两个、算一次、压回去
        } else {                  // + - * /
            long long b = st.top(); st.pop();   // 先弹出的是右操作数
            long long a = st.top(); st.pop();   // 后弹出的是左操作数
            long long r = 0;
            if (c == '+')      r = a + b;
            else if (c == '-') r = a - b;       // 不能写成 b - a
            else if (c == '*') r = a * b;
            else               r = a / b;       // 同上，顺序错了结果就反了
            st.push(r);           // 结果必须压回栈，后面的运算符要用它
        }
为什么

后缀表达式 3.5.- 的含义是 3 − 5，栈里是 [3, 5]，先弹出 5 才是被减数那一侧的 b。写成 b - a 后 5.3.- 会输出 −2 而不是 2。

加法和乘法满足交换律，会把这一处错法掩盖掉——所以只测全是 + 的数据查不出来。

结果必须压回栈顶，它是后续运算的操作数。漏了这一行，下一个运算符弹到的是更早的数据，整片错。

5第 5 步：拼回完整程序，算一遍复杂度

完整代码如下：一个栈包打天下。

完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    stack<long long> st;          // 中间结果可能很大，用 long long 不用 int
    long long num = 0;            // 正在读的那个数
    char c;
    while (cin >> c) {            // 逐字符读，cin >> char 会自动跳过空白
        if (c >= '0' && c <= '9') {
            num = num * 10 + (c - '0');      // 多位数：每来一位，前面的整体左移一位
        } else if (c == '.') {
            st.push(num);         // '.' 是这个数的结束符
            num = 0;              // 清零，准备读下一个数
        } else if (c == '@') {
            break;                // 表达式结束
        } else {                  // + - * /
            long long b = st.top(); st.pop();   // 先弹出的是右操作数
            long long a = st.top(); st.pop();   // 后弹出的是左操作数
            long long r = 0;
            if (c == '+')      r = a + b;
            else if (c == '-') r = a - b;       // 不能写成 b - a
            else if (c == '*') r = a * b;
            else               r = a / b;       // 同上，顺序错了结果就反了
            st.push(r);           // 结果必须压回栈，后面的运算符要用它
        }
    }
    cout << st.top() << '\n';     // 扫完栈里恰好剩一个数
    return 0;
}
为什么

复杂度 O(n)：每个字符进栈一次或做一次常数运算。长度 10⁵ 的表达式，几百微秒的事。

栈里存的是“中间结果”，不是字符。用 long long 是因为 7×8×9×… 这类连乘很快超出 int，本题数据小，但换个数据就爆。

竞赛用法

题型特征：给一串后缀/前缀记号，或要求“读到运算符就地结算”的表达式。看到“逆波兰”“后缀”“括号匹配”“最近的一个”，想到栈——它们要的都是“最近的那个”。

复杂度 O(n)：每个字符只被处理一次，栈操作 O(1)。空间 O(深度)，本题是中间结果的个数。

常见坑：先弹 a 后弹 b（减除写反）；'.' 当小数点；num 忘了清零；结果忘了 push 回栈；用 int 存中间结果。

模型：栈求后缀表达式O(n)坑：先弹的是右操作数坑：'.' 不是小数点
追问 · 落到代码上再想一遍
  1. 后缀表达式如果出现一元负号（比如 -3.4.+@），现在的代码会怎样？要支持它，需要在读数字时额外维护什么状态？
    想好了？点开核对思路与解析
    现在的代码会把开头的 '-' 当成二元减号，于是弹出两个操作数去算减——此时栈里可能只有 0 个或 1 个数，结果是空栈 top（RE）或答案乱掉。要支持一元负号，读数字时必须维护“我刚才是不是处在该读操作数的位置”：若上一个 token 是运算符或表达式开头，读到 '-' 就把它当负号（记一个符号位，等 num 攒完再 push 成负数），否则才是二元减号。正文 P1449 保证不出现一元负号，P1175 也明确约定不会出现负数，所以标准代码不用管。常见错路：用“栈空时 '-' 就是负号”来判——后缀表达式里 5.3.- 的 '-' 栈非空但确实是二元减号，规则不能只看栈空。
  2. 中缀表达式转后缀（调度场算法）需要两个栈：一个存数字、一个存运算符。为什么运算符栈的弹出规则是“栈顶优先级 ≥ 当前优先级就弹”，而不是“只看栈顶是否相同”？
    想好了？点开核对思路与解析
    因为弹出的依据是“左边这个运算符能不能先算”，而不是“两个运算符是不是同一个”。反例：2*3+4，见到 '+' 时栈顶是 '*'，若只看“是否相同”就不弹，后缀变成 2 3 4 + *，把 (2*3)+4 算成了 2*(3+4)。所以必须按优先级比：栈顶优先级 ≥ 当前优先级就弹；同级还要看结合性——左结合要弹，右结合不弹，正文 P1175 里那个 c != '^' 就是为乘方留的例外。常见错路：只写“大于”不写“等于”，同级左结合就算错：4/2/2 的后缀会变成 4 2 2 / /，答案从 1 变成 4。
同一个栈，换个问题：括号匹配

给一行字符串（可能含其他字符，忽略），判断其中 ()、[]、{} 三种括号是否配对且嵌套正确。

栈顶就是“最近的、还没被匹配的左括号”。遇到左括号压栈；遇到右括号，它必须和栈顶配对 ——因为括号的配对是后开的先闭，这正是 LIFO。扫描结束时栈必须为空，否则有左括号没闭上。

括号匹配：栈的三个出口
#include <bits/stdc++.h>
using namespace std;

bool check(const string &s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);                       // 左括号：记住它，等待配对
        } else if (c == ')' || c == ']' || c == '}') {
            if (st.empty()) return false;     // 右括号多了：没有左括号可以配
            char t = st.top();
            if ((c == ')' && t != '(') ||
                (c == ']' && t != '[') ||
                (c == '}' && t != '{')) return false;   // 类型不对，嵌套关系被破坏
            st.pop();                          // 配对成功，弹出这一个
        }
    }
    return st.empty();                        // 左括号多了时这里返回 false
}

int main() {
    string s;
    getline(cin, s);
    cout << (check(s) ? "YES" : "NO") << '\n';
    return 0;
}

三个返回点对应三种失败：①栈空却来了右括号（右括号多）；②类型不匹配（嵌套错）；③扫完栈非空（左括号多）。漏掉任何一个，都会把非法串判成合法。

只有一种括号时，其实一个计数器就够了：遇 ( 加一、遇 ) 减一，中途不能为负、最后必须为 0。这是同一个不变式的退化版本。一旦有第二种括号，计数器就不够了 —— 它记不住“该闭的是哪一种”，例如 ([)] 的计数完全合法，但嵌套是错的。

第三个变体：出栈顺序合法吗

按 1, 2, …, n 的顺序压栈，任意时刻都可以弹栈。给定一个出栈序列，问它是否合法。判断规则只有一条：按入栈顺序逐个压栈，每压一个就检查栈顶是不是出栈序列当前要的元素，是就一直弹；压完全部之后若栈为空，就合法。

为什么这一条规则够：出栈序列的第一个元素是 k，意味着 1…k 都已经压进来过（不压进去弹不出来），而 1…k−1 还压在 k 下面。此时“能弹就弹”不会损失任何选择 —— 早弹掉一个已经可以弹的元素，只是把它从栈顶移走，不改变剩下元素之间的压弹关系。

8 行判出栈序列（3 1 2 判 false，2 1 3 判 true）
// 入栈序列固定为 1..n，判断 out[1..n] 是不是合法的出栈序列
bool ok(int n, const vector<int> &out) {
    stack<int> st;
    int p = 1;                              // 下一个还没压进去的数
    for (int i = 1; i <= n; ++i) {
        // 栈顶不是 out[i]，就只能继续压，直到压出它或压完
        while (p <= n && (st.empty() || st.top() != out[i])) st.push(p++);
        if (st.empty() || st.top() != out[i]) return false;   // 压完了还是没有
        st.pop();                           // 栈顶正好是 out[i]，弹掉它
    }
    return true;
}
把递归搬到堆上：用栈模拟递归

第 21 节说过：递归靠系统栈，每层压入参数、局部变量和返回地址，深度到 10⁶ 就爆栈 RE。既然栈是显式的概念，就可以自己开一个栈放到堆上，把递归改写成循环 —— 求连通块这种“只关心访问过哪些点、不关心访问顺序”的问题，改完和递归完全等价。

显式栈版 flood fill
// 网格连通块：从 (sx, sy) 出发，把能走到的 '.' 全部标记
const int N = 1005;
int n, m;
char g[N][N];
bool vis[N][N];
int dx[4] = {-1, 1, 0, 0}, dy[4] = {0, 0, -1, 1};

void floodStack(int sx, int sy) {
    stack<pair<int, int>> st;
    st.push({sx, sy});
    vis[sx][sy] = true;               // ★ 入栈的同时就标记
    while (!st.empty()) {
        auto [x, y] = st.top();       // C++17 结构化绑定
        st.pop();
        for (int k = 0; k < 4; ++k) {
            int nx = x + dx[k], ny = y + dy[k];
            if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;
            if (g[nx][ny] != '.' || vis[nx][ny]) continue;
            vis[nx][ny] = true;       // ★ 这里也一样：push 之前标记
            st.push({nx, ny});
        }
    }
}

标记时机是唯一容易错的地方。递归版是“进函数就标记”，显式栈必须在 push 之前标记。如果等 pop 的时候才标记，同一个点会被它的多个邻居各压一次，在 10⁶ 的网格上栈会膨胀到千万级 → MLE 或 TLE。

两者的差别只在访问顺序：递归深度优先地一条路走到黑，显式栈的弹出顺序受入栈顺序影响，遍历次序不同但访问集合相同。所以连通性、可达性这类问题可以随意替换；要求“按字典序输出第一条路径”时不能随便换。

把队列当成一个圈：约瑟夫问题

n 个人围成圈编号 1…n，从 1 号开始报数，报到 m 的人出列，下一个人重新从 1 报，求出列顺序。

用队列，队头就是“当前该报数的人”。报 1 到 m−1 的人安全，把他从队头搬到队尾（相当于绕了一圈）；轮到第 m 个人就出队并输出。“搬队头到队尾”这一个动作，就把线性队列变成了环。

队列模拟约瑟夫环
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    queue<int> q;
    for (int i = 1; i <= n; ++i) q.push(i);

    while (!q.empty()) {
        // 前 m-1 个人安全：逐个搬到队尾，报数指针自然前移
        for (int k = 1; k < m; ++k) {
            q.push(q.front());
            q.pop();
        }
        cout << q.front() << ' ';      // 第 m 个人出列
        q.pop();
    }
    cout << '\n';
    return 0;
}

n = 10⁴、m = 10⁴ 时最坏要搬 10⁸ 次，勉强能过；n 到 10⁵ 就必须换算法。一个立刻见效的常数优化：当前还剩 s 个人时，搬 s 次就回到原点，所以只搬 (m - 1) % s 次。彻底的做法是把 m 从一开始就模掉，见下面的数学补给。

这一节的 8 个坑，每个都有具体症状

空栈上调用 top() 或 pop()：未定义行为，几乎必然 RE。后缀表达式里运算符比操作数多一个就会触发；括号匹配里 )abc 这种以右括号开头的串，不先判 empty() 就是 RE。

后缀表达式两个操作数顺序搞反（a - b 写成 b - a）：样例 3.5.2.-*7.+@ 会输出 −2 而不是 16，属于“样例就能查出来”的错；但很多人只测了全是 + 的数据 → WA。

运算符算完忘记 st.push(r)：下一个运算符弹出的是更早的数据或空栈 → WA 或 RE。

把 '.' 当成小数点，用 stod 读它：本题的 '.' 是数字结束符，3.5. 是“数 3、数 5”两个操作数，不是小数三点五 → WA。

括号匹配只用计数法（遇左加一、遇右减一）：([)] 会被判成合法 → WA。计数法只对单一类型括号成立。

括号匹配最后忘了 return st.empty()：(() 被判成合法 → WA。

约瑟夫轮转次数差一：for (int k = 1; k < m; ++k) 转 m−1 次是对的，写成 k <= m 会多转一个人，n = 5、m = 2 时第一个出列的人从 2 变成 3，整串输出全错 → WA。

显式栈 DFS 在 pop 之后才标记 visited：同一点被多个邻居重复压栈，10⁶ 网格直接 MLE / TLE。

数学补给 · 从 O(nm) 到 O(n)：约瑟夫的递推公式

队列模拟每次出列要搬 m 次，n 个人总共 O(nm)。n = m = 10⁵ 时是 10¹⁰ 次操作，必然超时。但这个环有一个只看“人数”的递推结构。

把编号改成 0 起：n 个人编号 0…n−1，报到 m 的人出列（下标是 (m−1) mod n）。出列后剩下 n−1 人，从原来编号 m mod n 的那个人开始重新报 1。把这 n−1 个人按新的起点重新编号 0…n−2，则新编号 k 对应原编号 (k + m) mod n。

于是得到递推：J(1) = 0，J(n) = (J(n−1) + m) mod n，其中 J 是胜者在新编号下的下标。答案就是 J(n) + 1（换回 1 起）。因为每次只在“少一个人”的同一个问题上加一步，复杂度 O(n)、空间 O(1)。

挑战题 · 表达式求值
洛谷 P1981普及/提高-去洛谷做这题 ↗

给定一个只含加法和乘法、不含括号的表达式，运算符按通常的优先级计算（先乘后加），求表达式的值，输出它除以 10000 的余数。

输入格式：一行字符串，为所求表达式。数字是非负整数、不含前导零，只出现 '+' 和 '*'。

输出格式：一行一个整数，表示表达式的值 mod 10000。

数据范围：表达式长度在 10⁵ 量级，单个数字可能有多位。

引导性提示（先只看这里）

从左到右直接算是不行的：1+1*3 从左结合会得 6，正确是 4。必须先算乘法。

整个表达式一定能唯一拆成若干个“加项”之和，每个加项是若干数字的连乘。想办法用一个栈保存“已经定型的加项”，再想乘法该作用在谁身上。

读到 '+' 就结算当前项、开一个新项；读到 '*' 就把当前的数直接乘到栈顶那一项上。结尾别忘了还有最后一个数没有结算。

想看思路了？点开完整思路

结构。任何只含 + 和 * 的表达式都能写成 a₁ + a₂ + … + a_k，其中每个 aᵢ 是若干数的连乘（先乘后加，加法是最后一步）。

用一个栈存加项。变量 num 表示正在读的数，op 表示上一个读到的运算符（初始设为 '+'，这样第一个数会以一个加项的形式入栈）。

读到运算符 c 时：先按上一个运算符 op 结算 num —— op 是 '+' 就把 num 作为新加项 push；op 是 '*' 就把它乘进栈顶那一项（乘法优先级高，它和栈顶属于同一个加项）。然后把 op 换成 c、num 清零。先结算、再换状态，顺序不能反。

结尾：字符串末尾没有运算符，循环里不会结算最后一个 num，必须再按 op 结算一次 ——漏掉这一步会少加最后一项。

取模。只要后四位，所以每次结算都 mod 10000；加法和乘法对取模是同余的，边算边模与最后取模结果相同，但避免了天文数字溢出。

正确性。栈顶始终是“正在构造的那个加项”，遇到 '+' 就封口并开新的，遇到 '*' 就往里乘。这正是“先乘后加”的栈化，等价于中缀转后缀后再求值。复杂度 O(长度)。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

const int MOD = 10000;

int main() {
    string s;
    getline(cin, s);

    stack<long long> st;      // 存已经定型的加项，栈顶 = 正在构造的那一项
    long long num = 0;        // 正在读的数（只保留后四位）
    char op = '+';            // 上一个运算符；初值 '+' 让第一个数以加项身份入栈

    for (size_t i = 0; i < s.size(); ++i) {
        char c = s[i];
        if (c >= '0' && c <= '9') {
            num = (num * 10 + (c - '0')) % MOD;   // 只保留后四位，等价于最后取模
        } else if (c == '+' || c == '*') {
            // 先按上一个运算符结算 num，再把 op 换成当前字符
            if (op == '+') st.push(num);          // 新的加项
            else st.top() = st.top() * num % MOD; // 上一个运算符是乘：并进栈顶那一项
            op = c;
            num = 0;
        }
        // 其他字符（空格、'\r'）直接忽略：不让它们被当成运算符
    }

    // 结尾的最后一个数还没有结算
    if (op == '+') st.push(num);
    else st.top() = st.top() * num % MOD;

    long long ans = 0;
    while (!st.empty()) {                     // 把所有加项加起来
        ans = (ans + st.top()) % MOD;
        st.pop();
    }
    cout << ans % MOD << '\n';
    return 0;
}
关键片段拆解
片段作用
char op = '+';虚拟一个“上一个运算符是加号”，于是第一个数会被当成一个新加项 push。少了这个初值，第一个数要么丢失、要么要单独写一段特判。
num = (num * 10 + (c - '0')) % MOD;多位数拼装 + 随时取模。因为只要后四位，(a × 10 + d) mod 10000 = ((a mod 10000) × 10 + d) mod 10000，所以可以边读边模，不必担心数字有几百位。
if (op == '+') st.push(num);上一个运算符是加号，说明 num 是一个独立的加项，压栈。
else st.top() = st.top() * num % MOD;上一个运算符是乘号，说明 num 属于栈顶那一项，直接乘进去。top() 返回引用，所以可以这样赋值；换成 long long t = st.top(); 再 push 就错了 ——那会多出一个加项。
op = c; num = 0;结算完才更新状态，顺序不能反。先清零再结算，num 就永远是 0。
else if (c == '+' || c == '*')只认这两个字符。用 else 兜底会把行末的 '\r' 或空格当成运算符，在某些评测环境下直接算错。
if (op == '+') st.push(num); // 循环之外字符串末尾没有运算符触发结算，最后一个 num 必须手工处理。这是本题最容易漏的一块，样例 1+1*3+4 漏了会输出 4 而不是 8。
ans = (ans + st.top()) % MOD;最后求和也要取模。栈里每项都小于 10000、项数最多 10⁵ 量级，总和不超过 10⁹，int 也勉强装得下；但写成 long long 并且边加边模是零成本的保险。
这题最容易错的地方
  • 从左到右直接算：1+1*3 得 6（正确 4），必须先乘后加。
  • 漏掉结尾的最后一个数（不结算栈外的 num）：1+1*3+4 输出 4 而不是 8 → WA。
  • 用 else 兜底处理运算符，把行末的 '\r' 或空格当成了运算符：轻则多出一次结算，重则 num 被错误压栈 → WA。
  • 把整条表达式的值全算出来最后才取模：数值迅速超出 long long，溢出成负数 → WA。
  • 遇到 '*' 时新开一项（push 而不是乘到栈顶）：2*3*4 会变成 2+3+4 = 9，正确是 24 → WA。

挑战 2 · 表达式的转换
洛谷 P1175普及/提高-去洛谷做这题 ↗

平常写的式子叫中缀表达式（运算符在两个操作数中间），括号用来指定运算顺序；把运算符挪到两个操作数后面的写法叫后缀表达式，它不需要括号，从左到右依次计算、用一个栈就能算完。

例如 8-(3+2*6)/5+4 的后缀形式是 8 3 2 6 * + 5 / - 4 +。

任务：读入一个中缀表达式，先输出它的后缀表达式，然后每执行一次运算就输出一行当前的后缀表达式，直到只剩一个数。也就是说：第 i+1 行比第 i 行少一个运算符和一个操作数，最后一行只有一个数字。

输入格式：一行字符串，只含 0~9、+ - * / ^ ( )，长度不超过 100，数字都是一位的，不会出现负数或形如 2*-3 的写法。

输出格式：若干行，每个数据之间用一个空格分隔。^ 是乘方，且从右往左结合（2^2^3 表示 2^(2^3)）；其余同级运算从左往右结合；/ 是整除（向下取整）。保证中间结果的绝对值不超过 2³¹。

样例
输入： 8-(3+2*6)/5+4 输出： 8 3 2 6 * + 5 / - 4 + 8 3 12 + 5 / - 4 + 8 15 5 / - 4 + 8 3 - 4 + 5 4 + 9
引导性提示（先只看这里）

分两步做：先把中缀转成后缀，再对后缀反复“找第一个运算符、把它和前面两个数换成结果”。

中缀转后缀用两个容器：一个放暂时还没轮到的运算符（栈），一个放输出。遇到运算符时，要把栈里“优先级不低于它”的都先弹出来——但乘方是右结合，这一条对它不成立。

左括号进栈后，遇到右括号就一直弹到左括号为止（左括号本身弹出但不输出）。表达式读完后，把栈里剩下的运算符全部弹出。

想看思路了？点开完整思路

第一步：中缀转后缀（调度场算法）。从左到右扫描字符：数字直接输出；左括号压栈；右括号就一路弹栈输出直到遇见左括号，再把左括号弹掉；运算符则先弹栈——只要栈顶不是左括号、且（栈顶优先级更高 或 优先级相同且当前不是乘方），就把栈顶弹出去输出，最后把自己压栈。扫描结束后把栈里剩下的全部弹出。

为什么“优先级 ≥ 就弹”。同级运算符左结合，左边的必须先算：4/2/2 要算成 (4/2)/2，所以看到第二个 / 时，栈里的第一个 / 必须立刻输出。

为什么乘方要特殊处理。乘方右结合，2^2^3 = 2^(2^3)，右边先算。所以遇到 ^ 时不能弹出栈里同级的 ^——这一行差别就是 c != '^' 这个条件。

第二步：逐步求值。后缀表达式里第一个运算符，它的两个操作数一定就是它前面的两个数。所以每次：找到第一个运算符 → 取它前面两个数算 → 用结果替换掉这三个 token → 打印整行。每做一次 token 数量减 2，做完 n 次只剩一个数。

为什么第一个运算符的两个操作数一定在前面。后缀表达式的定义就是“运算符紧跟在两个操作数之后”，而这个运算符能出现，说明它需要的两个操作数已经在左边凑齐了。所以从左往右找第一个运算符永远安全，不需要额外的栈。

两个数值细节。① ^ 用循环乘实现，指数不会大（中间结果受限）；② 整除要向下取整，而 C++ 的 / 是向零取整——负数时要减 1 修正。例如 (1-8)/2 = −7/2，向下取整是 −4，C++ 直接算得 −3。

复杂度。表达式长度 ≤ 100，运算符最多 50 个；每次求值 O(长度) 扫描 + O(长度) 打印，总代价 O(L²) ≤ 10⁴，可以忽略。

参考代码
#include <bits/stdc++.h>
using namespace std;

int prec(char c) {
    if (c == '^') return 3;
    if (c == '*' || c == '/') return 2;
    if (c == '+' || c == '-') return 1;
    return 0;
}

long long calc(long long a, long long b, char o) {
    if (o == '+') return a + b;
    if (o == '-') return a - b;
    if (o == '*') return a * b;
    if (o == '/') {                            // 向下取整，注意与 C++ 的向零取整不同
        long long q = a / b;
        if (a % b != 0 && ((a < 0) != (b < 0))) --q;
        return q;
    }
    long long r = 1;                           // 乘方：指数不会大，循环乘即可
    for (long long i = 0; i < b; ++i) r *= a;
    return r;
}

bool isOp(const string& t) {
    return t.size() == 1 && string("+-*/^").find(t[0]) != string::npos;
}

int main() {
    string s;
    cin >> s;

    // ① 中缀 → 后缀
    vector<string> post;
    vector<char> op;
    for (char c : s) {
        if (c >= '0' && c <= '9') post.push_back(string(1, c));
        else if (c == '(') op.push_back(c);
        else if (c == ')') {
            while (!op.empty() && op.back() != '(') { post.push_back(string(1, op.back())); op.pop_back(); }
            op.pop_back();                                   // 丢掉左括号
        } else {
            // 同级左结合要弹；乘方右结合不弹
            while (!op.empty() && op.back() != '(' &&
                   (prec(op.back()) > prec(c) || (prec(op.back()) == prec(c) && c != '^'))) {
                post.push_back(string(1, op.back())); op.pop_back();
            }
            op.push_back(c);
        }
    }
    while (!op.empty()) { post.push_back(string(1, op.back())); op.pop_back(); }

    auto print = [&]() {
        for (size_t i = 0; i < post.size(); ++i)
            cout << post[i] << (i + 1 == post.size() ? '\n' : ' ');
    };
    print();                                                  // 第一行：完整的后缀表达式

    // ② 逐步求值
    while (post.size() > 1) {
        for (size_t i = 0; i < post.size(); ++i) {
            if (!isOp(post[i])) continue;                     // 找第一个运算符
            long long b = stoll(post[i - 1]), a = stoll(post[i - 2]);
            long long r = calc(a, b, post[i][0]);
            post.erase(post.begin() + i - 2, post.begin() + i + 1);   // 删掉两个数和一个运算符
            post.insert(post.begin() + i - 2, to_string(r));          // 原地换成结果
            break;                                            // 一行只算一次
        }
        print();
    }
    return 0;
}
关键片段拆解
片段作用
int prec(char c)优先级表：乘方 3、乘除 2、加减 1、左括号 0（它要留在栈里当分隔符）。
while (!op.empty() && op.back() != '(' && (prec(op.back()) > prec(c) || ...))弹栈条件。括号是墙，不能弹穿；优先级更高的一定先算；同级的要看结合性。
... && c != '^'乘方右结合：遇到 ^ 时不弹栈里同级的 ^。少了这个条件，2^2^3 会被算成 (2^2)^3。
op.pop_back(); // 丢掉左括号右括号的处理：一路弹到左括号，然后把左括号也弹掉（它不输出）。
post.push_back(string(1, c));数字直接进输出。本题数字都是一位，不需要拼多位数；若要支持多位数，就在这里连续读数。
if (a % b != 0 && ((a < 0) != (b < 0))) --q;把 C++ 的向零取整改成向下取整。只差负数且不整除的情况，但题面明确要求向下取整。
post.erase(...); post.insert(..., to_string(r));三换一：删掉两个操作数与一个运算符，在同样的位置插入结果。注意插入位置是 i-2，删完之后该位置正好是原第一个操作数的位置。
break;一行只做一次运算。少了它，一行里会连着算好几步，输出行数就不对了。
这题最容易错的地方
  • 乘方当普通同级运算符处理（去掉 c != '^'）：2^2^3 的后缀变成 2 2 ^ 3 ^，结果差很多。
  • 右括号处理时忘了弹掉左括号：栈里残留 '('，最后的输出里混进括号字符。
  • 用 a / b 直接当整除：负数且不整除时与“向下取整”差 1。
  • 每轮求值忘了 break：一行里连算多次，输出行数与题目要求的“每步一行”不符。
  • 读入用 getline 却没处理行末换行：表达式末尾可能多出一个 '\n' 字符，被当成非法符号。
