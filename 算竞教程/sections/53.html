53 · 倍增与 ST 表

把“走 2^k 步”预先存下来，任意步数就能拆成二进制去拼。本节用这一招做 O(1) 的静态区间最值（ST 表），以及 O(log n) 的树上 LCA，并给出 lg 数组、st 递推、up 跳表三张必须背下来的表。
提高预计 65 分钟ST 表倍增LCA

倍增只有一个动作：先把“走 2k 步之后到哪”全部算出来，再把任意步数拆成二进制去拼。正整数的二进制分解唯一，所以 105 步最多拆成 17 段，每段长度都是 2 的幂。这一节用它做两件事：O(1) 的静态区间最值（ST 表）、O(log n) 的树上 LCA。

ST 表 = 预处理所有长度是 2 的幂的区间 + 每次查询用两段这样的区间拼出目标区间。建表 O(n log n)，查询 O(1)，代价是只能用于 max、min、gcd 这类“重复算不影响结果”的运算。

问题

ST 表的查询要在 O(1) 里完成：已知询问区间长度 len，必须先知道“不超过 len 的最大 2 的幂”是哪一档，也就是 k = ⌊log2 len⌋。

麻烦的是这个 k 每次询问都要算一次，m 到 2×106 就是 2×106 次。能不能让“长度 → 层号”这一步也是一次数组访问？

1第一步：看清层号就是二进制位数减一

k = ⌊log2 i⌋ 的含义是：最大的非负整数 k，使 2k ≤ i。换成二进制看，它就是 i 的二进制位数减 1：7 = 1112 是 3 位，⌊log2 7⌋ = 2。

这也解释了为什么长度翻倍层号才加一：i 与 ⌊i/2⌋ 的二进制位数最多差 1，而 ⌊log2 i⌋ = ⌊log2⌊i/2⌋⌋ + 1 对 i ≥ 2 恒成立（乘 2 = 指数加 1，奇数末位被取整吃掉）。

验证 / 关键

验证：把这句恒等式写成递推，就是 lg[i] = lg[i >> 1] + 1——因为 ⌊i/2⌋ < i，从小到大循环时右式一定已经算好。

2第二步：为什么不用 log2

直接写 (int)log2(len) 有两个问题。一是慢：浮点函数一次调用几十纳秒，2×106 次询问就是上百毫秒，正好卡在时限边上。

二是不准：log2 是浮点运算，对 2 的幂不保证返回恰好整数（可能算出 2.9999999），转 int 后少 1，直接查错层，答案偏小。查表既快又准。

验证 / 关键

验证：GCC 内建 __lg(x) 直接返回 ⌊log2 x⌋（x ≥ 1），确实准；但它不是标准 C++（MSVC 没有），且实测在密集查询里略慢于查表，竞赛里一般还是预计算。

3第三步：四行预处理

初始化 lg[1] = 0（20 = 1 ≤ 1，而 21 = 2 > 1）；lg[0] 用不到，全局数组默认 0 正好无害。循环必须从 i = 2 开始，从 1 开始会把 lg[1] 改写成 1。

签名
lg[i] = lg[i >> 1] + 1;          // 预处理，O(n)
int k = lg[r - l + 1];           // 查询时 O(1) 取出

查询里用的长度是 r − l + 1，不是 r − l。差一个 1 会让 k 取小一层，结果只覆盖半个区间（WA，答案偏小）。

推导m 很大时，区间最值还能不能只查一次表覆盖：ST 表 / st[k][i] 递推 / 两段查询需求 → 尝试 → 验证 → 定理
问题

给 n 个数、m 次区间最大值询问（n ≤ 105、m ≤ 2×106）。每次扫一遍 [l, r] 是 O(n)，总共 2×1011 次比较，按每秒 109 次也要 200 秒。

要 O(1)，答案就必须“提前算好、查询时只做常数次查表”。于是问题变成：预处理哪些区间，才既装得下、又够用？

1第一步：把所有区间砍到只剩 2 的幂

所有区间有 n(n+1)/2 个，n = 105 时约 5×109 个，装不下。于是只留长度是 2 的幂的区间：每一层 n 个，一共 17 层，1.7×106 个数，只占 6.8 MB。少算的代价，用“两段拼接”补回来。

这就是倍增：先把“长度 2k 的所有区间”全部算出来，任意长度都能用两段这样的区间盖住。

验证 / 关键

验证：n = 105 时 ⌊log2 n⌋ = 16，所以层号 0…16 共 17 层，空间 17n 个 int。

2第二步：定义 st[k][i] 与一行递推

st[k][i] 是“以 i 为左端点、长度恰好 2k”的区间的答案：k 叫层，i 叫起点，两者一起唯一确定一个区间。第 0 层长度 20 = 1，就是原数组——建表时可以直接把读入写进 st[0][i]，省掉一个 a[] 数组。

长度 2k 的区间从中间劈成两个长度 2k−1 的半段：[i, i+2k−1−1] 与 [i+2k−1, i+2k−1]，正好是 st[k−1][i] 与 st[k−1][i + 2k−1]。所以一行 max 就能合成。

签名
st[k][i] = 区间 [i, i + 2^k - 1] 的答案
st[0][i] = a[i];
st[k][i] = max(st[k-1][i], st[k-1][i + (1 << (k-1))]);
ans = max(st[k][l], st[k][r - (1 << k) + 1]);   // k = lg[r-l+1]

示例：建表 + 查询
// n = 1e5，K = 17（2^16 = 65536 <= 1e5 < 2^17）
int st[17][100005], lg2v[100005];

lg2v[1] = 0;
for (int i = 2; i <= n; ++i) lg2v[i] = lg2v[i >> 1] + 1;

for (int k = 1; (1 << k) <= n; ++k)                       // 只要 2^k <= n 就有合法区间
    for (int i = 1; i + (1 << k) - 1 <= n; ++i)           // 右端点不能越过 n
        st[k][i] = max(st[k-1][i], st[k-1][i + (1 << (k-1))]);

int query(int l, int r) {
    int k = lg2v[r - l + 1];
    return max(st[k][l], st[k][r - (1 << k) + 1]);
}
验证 / 关键

验证：并成两段只用了 max，所以合并只要求结合律 + 幂等——同一元素算两次不影响结果。max、min、gcd、按位或、按位与都满足；求和、乘积不满足，套进来就错。

3第三步：查询为什么只查两段

取 k = ⌊log2 len⌋。左段从 l 起（覆盖前 2k 个），右段以 r 结尾（起点 r − 2k + 1）。两段的端点都落在 [l, r] 里，所以都在区间内。

为什么两段一定盖满：由 k 的定义有 2k ≤ len < 2k+1。若两段之间有缝，则 len > 2k+1，矛盾。所以要么重叠、要么恰好相接。

验证 / 关键

验证：重叠部分被算了两次，但 max 对同一个数算两次没有影响——这就是“幂等”两个字的用处。换成求和，重叠部分会被加两遍，答案必偏大。

4第四步：空间与写法

st[K][n+1] 个 int，约 6.8 MB。第一维放层、第二维放起点：查询时同一个 k 连查两个起点，行内地址连续，缓存命中率更高；反过来写成 st[i][k] 会在两个不相邻的行之间来回跳。

内层循环的右端点判断 i + (1 << k) - 1 <= n 不能省：省掉就是越界写，会踩坏后面的数组，症状是 RE 或者只有大数据才错。

验证 / 关键

验证：把 max 换成 + 立刻 WA——查询时两段重叠，重叠部分会被加两次。这就是“只支持幂等运算”的实际含义。

追问 · 把这一步想透
  1. 如果询问换成“区间 gcd”或“区间按位或”，ST 表还能不能原样用？区间和为什么不行？请从“一个元素最多被算几次”这个角度回答。
    想好了？点开核对思路与解析
    gcd 和按位或都能原样用，一行递推只换合并运算：__gcd 或 |。它们都满足结合律，并且幂等——gcd(x,x)=x、x|x=x，所以重叠部分算两次不改变结果。从“一个元素最多被算几次”看：两段长度都是 2k，合计盖住 2k+1 个位置，而 len ∈ [2k, 2k+1)，于是重叠 2k+1 − len 个元素，最多能到 2k 个（len 恰好是 2k 时两段完全重合）。区间和不行：a + a = 2a ≠ a，重叠部分被加两遍，答案恒偏大（例题里 [1,6] 会算成 16 而真实和是 27）。常见错路是把“结合律”当成充分条件——加法也有结合律，但它不幂等；另一条是 gcd 表忘了第 0 层，全局数组的 0 参加 gcd 反而无害（gcd(x,0)=x），但换成 min 表就会把 0 卷进去，这类“初值恰好无害”的巧合不能当成通用规律。
  2. 要用 ST 表查“区间内出现次数最多的数”或者“区间第 k 小”，行不行？不行的根本原因是缺少哪条性质？
    想好了？点开核对思路与解析
    都不行，缺的是可合并性：每段的答案能不能用 O(1) 大小的信息表示。众数不满足——左段的众数和右段的众数拼不出整体的众数，右段里一个出现 3 次的数可能反超左段的 5 次，你根本不知道它出现了几次；第 k 小同理，两段的“第 k 小”给不出整体的第 k 小，除非知道完整分布。注意这里缺的不是幂等性，而是“信息量”：ST 表能成立的前提是“一段的答案就是一个数、合并只要 O(1)”，而众数和第 k 小的答案携带的信息量是 O(值域)。常见错路是用“左段众数 vs 右段众数，谁出现次数多取谁”——反例：左段 1 1 1、右段 2 2，整体众数是 1 而不是 2 也不是 1 对 2 的直接比较；另一条是把“可合并”误当成“满足结合律”，其实还要 O(1) 合并。这类题的正解是分块 / 莫队 / 值域线段树，不是 ST 表。
  3. 如果数组会被单点修改、同时要区间最大值，ST 表还能保持 O(1) 查询吗？为什么？这时候应该换成什么结构？
    想好了？点开核对思路与解析
    不能。ST 表是“把所有 2k 段提前算好”，改一个位置会让所有包含它的段失效：长度 2k 的段里，包含位置 p 的起点有 2k 个（从 p−2k+1 到 p，截断后更少），全部层加起来约 2n 个，所以单点修改要 O(n) 重建。这时换成线段树：单点改 O(log n)、区间查 O(log n)，n = 105、m = 2×106 时约 3.4×107 次操作，勉强能过。注意不能换树状数组——max 没有逆运算，max(1..r) − max(1..l−1) 什么也还原不出（第 46 节已经算过这笔账）。常见错路是“只更新 st[0][p] 就行”，上层全部陈旧，查询命中旧区间时答案随机；另一条是以为可以像树状数组那样“改一个点只动 log n 个格子”——ST 表没有“管辖关系”，它存的是互不相同的固定长度段。

这两块拼起来就是 ST 表模板。下面这道题把 m 堆到 2×106，正是逼你把单次查询压到 O(1) 的经典设置——线段树 O(log n) 会多出一个 17 的常数，在 3.4×107 次操作上就是过与不过的差别。

1读入：第 0 层直接就是原数组

st[0][i] 表示长度 20 = 1 的区间，也就是 a[i] 本身。所以读入时直接写进第 0 层，省掉 a[] 数组，也省掉一次复制。

读入
const int N = 100005;
const int K = 17;                       // 2^16 = 65536 <= 1e5 < 2^17，层数最多到 16

int st[K][N];                           // st[k][i]：区间 [i, i + 2^k - 1] 的最大值
int lg2v[N];                            // lg2v[len] = floor(log2(len))

int main() {
    int n, m;
    scanf("%d %d", &n, &m);             // m 到 2e6，用 scanf/printf 比 cin/cout 稳

    for (int i = 1; i <= n; ++i) scanf("%d", &st[0][i]);   // 第 0 层直接读入，省掉 a[]
为什么

K = 17 是层数上限：n ≤ 105 时 ⌊log2 n⌋ = 16，需要 0…16 共 17 层。少开一层就会写越界。

层放第一维、起点放第二维：查询时同一个 k 连查两个起点，行内地址连续；写成 st[i][k] 会在两个不相邻的行之间来回跳。

询问最多 2×106 次、整数最多 4×106 个，scanf 直读比 cin 少一层类型解析。

2lg 表：长度换算成层号

这一段把 len 映射到 ⌊log2 len⌋，查询时一次数组访问就够了。

lg 表
    lg2v[1] = 0;                                            // 长度 1 只需要第 0 层
    for (int i = 2; i <= n; ++i) lg2v[i] = lg2v[i >> 1] + 1;
为什么

lg2v[1] = 0; 这个初值必须写，循环是从 2 开始的。

lg2v[i] = lg2v[i >> 1] + 1：i 的层号 = ⌊i/2⌋ 的层号 + 1。从小到大推，右式一定已算好。

别换成 (int)log2(len)：浮点慢，而且对 2 的幂可能算出 2.9999999，转 int 后少 1，直接查错层。

3建表：长度 2^k 的区间由两个 2^(k-1) 合成

外层枚举层 k，内层枚举起点 i。右端点不能越过 n，所以内层上界是 n − 2k + 1。

建表
    // 递推：长度 2^k 的区间 = 左右两个长度 2^(k-1) 的区间
    for (int k = 1; (1 << k) <= n; ++k)
        for (int i = 1; i + (1 << k) - 1 <= n; ++i)         // 右端点不越界
            st[k][i] = max(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
为什么

(1 << k) <= n：只要 2k ≤ n，这一层就存在合法区间。n = 105 时建到 k = 16 为止。

i + (1 << k) - 1 <= n 不能省。缺这个条件的症状是越界写，小数据正常、大数据 RE。

st[k-1][i + (1 << (k-1))] 的右半段左端点 = i + 2k−1，这是整个递推唯一容易写错的下标。

4询问：两段长 2^k 的区间拼出 [l, r]

k = lg2v[r − l + 1]，左段以 l 开头、右段以 r 结尾，两段必然盖满整个区间。

为什么

长度换层号只花一次数组访问，O(1)。写成 r − l 会取小一层，只覆盖大半个区间，答案偏小。

st[k][r - (1 << k) + 1] 的 +1 不能丢：丢了整段左移一格，答案可能取到区间外的数。

走一遍 l = 2、r = 8：len = 7，k = ⌊log2 7⌋ = 2。左段 st[2][2] 覆盖 [2,5] 值是 7，右段起点 8 − 4 + 1 = 5，st[2][5] 覆盖 [5,8] 值是 6，答案 max(7, 6) = 7。

2×106 行输出用 "\n" 而不是 endl：endl 每次都刷新缓冲区，实测慢 3~10 倍。

完整代码
#include <bits/stdc++.h>
using namespace std;

const int N = 100005;
const int K = 17;                       // 2^16 = 65536 <= 1e5 < 2^17，层数最多到 16

int st[K][N];                           // st[k][i]：区间 [i, i + 2^k - 1] 的最大值
int lg2v[N];                            // lg2v[len] = floor(log2(len))

int main() {
    int n, m;
    scanf("%d %d", &n, &m);             // m 到 2e6，用 scanf/printf 比 cin/cout 稳

    for (int i = 1; i <= n; ++i) scanf("%d", &st[0][i]);   // 第 0 层直接读入，省掉 a[]

    lg2v[1] = 0;                                            // 长度 1 只需要第 0 层
    for (int i = 2; i <= n; ++i) lg2v[i] = lg2v[i >> 1] + 1;

    // 递推：长度 2^k 的区间 = 左右两个长度 2^(k-1) 的区间
    for (int k = 1; (1 << k) <= n; ++k)
        for (int i = 1; i + (1 << k) - 1 <= n; ++i)         // 右端点不越界
            st[k][i] = max(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);

    while (m--) {
        int l, r;
        scanf("%d %d", &l, &r);
        int k = lg2v[r - l + 1];                            // 2^k <= 长度 < 2^(k+1)
        // 左段以 l 开头，右段以 r 结尾；两段必然覆盖整个区间
        printf("%d\n", max(st[k][l], st[k][r - (1 << k) + 1]));
    }
    return 0;
}
为什么

总复杂度：建表 O(n log n) ≈ 1.7×106 次合并，查询 O(1)，总 O(n log n + m)。

线段树同样能做这题，但单次 O(log n) 会多出一个 17 的常数，在 3.4×107 次操作上就是过与不过的差别——这正是出题人把 m 堆到 2×106 的原因。

问题

树上求两点最近公共祖先（LCA）。朴素做法：从 u 一路往上走，把经过的点打标记；再从 v 往上走，第一次踩到标记的点就是 LCA。单次 O(深度)。

一条链状的树上，深度就是 5×105，5×105 次询问直接退化成 2.5×1011 次操作。能不能把“往上走”也像 ST 表那样预先算好、按 2 的幂跳？

1第一步：把“跳 2^k 步到哪”存下来

定义 up[k][v] 为“从 v 往上走 2k 步到达的点”：k = 0 是父亲，k = 1 是爷爷，k = 2 是往上第 4 个点。这样“走 d 步”就能拆成 d 的二进制位，最多 O(log n) 次查表。

递推依据：走 2k 步 = 先走 2k−1 步、再走 2k−1 步，所以两次 up[k−1] 串起来就是 up[k]，一行搞定。

验证 / 关键

验证：up[k][v] = up[k-1][up[k-1][v]] 要求内层那个点的整行已经算好，所以计算顺序必须是“父亲先、儿子后”。

2第二步：一行递推，和建表的顺序

把根的父亲设成 0，并让 up[*][0] = 0、dep[0] = 0。往上跳出树根时自动停在 0，全程不用特判——这个 0 号哨兵省掉了所有边界讨论。

计算顺序必须保证 up[k−1][v] 的整行算完才能算 up[k][v]。两种做法：BFS（父亲先出队），或在 DFS 里“进儿子之前”把当前点整行算完。

// 建表（跟 BFS 一起做，避免链状树爆栈）
void bfs(int root) {
    queue<int> q; q.push(root); dep[root] = 1;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int k = 1; k < K; ++k) up[k][u] = up[k-1][up[k-1][u]];
        for (int e = head[u]; e; e = nxt[e]) {
            int v = to[e];
            if (v == up[0][u]) continue;      // 跳过父亲
            up[0][v] = u; dep[v] = dep[u] + 1;
            q.push(v);
        }
    }
}

验证：路径 3 → 5 → 8 → 12 → 1 → 0 上，up[0][3] = 5、up[1][3] = 8、up[2][3] = 1，每一步都是把上一行“再跳一次”，跳的步数翻倍。

3第三步：用二进制拆开深度差

d = dep[u] − dep[v] 是个整数，按二进制位从低到高扫：第 k 位是 1 就 u = up[k][u]。总共只有 O(log n) 跳，而且跳的步数加起来恰好是 d——正整数的二进制分解唯一。

深度对齐后，若 u == v，说明 v 本来就是 u 的祖先，直接返回。否则从 k = K−1 往 0 试：若 up[k][u] ≠ up[k][v]（跳完还不同），才跳；循环结束时 u、v 是 LCA 的两个不同儿子，答案是 up[0][u]。

验证 / 关键

验证：为什么第二步必须从大到小——每次跳“跳了还不同”的最大步长，保证一直停在 LCA 下方；从小到大很可能第一步就跨过 LCA，再也回不来。

倍增求 LCA（输入格式同 P3379：n、m、根，n−1 条边，m 次询问）
#include <bits/stdc++.h>
using namespace std;

const int N = 500005;                  // P3379 的量级：5×10^5 个点
const int K = 20;                      // 2^18 = 262144 <= 5e5 < 2^19，层数到 18，开 20 留余量

int head[N], nxt[N << 1], to[N << 1], ecnt;   // 链式前向星（第 41 节）
int up[K][N], dep[N];

void addEdge(int u, int v) {
    to[++ecnt] = v; nxt[ecnt] = head[u]; head[u] = ecnt;
}

void bfs(int root) {
    queue<int> q;
    q.push(root);
    dep[root] = 1;                     // 根的深度设 1，于是 dep[0] = 0 天然是哨兵
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int k = 1; k < K; ++k)    // 整行一次算完：2^k = 2^(k-1) + 2^(k-1)
            up[k][u] = up[k - 1][up[k - 1][u]];
        for (int e = head[u]; e; e = nxt[e]) {
            int v = to[e];
            if (v == up[0][u]) continue;         // 无向边存了两遍，跳过父亲
            up[0][v] = u;                        // 儿子的一级祖先就是 u
            dep[v] = dep[u] + 1;
            q.push(v);
        }
    }
}

int lca(int u, int v) {
    if (dep[u] < dep[v]) swap(u, v);   // 让 u 更深
    int d = dep[u] - dep[v];
    for (int k = 0; k < K; ++k)        // 深度差按二进制拆开，逐位往上跳
        if (d >> k & 1) u = up[k][u];
    if (u == v) return u;              // v 本来就是 u 的祖先
    for (int k = K - 1; k >= 0; --k)   // 从大到小试：跳完还不同就跳
        if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }
    return up[0][u];                   // 此时 u、v 是 LCA 的两个儿子
}

int main() {
    int n, m, s;
    scanf("%d %d %d", &n, &m, &s);
    for (int i = 1; i < n; ++i) {
        int u, v; scanf("%d %d", &u, &v);
        addEdge(u, v); addEdge(v, u);
    }
    bfs(s);
    while (m--) {
        int a, b; scanf("%d %d", &a, &b);
        printf("%d\n", lca(a, b));
    }
    return 0;
}

这一节的 8 种典型错法（附症状）

WA，答案偏小。—— 查询写成 st[k][l] 与 st[k][l + 2^k - 1]，右对齐的那一段没取，区间右半边根本没参与。第二个下标必须是 r - (1 << k) + 1。

WA，答案偏大。—— 把 max 换成 + 或 ×。两段在 len 不是 2 的幂时必然重叠，重叠部分被算了两次。

RE，或只有大数据错。—— 建表少了 i + (1 << k) - 1 <= n，st[k][i] 写到数组外面，踩坏 lg 数组或别的变量。

RE，段错误。—— K 开小一层。n = 105 时要用到第 16 层，写 K = 16 就越界；n = 5×105 的 LCA 要用到第 18 层，写 K = 18 同样越界。

TLE。—— m = 2×106 还开着 cin/cout 同步、每行用 endl。总量 4×106 次读写，光刷新缓冲区就能吃掉 1 秒以上。

WA，全负区间输出 0。—— 把答案初值写成 0 再 max 累加。区间里全是负数时 0 比任何元素都大。正确写法是直接对两个真实元素取 max，不设初值。

RE（爆栈）。—— 倍增 LCA 用递归 DFS 建表，遇到链状树（深度 5×105）栈溢出。改用 BFS。

WA，LCA 差一层。—— 第二步的循环写成 for (int k = 0; k < K; ++k)。从小到大跳会越过 LCA，返回的是 LCA 的某个祖先。

数学补给 · log2、二进制分解与区间覆盖

⌊log2 n⌋ 就是 n 的二进制位数减 1。这个等式说明：倍增的层数，和整数的二进制长度是同一件事。估 K 的时候不用背表，把 n 写成二进制数位数即可。

  • n = 8 = 10002，4 位，⌊log2 n⌋ = 3，需要 0…3 共 4 层。
  • n = 105 = 110000110101000002，17 位，⌊log2 n⌋ = 16，K 至少 17。
  • n = 5×105：218 = 262144 ≤ 5×105 < 524288 = 219，故 ⌊log2 n⌋ = 18，K 至少 19。

两段必覆盖的严格论证：设 len = r − l + 1，k = ⌊log2 len⌋，于是 2k ≤ len < 2k+1。左段 L = [l, l+2k−1]，右段 R = [r−2k+1, r]。两段的端点都落在 [l, r] 里，所以 L、R ⊆ [l, r]。若 L ∪ R 有缺口，则 l+2k−1 < r−2k+1，即 len = r−l+1 > 2k+1，与 k 的定义矛盾。所以 L ∪ R = [l, r]，两段至多重叠 2k+1 − len 个元素。

幂等性为什么是必要条件：把运算记作 ⊕。要允许“同一元素被算两次”，必须 a ⊕ a = a（幂等）；要能“劈半合并”，必须有结合律。max、min、gcd、lcm、按位或、按位与都满足这两条；加法、乘法、异或只满足结合律不满足幂等，所以 sum 的区间查询必须用前缀和（第 18 节）或线段树（第 47 节）。

空间账：ST 表存 (⌊log2 n⌋ + 1) × n 个 int。n = 105 时 17 × 105 × 4 B = 6.8 MB；lg 数组 0.4 MB。总计 7 MB 出头，洛谷常见的 125 MB 限制下非常宽裕；但 n 涨到 106 就要 20 层、80 MB，这时候要么改用分块（第 57 节），要么改用线段树把空间压回 O(n)。

LCA 的运算量：预处理 n log n ≈ 5×105 × 19 = 9.5×106 次赋值；单次询问第一步最多 19 次跳、第二步最多 20 次判断，合计不到 40 次比较，与树有多大完全无关。这就是“把 O(n) 压成 O(log n)”的实际含义：把和规模成正比的部分全部搬到预处理里。

挑战题 · Balanced Lineup G
洛谷 P2880普及/提高-去洛谷做这题 ↗

农夫约翰有 N 头奶牛，每天按固定顺序站成一排，第 i 头奶牛身高为 hi。有 Q 次询问，每次给出一个区间 [A, B]，求这段区间里最高牛与最矮牛的身高差。

输入：第一行两个整数 N、Q（1 ≤ N ≤ 5×104，1 ≤ Q ≤ 2×105）。接下来 N 行，每行一个整数 hi（1 ≤ hi ≤ 106）。接下来 Q 行，每行两个整数 A、B（1 ≤ A ≤ B ≤ N）。

输出：Q 行，每行一个整数，表示 hA 到 hB 中的最大值减最小值。

引导性提示（先只看这里）

题目只要区间最值，没有任何修改操作——这类题的第一反应应该是 ST 表，而不是线段树。

一次询问要两个最值。同一套 st 数组能不能同时存最大和最小？如果不能，要开几个二维数组？

答案就是“区间最大值 − 区间最小值”。注意：局部变量的初值、数组的默认值会不会影响 min 的结果？

想看思路了？点开完整思路

把 ST 表模板复制两份：mx[k][i] 存区间 [i, i+2^k−1] 的最大值，mn[k][i] 存最小值，两者的建表方式完全一样，只是合并时一个用 max、一个用 min。

第 0 层就是原数组，mx[0][i] = mn[0][i] = h[i]。这一步是 min 表唯一能拿到真实值的地方，不能指望全局数组的 0 初值——hi ≥ 1，用 0 初始化会让所有 min 都变成 0。

每次询问按同样的 k 取出两段：hi = max(mx[k][A], mx[k][B−2^k+1])，lo = min(mn[k][A], mn[k][B−2^k+1])，输出 hi − lo。两段重叠对 max 和 min 都没有影响，所以同一个 k 可以直接用于两张表。

复杂度：预处理 O(N log N) ≈ 5×104 × 16 = 8×105，Q 次询问每次 4 次取最值，总计不到 106 次运算。

#include <bits/stdc++.h>
using namespace std;

const int N = 50005;
const int K = 17;                       // 2^15 = 32768 <= 5e4 < 65536，层数最多到 15

int mx[K][N], mn[K][N];
int lg2v[N];

int main() {
    int n, q;
    scanf("%d %d", &n, &q);

    lg2v[1] = 0;
    for (int i = 2; i <= n; ++i) lg2v[i] = lg2v[i >> 1] + 1;

    for (int i = 1; i <= n; ++i) {
        int x; scanf("%d", &x);
        mx[0][i] = mn[0][i] = x;        // 长度 1 的区间，最大最小都是自己
    }

    for (int k = 1; (1 << k) <= n; ++k) {
        for (int i = 1; i + (1 << k) - 1 <= n; ++i) {
            int j = i + (1 << (k - 1));             // 右半段的左端点
            mx[k][i] = max(mx[k - 1][i], mx[k - 1][j]);
            mn[k][i] = min(mn[k - 1][i], mn[k - 1][j]);
        }
    }

    while (q--) {
        int a, b;
        scanf("%d %d", &a, &b);
        int k = lg2v[b - a + 1];
        int hi = max(mx[k][a], mx[k][b - (1 << k) + 1]);
        int lo = min(mn[k][a], mn[k][b - (1 << k) + 1]);
        printf("%d\n", hi - lo);         // 身高差，不是和
    }
    return 0;
}

片段作用
int mx[K][N], mn[K][N];两张表结构完全相同，只有合并运算不同。一次建表顺手把两个都填好，比建两遍各扫一次省一半时间。

(1 << k) <= n层数上限由 n 决定：215 = 32768 ≤ 5×104，所以最高建到 k = 15。
int j = i + (1 << (k - 1));右半段起点。写成 i + (1 << k) 会跳过半个区间，写成 i + (1 << k) - 1 会少覆盖一个元素。

b - (1 << k) + 1右段的起点。与模板一致，+1 不能丢。
hi - lo题目要的是差。写成 lo - hi 会输出负数；写成 hi + lo 是另一道题。
这题最容易错的地方
  • mn 表没有写第 0 层：全局数组的 0 被卷进 min，n 以内的最小值全变 0，输出恒等于最大值，样例就能看出来。
  • K 写成 15：n 到 5×104 时需要第 15 层，数组只有 0…14，越界写 → RE 或答案随机。
  • 两张表用了不同的 k：mx 取 lg2v[len]、mn 取 lg2v[len−1]，覆盖区间不同，差值没有意义。
  • 把 hi − lo 写成 lo − hi 或 hi + lo：前者三个询问全是负数，后者全错，样例一眼可见，别靠样例蒙。

挑战 2 · 货车运输
洛谷 P1967提高-/提高去洛谷做这题 ↗

A 国有 n 座城市（编号 1..n）和 m 条双向道路，每条道路对车辆有限重 z。有 q 辆货车，第 i 辆要从城市 x 运货到城市 y。问：在「路径上每条边的限重都不小于车载重」的前提下，这辆车最多能运多重的货？也就是求 x 到 y 所有路径中，路径上最小边权的最大值。

输入：第一行两个整数 n、m（1 ≤ n < 104，1 ≤ m < 5×104）；接下来 m 行，每行三个整数 x、y、z（0 ≤ z ≤ 105），表示 x 与 y 之间有一条限重 z 的道路，两点之间可能有多条道路。接下来一行一个整数 q（1 ≤ q < 3×104），再往下 q 行，每行两个整数 x、y，表示一次运输。

输出：q 行，每行一个整数，表示该次运输的最大载重；若 x 到 y 不连通，输出 −1。

样例：4 座城市、(1,2,7)、(2,3,5)、(1,3,3) 三条路。1 到 3 可以走 1-2-3（瓶颈 5）或直接走 1-3（瓶颈 3），取大的 5；4 号城市孤立，任何询问含 4 都输出 −1。

样例
输入： 4 3 1 2 7 2 3 5 1 3 3 3 1 3 3 1 1 4 输出： 5 5 -1
引导性提示（先只看这里）

q 只有 3×104，但 m 有 5×104。先想一个更基本的问题：图里那么多条边，哪些边是永远不可能成为最优路径的一部分的？

如果一条边的权值比另一条「同样连通这两堆点」的边小，它就没用。把所有「把两部分连通的最宽的那条边」留下来，剩下的结构是什么？

换成一片森林之后，一次询问变成「树上两点路径上的最小边权」。链上求这个、还要 q 次，本节的正课里正好有一张表能让单次询问降到 log 级。

想看思路了？点开完整思路

暴力：每次询问跑一次「最大瓶颈路」的 Dijkstra 变体，O(m log n) 一次，q = 3×104 时约 1.5×109，TLE。

关键结论：这样的边只可能来自最大生成森林。Kruskal 从大到小加边时，两点在「只保留权值 ≥ X 的边」下连通，当且仅当它们在最大生成森林里也连通。所以最大瓶颈路的瓶颈值 = 生成森林路径上的最小边权。

第一步：边按权值降序排，用并查集合并，能合并就把这条边加进森林。O(m log m)，最多留下 n−1 条边。

第二步：对森林的每一棵树 BFS，填 dep[v]、up[0][v]（父亲）、mn[0][v]（到父亲这条边的权值）。图可能不连通，所以要对每个没访问过的点都起一次 BFS。

第三步：倍增。up[k][v] 是 v 的 2k 级祖先，mn[k][v] 是从 v 往上走 2k 步经过的最小边权，递推 mn[k][v] = min(mn[k−1][v], mn[k−1][up[k−1][v]])：跳 2k 步 = 先跳 2k−1 再跳 2k−1。

询问：先把深的点跳到同一深度（沿途取 min）；两点重合就结束；否则从高位到低位同时往上跳，只要跳完祖先不同就跳并取 min，最后停在 LCA 的两个儿子上，再补上各自到 LCA 的那条边。

不连通：并查集根不同，直接 −1。复杂度 O(m log m + (n + q) log n)。

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 10005, MAXM = 50005, LOG = 15, INF = 1e9;
struct Edge { int u, v, w; } e[MAXM];

int head[MAXN], nxt[MAXN << 1], to[MAXN << 1], wt[MAXN << 1], ecnt = 0;
void addEdge(int u, int v, int w) {
    to[++ecnt] = v; wt[ecnt] = w; nxt[ecnt] = head[u]; head[u] = ecnt;
}

int fa[MAXN];
int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

int up[LOG][MAXN], mn[LOG][MAXN], dep[MAXN];
bool vis[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= m; ++i) cin >> e[i].u >> e[i].v >> e[i].w;

    // 1) Kruskal 建最大生成森林：只有这些边可能出现在最优路径上
    for (int i = 1; i <= n; ++i) fa[i] = i;
    sort(e + 1, e + m + 1, [](const Edge& a, const Edge& b) { return a.w > b.w; });
    for (int i = 1; i <= m; ++i) {
        int ru = find(e[i].u), rv = find(e[i].v);
        if (ru == rv) continue;
        fa[ru] = rv;
        addEdge(e[i].u, e[i].v, e[i].w);
        addEdge(e[i].v, e[i].u, e[i].w);
    }

    // 2) 每棵树 BFS 一遍，填第 0 层：父亲与到父亲的边权
    queue<int> q;
    for (int r = 1; r <= n; ++r) {
        if (vis[r]) continue;
        vis[r] = true; dep[r] = 0; up[0][r] = r; mn[0][r] = INF;
        q.push(r);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int i = head[u]; i; i = nxt[i]) {
                int v = to[i];
                if (vis[v]) continue;
                vis[v] = true; dep[v] = dep[u] + 1;
                up[0][v] = u; mn[0][v] = wt[i];
                q.push(v);
            }
        }
    }

    // 3) 倍增表：2^k 级祖先 + 这一段路径上的最小边权
    for (int k = 1; k < LOG; ++k)
        for (int v = 1; v <= n; ++v) {
            up[k][v] = up[k - 1][up[k - 1][v]];
            mn[k][v] = min(mn[k - 1][v], mn[k - 1][up[k - 1][v]]);
        }

    int Q;
    cin >> Q;
    while (Q--) {
        int u, v;
        cin >> u >> v;
        if (find(u) != find(v)) { cout << -1 << '\n'; continue; }
        int ans = INF;
        if (dep[u] < dep[v]) swap(u, v);
        int diff = dep[u] - dep[v];
        for (int k = 0; k < LOG; ++k)
            if (diff >> k & 1) { ans = min(ans, mn[k][u]); u = up[k][u]; }
        if (u == v) { cout << ans << '\n'; continue; }
        for (int k = LOG - 1; k >= 0; --k)
            if (up[k][u] != up[k][v]) {
                ans = min(ans, min(mn[k][u], mn[k][v]));
                u = up[k][u]; v = up[k][v];
            }
        ans = min(ans, min(mn[0][u], mn[0][v]));   // 补最后一条边，跳到 LCA
        cout << ans << '\n';
    }
    return 0;
}
