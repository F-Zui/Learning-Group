51 · 字符串哈希与 Trie

把字符串压成整数、把前缀压成路径：多项式哈希与 ull 自然溢出解决整串比较，前缀哈希 + 幂表解决子串比较，Trie 解决前缀计数，01-Trie 解决最大异或。附带一套防冲突的规矩：基数大于字符集、模数用双哈希、溢出必须无符号。
提高-预计 65 分钟哈希Trie冲突

字符串题只有两个基本动作：比较和查找。直接比较两个长 L 的串要 L 次字符比较；一万个长 1000 的串两两比较是 5×1010 次，必然超时。这一节给两种把动作变便宜的工具：哈希把整个串压成一个整数，比较退化成一次整数比较；Trie 把公共前缀折叠成一条路径，插入和查询都只走 L 步。Trie 的一个变体把整数按二进制位建树，就能回答“和 x 异或最大的数是谁”。

哈希回答“这两个串一样吗”，Trie 回答“这个前缀出现过几次”，01-Trie 回答“和 x 异或最大的数是谁”。三个问题，一条共同的思路：把串或数变成可以随手比较、随手走几步的东西。

问题

要把 106 长的串压成一个整数指纹，标准做法是逐字符累加 h = h * B + c。可这样 h 会长到 1311000000 这个量级，没有任何类型装得下，必须先取模。

取模却是有代价的：% 编译出来是一条除法指令，10~40 个时钟周期，而乘法和加法各只要 1 个。106 次哈希、每次一次取模，整个程序能差出 3 倍时间。能不能有一种取模，代价是零？

1第一步：把模数换成 2 的幂

取模的定义是“减去若干个 M，直到落进 [0, M)”。当 M 是 2 的幂时，剩下的恰好是二进制的最低若干位，更高的位全部丢弃——而丢弃高位在硬件里什么指令都不用：寄存器只有 64 位，溢出的部分本来就被扔掉了。

于是模数取 264 时，乘法溢出的高位直接消失，% 一次都不用写。C++ 里唯一保证“溢出按 264 取模”的类型是无符号整数，所以用 unsigned long long。

验证 / 关键

验证：这不是“碰巧能用”，是标准写明的行为——无符号整数的运算结果等于数学结果模 2N。所以 h * 131 溢出后的值确定等于 (h * 131) mod 264，和手写取模的结果逐位相同。

2第二步：把类型和写法固定下来

签名与写法：typedef unsigned long long ull;，累加式 h = h * B + (ull)c;——先乘再加，等价于把串看成 B 进制数。

ull h = 0;

要点含义 / 格式
取值范围0 ~ 264−1 = 18446744073709551615，20 位十进制。
自然溢出无符号整数的运算按 264 取模：溢出的高位被硬件直接丢弃，不用写 %。
写法h = h * B + (ull)c；先把 char 转成无符号再加，字符值 ≥ 128 时才不会被符号扩展成负数。
为什么快取模 % 是一条除法指令，10~40 个时钟周期；乘法和丢弃高位只要 1 个。106 次哈希能差 3 倍时间。
怎么观察它cout 直接输出十进制；ull x = 0; --x; 得到 18446744073709551615。
示例：观察回绕，再算一个指纹
#include <bits/stdc++.h>
using namespace std;
typedef unsigned long long ull;

int main() {
    ull x = 0;
    --x;                              // 0 - 1 回绕到 2^64 - 1
    cout << x << "\n";                // 18446744073709551615

    string s = "abc";
    ull h = 0;
    for (char c : s) h = h * 131 + (ull)c;   // 等价于 (h * 131 + c) % 2^64
    cout << h << "\n";

    // 同一个函数对 "abc" 永远给出同一个数，这就是“指纹”
    return 0;
}
验证 / 关键

跑一遍就知道它不是“差不多”：ull x = 0; --x; 打印出来正是 18446744073709551615；而同一个串每次算出的 h 完全相同——这就是“指纹”能代替串的原因。

3第三步：换成 long long 会怎样

把类型换成 long long，h * 131 一旦越过 9.2×1018 就是有符号溢出 = 未定义行为（UB）。编译器可以假设它不会发生，在 -O2 下把比较整段优化掉，于是同一份代码本地对、交上去错。

两个必须记住的溢出细节

减法也回绕：ull a = 1, b = 2; a - b 得到 1.8×1019，不是 −1。哈希里大量用到“减法回绕”，这正是子串哈希公式能成立的原因。

把 ull 换成 long long，h * 131 一旦超过 9.2×1018 就是 UB，g++ 可能直接按“不溢出”优化，结果无法预测。

验证 / 关键

验证：ull a = 1, b = 2; 时 a - b 回绕到 264−1，恰好等于 (1 − 2) mod 264。后面子串哈希里的 h[r] − h[l−1]·Br−l+1 正是靠这个回绕，才不用写 +M 再取模。

这条规则的另一面同样重要：类型必须无符号。换成 long long 后溢出变成 UB，算法的正确性就从“按 264 取模”变成了“编译器说了算”。

推导一个 64 位指纹，够不够用覆盖：双哈希 / 模数与基数选择 / pair 比较需求 → 尝试 → 验证 → 定理
问题

上一张卡把每个串压成一个 64 位整数。可是压缩一定伴随碰撞：不同的串可能落到同一个数上。随机数据下这个概率小到可以不算，但赛场上的数据不是随机的——它是出题人挑的。

真正的问题因此不是“概率多大”，而是“别人能不能针对我的哈希造出一组数据”。洛谷 P3370 的“拓展阅读”里整排 Hash Killer 就是现成的答案。

1第一步：先算清随机数据下有多稳

生日问题：把 n 个串丢进 264 个桶，期望冲突对数 ≈ n(n−1)/(2·264)。n = 105 时代进去得到 2.7×10−10——一万次评测都碰不上一次。

所以单哈希在“数据随机”的前提下是安全的。问题在于，竞赛数据恰恰可以不随机。

验证 / 关键

这一步只解决了一半问题：它证明的是“随机输入下安全”，而不是“任意输入下安全”。

2第二步：看清攻击是怎么构造的

模 264 不是质数，奇数基数 B 的高次幂在模 264 下很快退化。按 Thue–Morse 串取位（第 i 位由 popcount(i) 的奇偶决定），能构造出两个等长且哈希完全相同的串。这不是运气，是构造——所以叫 anti-hash 数据。

结论：固定基数 + 模 264 的单哈希，存在确定的反例，出题人放一组 Hash Killer 就必挂。

验证 / 关键

验证：这解释了为什么“本地对拍一万组随机数据全过”仍然可能 WA——随机数据根本覆盖不到这种输入。

3第三步：加一道独立的锁

做法是：对同一个串，用两组 (模数, 基数) 各算一个值，组成 pair 一起比较。签名是 pair<long long, long long> H(const string& s);，参数如下表。

参数 / 选择含义与格式
为什么一个不够模 264 且基数固定时，存在确定的构造性攻击（Thue–Morse 串）。洛谷 P3370 的“拓展阅读”里整排 Hash Killer 就是干这个的。
做法对同一个串，用两组 (模数, 基数) 各算一个值，组成 pair 一起比较。
模数怎么选两个互不相同的大质数：109+7 与 109+9，或 998244353 与 109+7。
基数怎么选大于字符集（62），常用质数 131、13331。两套的基数也要不同，否则等于一个哈希算两遍。
比较方式pair 自带 operator< 和 operator==（先比 first，再比 second），可以直接 sort、unique、放 set。
代价常数 ×2，代码多三行。字符串题里这是最便宜的保险。
示例：双哈希 + sort/unique
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

const ll M1 = 1000000007, M2 = 1000000009;    // 两个不同的大质数
const ll B1 = 131,        B2 = 13331;        // 两套基数也要不同

pair<ll, ll> H(const string& s) {
    ll h1 = 0, h2 = 0;
    for (unsigned char c : s) {              // 转无符号，防止负字符
        h1 = (h1 * B1 + c) % M1;
        h2 = (h2 * B2 + c) % M2;
    }
    return {h1, h2};
}

int main() {
    vector<pair<ll, ll>> v = {H("abc"), H("abc"), H("abd")};
    sort(v.begin(), v.end());
    cout << unique(v.begin(), v.end()) - v.begin() << "\n";   // 2
    return 0;
}
验证 / 关键

验证：两套哈希同时撞上的概率近似为两个概率之积。两个 109 量级的模数给出 1018 的组合空间，而且两套的基数不同，Thue–Morse 那种构造只对其中一个模数有效。

4第四步：把剩下的坑填掉

两条经验：模数取 109 量级时，乘积约 1018，随机数据下 n = 105 个串的期望冲突数约 5×10−9。另外，别用 998244353 与 109+7 配同一个基数——基数相同会让两个哈希产生关联，安全性下降。

更狠的一招是运行时随机基数：B = chrono::steady_clock::now().time_since_epoch().count() | 1，出题人无法预先构造。

验证 / 关键

验证：这两个数来自同一个生日公式，换成 1018 的桶后 n = 105 的期望是 5×10−9，比单哈希的 2.7×10−10 只大一点，但攻击面完全不同——一个防概率，一个防构造。

推导前缀能不能只存一份覆盖：Trie / ch 数组 / pass 与 ended需求 → 尝试 → 验证 → 定理
问题

哈希能判“两个串是否相等”，却回答不了另一个问题：有多少个串以 s 为前缀。拿哈希硬做只能把 N 个串全扫一遍，每次比较 O(|s|)，N = 104、询问 105 时约 109 次字符比较。

要的是：一次查询的开销只跟 s 的长度有关，跟集合里有多少串完全无关。而字符串集合里，前缀本来就是重复的——abc 与 abd 的前两个字符一模一样。怎么把这份重复折叠掉？

1第一步：把公共前缀折成一条路径

把每个前缀看成一个点，字符看成边：从空串出发，读一个字符走一条边，走到哪个点就代表读到了哪个前缀。这样 abc 与 abd 共用 a、ab 两个点，只在第三个字符处分叉——插入 abd 只多花 1 个节点，不是 3 个。

于是“以 s 为前缀的串有多少个”变成“s 走到的那个点的子树里有多少个词”：查询退化成走 |s| 步。

验证 / 关键

验证：节点总数 = 所有串的总长度 + 1（每个字符最多新增一个节点），与字符集大小无关。这正是 Trie 比“把所有前缀塞进 set”省的地方——后者每个前缀都要独立存一份。

2第二步：用数组把这棵树摆平

树有两种存法：指针和数组。竞赛里一律用数组：下标就是节点编号，ch[u][c] 就是一条边。四个量的含义见下表——其中根是 0，且 0 也表示“这条边不存在”，所以编号从 1 开始分配。

签名
int ch[MAXN][26];
int pass[MAXN], ended[MAXN], tot = 0;
量含义 / 格式
ch[u][c]节点 u 沿字符 c 这条边走到的节点编号。0 表示这条边不存在；根固定是 0，所以节点编号从 1 开始分配。
tot已分配的节点数，也是最新节点的编号。新建节点就是 ch[u][x] = ++tot。
pass[u]有多少个串经过节点 u，也就是“以该节点对应的字符串为前缀的串数”。
ended[u]有多少个串恰好结束在 u。用来区分“是某个串的前缀”和“自己就是一个串”。
空间怎么估节点数 = 所有串的总长度 + 1。ch 占 MAXN×26×4 字节：总长 105 约 10 MB，总长 106 约 104 MB。
为什么不用指针new 一次约 100 字节开销还慢。数组连续分配，缓存友好，清空只要 memset(ch, 0, sizeof ch)，多测方便。
示例：insert 与 node
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;                 // 节点上限 = 总字符数 + 1
int ch[MAXN][26], pass[MAXN], ended[MAXN], tot = 0;

void insert(const string& s) {
    int u = 0;                           // 从根出发
    for (char c : s) {
        int x = c - 'a';
        if (!ch[u][x]) ch[u][x] = ++tot; // 边不存在才新建，这是“共享前缀”的全部秘密
        u = ch[u][x];
        ++pass[u];
    }
    ++ended[u];                          // 有一个串在这里结束
}

int node(const string& s) {              // 返回路径终点；-1 表示走不通
    int u = 0;
    for (char c : s) {
        int x = c - 'a';
        if (!ch[u][x]) return -1;
        u = ch[u][x];
    }
    return u;
}
// node(s) != -1 → 以 s 为前缀的串有 pass[node(s)] 个
// ended[node(s)] > 0 → s 本身是一个插入过的串
验证 / 关键

验证：0 号既当根又当“不存在的边”，所以判定必须是 if (!ch[u][x])，而不是 == -1——全局数组默认 0，拿 -1 判永远不成立，会把 0 当合法子节点原地打转。

3第三步：把两件事分开记

插入时沿路 ++pass[u]，走完整个串再 ++ended[u]。前者回答“有几个串以它为前缀”，后者回答“它自己是不是一个词”。

查询 node(s) 返回路径终点，走不通返回 −1。于是：node(s) != -1 → 以 s 为前缀的串有 pass[node(s)] 个；ended[node(s)] > 0 → s 本身是一个插入过的串。

验证 / 关键

验证：ab 是 abc 的前缀，但 ab 自己可能没被插入——这时 ended[ab] = 0，pass[ab] 却可以是 1。两个量缺一不可。

    哈希答不出“有多少个串以 s 为前缀”。它能 O(1) 判出“某一个串是不是以 s 开头”（比该串的前缀哈希），但要数个数就得把 N 个串全扫一遍，代价 O(N) 次比较——Trie 是 O(|s|)，与 N 完全无关。根子在于哈希把每个串独立压成一个数：共享 999 个字符前缀的两个串，那 999 个字符的贡献混在同一个 64 位数里，取不出结构；Trie 的 pass[u] 天生就是“经过这个节点的串数”，因为公共前缀在树上是同一批节点。常见错路是“把所有前缀都哈希一遍存进哈希表”——那确实能数，但每个串的每个前缀都要算一次，总共 ΣMi 个条目，空间和 Trie 同量级而常数大得多，还丢掉了字典序，等于用哈希表把 Trie 重写了一遍。
推导和 x 异或最大的数，是哪一个覆盖：01-Trie / 最大异或 / 位宽需求 → 尝试 → 验证 → 定理
问题

给一堆整数，问“与 x 异或最大的数是谁”。暴力做法：把每个数和 x 异或一遍取最大，一次 O(n)；n = 105、询问 105 次就是 1010 次运算。

异或没有大小上的单调性，也不能像前缀和那样直接相减。要跳过逐个枚举，必须找到一个能逐位定下来的结构。

1第一步：看清异或的位权

异或的第 b 位是 1，就给答案贡献 2b；而所有更低的位全取 1 也只有 2b−1。所以高位赢一次，就赢过所有低位之和。

这句话把“求最大值”拆成了 31 个互不干扰的小决定：从第 30 位往下，每一位都尽量让它异或出 1。

验证 / 关键

验证：2b > Σi<b 2i = 2b−1。所以“先保高位”的贪心与全局最优一致——高位定了 1，低位怎么取都追不回来。

2第二步：把 31 个位摆成一棵树

把每个数按二进制位从高到低插进 Trie：根往下第 b 层存第 b 位，一条根到叶的路径就是一个 31 位二进制数。每条边只有 0、1 两种，于是 ch[u][2]；节点数上限 = 数值个数 × 31。

签名
void insert(int x);
int query(int x);      // 返回与 x 异或能取到的最大值
量含义 / 格式
节点含义从根往下第 b 层存的是 x 的第 b 位（b 从 30 降到 0）。一条根到叶的路径就是一个 31 位二进制数。
ch[u][2]只有 0、1 两条边。节点数上限 = 数值个数 × 31。
query 的贪心从高位到低位，尽量走与当前位相反的边；走不通才走相同的边。
为什么贪心对第 b 位是 1 贡献 2b，而低 b 位全取 1 也只有 2b−1。高位赢一次就赢过所有低位，所以从高到低逐位定。
位宽值 < 231 时从第 30 位开始；值 < 109 < 230 时从第 29 位开始也够。多枚举一位不会错，只多一层。
示例：insert 与 query
const int MAXN = 100005;
int ch[MAXN * 31][2], tot = 0;

void insert(int x) {
    int u = 0;
    for (int b = 30; b >= 0; --b) {
        int c = (x >> b) & 1;
        if (!ch[u][c]) ch[u][c] = ++tot;
        u = ch[u][c];
    }
}

int query(int x) {                       // 与 x 异或的最大值
    int u = 0, r = 0;
    for (int b = 30; b >= 0; --b) {
        int c = (x >> b) & 1;
        if (ch[u][c ^ 1]) {              // 反边存在：这一位异或出 1
            r |= 1 << b;
            u = ch[u][c ^ 1];
        } else {                         // 只能将就，这一位异或出 0
            u = ch[u][c];
        }
    }
    return r;
}
验证 / 关键

验证：ch[u][c ^ 1] 存在，就说明有一条边能让这一位异或出 1。因为这一位比所有低位加起来还重，只要它存在就必须走——这就是“贪心不会错”的全部依据。

3第三步：把代价算清楚

插入和查询都是 31 步固定开销，与数值大小、集合大小都无关。节点数上限 31n，n = 105 时 ch 占 3.1×106×2×4 ≈ 25 MB，刚好放得下。

答案 r 用 int 就够：两个 < 231 的数异或仍 < 231。若把值域改到 1018，位宽要改成 62，r 必须换 long long。

验证 / 关键

验证：1 << b 在 b ≤ 30 时不会溢出 int；但值域一旦到 231，就必须写 1LL << b，否则有符号左移溢出。

它的正确性来自一句话：第 b 位的 2b 大于所有低位之和 2b−1，所以高位优先的局部最优就是全局最优。

  1. 01-Trie 求“最大异或对”是 O(31n)。如果改问“异或值 ≥ k 的数对有多少个”，怎么在树上做？提示：走边时同时统计子树里的数值个数。
    想好了？点开核对思路与解析
    在 01-Trie 上边统计：每个节点记 cnt[u] = 子树里的数值个数（插入时沿路 ++）。对每个 x 从第 30 位往下走，同时看 k 的当前位：k 这一位是 0，就往“异或出 1”的反边走，并把那条边整棵子树的 cnt 一次性加进答案（这一位已经比 k 大，低位随便），然后自己走“异或出 0”的边继续；k 这一位是 1，就只能走反边（走同边立刻小于 k，整枝舍弃），继续往下。走到 b < 0 说明正好等于 k，也算一对。每个 x 走 31 步、每步 O(1)，总 O(31n)；这样每个数对会被数两遍，最后除以 2（或者先插入全部、再统一查询）。常见错路是只在“等于 k”时判一次，把“高位已经严格大于”的整片子树漏掉，答案偏小；另一条是对每个 x 遍历整棵子树，直接退化成 O(n²)。

给定 N 个字符串（第 i 个长度为 Mi），字符串内只含数字与大小写字母，大小写敏感。请求出这 N 个字符串中共有多少个不同的字符串。

输入：第一行一个整数 N；接下来 N 行，每行一个字符串。输出：一行一个整数，表示不同字符串的个数。数据范围：N ≤ 10000，Mmax ≤ 1500（总字符数可达 1.5×107）。

样例
输入：
5
abc
aaaa
abc
abcc
12345
输出：
4
1读进来一个串，就当场压成一个整数

题目只问“有几个不同的串”，不问“谁和谁相同”。于是每个串一进来就压成一个 64 位指纹，把“字符串去重”降级成“整数去重”。

逐个压成指纹
    vector<ull> h;
    h.reserve(n);

    string s;
    for (int i = 0; i < n; ++i) {
        cin >> s;
        ull x = 0;
        // 每个串独立从 0 开始累；乘 131 后的溢出位被丢弃，正是 mod 2^64
        for (char c : s) x = x * B + (ull)c;
        h.push_back(x);
    }
为什么

朴素做法：读进 N 个串两两比较是否相同。N = 104 时约 5×107 对，每对最多比 1500 个字符，最坏 7×1010 次字符比较，TLE。

x 必须写在读串的循环内部：写在循环外，所有串的指纹会首尾相连，变成一个数。

每个串只留一个 8 字节整数，vector 的长度是 N，与串长无关。

2两行定生死：类型与基数

整段程序里最容易写错的是这两行——一个是类型，一个是基数。

类型与基数
typedef unsigned long long ull;

const ull B = 131;          // 基数：大于字符集(62)，且是质数
为什么

基数必须大于字符集大小。取 B = 1 时 ab 与 ba 哈希都是 a+b，重排必撞；取 B = 2 时同样会混叠。质数让各次幂分布更散。

不取模时这是 B 进制表示，B 大于字符集则不同串必得不同整数——这就是“指纹”能代表串的原因；取模才把信息丢掉，于是产生冲突。

ull 的无符号溢出等价于按 264 取模，是标准写明了的；换成 long long 就是 UB，同一份代码可能本地过、评测机挂。

3排序 + unique：把“有几个不同”数出来

N 个指纹排个序，再 unique 一遍，答案就出来了。

排序与去重
    sort(h.begin(), h.end());              // 整数排序，比字符串比较便宜得多
    // unique 把不重复的元素挪到前面，返回新结尾；减去 begin 即个数
    cout << (int)(unique(h.begin(), h.end()) - h.begin()) << "\n";
为什么

sort 比较的是 8 字节整数，O(N log N)；直接 sort 字符串时每次比较是 O(串长)，代价差一个量级。

unique 只消除相邻重复，所以必须先排序，否则答案偏大。

unique 返回去重后区间的新结尾，减去 begin 就是个数；迭代器相减得到 ptrdiff_t，转 int 再输出。

const ull B = 131;          // 基数：大于字符集(62)，且是质数

竞赛用法

题型特征：看到“N 个串里有多少个不同”“判断两个长串的某一段是否相同”“O(1) 比较任意子串”，第一反应就是多项式哈希；再看到“允许重叠 / 只问数量”，就接排序去重。

复杂度：O(Σ|s| + N log N) 时间，O(N) 额外空间；瓶颈在读入，不在哈希。

  • 基数必须大于字符集，且双哈希的两套基数要不同。
  • 溢出必须用 unsigned long long；long long 溢出是 UB，-O2 下行为不可预测。
  • unique 之前必须 sort，它只消除相邻重复。
  • 单哈希在固定基数 + 模 264 下能被 Thue–Morse 构造攻击，上双哈希或随机基数。
  • N ≤ 104 时排序足够快，不需要 set（set 每次比较是 O(串长)）。

    标准写法不会退化成 O(nm)：主串预处理 O(n)、幂表 O(n)，枚举 n−m+1 个起点各 O(1)，合计 O(n+m)。退化只发生在三种写法上：① 不用前缀哈希，每个起点重新扫 m 个字符算一份哈希，正好 O(nm)；② 哈希相等后再逐字符 verify 防冲突，遇到全 a 这类数据每次都要比 m 个字符，最坏 O(nm)；③ 求“最长公共前缀”时对每个起点线性往后比。必须用 KMP 的场合有两类：要 next 数组本身（最小循环节、所有 border、前缀出现次数、AC 自动机），哈希给不出失配位置，只能对每个长度二分或枚举，退成 O(n log n) 甚至 O(n²)；要求确定性正确，题目专门放了 anti-hash 数据（固定基数 + 模 264 的 Thue–Morse 构造），这时哈希不是慢，是错。

    想好了？点开核对思路与解析
    关键认识：改一个字符会让后面所有 h[i] 都变，所以不能直接在 h 上做单点改。换成固定指数写法：令 t[j] = cj·Bn−j，那么 Σ(j=l..r) t[j] = Bn−r·H(l..r)，区间哈希 = 两次前缀和相减再乘 Bn−r 的逆元。于是单点改字符只改 t[p] 一项，正好落在树状数组上：改一次 O(log n)，查一段 O(log n)（模意义下要预存逆元表，或者用线段树合并哈希，免掉逆元）。常见错路是“在 h[i] 上做单点修改”——修改的真实效果是给后缀每个 h[i] 加上 Δ·Bi−p，这个增量随下标指数变化，普通树状数组的区间加根本表达不了，硬做出来的区间和全是错的。

需求

哈希真正的威力不在“整串比较”，而在任意子串比较。给 s = abcab、B = 131，要回答两次询问：s[2..4] 与 s[1..3] 是否相同？s[1..2] 与 s[4..5] 是否相同？

答案是 No 和 Yes——bca ≠ abc，而两段 ab 相等。暴力逐字符比是 O(L)；要先算前缀哈希，再用一次减法把任意一段“抠”出来。

1先把前缀哈希与幂表打出来

设 h[i] 是前 i 个字符的哈希，则 h[r] = h[l−1]·Br−l+1 + H(l..r)：前 r 个字符 = 前 l−1 个字符整体左移 r−l+1 位，再接上第 l..r 个字符。移项就得到子串公式。

建表
pw[0] = 1;
for (int i = 1; i <= n; ++i) {
    h[i]  = h[i - 1] * B + (ull)s[i];   // 前 i 个字符的指纹

代码片段含义与理由
cin >> (s + 1);把字符串读到 s[1] 起始的位置，这样下标 1 就是第一个字符。括号不能省：cin >> s + 1 会被解析成 (cin >> s) + 1。

为什么

幂表不是可选项：每次询问现算 Br−l+1 要 O(log n)，105 次询问白扔一个 log。

2子串怎么一次减法抠出来

把 h[r] 里“前 l−1 个字符贡献的那部分”减掉，剩下的就是 H(l..r)。关键在于减之前要把 h[l−1] 乘上 Br−l+1，把它的位权抬到和 h[r] 一致——不然减的是“两个不同长度的前缀”之差，毫无意义。

子串指纹
auto sub = [&](int l, int r) -> ull {
    return h[r] - h[l - 1] * pw[r - l + 1];
};
代码片段含义与理由
h[r]前 r 个字符的指纹，等于 H(1..l−1) 左移 r−l+1 位后加上 H(l..r)。
h[l - 1] * pw[r - l + 1]把前缀 1..l−1 移到与 h[r] 相同的位权上，才能相减。
h[r] - h[l - 1] * pw[...]减法在 ull 里回绕，正好等价于模 264 的减法，不需要 +M 再取模。

为什么

减法是模 264 的减法：真值可能为负，但在无符号整数里回绕出来的结果就是正确值，不需要 +M 再取模。

3完整程序
子串哈希：O(1) 判断两段是否相同
#include <bits/stdc++.h>
using namespace std;
typedef unsigned long long ull;

const ull B = 131;
const int MAXN = 1000005;
char s[MAXN];
ull h[MAXN], pw[MAXN];          // h：前缀哈希；pw：B 的幂

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> (s + 1);             // 1 基下标，s[1] 是第一个字符
    int n = strlen(s + 1);

    pw[0] = 1;
    for (int i = 1; i <= n; ++i) {
        h[i]  = h[i - 1] * B + (ull)s[i];   // 前 i 个字符的指纹
        pw[i] = pw[i - 1] * B;              // B^i
    }

    // 子串 [l, r]（1 ≤ l ≤ r ≤ n）的指纹
    auto sub = [&](int l, int r) -> ull {
        return h[r] - h[l - 1] * pw[r - l + 1];
    };

    int q;
    cin >> q;
    while (q--) {
        int l1, r1, l2, r2;
        cin >> l1 >> r1 >> l2 >> r2;
        cout << (sub(l1, r1) == sub(l2, r2) ? "Yes\n" : "No\n");
    }
    return 0;
}
为什么

读入用 1 基下标，sub(l,r) 与定义一一对应；输出 Yes/No 与手算结果一致。

Trie 把公共前缀压成一条公共路径，走到某个节点，子树里有多少个词就是这个前缀的出现次数。

样例

abd

1建点：没有这条边才新建

插入时沿路径往下走，边已存在就直接复用——这就是“前缀只存一份”的全部秘密。abc 和 abd 因此只多花 1 个节点，不是 3 个。

建点
int ch[MAXN][26], pass[MAXN], ended[MAXN], tot = 0;

void insert(const string& s) {
    int u = 0;                         // 根
    for (char c : s) {
        int x = c - 'a';
        if (!ch[u][x]) ch[u][x] = ++tot;   // 没有这条边才新建
        u = ch[u][x];
    }
}
代码片段含义与理由
if (!ch[u][x]) ch[u][x] = ++tot;共享前缀的全部秘密。边已存在就直接复用，不新建节点。
u = ch[u][x];沿着边走一步。循环结束时 u 就是整个串对应的节点。
为什么

节点总数等于所有串的总字符数，不是串的个数——MAXN 按串数开会 RE。

2计数：pass 与 ended 是两回事

每走一步就给目标节点的 pass 加 1，统计的是“经过该节点的串数”；整个串走完再给 ended 加 1，表示“有串正好在这里结束”。

两个计数器

        ++pass[u];                     // 经过 u 的串多了一个
    }
    ++ended[u];                        // 有一个串在这里结束
代码片段含义与理由
++pass[u];放在“走完这一步”之后，统计的是“经过该节点的串数”。若放在走之前，统计的就变成了父节点的信息。
++ended[u];区分“是前缀”和“是单词”。ab 是 abc 的前缀，但 ab 自己可能没被插入——这时 ended[ab] = 0。
为什么

这两个计数器的位置差一行，含义完全不同：pass 在循环内累加，ended 在循环外累加一次。

3查询：走不通就是 0

查询不需要重新建树，只要沿边走；中途没边可走，说明这个前缀从没被插入过。

查询

    int u = 0;
    for (char c : s) {
        int x = c - 'a';

为什么

复杂度与集合规模无关，只与串长有关——这正是 Trie 值钱的地方。

竞赛用法

看到“前缀出现次数”“按字典序第 k 小”“补全提示”就用 Trie；它把公共前缀折叠成一条路径，插入与查询都只走 len 步。

模型：字典树O(len) 插入查询坑：MAXN 按总长开
算法落地用法 · 01-Trie：每一位尽量走反边，求最大异或覆盖：01-Trie / 最大异或对 / 按位贪心
需求

给定 3 10 25 三个数，问“哪两个数异或最大”。两两配对：3⊕10 = 9、3⊕25 = 26、10⊕25 = 19，答案是 26。暴力两两试是 O(n²)，n = 105 时 5×109 次。

把 Trie 的边从 26 条换成 2 条、从字符换成二进制位，就得到 01-Trie：它能在 O(31) 内回答“与 x 异或最大的数是谁”。

样例
n = 3
3 10 25
输出：26
1按位建树：从第 30 位往下

每个数从最高位到最低位拆成 31 层，走一条 0/1 的路径。高位决定大小，所以要先建高位。

建树
void insert(int x) {
    int u = 0;
    for (int b = 30; b >= 0; --b) {    // 从最高位开始，高位决定大小
        int c = (x >> b) & 1;
        if (!ch[u][c]) ch[u][c] = ++tot;
        u = ch[u][c];
    }
}
为什么

值 < 231，所以第 30 位是最高可能出现的位；位宽取错（30 写成 31 或 20）直接 WA。

2查询：能走反边就一定走

当前位是 c，反边就是 c^1。反边存在意味着这一位异或结果是 1——第 b 位的一个 1 抵得过所有低位之和，所以必选。

查询
int query(int x) {                     // 返回与 x 异或能得到的最大值
    int u = 0, r = 0;
    for (int b = 30; b >= 0; --b) {
        int c = (x >> b) & 1;
        if (ch[u][c ^ 1]) {            // 反边存在 → 这一位异或出 1，必选
            r |= 1 << b;
            u = ch[u][c ^ 1];
        } else {
            u = ch[u][c];              // 没得选，这一位异或出 0
        }
    }
    return r;
}
为什么

为什么可以一位一位贪：第 b 位贡献 2b，低 b 位全取 1 也只有 2b−1 < 2b。高位多赢一位就大于所有低位之和，所以逐位贪心与全局最优一致。

3先问后插：答案必须来自两个不同的数

读入第 i 个数时，先用它查前面已插入的数，再把它插进去——这样每一对只被算一次，且不会问到自己。

边读边算
for (int i = 1; i <= n; ++i) {
    int x;
    cin >> x;
    if (i > 1) ans = max(ans, query(x));   // 先问已有的数
    insert(x);
}
代码片段含义与理由
先 query 再 insert若先插后问，可能问到自己（x xor x = 0）；虽然不影响最大值，但“重复元素”的题会算错计数。顺序写对一次，以后不用想。
ans 用 int 就够两个 < 231 的数异或仍 < 231，不会超 int。若把值域改到 1018，位宽要改成 62，r 必须换 long long。
r |= 1 << b;这一位确定为 1，把 2b 记进答案。b ≤ 30，1 << b 不会溢出 int。
为什么

顺序写反不会影响最大值，但会算错“有多少对”这类计数——一次写对，后面不用回头改。

竞赛用法

看到“异或最大/最小”“值域 < 231”“按位统计”就用 01-Trie；单次 O(31)，n = 105 时总代价 3×106。持久化版本还能查“区间内与 x 异或最大”。

模型：二进制 TrieO(31) 查询坑：位宽取错
这一节的 7 种错法（都带症状）

RE / 段错误。—— Trie 的 MAXN 按“串的个数”开成 104。节点数等于总字符数，1 万个长 1500 的串要 1.5×107 个节点，insert 时写 ch[u][x] 越界。

WA，形如 ab 和 ba 被判成同一个串。—— 基数取了 B = 1 或 2，哈希退化成字符求和，任何重排都同值。B 必须大于字符集大小。

WA，本地全对、-O2 下答案诡异。—— 用 long long 做自然溢出。有符号溢出是 UB，编译器可以按“不会溢出”优化。必须 unsigned long long。

TLE。—— 用 set<string> 或 map<string,int> 存 105 个长 103 的串：每次比较 O(L)，总代价 O(N·L·log N)。哈希后排序整数是 O(N log N)。

WA，只有个别测试点错。—— 单哈希被卡。长串 + 固定基数 + 模 264 有确定的 Thue–Morse 反例，换双哈希或随机基数。

RE / 死循环。—— 用 -1 表示“边不存在”，但全局数组默认 0。判定写成 if (ch[u][x] == -1) 永远不成立，于是把 0 当成合法子节点原地打转。约定：0 表示不存在，编号从 1 开始。

WA，01-Trie 答案偏小。—— 位宽只写到第 20 位而数据里有 106 以上的数；或者值域到 231 还写 1 << 31（有符号移位溢出），应写 1LL << b。

数学补给 · 哈希为什么会有冲突：生日问题与 2^64

多项式哈希把长 L 的串映射到 H(s) = Σ si·BL−i mod M。不取模时这是 B 进制表示，B 大于字符集时不同串必得不同整数；取模把 M 以外的信息丢掉了，不同的串就可能落到同一个余数上，这就是冲突。

生日问题：把 n 个串丢进 M 个桶，期望冲突对数 ≈ n(n−1)/(2M)。要让冲突概率低于 10−6，需要 M ≳ 5×1011·n2。

模数大小n = 10⁵ 时的期望冲突数能否被构造攻击
2324.3×109≈ 1.2能
2641.8×1019≈ 2.7×10−10能（Thue–Morse）
109+7 单哈希109≈ 5能
双哈希 109+7 × 109+91018≈ 5×10−9极难

为什么模 264 特别脆：264 不是质数，奇数基数 B 的高次幂在模 264 下很快退化，于是可以用“差分”构造出等长且哈希相同的两个串。已知的构造按 Thue–Morse 串取位（第 i 位由 popcount(i) 的奇偶决定），在模 264、基数为奇数时两个串哈希完全相同。这就是 anti-hash 数据的来源——它不是运气，是构造。

双哈希为什么够：两套哈希同时撞上的概率近似为两个概率之积。两个 109 量级的模数给到 1018 的组合空间，且出题人要同时对两个不同模数构造反例，难度远超对 264。代价只是常数 ×2。

子串哈希的恒等式：h[r] = h[l−1]·Br−l+1 + H(l..r)，移项即 H(l..r) = h[r] − h[l−1]·Br−l+1。这一步把任意子串的指纹变成两次查表加一次乘法，是所有“子串比较”类题目的地基。

基数怎么选：B 要大于字符集（否则不同字符会进位混叠），且最好与模数互质（取质数最省事）。131、13331 是习惯用法；更稳的是运行时随机取一个 108 附近的质数，让反例无法预先构造。

化学竞赛组有 n 名学生，教练手里有名单。教练会依次报出 m 个名字，你要对每个名字给出判断：

若这个名字在名单里且是第一次被点到，输出 OK；若在名单里但之前已经被点过，输出 REPEAT；若不在名单里，输出 WRONG。

输入：第一行一个整数 n；接下来 n 行每行一个名字（互不相同，只含小写字母，长度 ≤ 50）；第 n+2 行一个整数 m；接下来 m 行每行一个教练报的名字（只含小写字母，长度 ≤ 50）。数据范围 n ≤ 104，m ≤ 105。

输出：对教练报的每个名字输出一行，为 OK、REPEAT 或 WRONG。

引导性提示（先只看这里）

名字总数 104、长度 ≤ 50，总字符数不超过 5×105。这个数字提示你：可以按字符建结构，不必按名字建。

查询要区分三件事：这条路径存在吗？路径的终点真的有名字结束吗？这个名字之前被点过吗？三件事需要三种不同的信息。

“前缀”和“单词”要分开：名单里只有 ab，教练报 abc，这条路径走不通；名单里只有 abc，教练报 ab，路径走得通但 ab 不结束。

想看思路了？点开完整思路

把名单建成 Trie：每个名字从根出发逐字符走，没有边就新建节点。走完整个名字时，把该节点的“结束计数”加一。

查询一个名字也是逐字符走：中途某条边不存在，说明名单里没有以它为前缀的名字，直接 WRONG。

走完整条路径后，还要看终点节点的结束计数是否为 0。为 0 说明它只是某个更长名字的前缀，自己不是名单里的名字——也是 WRONG。

为了区分 OK 和 REPEAT，再给每个节点一个 vis 标记：第一次走到这里输出 OK 并置 true，之后再走到就输出 REPEAT。

为什么用 Trie 而不是 set：set 查一次是 O(len·log n) 次字符串比较，Trie 是 O(len) 次下标访问，而且 m 到 105，差距会放大。

复杂度：插入 O(总字符数) ≤ 5×105，查询 O(m×50) ≤ 5×106，空间 O(总字符数)。

  • 忘了判 ended[u] == 0：名单里只有 abc 时报 ab，会错判成 OK。
  • 用 map<string,int> 记是否点过名：能过，但多了一次哈希，且意图不如“节点编号当 ID”清晰；n、m 更大时会被卡。
  • 用 ended[u]-- 表示“点过”：同一个名字第二次来时 ended[u] 已变成 0，会被判成 WRONG 而不是 REPEAT。
  • 多测不清空：本题只有一组，但换到多测题时必须把 tot、ch、ended、vis 一起清。

挑战 2 · 最长异或路径
洛谷 P4551提高-/提高去洛谷做这题 ↗

给定一棵 n 个点的带权树，点编号 1..n。一条“异或路径”指树上 u、v 两点之间唯一路径上所有边权的异或值。求所有点对之间异或路径的最大值。

输入：第一行一个整数 n（1 ≤ n ≤ 105）；接下来 n−1 行，每行三个整数 u、v、w，表示 u 与 v 之间有一条权值为 w 的边（0 ≤ w < 231）。

输出：一行一个整数，最大的异或路径值。

样例：4 个点，边是 (1,2,3)、(2,3,4)、(2,4,6)。1 到 3 要经过权值 3 和 4 两条边，3 ⊕ 4 = 7，这一对是所有点对里最大的。

样例
输入： 4 1 2 3 2 3 4 2 4 6 输出： 7
引导性提示（先只看这里）

先把问题从树上搬下来：记 d[u] 为“根走到 u”这一路的边权异或值。一条 u→v 的路径，和 d[u]、d[v] 之间差了什么？注意异或的逆运算是它自己，两个相同的数异或起来是多少？

树上 n 个 d 值两两异或要 5×109 次。本节正课里有个结构能把“和 x 异或最大”压到 31 步，它要求的输入是“一堆整数”还是“一棵树”？

别按点数开数组：一个数要 31 个二进制位，105 个数最多需要 3.1×106 个 Trie 节点。

想看思路了？点开完整思路

记 d[u] 为根到 u 路径上的边权异或值。u→v 的路径 = u→lca→v，而 d[u] ⊕ d[v] 里“根→lca”那一段出现了两次，异或后归零，剩下的正好是 u→v 这一段的异或值。所以答案 = max{d[u] ⊕ d[v]}，与树的形状无关，只跟这 n 个数有关。

题目于是变成：给 n 个不超过 231 的整数，求两两异或的最大值。暴力 C(n,2) = 5×109 次，超时。

把这 n 个数从第 30 位到第 0 位插进 01-Trie，查询 x 时从高位往下走：只要 x 这一位的反向儿子存在，就一定走它。因为第 k 位贡献 2k，而 2k 大于所有更低位之和 2k−1，所以“先保高位”的贪心不会错。

对每个 d[i] 查一次，答案取最大。单次 31 步，总计 O(31n)；Trie 节点数上限 31n+1。

边界：n = 1 时没有边，只有 d[1] = 0，答案为 0（自己和自己异或）；w 可以取 0；d 用 int 就够，因为异或不会超过 231−1。

复杂度：时间 O(31n)，空间 O(31n)，n = 105 时约 3.1×106 个节点、25 MB。

参考代码
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
int head[MAXN], nxt[MAXN << 1], to[MAXN << 1], wt[MAXN << 1], ecnt = 0;
int d[MAXN];                 // d[u] = 根到 u 的边权异或值
bool vis[MAXN];

void addEdge(int u, int v, int w) {
    to[++ecnt] = v; wt[ecnt] = w; nxt[ecnt] = head[u]; head[u] = ecnt;
}

// 01-Trie：每个数从第 30 位插到第 0 位，节点数 <= 31n + 1
const int MAXT = 3200005;
int ch[MAXT][2], tot = 0;

void insert(int x) {
    int u = 0;
    for (int i = 30; i >= 0; --i) {
        int b = (x >> i) & 1;
        if (!ch[u][b]) ch[u][b] = ++tot;      // 走不通才建新点，前缀靠共享
        u = ch[u][b];
    }
}

int query(int x) {
    int u = 0, res = 0;
    for (int i = 30; i >= 0; --i) {
        int b = (x >> i) & 1;
        if (ch[u][b ^ 1]) {                    // 反向位存在就先走，这一位能拿到 1
            res |= 1 << i;
            u = ch[u][b ^ 1];
        } else {
            u = ch[u][b];
        }
    }
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i < n; ++i) {
        int u, v, w;
        cin >> u >> v >> w;
        addEdge(u, v, w);
        addEdge(v, u, w);
    }
    // 迭代 BFS 求前缀异或：链状树深度 10^5，递归 DFS 有爆栈风险
    queue<int> q;
    q.push(1);
    vis[1] = true;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        insert(d[u]);
        for (int e = head[u]; e; e = nxt[e]) {
            int v = to[e];
            if (vis[v]) continue;
            vis[v] = true;
            d[v] = d[u] ^ wt[e];               // 异或是自己的逆运算，可沿路径累积
            q.push(v);
        }
    }
    int ans = 0;
    for (int i = 1; i <= n; ++i) ans = max(ans, query(d[i]));
    cout << ans << '\n';
    return 0;
}
关键片段拆解
片段作用
d[v] = d[u] ^ wt[e];地基：异或是自己的逆运算，所以 d[u] ⊕ d[v] 里“根→lca”那一段自动消掉，剩下正是 u→v 的路径异或值。
for (int i = 30; i >= 0; --i)位宽。w < 231，最高位是第 30 位；写成从 29 起循环会把 230 那一档算漏。
if (ch[u][b ^ 1]) { res |= 1 << i; ... }★ 贪心核心：反向位存在就选它。第 k 位的一个 1 抵得过后面所有位之和。
const int MAXT = 3200005;节点上限 31n+1 ≈ 3.1×106。按点数 n 开数组必 RE。
queue<int> q; ... vis[v] = true;链状树深 105，递归 DFS 会爆栈；BFS 里顺手算 d 并插入，一个循环干完两件事。
for (int i = 1; i <= n; ++i) ans = max(ans, query(d[i]));每个 d 查一次。n = 1 时循环仍执行，答案是 0，正确。
这题最容易错的地方
  • Trie 数组按点数 n 开：节点数是 31n+1（每个节点 2 个儿子），105 时直接越界 RE。
  • 位宽取错：w < 231 意味着第 30 位也要建，从 29 或从 20 起循环都会答案偏小。
  • 忘了每条无向边要建两条：只 addEdge(u, v, w) 时树是断的，一半的点 d 值永远是 0。
  • n = 1 时特判成“无解”或直接输出 −1：此时答案是 0（自己到自己），不该特殊处理掉。
