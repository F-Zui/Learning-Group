43 · 最小生成树与并查集

一张图里挑 n−1 条边把所有点连起来，还要最省。Kruskal 的两块拼图：并查集负责判断“会不会成环”，排序贪心负责“最省”。顺带把 MST 的唯一性与瓶颈路两个理论问题一次讲清。
提高-预计 70 分钟Kruskal并查集瓶颈路

给定一张 n 个点、m 条带权边的连通图，从中选 n−1 条边把所有点连起来，使边权和最小——这就是最小生成树（MST）。先记住一个事实：n 个点、n−1 条边、连通，这三条同时成立时，图一定是树——任意两点之间路径唯一，没有环。于是“选一棵树”只剩一个自由度：到底选哪 n−1 条边。

Kruskal 的正文只有三句话：把边按权值升序排；从小到大逐条看；两端还没连通就要它，已经连通就扔掉。“连通”这个词在图上很难判，但对一张不断合并的图来说，它恰好是并查集的全部工作。

Kruskal 的正确性只靠一条性质：当前还未处理过的最轻的那条边，只要它跨了两个连通块，要它一定不吃亏。

问题

Kruskal 每看一条边都要回答同一个问题：它的两个端点，现在是不是已经连通？“连通”可以用一次 DFS 判，代价 O(n + m) —— 而 Kruskal 要问 m 次，2×10⁵ 条边乘 5000 个点就是 10⁹ 级，必超时。

更麻烦的是这张图在不断变化：每加一条边，两个连通块就合成一个。所以需要的不是“跑一次最短路”，而是一个能边合并边询问的数据结构。

先解决其中一半：给每个点一个“上级”，能不能用一条父指针链表示“我在哪个集合里”？

1尝试①：每个点只记一个上级

让每个集合是一棵有根树，fa[x] 是 x 的父指针。根的特征很好认：它的父指针指向自己。初始化 fa[i] = i，每个点自成一个集合、自己就是根。

签名：一行路径压缩
int fa[N];
int find(int x) {
    return fa[x] == x ? x : fa[x] = find(fa[x]);
}
验证 / 关键

判“u、v 是否同集合”就变成判“find(u) == find(v)”—— 比一次 DFS 便宜得多，而且合并时只改一个父指针。

2尝试②：逐项确认这一行在干什么
组成部分含义 / 格式要求
fa[x]x 的父指针。fa[x] == x 时 x 就是所在集合的代表（根）。初始化 fa[i] = i，每个点自成一个集合。
fa[x] == x ? x :递归出口：自己就是根，返回自己。整个函数只有这一个终止条件。
fa[x] = find(fa[x])先递归找到根，再把 x 直接挂到根下面——这就是路径压缩。赋值号不能省，省掉就只剩递归、没有压缩。
路径压缩的效果链 a→b→c→root：第一次 find(a) 沿链走到底，返回时顺手把 a、b、c 全改成指向 root；之后再问就是 O(1)。
返回值根节点的编号。它只用来判“是不是同一集合”，不代表任何顺序或大小。
为什么递归不会爆栈没压缩前树高最多 log₂n（按大小合并保证），n = 5000 时不过 13 层；压缩后更浅。
初始化必写for (int i = 1; i <= n; ++i) fa[i] = i; 漏写时 fa 全是 0，所有点被认成同一集合 → 一条边都加不进去 → WA。
三目写法比 if/else 短，能直接写成 return 表达式，编译器容易内联。竞赛里几乎只写这一种。
验证 / 关键

注意“循环”和“递归”不是重点，赋值号才是：fa[x] = find(fa[x]) 让压缩发生在返回的路上，没有这个等号，函数照样能正确找到根，只是永远不压缩。

3尝试③：跑一段，看链被压平
示例：一次 find 压平整条链
#include <bits/stdc++.h>
using namespace std;

int fa[10];

int find(int x) {                              // 找根 + 顺手压缩
    return fa[x] == x ? x : fa[x] = find(fa[x]);
}

int main() {
    for (int i = 1; i <= 5; ++i) fa[i] = i;    // 初始化：各自是根
    fa[3] = 2; fa[2] = 1;                      // 手工造一条链 3 → 2 → 1

    cout << find(3) << "\n";                   // 1：根是 1
    cout << fa[3] << "\n";                     // 1：压缩后 3 直接指向 1
    cout << fa[2] << "\n";                     // 1：2 也被压平了
    return 0;
}
验证 / 关键

看输出：find(3) 返回 1，而且 fa[3]、fa[2] 都变成了 1 —— 一次调用就把整条链压平了。这就是“路径压缩”这个名字的由来。

4尝试④：两条必须记住的细节
  • 压缩发生在返回的路上：先递归到根，再一层层把 fa[x] 改成根。所以第一次调用最慢，之后全是 O(1)。
  • fa 数组是全局的，多组数据时必须重新 for (i) fa[i] = i，不然上一组的关系会被继承下来。
于是我们得到：

并查集的查找：一行 return fa[x] == x ? x : fa[x] = find(fa[x]);，边找根边把沿途的点挂到根上。

一句话记住：一行路径压缩：边找根边把沿途的点挂到根上。它把“查一次 O(n)”压到“第一次贵、之后 O(1)”。

问题

现在能查“谁是根”了，但还差一步：加一条边时，怎么把两个集合合成一个？

最直接的做法是 fa[find(x)] = find(y)：把 x 的根直接挂到 y 的根下。能跑，但会出问题 —— 父指针的深度没有任何上界。数据可以每次都把小集合挂到大集合下面，把树串成一条长链，单次 find 从 O(1) 退化成 O(n)。

所以合并时还得挑一下：谁挂谁？

1尝试①：把根接起来

第一步永远是把两个点换成各自的根：传进来的是普通点，直接 fa[y] = x 会把一条路径接乱，之后全错。

签名：五行
int sz[N];
void merge(int x, int y) {
    x = find(x); y = find(y);
    if (x == y) return;
    if (sz[x] < sz[y]) swap(x, y);
    fa[y] = x; sz[x] += sz[y];
}
验证 / 关键

然后在挂之前判一次 if (x == y) return;：已经在同一集合，合并是空操作。

2尝试②：逐行确认
组成部分含义 / 格式要求
x = find(x); y = find(y);先把两个点换成各自的根。传进来的是普通点，直接 fa[y] = x 会把一条路径接乱，之后全错。
if (x == y) return;已在同一集合，合并是空操作。漏写不崩，但 size 会重复累加、判环失效（见易错清单）。
if (sz[x] < sz[y]) swap(x, y);保证 x 是大的那块。把小树挂到大树底下，树高最多涨 1。这就是按大小合并。
fa[y] = x;把 y 的根接到 x 的根下面。整个集合的结构只靠这一行改动。
sz[x] += sz[y];只维护新根 x 的 size。y 已经不是根了，它的 size 再没人读，不用清。
返回值void。想知道“这次合并是否真的发生”，判 find(u) == find(v) 更好——Kruskal 正是靠它跳过成环的边。
按秩还是按大小维护 size 比维护 rank（树高）简单，效果一样：都给 O(log n) 上界，配上路径压缩就都是 O(α(n))。本节用 size。
复杂度单次 merge = 两次 find + 常数。α(n) ≤ 4，见本节数学补给。
验证 / 关键

swap 那一行是全部智慧所在：永远让小树挂到大树下面。这样树高最多涨 1，深度被压在 log₂n 以内；配上路径压缩之后，单次操作均摊到常数（α(n) ≤ 4）。

3尝试③：跑一段，看合并顺序
示例
#include <bits/stdc++.h>
using namespace std;

int fa[10], sz[10];

int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

void merge(int x, int y) {
    x = find(x); y = find(y);
    if (x == y) return;                     // 已经在一起
    if (sz[x] < sz[y]) swap(x, y);          // 小的挂到大的下面
    fa[y] = x;
    sz[x] += sz[y];
}

int main() {
    for (int i = 1; i <= 5; ++i) { fa[i] = i; sz[i] = 1; }

    merge(1, 2);                            // {1,2}
    merge(3, 4);                            // {3,4}
    merge(2, 3);                            // 合成 {1,2,3,4}

    cout << find(4) << " " << sz[find(1)] << "\n";   // 1 4
    return 0;
}
验证 / 关键

输出 1 4：4 的根是 1，整块大小是 4。注意 sz 只在根上有意义 —— sz[find(1)] 就是这么读的。

4尝试④：两个容易漏的地方
  • merge 内部一定会重新 find，所以调用时传原始点即可，别在外面再 find 一次（不报错，但容易忘）。
  • 按大小合并防的是最坏情况：不加这一步，父指针的深度没有任何上界——数据可以把它串成一条长度为 n 的链，单次 find 从 O(1) 退化成 O(n)。
于是我们得到：

并查集的合并：先 find 再判同集合，小树挂大树，只改 fa 与 sz 两处。

一句话记住：先 find 再判同集合，小树挂大树，只改 fa 与 sz 两处。因为合并时要判 x == y，它顺便也回答了“这条边会不会成环”。

问题

判环的工具已经有了。现在面对的是原问题：n 个点、m 条带权边，选哪 n−1 条，使边权和最小？

暴力是 C(m, n−1) 种组合，m = 2×10⁵ 时是天文数字。要一个贪心：按什么顺序看边，才敢“要了就不后悔”？

直觉是先拿轻的。但“轻的都要”不行（会成环），所以顺序 + 判环两件事必须组合起来。

1尝试①：先给边排序

把边按权值升序，然后从小到大逐条看。这条贪心的正确性由例题卡里的割性质保证：当前还没处理的最轻那条边，只要它跨两个连通块，要它一定不吃亏。

签名：排序 + 主循环
struct Edge { int u, v, w; } e[M];
sort(e + 1, e + m + 1, [](const Edge &a, const Edge &b) { return a.w < b.w; });
int cnt = 0; long long ans = 0;
for (int i = 1; i <= m && cnt < n - 1; ++i) {
    if (find(e[i].u) == find(e[i].v)) continue;
    merge(e[i].u, e[i].v);
    ans += e[i].w; ++cnt;
}
验证 / 关键

排序是最贵的一步：m = 2×10⁵ 时约 3.5×10⁶ 次比较，比并查集那几十万次操作重得多。想优化，先优化排序。

2尝试②：逐项确认
组成部分含义 / 格式要求
struct Edge一条边存三个 int：u、v 是无向的两个端点，w 是权值。用结构体而不是三个平行数组，排序时整条边一起搬。
sort 的第三参数lambda，按 w 升序。必须写 < 不能写 <=——cmp 违反严格弱序会让 GCC 的 sort 越界访问，直接 RE。
e + 1, e + m + 11-indexed 的数组要用这两根指针。写成 e, e+m 会漏掉第 m 条边（代价是偶尔少一条最重边，答案偏小）。
cnt < n − 1树只有 n−1 条边，凑够就停。它既是提前退出，也是最后判连通的依据。
find(u) == find(v)两端已连通 → 加这条边会成环 → 跳过。整个算法唯一做判断的地方。
merge(u, v)两端不在同一块，这条边把两个连通块缝起来了。并查集记下这次合并，后续判环就靠它。
ans += e[i].w只有真加进树的边才累加权值。必须写在 continue 之后。
结束条件cnt == n−1 说明成功；cnt < n−1 说明图不连通，此时 ans 只是“最小生成森林”的权值，不是答案。
验证 / 关键

把这四行读成一句话：排序 + 逐条尝试 + 并查集判环。判环是全题唯一需要判断的地方，它只要一次 find 比较。

3尝试③：完整跑一遍
示例：4 个点、5 条边
#include <bits/stdc++.h>
using namespace std;

const int N = 10, M = 20;
struct Edge { int u, v, w; } e[M];
int fa[N], sz[N];

int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }
void merge(int x, int y) {
    x = find(x); y = find(y);
    if (x == y) return;
    if (sz[x] < sz[y]) swap(x, y);
    fa[y] = x; sz[x] += sz[y];
}

int main() {
    int n = 4, m = 5;
    int raw[6][3] = {{0,0,0}, {1,2,2}, {1,3,2}, {1,4,3}, {2,3,4}, {3,4,3}};
    for (int i = 1; i <= m; ++i) { e[i].u = raw[i][0]; e[i].v = raw[i][1]; e[i].w = raw[i][2]; }

    sort(e + 1, e + m + 1, [](const Edge &a, const Edge &b) { return a.w < b.w; });
    for (int i = 1; i <= n; ++i) { fa[i] = i; sz[i] = 1; }

    long long ans = 0; int cnt = 0;
    for (int i = 1; i <= m && cnt < n - 1; ++i) {
        if (find(e[i].u) == find(e[i].v)) continue;   // 成环，扔掉
        merge(e[i].u, e[i].v);
        ans += e[i].w; ++cnt;
    }
    cout << cnt << " " << ans << "\n";   // 3 7：加了 3 条边，权和 7
    return 0;
}
验证 / 关键

输出 3 7：加了 3 条边（= n−1），权和 7。第 4、5 条边加进去都会成环，被 find 挡掉。

4尝试④：两条容易写错的
  • 排序是最贵的一步：m = 2×10⁵ 时约 3.5×10⁶ 次比较，比并查集那几十万次操作重得多。想优化，先优化排序。
  • cnt 一定要在真加边时才 ++。写在 for 里或写在 continue 之前，会让“边数”算成 m，判连通永远成立 → 输出一个偏小的错答案。
于是我们得到：

Kruskal 的主体：sort 按权值升序，逐条边 find 判环，不连通的就 merge 并累加权值，凑满 n−1 条就停。

一句话记住：排序 + 逐条尝试 + 并查集判环，五行就是全部。复杂度 O(m log m)，瓶颈在排序。

  1. 把所有权值取负再求“最大生成树”，Kruskal 要改几处？最大生成树能回答“删掉哪些边最省”这类问题吗？

    排序改一处：把 cmp 的 < 换成 >（降序），ans 照常累加就是最大生成树的权和。用“取负”的写法更省心：读入时 w = −w，全段代码一字不改，最后输出 −ans——两者是同一件事。它能回答的是“保留的边权和最大”，也就是“删掉的边权和最小（且剩下的仍连通）”；如果题意是“删掉最少的边让图不连通”，那是最小割，MST 帮不上忙。常见错路：改了排序却忘了最后取反，或者以为最大生成树要换一套判环逻辑——判环与贪心骨架完全不变。
  2. 如何判断某一条给定的边 e 是否“属于某一棵最小生成树”？又怎么判断它是否“属于所有最小生成树”？提示：想想 e 与 u、v 在 MST 上路径最大边的关系。
    想好了？点开核对思路与解析
    “属于某一棵”用环性质判：先求一棵 MST T，查出 T 上 u→v 路径的最大边权 mx。若 w(e) ≤ mx，把那条最大边换成 e 就得到另一棵 MST（e 本来在 T 里则更显然）；若 w(e) > mx，加进 e 形成的环上 e 严格最重，任何 MST 都不会要它。“属于所有”要更强的条件，路径最大值这一招不够：正确判据是 e 在“只保留权值 ≤ w(e) 的边”那张子图里是不是桥，或者实用做法——把 w(e) 减 1 重跑一次 Kruskal，总权恰好减 1 就说明每一棵都少不了它。常见错路：拿 w(e) < mx 当“属于所有”的判据，边权相等时会把共享边误判成非共享。
算法落地例题 · 【模板】最小生成树 · Kruskal覆盖：洛谷 P3366 / Kruskal 最小生成树
需求

例题 · 【模板】最小生成树 · 洛谷 P3366 普及/提高-

给出一个包含 N 个结点的无向图，求它的最小生成树。

输入格式：第一行两个整数 N、M，表示 N 个结点、M 条无向边。
接下来 M 行，每行三个整数 Xᵢ、Yᵢ、Zᵢ，表示有一条长度为 Zᵢ 的边连接结点 Xᵢ 与 Yᵢ。

输出格式：如果图连通，输出一个整数，表示最小生成树各边长度之和；如果图不连通，输出 orz。

数据范围：1 ≤ N ≤ 5000，1 ≤ M ≤ 2×10⁵，1 ≤ Zᵢ ≤ 10⁴。

样例
输入：
4 5
1 2 2
1 3 2
1 4 3
2 3 4
3 4 3
输出：
7
1① 把“选边”拆成三个问题

问题一：什么样的边集是树？n 个点、n−1 条边、连通。前两条用计数就能保证，第三条只能靠“加边时不成环”来保证——从 n 个孤立点开始，每加一条两端不在同一块的边，连通块数量恰好减 1。加满 n−1 条，块数变成 1。

问题二：怎么保证最小？用贪心：把边按权值升序，能加就加。正确性靠割性质。

割性质（cut property）。把点集任意分成两块，取所有“一端在这块、一端在另一块”的边里最轻的一条 e，则存在一棵最小生成树包含 e。
证明：设 T 是不含 e 的最小生成树。T 中从 e 的一个端点到另一个端点有唯一路径，这条路径必然在某处跨出该块，设为边 f。则 T − f + e 仍是生成树，且 w(e) ≤ w(f)，权值不增，故它也是最小生成树并含 e。∎

问题三：Kruskal 选的那条边，凭什么是“跨割最轻”的？设当前考察 eₖ，它的一端 u 在连通块 C、另一端不在。若有一条更轻的边 f 跨 (C, 外部)，它一定在 eₖ 之前被处理过：f 若被加入，C 早已跨出去；f 若被跳过，说明 f 两端当时已连通，那另一端的点今天也该在 C 里。两种都矛盾。所以 eₖ 就是跨这个割最轻的边，由割性质它可以进 MST。

贪心骨架
// 三个问题落到代码上，骨架只有这五行
sort(e + 1, e + m + 1, [](const Edge &a, const Edge &b) { return a.w < b.w; });
for (int i = 1; i <= m && cnt < n - 1; ++i) {
    if (find(e[i].u) == find(e[i].v)) continue;   // 问题一：成环就扔
    merge(e[i].u, e[i].v); ans += e[i].w; ++cnt;  // 问题二/三：跨割最轻，加它不吃亏
}
为什么

三个问题各占一件事：计数管“是不是树”，割性质管“为什么贪心对”，问题三把两者接起来 —— 所以“排序 + 判环就加”这个框架本身就是证明过的，不需要再去验算每组数据。

2② 读入边、按权值排序

为什么

边存成结构体 {u, v, w}，排序时整条边一起搬。cmp 用 < 而不是 <=：相等时两边都返回 true 会破坏严格弱序，GCC 的 sort 在数据稍大时越界访问 → RE，而且报错位置在 sort 里面，看起来跟你的代码无关。

1-indexed 的数组要用 e + 1, e + m + 1 这两根指针。写成 e, e + m 会漏掉第 m 条边。

3③ 初始化并查集，逐条加边
Kruskal 主循环
    for (int i = 1; i <= n; ++i) { fa[i] = i; sz[i] = 1; }   // 并查集初始化

    long long ans = 0;
    int cnt = 0;                                   // 已加入树的边数
    for (int i = 1; i <= m && cnt < n - 1; ++i) {  // 凑够 n-1 条就停
        if (find(e[i].u) == find(e[i].v)) continue;  // 两端已连通，加了会成环
        merge(e[i].u, e[i].v);
        ans += e[i].w;
        ++cnt;
    }
为什么

初始化必须放在加边之前，而且要在读入 n 之后 —— 写在读入之前，n 还是 0，一个点都没初始化，fa 全是 0，所有点被认成同一集合，一条边都加不进去。

循环条件带 cnt < n - 1：n−1 条边已经构成生成树，再看的边只可能更重。ans += e[i].w; ++cnt; 两条都要在 continue 之后：顺序反了（cnt 先加）会让计数多 1，判连通永远成立。

4④ 最后判一次连通
输出

    else cout << ans << "\n";
    return 0;
为什么

加不满 n−1 条边时，ans 只是“最小生成森林”的权值，不是最小生成树 —— 题目要的是 orz。所以最后必须用 cnt 判一次，而不是直接输出 ans。

ans 用 long long：本题 5000 个点、边权 10⁴，上界 5×10⁷，int 也够；但求和一律 long long 是习惯，改题面时不用重想。

5⑤ 样例手推 + 完整程序
完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

const int N = 5005, M = 200005;      // 点数与边数差 40 倍，千万别共用一个上界

struct Edge { int u, v, w; } e[M];
int fa[N], sz[N];

int find(int x) {                    // 路径压缩：找到根，顺便把路上的点挂到根上
    return fa[x] == x ? x : fa[x] = find(fa[x]);
}

void merge(int x, int y) {
    x = find(x); y = find(y);
    if (x == y) return;              // 已同集合：不需要改任何东西
    if (sz[x] < sz[y]) swap(x, y);   // 小树挂大树，保证树高只涨 1
    fa[y] = x;
    sz[x] += sz[y];
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= m; ++i) cin >> e[i].u >> e[i].v >> e[i].w;

    sort(e + 1, e + m + 1, [](const Edge &a, const Edge &b) { return a.w < b.w; });

    for (int i = 1; i <= n; ++i) { fa[i] = i; sz[i] = 1; }   // 并查集初始化

    long long ans = 0;
    int cnt = 0;                                   // 已加入树的边数
    for (int i = 1; i <= m && cnt < n - 1; ++i) {  // 凑够 n-1 条就停
        if (find(e[i].u) == find(e[i].v)) continue;  // 两端已连通，加了会成环
        merge(e[i].u, e[i].v);
        ans += e[i].w;
        ++cnt;
    }

    if (cnt < n - 1) cout << "orz\n";              // 图不连通
    else cout << ans << "\n";
    return 0;
}
为什么

两个上界要分开写：N = 5005, M = 200005。n ≤ 5000、m ≤ 2×10⁵，共用一个 5005 会读入越界 → RE。

样例手推：排序后依次看 (1,2,2)、(1,3,2)、(1,4,3)，三条都不成环，全加，权和 7；再看 (3,4,3)、(2,3,4) 时 1..4 已连通，被 find 挡掉，cnt 已经到 3 提前退出。

竞赛用法

看到什么想到它：“把所有点连通起来，总花费最小 / 总长度最短 / 边权和最小”，或者“用最小的最大边长连通”（瓶颈路）—— 前者是 MST，后者是 Kruskal 最后加进去那条边的权值。

复杂度：排序 O(m log m) ≈ 3.5×10⁶ 次比较；加边部分每条边至多两次 find，共 4×10⁵ 次、每次不超过 4 步。总计 10⁶ 量级，实测 20~40 ms。

常见的坑：① cmp 写成 <=，大数据下 sort 越界 RE；② 漏写 if (find(u) == find(v)) continue;，每条边都 merge，cnt 超 n−1、ans 偏大；③ 并查集初始化漏写或写错位置，fa 全是 0，一条边都加不进去；④ find 省掉赋值、merge 又不按大小合并，父指针退化成链 → TLE；⑤ 边数组按 n 开（e[5005] 存 2×10⁵ 条边）→ RE 或随机 WA；⑥ 不连通时直接输出 ans，题目要 orz。

模型：最小生成树（Kruskal）O(m log m)坑：cmp 写 <= 会 RE

  1. 题目问“最早加入第几条边时整张图连通”，用二分答案 + 并查集怎么做？为什么直接跑一遍 Kruskal、看第 n−1 条边是第几轻的，就更快？
    想好了？点开核对思路与解析
    二分边的序号 k，check(k) 用并查集把排序后的前 k 条边合并，看是否只剩一个连通块——k 越大越容易连通，单调性成立；共 O(m log m · α(m))。而直接跑一遍 Kruskal 就够了：第 n−1 条成功加入的边，正是“连通块数第一次降到 1”的那条，它的位置就是答案，省掉了 log m 次从头合并。两者同阶，但常数差 log m 倍，而且不用写 check。常见错路：check 里忘了把 fa 重置成 fa[i] = i；或者把“第几条”当成输入顺序，而答案其实按排序后的位置。

    想好了？点开核对思路与解析
    Kruskal 更合适，而且要先发现一件事：n = 10⁶、m = 10⁵，连 n−1 = 10⁶−1 条边都不到，图不可能连通，Kruskal 跑完 cnt < n−1，得到的只是最小生成森林——题目多半就是要求森林，或者数据本身如此。Kruskal 只跟边数有关：O(m log m) ≈ 10⁵×17 = 1.7×10⁶，边集数组 10⁵ × 12 B ≈ 1.2 MB，再加 fa/sz 十几 MB。Prim 则必须建邻接表：10⁶ 个 vector 对象本身就 24 MB，堆里还要塞 n 个点，O((n+m)log n) ≈ 10⁶×20 = 2×10⁷，内存和时间都更贵。所以稀疏大点集选 Kruskal，稠密小点集才用 Prim。

算法落地用法 · MST 的两个理论问题：唯一性与瓶颈路覆盖：MST 唯一性 / 对称差证明 / 瓶颈路 / Kruskal 最后一条边
需求

需求：先用 Kruskal 求出最小生成树，再回答两个问题——① 最小生成树唯一吗？② 两点之间所有路径里，“最大边权”的最小值是多少（瓶颈路）？

先看唯一性。三个点两两相连、三条边权都是 1 时，任取两条边都连通三个点，所以 MST 有 3 棵，权值和都是 2；把边权换成 1、2、4，就只有 1+2 这一种取法，MST 唯一。

输出：

输入（边权 1、2、4）：

输出：

1① 唯一性：三条等权边的三角形有 3 棵 MST

最小生成树唯一吗？不一定。所有边权互不相同时，MST 唯一；有相等边权时可能有多棵。反例：三个点两两相连、三条边权都是 1，删掉任意一条都是一棵 MST，共 3 棵，但它们的权值和都是 2。

数出 3 棵：C(3,2) = 3
// 三点完全图，三条边权都是 1：任取两条都连通、都不成环
int ew[3] = {1, 1, 1};
int cnt = 0, best = INT_MAX;
for (int a = 0; a < 3; ++a)
    for (int b = a + 1; b < 3; ++b) {          // 3 条边里选 2 条
        int sum = ew[a] + ew[b];
        if (sum < best) { best = sum; cnt = 1; }
        else if (sum == best) ++cnt;
    }
printf("%d %d\n", best, cnt);                  // 2 3：权值和 2，共 3 棵
为什么

所以做题时要分清题目问的是哪一个：问“最小代价”永远有唯一答案（Kruskal 直接输出）；问“方案数 / 是否唯一”才需要额外处理，那属于生成树计数，超出本节范围。

2② 边权互不相同就一定唯一：对称差证明

把同一段枚举换成互不相同的边权，计数立刻变成 1：三条候选边的权和分别是 1+2=3、1+4=5、2+4=6，最小只有 3 这一种。

换成互异权值，计数变成 1
// 同样的三点完全图，边权换成 1、2、4
int ew[3] = {1, 2, 4};
int best = INT_MAX, cnt = 0;
for (int a = 0; a < 3; ++a)
    for (int b = a + 1; b < 3; ++b) {
        int sum = ew[a] + ew[b];               // 3、5、6
        if (sum < best) { best = sum; cnt = 1; }
        else if (sum == best) ++cnt;
    }
printf("%d %d\n", best, cnt);                  // 3 1：唯一一棵
为什么

边权互不相同时一定唯一，证明如下。假设有两棵不同的 MST，取它们的对称差，其中必有一条权值最小的边 e 属于 T₁ 不属于 T₂。把 e 加进 T₂ 形成环，环上必有一条不属于 T₁ 的边 f；由最小性 w(f) ≥ w(e)，又因边权全不同只能 w(f) > w(e)，于是 T₂ − f + e 更轻，与 T₂ 最小矛盾。∎

3③ 瓶颈路：MST 上路径的最大边权就是答案

瓶颈路。定义 d(u,v) = 所有 u→v 路径中“最大边权”的最小值——走这条路，最宽的那道坎最窄。定理：对任意一棵 MST，树上 u→v 路径的最大边权就等于 d(u,v)。

一次 DFS 回答一对询问
vector<pair<int,int>> tr[N];        // 只存 MST 的 n-1 条边：(邻点, 边权)
int best;

bool dfs(int u, int fa, int target, int cur) {
    if (u == target) { best = cur; return true; }
    for (auto [v, w] : tr[u]) {
        if (v == fa) continue;
        if (dfs(v, u, target, max(cur, w))) return true;   // 沿途记最大边权
    }
    return false;
}
// 调用：dfs(1, 0, 4, 0);  best 就是 d(1,4)
为什么

这条定理的用途很直接：把“最小化最大值”的连通问题全部交给 MST。比如“用最小的最大边长把所有点连通”，答案就是 Kruskal 最后加进去的那条边的权值，连和都不用求——这正是 P2330 一类的题。单次询问的做法就是上面的 DFS，O(n)；多组询问要用倍增在树上跳（第 53 节），或把 Kruskal 的合并过程建成一棵重构树。本节只需记住结论。

4④ 完整程序：Kruskal 建树，再回答一次瓶颈询问
完整可编译代码（C++17）
#include <bits/stdc++.h>
using namespace std;

const int N = 5005, M = 200005;
int n, m, fa[N];
struct Edge { int u, v, w; } e[M];
vector<pair<int,int>> tr[N];        // MST 的邻接表：(邻点, 边权)
int qu, qv, best;

int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

bool dfs(int u, int p, int cur) {
    if (u == qv) { best = cur; return true; }
    for (auto [v, w] : tr[u]) {
        if (v == p) continue;
        if (dfs(v, u, max(cur, w))) return true;
    }
    return false;
}

int main() {
    cin >> n >> m;
    for (int i = 0; i < m; ++i) cin >> e[i].u >> e[i].v >> e[i].w;
    sort(e, e + m, [](const Edge &a, const Edge &b) { return a.w < b.w; });
    for (int i = 1; i <= n; ++i) fa[i] = i;

    int cnt = 0, last = 0;
    for (int i = 0; i < m && cnt < n - 1; ++i) {
        int u = e[i].u, v = e[i].v;
        if (find(u) == find(v)) continue;
        fa[find(u)] = find(v);
        tr[u].push_back({v, e[i].w});
        tr[v].push_back({u, e[i].w});
        ++cnt;
        last = e[i].w;                 // 排过序，最后加进去的就是最大边权
    }
    if (cnt < n - 1) { cout << "orz\n"; return 0; }

    cin >> qu >> qv;
    dfs(qu, 0, 0);
    cout << best << "\n";              // 这一对点的瓶颈路
    // 若题目问“把所有点连通的最小最大边长”，答案就是 last
    return 0;
}
为什么

样例：4 3 / 1 2 2 / 2 3 5 / 3 4 3 / 1 4，输出 5。MST 就是这三条边；1→4 的路径 1–2–3–4 上最大边权是 5，也就是把 4 个点连通所需的“最小最大边长”（last）。换一对点，比如 1 2，输出 2——同一棵树上不同点对的瓶颈值不同，最后一次 Kruskal 的边只回答“全局连通”那一问。

竞赛用法

看到什么想到它：问“MST 是否唯一 / 有几棵”“最小化最大边权”“最大边最小的路径”“用最小的最大边长把所有点连通”—— 都先求 MST，再在树上回答，或直接看 Kruskal 最后加进去的边。

复杂度：Kruskal O(m log m)；单次瓶颈询问在树上 DFS 是 O(n)，多组询问要倍增 O(log n)。

常见的坑：① 把“最小代价”和“方案数”混为一谈——前者永远唯一，后者要生成树计数；② 把瓶颈路当成最短路，求成边权和；③ 多组询问还每次 O(n) 地 DFS，n、q 都到 10⁵ 时必超时；④ 图不连通时直接输出 last，题目要的是 orz。

模型：MST 的推论O(m log m)坑：瓶颈路不是最短路
这一节的 6 个坑，按症状记

cmp 写成 return a.w <= b.w;：违反严格弱序，GCC 的 sort 在数据稍大时越界访问 → RE，而且报错位置在 sort 里面，看起来跟你的代码无关，最难查。

漏写 if (find(u) == find(v)) continue;：每条边都被 merge、都计入 cnt，边数超过 n−1、ans 多加权值 → WA，并且程序不崩、不超时，只是答案偏大。

并查集初始化漏写或写错位置：fa 全是 0，所有点被判成同一集合 → 一条边都加不进去，cnt 恒为 0 → WA（输出 orz，或对 n = 1 才偶然正确）。

find 里省掉 fa[x] = ，同时 merge 又不按大小合并：父指针退化成一条长链，每次 find 走 O(n)，2×10⁵ 条边 × 5000 步 = 10⁹ 次操作 → TLE。两个优化至少要留一个。

边数组按 n 开：n ≤ 5000 但 m ≤ 2×10⁵，只开 e[5005] 读入就写穿 → RE；开小了还能跑完时更可怕，表现为随机 WA。

不连通时直接输出 ans：题目要 orz，你输出了森林权值 → WA。养成“最后判 cnt == n−1”的习惯。

挑战题 · 无线通讯网
洛谷 P1991提高-去洛谷做这题 ↗

国防部计划用无线网络连接若干个边防哨所。每台哨所都配一台无线电收发器，收发器的通信距离为 d：两个哨所之间的距离不超过 d 时才能用无线电直接通信。

现在有 S 台哨所可以额外加装卫星电话，卫星电话之间的距离不受任何限制（装了卫星电话的两台哨所永远可以通信）。

给出 S、P 和 P 个哨所的坐标，求能连通所有哨所的最小的 d。

输入格式：第一行两个整数 S、P（1 ≤ S ≤ 100，S ≤ P ≤ 500）。
接下来 P 行，每行两个整数 xᵢ、yᵢ（0 ≤ xᵢ, yᵢ ≤ 10000），表示第 i 个哨所的坐标。

输出格式：一行一个实数，表示 d 的最小值，保留两位小数。

引导性提示（先只看这里）

卫星电话的作用不是“传得更远”，而是“允许整张网络断成 S 块”——块内必须靠无线电连起来。

先假想 d 已经确定：只保留长度 ≤ d 的边，你能算出图被分成几块吗？这个判定和 Kruskal 有什么关系？

把边按长度从小到大加，每加一条能连通两块的边，块数就减 1。数一数块数减到 S 时你加到第几条边。

想看思路了？点开完整思路

把卫星电话翻译成连通块数。S 台卫星电话各自装在一个连通块里，块与块之间靠卫星通信，块内部必须靠无线电连通。所以最终恰好允许剩下 S 个连通块。分成更少块就浪费了电话，分成更多块则有一块没有电话、无法与外界通信。

问题变成：把 P 个点分成 S 块，使每块内部连通所需的无线电距离尽可能小，并对所有块取最大值。这正是“最小化最大边”的瓶颈问题，交给 MST。

Kruskal 恰好是一个不断减少连通块的过程。初始 P 块，每加入一条不成环的边，块数减 1。块数从 P 减到 S 需要 P − S 次合并，第 P − S 条被加入的边的长度就是答案——因为它正是“让块数刚好降到 S”的那道坎。

为什么不是第 P − S + 1 条？第 P − S 条加入后块数已经是 S，此时可以收手了；再加一条就把块数压到 S − 1，等于浪费了一台卫星电话，而那条边只会更长。

边界：S ≥ P 时每台哨所都能装卫星电话，不需要任何无线电，d = 0。不特判会让“凑够 P − S 条”永远不成立，ans 被更新到最大边。

复杂度。边数 P(P−1)/2 ≤ 124750，排序约 1.2×10⁵ × 17 ≈ 2×10⁶ 次比较，并查集十余万次操作，几十毫秒。

等价写法。也可以二分 d，判定“只用长度 ≤ d 的边能否把图连成 ≤ S 块”，复杂度 O(P² log)，能过但多一个 log，而 Kruskal 一次就做完了。

#include <bits/stdc++.h>
using namespace std;

const int MAXP = 505, MAXE = MAXP * MAXP;   // 完全图最多 P(P-1)/2 条边

struct Edge { int u, v; double w; } e[MAXE];
int fa[MAXP], sz[MAXP];
double x[MAXP], y[MAXP];

int find(int a) { return fa[a] == a ? a : fa[a] = find(fa[a]); }

bool merge(int a, int b) {                  // 返回 true 表示这次真的合并了两块
    a = find(a); b = find(b);
    if (a == b) return false;               // 已连通，这条边会成环
    if (sz[a] < sz[b]) swap(a, b);
    fa[b] = a; sz[a] += sz[b];
    return true;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int S, P;
    cin >> S >> P;
    for (int i = 1; i <= P; ++i) cin >> x[i] >> y[i];

    if (S >= P) {                           // 每台都装卫星电话，不需要无线电
        cout << fixed << setprecision(2) << 0.0 << "\n";
        return 0;
    }

    int m = 0;
    for (int i = 1; i <= P; ++i)            // 建完全图：任意两点都可能用无线电通信
        for (int j = i + 1; j <= P; ++j) {  // 从 i+1 开始，避免自环与重复边
            double dx = x[i] - x[j], dy = y[i] - y[j];
            e[++m] = {i, j, sqrt(dx * dx + dy * dy)};
        }

    sort(e + 1, e + m + 1, [](const Edge &a, const Edge &b) { return a.w < b.w; });

    for (int i = 1; i <= P; ++i) { fa[i] = i; sz[i] = 1; }

    int need = P - S;                       // 从 P 块压到 S 块，需要 P-S 次合并
    int got = 0;
    double ans = 0;
    for (int i = 1; i <= m; ++i) {
        if (!merge(e[i].u, e[i].v)) continue;   // 成环，跳过
        ans = e[i].w;                       // 记下这次合并用的边长
        if (++got == need) break;           // 凑够 P-S 条就停
    }

    cout << fixed << setprecision(2) << ans << "\n";
    return 0;
}

片段作用
const int MAXE = MAXP * MAXP;完全图有 P(P−1)/2 条边，P ≤ 500 时是 124750。开 P² 更宽松，也不用算半天。
bool merge(...)把 merge 改成返回 bool：返回 true 表示“这次真的合并了两块”，Kruskal 的计数就靠它。返回值比在外面再判一次 find 更省一次查找。
S >= P每台哨所一台卫星电话，d 可以取 0。不特判的话 need ≤ 0，++got == need 永远不成立，循环会一路加到最后一条边，ans 变成最大边长 → WA。
for (int j = i + 1; ...)只连 i < j 的点对。写成 j = 1 会多出一倍的重复边和 P 条自环（距离 0，会排在最前面，被 merge 判成同集合跳过，不致命但白排一遍）。
sqrt(dx * dx + dy * dy)欧氏距离。坐标差最大 10⁴，平方和最大 2×10⁸，double 有 53 位有效位，精度绰绰有余。
sort 按 w 升序Kruskal 的核心。用 double 排序时 cmp 仍写 <，别写 <=。

if (++got == need) break;凑够就停。后面的边更长，不可能让答案更小。
fixed << setprecision(2)固定两位小数。用 cout 而不是 printf，避免和关闭同步的 cin 混用出问题。
这题最容易错的地方
  • 忘了 S ≥ P 的特判：need ≤ 0 时 break 永远不触发，ans 变成最大边长 → WA。
  • 距离用 int 存或让 sqrt 结果被截断成整数：排序顺序错，答案偏差可达 0.5 以上 → WA。
  • 只统计到 P − S − 1 条（下标差一）：答案取到了第二大的那条，比正确答案小 → WA。
  • 把 ++got == need 写成 got++ == need：先比较后自增，会多加一条边 → 答案偏大。
  • 输出不带两位小数，或写成 cout << ans：评测要求 212.13 这样的格式 → WA。
  • 二分答案的写法里把“连通块数 ≤ S”错写成“< S”：答案偏大 → WA。

挑战 2 · 关押罪犯
洛谷 P1525提高-/提高去洛谷做这题 ↗

S 城有两座监狱，关着 N 名罪犯，编号 1..N。有 M 对罪犯之间有仇恨，第 i 对的怨气值是 cᵢ。如果两名有仇恨的罪犯被关进同一座监狱，就会发生影响力为 cᵢ 的冲突；一年里所有冲突会按影响力从大到小排成一张表，市长只看最上面那一条。你要安排每名罪犯进哪座监狱，使这张表的第一条影响力最小。

输入格式：第一行两个整数 N、M；接下来 M 行，每行三个整数 aⱼ、bⱼ、cⱼ（1 ≤ aⱼ < bⱼ ≤ N，0 < cⱼ ≤ 10⁹），表示 aⱼ 与 bⱼ 之间有怨气值为 cⱼ 的仇恨，每对罪犯组合只出现一次。

数据范围：N ≤ 2×10⁴，M ≤ 10⁵。

输出格式：一行一个整数，表示市长看到的最小影响力；如果一座监狱里都不发生冲突，输出 0。

样例输入
4 6
1 4 2534
2 3 3512
1 2 28351
1 3 6618
2 4 1805
3 4 12884
样例输出
3512
样例解释：把 1、3 关进一座、2、4 关进另一座，剩下唯一同监狱的一对是 2 和 3，怨气 3512。

样例
输入： 4 6 1 4 2534 2 3 3512 1 2 28351 1 3 6618 2 4 1805 3 4 12884 输出： 3512
引导性提示（先只看这里）

题目要最小化的是「同一监狱内怨气值的最大值」。先想一个更简单的判定：如果允许的上界是 x，能不能把所有冲突都压到 ≤ x？这个判定比原问题好做得多。

判定就是：只保留怨气 > x 的那些仇恨对，它们必须被分到两座不同的监狱——这不就是「这张图能不能二分染色」吗？一旦判定是单调的，答案就能二分。

还有一条更像 Kruskal 的路：把仇恨按怨气从大到小排序，一条一条处理，每次把两个人拆到两边（用并查集维护「谁和谁同侧」，另开一个 enemy 数组记住每个人第一个敌人）。第一次遇到「这两个人已经被逼到同一侧」时，那条边的怨气值就是答案。

想看思路了？点开完整思路

① 换一个问法。答案是「最小的 x，使得把怨气 > x 的仇恨对全部分隔到两座监狱是可行的」。x 越大越容易做到，单调性成立。

② 并查集 + 贪心（本节做法，与 Kruskal 同一个骨架）。把边按怨气从大到小排序，依次处理。对边 (u, v, c)：如果 find(u) == find(v)，说明 u、v 已经被前面那些更大的怨气逼到了同一侧，这条 c 无论怎么分都躲不掉，它就是答案；否则把两人拆开——并查集里「u 与 v 的敌人同侧」、「v 与 u 的敌人同侧」。

③ 为什么贪心对。处理到 (u,v,c) 时，所有怨气更大的边都已经被成功拆开了，所以存在一种分配把 > c 的冲突全部消掉，答案 ≤ c 是上界；而此刻 find(u) == find(v) 说明「u、v 不同侧」这个要求与前缀里的约束已经矛盾，任何分配都无法避免这条 c 的冲突，答案 ≥ c。两边合起来就是答案 = c。

④ 输出 0 的情况。整张图（所有仇恨对）本身能被二分，一次冲突都不会发生。此时循环一次也没 break，ans 保持初值 0。

等价做法：二分 + 二分图染色。二分上界 x，只保留 c > x 的边跑染色判定，O((n+m) log 10⁹)。两条路都对，选一条写熟即可；并查集版常数更小，且直接复用了本节 Kruskal 的并查集。

复杂度。排序 O(m log m) = 10⁵ × 17 ≈ 1.7×10⁶ 次比较，并查集部分 2m 次 find，几乎不耗时。

#include <bits/stdc++.h>
using namespace std;

const int N = 20005, M = 100005;
int n, m;
struct Edge { int a, b, c; } e[M];
int fa[N], enemy[N];

int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

void merge(int x, int y) {
    x = find(x); y = find(y);
    if (x != y) fa[x] = y;
}

int main() {
    scanf("%d%d", &n, &m);
    for (int i = 0; i < m; ++i) scanf("%d%d%d", &e[i].a, &e[i].b, &e[i].c);

    // 怨气大的先处理：先保证更严重的冲突被拆开（与 Kruskal 同一个贪心骨架）
    sort(e, e + m, [](const Edge &p, const Edge &q) { return p.c > q.c; });

    for (int i = 1; i <= n; ++i) fa[i] = i;

    int ans = 0;
    for (int i = 0; i < m; ++i) {
        int u = e[i].a, v = e[i].b;
        if (find(u) == find(v)) { ans = e[i].c; break; }   // 只能关进同一间：这条就是答案
        if (enemy[u]) merge(enemy[u], v); else enemy[u] = v;   // u 的敌人和 v 同侧
        if (enemy[v]) merge(enemy[v], u); else enemy[v] = u;
    }

    printf("%d\n", ans);
    return 0;
}
