21 · 递归：出口、递推与栈

把问题照原样拆成同类的小问题：写清出口、保证参数变小、数清递归树的深度与节点数，并知道什么时候必须改成循环。
⭐ 已学范围普及-预计 60 分钟递归递归树爆栈

把一个规模为 n 的问题，交给规模更小的同类问题去解决——这就是递归。它能停下来，只因为存在一个不需要再拆的小情形。

两个错法
int f(int n) { return f(n - 1) + 1; }          // ① 没有出口

int g(int n) {                              // ② 有出口，但同一件事算了又算
    if (n <= 2) return 1;
    return g(n - 1) + g(n - 2);
}

① 的调用链 f(n) → f(n−1) → f(n−2) → …永不停，栈一直往下压，直到用完栈空间，程序收到 SIGSEGV（Windows 上是 0xC00000FD），评测判 RE。② 有出口，但 g(n−1) 展开时已经把 g(n−2)、g(n−3) 都算过一遍，外面又为 g(n−2) 把这一整批下标重新算一遍。调用次数是 φⁿ 级——g(40) 约 3×10⁸ 次，g(50) 到 4×10¹⁰ 次，判 TLE。小数据它跑得飞快，这才是最坑的地方。这个“重复计算”的毛病下一节用记忆化治。

写递归只问三句话：① 最小的情形，答案是多少？② n 的答案能不能用更小的答案拼出来？③ 每次调用，参数是不是真的变小了？三句话答不上任何一句，代码一定是错的。
推导递归函数：把数学定义照抄成代码覆盖：递归函数 / 出口 / 递推 / 参数变小 / 返回类型 / 调用深度需求 → 尝试 → 验证 → 定理
问题

现在要算 n!，手上只有两条数学事实：1! = 1、n! = n × (n−1)!。写成 for 循环，得先把“从 1 乘到 n”这个过程在脑子里翻译一遍；换成二叉树大小、汉诺塔、全排列，这个过程每次都要重新想一遍，而且很容易想漏。

更别扭的是第二条事实：n! 的定义里出现了 (n−1)!，它是一个“自己依赖自己”的结构，循环的语法里根本没有对应的写法。

直接硬写又会踩两个坑：忘了什么时候停，调用链一直往下压、栈被用完（RE）；停是停了，可同一件事被反复算（本节开头那两个错法，第二个是 TLE）。所以先要弄清：一个能停、能算对、还能把结果带回上一层的“自己调自己”的函数，由哪几块拼成？

1先找出“不用再拆”的那一档

任何递归定义里都藏着最小的一档：0! = 1! = 1、空树大小 0、只剩一个盘子时直接搬。它不需要再问下一层，答案直接给出来，这叫出口（base case）。

① 出口写在函数最前面
if (n <= 1) return 1;      // 出口：0! = 1! = 1，不再往下问

它是整个递归的“地基”：有它，函数才有停下来的地方。

验证 / 关键

出口必须存在，而且必须能到达。参数每次减 1，从 n 出发一定会经过 1；但如果出口写成 if (n == 0)、而参数每次减 2，5 → 3 → 1 → −1 就整个越过了出口，函数再也停不下来——这就是“没有出口”的死法。

2再把“大问题 = 小问题 + 一点活”写成一行

定义的第二条 n! = n × (n−1)! 本身就是一条现成的递推式：把 (n−1)! 交给下一层去算，本层只负责乘一个 n。

② 递推：把问题变小
return (long long)n * fact(n - 1);   // ② ③ n! = n × (n-1)!

这里 fact(n - 1) 就是“更小的同类问题”，前面的乘号就是“本层要多做的一点活”。数学定义怎么写，代码就怎么抄，一个符号都不用改。

验证 / 关键

参数必须变小。n−1、n/2、左半区间……只要保证每次调用都朝出口靠近。参数不变（误写成 fact(n)）就是无限递归。判断依据是“从 n 到出口要走几步”，而不是“总共调用几次”。

3最后核对签名：返回什么、拿什么当参数

函数体的形状定了，剩下的都是签名问题：返回值要能被上一层接住并参与运算（要算数就用 int / long long，只做事写 void）；想往下传信息，就再加一个参数（例如当前深度）。

把递归函数的每个组成部分和它的要求列成一张表，写递归时逐条对一遍，就不会漏：

组成含义 / 格式要求
出口（base case）不再递归、直接给答案的最小情形。必须存在，且必须能到达。
递推（recursive step）用 f(更小的参数) 表示 f(参数)。这个等式就是数学上的递推关系，照抄即可。
参数必须变小n−1、n/2、左半区间……只要保证每次调用都向出口靠近。参数不变就是无限递归。
返回类型递归函数首先是函数，返回值能被上一层接住、参与运算。要算数就用 int/long long，只做事就写 void。
调用深度从 main 到最底层出口的调用层数。它由“参数从 n 减到出口要走几步”决定，与调用总次数无关。
返回值累加多层结果靠 return 一层层往上传；想往下传就加一个参数（例如当前深度）。
最小可运行示例
long long fact(int n) {              // 求 n!
    if (n <= 1) return 1;            // ① 出口：0! = 1! = 1
    return (long long)n * fact(n - 1);   // ② ③ n! = n × (n-1)!
}

int main() {
    cout << fact(5) << "\n";         // 120
    return 0;
}
注意

fact 的调用链是 fact(5)→fact(4)→…→fact(1)，深度 5。语句 return n * fact(n-1)里，“乘 n”这一步要等下层返回后才执行，所以它发生在“回来的路上”。

递归不是“循环的替代品”，它是“把问题定义照抄成代码”。数学定义里有 f(n)=n·f(n−1)，代码里就有一行一样的。

验证 / 关键

对着示例走一遍：fact(5) 压 5 层，fact(1) 返回 1，回来时依次 1×2=2、2×3=6、6×4=24、24×5=120。三条检查同时成立——有出口、参数每次都变小、返回值一路都是 long long——这个递归就是对的。

于是我们得到：

于是我们得到：递归函数 = 出口 + 递推 + 参数变小，三样缺一不可。只有出口没有递推，等于只处理了最小情形；只有递推没有出口，调用链停不下来，必 RE；递推里参数没变小，也一样停不下来。

写法上就是“把数学定义照抄成代码”：定义里“什么时候不用再拆”写成 if ... return，定义里“n 和 n−1 的关系”写成 return ... f(n-1)；最后核对返回类型、参数、深度。递归不是循环的替代品，它是把定义直接翻译成程序。

追问 · 把这一步想透
  1. 斐波那契的朴素递归 f(n) = f(n−1) + f(n−2) 画出 n = 5 的递归树，数一数 f(1) 被算了几次、f(2) 被算了几次。为什么越靠下的项被算的次数越多？这个观察是下一节记忆化的出发点。
    想好了？点开核对思路与解析
    n = 5 时共 9 次调用：f(5) 1 次、f(4) 1 次、f(3) 2 次、f(2) 3 次、f(1) 2 次。越靠下的项被算得越多，是因为每个 f(k) 都是 f(k+1) 与 f(k+2) 两条分支的交汇点——往上每走一层就多一条路通向它，调用次数约按 φ 的 (n−k) 次方增长。n = 40 时总数到 3×10⁸，而状态只有 40 个，这就是下一节记忆化要修的“重复计算”。常见错路：把“状态数 40”当成“调用次数 40”——爆炸的是调用次数，状态数一直是线性的。
  2. 汉诺塔 n 层的移动次数是 2ⁿ − 1，递归树的节点数也是 2ⁿ − 1 吗？把它和烤鸡的三叉树比一比，谁的树更“宽”、谁的更“深”？两者的节点数各是深度的什么函数？
    想好了？点开核对思路与解析
    节点数确实是 2ⁿ − 1，不是 2^(n+1) − 1：hanoi(n) 每次只产生两个子调用，第 k 层有 2^(k−1) 个结点，求和就是 2ⁿ − 1。它与移动次数数值相同纯属巧合——每个结点恰好执行一次移动；但“调用次数”和“第几层”始终是两个量。和烤鸡的三叉树比：烤鸡更“宽”（每层 3 叉，同深度 11 时叶子 59049 对汉诺塔 n = 11 的 1024），汉诺塔更“深”（深度等于 n，30 以上就爆栈）。对深度的函数：汉诺塔 2ⁿ − 1 是纯指数，烤鸡 (3^(h+1) − 1)/2 也是指数、底数更大——所以“深度小、分支多”的树节点更多但更安全。常见错路：把节点数记成 2^(n+1) − 1（多算一层），或者把“移动次数”直接当“递归调用次数”——换一道每层要做多次操作的题就不成立了。
推导栈帧：一次调用在内存里留下什么覆盖：栈帧 / 一帧多大 / 栈大小 / 深度估算 / 爆栈症状需求 → 尝试 → 验证 → 定理
问题

上一页的 fact(10) 写得对，可换成 fact(1000000) 就 RE；而刚看的那个搜索“调用 88573 次、深度只有 11”却一点事没有。同样是用递归，为什么一个炸、一个稳？

说明“调用”本身有代价，而且这个代价不是按调用次数算的。要算清这笔账，得先看看每次调用在内存里到底留下了什么。

1调用 = 压入一帧，返回 = 弹出这一帧

程序运行时，函数调用用的是一块叫栈的内存：调用 f 时压入一帧（栈帧），f 返回时把这一帧弹出，返回值交给调用者。

栈的进出
调用 f  →  压入一帧：形参、局部变量、返回地址
f 返回   →  弹出这一帧，返回值交给调用者
验证 / 关键

所以栈的占用是“同时活着的帧数”，也就是深度，不是“一共调用过多少次”。深度 11 的搜索，栈上最多 11 帧；深度 10⁶ 的递归，栈上就有 10⁶ 帧——调用次数再多，只要不同时活着，就不占栈。

2一帧多大，栈有多小

一帧里装的是这个函数自己的形参、局部变量，以及“返回后从哪一行继续执行”的地址，通常 32~64 字节。

如果函数里定义了局部数组，一帧会猛涨：一句 int t[1000];，每帧立刻多 4KB。

问题答案
一帧装什么这个函数自己的形参、局部变量，以及“返回后从哪一行继续执行”的地址。
一帧多大通常 32~64 字节。函数里定义了局部数组会猛涨：写一句 int t[1000];，每帧立刻多 4KB。
栈有多小全局数组、new/malloc 在堆上，能用几百 MB；函数调用和局部变量在栈上，Linux 常见 8MB，Windows 默认 1MB。
算深度8MB ÷ 48B ≈ 1.7×10⁵ 层。所以递归深度几千是安全的，几十万就要出事，一百万一定 RE。
验证 / 关键

把数字代进去就能预先判断：每帧 48 字节、深度 10⁵ 时约 5MB，8MB 栈刚好够；深度 10⁶ 时约 50MB，必 RE。这就是 fact(100000) 勉强能跑、fact(1000000) 一定炸的原因。

3爆栈长什么样，怎么和“调用次数”区分开

爆栈不会给你一个漂亮的报错，只会让程序在某一刻突然没了。看症状能判断是不是栈的问题：

症状 / 判据含义
爆栈症状Windows 弹 0xC00000FD，Linux 收 SIGSEGV，洛谷上都显示 RE；也可能是“输出到一半突然停住”。
与调用次数的区别调用 10⁶ 次、深度 10 的递归完全安全；调用 10⁶ 次、深度 10⁶ 的递归必炸。
最小可运行示例
long long fact(int n) {
    if (n <= 1) return 1;
    return (long long)n * fact(n - 1);   // 每层一帧
}

// fact(100000);   深度 10⁵，约 5MB，8MB 栈刚好够
// fact(1000000);  深度 10⁶，约 50MB，必 RE
注意

把 const int MAXN = 1e6; 的数组写进函数里，是最常见的爆栈原因——递归还没开始，一帧就已经 4MB。大数组一律开在全局。

深度到 10⁵ 时，先想能不能改迭代；实在要递归，就把栈调大（ulimit -s 或编译选项），但那只是把上限往后推。

验证 / 关键

一句话判据：只看深度和每帧大小，不看调用总次数。深度 = 参数从入口减到出口要走几步；每帧大小 = 形参 + 局部变量 + 返回地址。两者相乘不超过栈大小，就一定不会爆。

于是我们得到：

于是我们得到：递归的空间代价 = 深度 × 每帧字节数，它必须小于栈大小。调用总次数不进这个乘积——调用 10⁶ 次、深度 10 的搜索，与调用 10⁶ 次、深度 10⁶ 的递归，空间差 10⁵ 倍。

所以判断一个递归安不安全，只做两个估计：深度会不会到 10⁵ 以上；每帧里有没有大数组。两个都过关，就放心递归；有一个不过关，就先想迭代，或者把数组挪到全局。

    空间 O(log n)：每层一帧，深度是 ⌊log₂n⌋ + 1，n = 10⁶ 时只有 20 层、不到 1KB，所以二分递归版在空间上毫无风险。尾递归能被压成循环的条件是：递归调用是函数的最后一条语句、返回值不被后续使用，且编译器开了优化（GCC/Clang 的 -O2 默认开启 sibling call optimization，MSVC 不保证）。所以二分这种 return f(...) 的写法在 O2 下确实常被压成循环，但标准不保证，不能拿它当“不会爆栈”的依据。常见错路：以为“递归一定比循环费空间”（深度 20 的递归只占 1KB）；反过来以为“写成尾递归就一定被优化”，于是拿它处理 10⁶ 层的数据，在 MSVC 或 debug 构建上直接 RE。
推导assert：把“不可能发生”写成会喊的检查覆盖：assert / 前置条件 / NDEBUG / 副作用需求 → 尝试 → 验证 → 定理
问题

递归写好了，逻辑也对，可跑出来答案是错的，甚至把相邻的全局变量踩坏了。回头看代码，问题往往出在一个“本来不可能出现”的参数上——下标成了 −1、深度超出了数组范围。

C++ 遇到这种参数不会喊：它照样算，读出随机内存里的值，把错误悄悄带到很远的地方。等你在输出里发现不对，已经说不清是哪一层出的错了。

有没有一种写法，能让“这个参数不该是这样”这个假设，在它被破坏的那一瞬间就当场停下？

1assert：条件为假就立刻停

assert(条件表达式); 的语义只有两句：条件为真，什么都不做；条件为假，打印表达式、文件名、行号，然后 abort() 结束程序。

把隐含前提写成一条会喊的检查
assert(n >= 0 && n <= 20);   // 21! 就超出 long long 了

它检查的正是那种“我假设它一定成立、却没写进代码”的前提。

验证 / 关键

代价几乎为零：条件为真时它只是一次判断。所以它可以在递归入口、循环里随便写，真正昂贵的只有“它喊出来”的那一次——而那一次本来就是你想要的。

2用在哪、怎么关掉

递归里最常见的两个隐含前提是“下标不越界”和“深度没超限”，把它们写成断言，调试时间能从一小时缩到一分钟。

提交时不用手删：编译时定义 NDEBUG（g++ -DNDEBUG）后所有 assert 消失，零开销。头文件是 <cassert>，bits/stdc++.h 里已经包含。

组成含义 / 格式要求
头文件<cassert>，bits/stdc++.h 里已经包含，不用另写。
语义条件为真 → 什么都不做；条件为假 → 打印表达式、文件名、行号，然后 abort() 结束程序。
用在哪在递归入口写 assert(k >= 0)，把“这个参数不该是负数”这个假设变成一条会喊的检查。
怎么关掉编译时定义 NDEBUG（g++ -DNDEBUG）后所有 assert 消失，提交时零开销。
验证 / 关键

注意“关掉”这件事本身也是语义的一部分：既然 assert 在正式构建里会消失，它就不能承担任何必须执行的工作。

3两个不能踩的坑：副作用与输入校验

assert 最容易被误用的地方，正好是它的两个边界：

组成含义 / 格式要求
别写副作用assert 里的表达式在 NDEBUG 下根本不执行，所以 assert(f(x)++) 这种写法是陷阱。
别当输入校验输入不合法时应该输出答案，而不是让程序崩在断言上。assert 是调试工具，不是容错机制。
最小可运行示例
long long fact(int n) {
    assert(n >= 0 && n <= 20);   // 21! 就超出 long long 了
    if (n <= 1) return 1;
    return (long long)n * fact(n - 1);
}

// fact(-1) → Assertion `n >= 0 && n <= 20' failed. 程序立刻停下
注意

assert 最大的价值是“把隐含前提写出来”。递归里最常见的隐含前提是“下标不越界”“深度没超限”，这两条写成断言，调试时间能从一小时缩到一分钟。

本地加 assert、提交前不用删——NDEBUG 一开它们就没了。

验证 / 关键

检查两条：断言里有没有改动状态的表达式；被断言拦下的情况，是不是本来应该正常输出答案。两条都没问题，这些 assert 就可以安心留着。

递归迭代（循环）
代码形状照抄数学定义，n 的方案里出现 n−1手工维护一个“当前状态”变量
空间深度 × 每帧字节，受栈大小硬限制O(1)，与规模无关
速度每层一次函数调用，慢 2~5 倍最快
适合结构本身嵌套：树、分治、括号、嵌套表达式一条链、顺序一眼可见：累加、递推
主要风险爆栈（RE）、重复计算（TLE）下标写错、边界写错（WA）
算法落地烤鸡：10 个格子逐个填，两条区间剪枝覆盖：洛谷 P2089 / DFS 枚举 + 可行性剪枝
需求

例题 · 烤鸡 · 洛谷 P2089 普及-

Hanke 有 10 种配料，每种配料可以放 1 到 3 克（整数克），烤鸡的美味程度等于所有配料质量之和。现在给定美味程度 n，要求输出 10 种配料的所有搭配方案。

输出格式：第一行一个整数，为方案总数；接下来每行 10 个整数，依次是这 10 种配料的质量，方案之间按字典序排列。如果没有任何方案，只输出一行 0。

数据范围：n ≤ 10000。注意每种配料最多 3 克，10 种配料最多 30 克，所以 n > 30 时答案必为 0。

1第 1 步：把一个方案看成 10 个格子

换一种说法：一个方案就是 10 个整数 a₁…a₁₀，每个取 1~3，且 a₁ + … + a₁₀ = n。“输出所有方案”于是变成“枚举所有填法”，而填法可以一层一层决定：第 1 格放几克，第 2 格放几克……

数组准备
int n, cnt = 0;
int a[15];                  // 正在拼的这 10 个质量，用 a[1..10]
int ans[9005][11];          // 全部方案：n = 20 时最多 8953 个
为什么

状态只记两样：已经填好的 a[1..step-1]，以及它们的和 sum。和顺着参数往下传，回来时不用还原——它是“这一层的事实”，不是所有分支共享的状态。这一点和后文要用到的 vis[] 正好相反。

方案表 ans[9005][11] 只能放全局：它占 9005×11×4 ≈ 396KB，放进 main 直接压栈；9005 这个数字来自 n = 20（方案最多的一档）的 8953 个方案，开成 1000 就是越界写。

2第 2 步：出口是第 11 层，而且要“先存表、不输出”

step 走到 11 表示 10 格全填好了，这一行方案确定下来。

出口
if (step == 11) {               // 10 格填满；能走到这里，和一定正好等于 n
    ++cnt;
    for (int i = 1; i <= 10; ++i) ans[cnt][i] = a[i];
    return;
}
为什么

注意这里不能立刻输出：题目要求第一行先给方案总数，必须把方案存进一张表，等搜索结束、总数确定了再一起输出。这是本题比一般搜索多出来的一步。

出口写成 step == 10 会漏掉最后一格：第 10 格还没定案就记录，n = 11 时会输出一堆只有 9 个数的行。正确的出口是 step == 11。

3第 3 步：两条区间剪枝，把够不着的子树整棵砍掉

没到出口也能提前判死。剩下 11 - step 格，每格最多 3 克、最少 1 克，所以从当前的和出发，最终结果一定落在 [sum + (11-step), sum + 3(11-step)] 里。

两条剪枝
// 可行性剪枝：剩下的 11-step 格，全填 1 都超了、或全填 3 都不够，整棵子树砍掉
if (sum + (11 - step) > n) return;
if (sum + 3 * (11 - step) < n) return;
为什么

两条判断都在“进下一层之前”，代价 O(1)，换掉的是一整棵子树。n = 11 时访问节点从 88573 掉到 166，n = 20（方案最多的一档）也只访问 50101 个；n = 10、n = 30 这种贴边界的输入只剩 31 个节点。

坑在 11 - step：剩下的格子数是 11 减 step，不是 step。上界剪枝写成 sum + 3 * step < n，后半段的界会算得偏小，合法方案被一起砍掉。

4第 4 步：候选值 1→3，字典序是白送的

第 step 格可以取 1、2、3。让 v 从 1 到 3 递增，输出顺序就天然是字典序。

枚举这一格的取值
for (int v = 1; v <= 3; ++v) {  // 从小到大：字典序靠的就是这个顺序
    a[step] = v;
    dfs(step + 1, sum + v);
}
为什么

字典序比的是第一个不同的位置，而前面的位置先定下来、并且按从小到大尝试——所以先产生的方案字典序一定更小。改成 3→1 递减，答案集合一个不差，但顺序整个反过来，逐字比对必挂。

sum 是值传递的：dfs(step + 1, sum + v) 里的 sum + v 只影响下一层，回来时本层的 sum 原封不动，所以不用写“还原 sum”。a[step] 也不用还原，下一层的循环会覆盖它。

5第 5 步：先打总数、再逐行输出，最后拼回完整程序

搜索结束后 cnt 就是方案总数，先打它，再按存的顺序输出每一行。

main 里做的事
cin >> n;
dfs(1, 0);                      // 从第 1 格开始填，当前和是 0

cout << cnt << "\n";            // 第一行：方案总数
for (int i = 1; i <= cnt; ++i)
    for (int j = 1; j <= 10; ++j)
        cout << ans[i][j] << (j == 10 ? '\n' : ' ');

把上面五段拼起来就是完整程序，可以直接提交：

完整代码
#include <bits/stdc++.h>
using namespace std;

int n, cnt = 0;
int a[15];                  // 正在拼的这 10 个质量，用 a[1..10]
int ans[9005][11];          // 全部方案：n = 20 时最多 8953 个

void dfs(int step, int sum) {
    // 可行性剪枝：剩下的 11-step 格，全填 1 都超了、或全填 3 都不够，整棵子树砍掉
    if (sum + (11 - step) > n) return;
    if (sum + 3 * (11 - step) < n) return;

    if (step == 11) {               // 10 格填满；能走到这里，和一定正好等于 n
        ++cnt;
        for (int i = 1; i <= 10; ++i) ans[cnt][i] = a[i];
        return;
    }
    for (int v = 1; v <= 3; ++v) {  // 从小到大：字典序靠的就是这个顺序
        a[step] = v;
        dfs(step + 1, sum + v);
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    dfs(1, 0);                      // 从第 1 格开始填，当前和是 0

    cout << cnt << "\n";            // 第一行：方案总数
    for (int i = 1; i <= cnt; ++i)
        for (int j = 1; j <= 10; ++j)
            cout << ans[i][j] << (j == 10 ? '\n' : ' ');
    return 0;
}
为什么

输出格式是易错点：10 个数之间一个空格、行末换行，所以写 (j == 10 ? '\n' : ' ')；写成每个数后面都跟空格，会因行末多空格而 WA。

规模也不用担心：n = 20 要打 8953 行、每行 10 个数，约 3×10⁶ 个字符。但输出用 endl 会行行刷新缓冲区，同一份答案直接 TLE。

竞赛用法

题型特征：要求“输出全部方案”，且方案可以按位逐个决定——每格取值独立、方案之间靠前缀区分。看到“所有搭配 / 所有序列 / 按字典序输出”，就往 DFS 枚举上想；再找一条“剩下的怎么填都不够、或都超了”的区间判断，就是可行性剪枝。

复杂度：与搜索树的节点数成正比，不是与 n 成正比。不剪枝时节点 1+3+…+3¹⁰ = 88573、叶子 3¹⁰ = 59049；加两条区间剪枝后 n = 11 只访问 166 个、n = 20 最多 50101 个。深度固定 11 层，栈占用不到 1KB。

常见坑：出口写成 step == 10；剪枝写成 3 * step；方案表开小（n = 20 有 8953 个方案）；候选逆序导致字典序反转；行末多空格；用 endl 输出。

模型：DFS 枚举填格O(搜索树节点数)坑：出口是 step == 11坑：ans 要开 9005

    递归树变成 4 叉：每层候选从 3 个变成 4 个，深度仍是 11，不剪枝时节点数 (4¹¹ − 1)/3 = 1398101、叶子 4¹⁰ = 1048576。出口不用改还是 step == 11；下界剪枝要改成 sum + 0*(11−step) > n（也就是 sum > n，可以直接删掉），上界剪枝 sum + 3*(11−step) < n 原样保留。n = 20 时的方案数从 8953 变成 44803（容斥：C(29,9) − 10·C(25,9) + 45·C(21,9) − 120·C(17,9) + 210·C(13,9) − 252）。常见错路：只把 for 的起点改成 0，忘了方案表也要跟着加大——ans[9005][11] 装不下 44803 个方案，越界写会踩坏相邻全局变量，症状是满屏随机数。

同一件事换一种遍历顺序：递归是“一格一格往下钻”，迭代可以“把一个方案看成一个 10 位的三进制数”，从 0 数到 3¹⁰ − 1。第 i 位是几，第 i 种配料就放几克；数从 0 往上加，输出顺序正好还是字典序。

递归转迭代（暴力枚举全部 3¹⁰ 个方案）
// 迭代版：把 10 个质量看成一个 10 位的三进制数，从 0 数到 3^10 - 1
long long total = 1;
for (int i = 0; i < 10; ++i) total *= 3;        // 3^10 = 59049
for (long long mask = 0; mask < total; ++mask) {
    long long t = mask;  int sum = 0;
    for (int i = 10; i >= 1; --i) {             // 低位给 a[10]，高位给 a[1]
        a[i] = t % 3 + 1;  t /= 3;  sum += a[i];
    }
    if (sum == n) { /* 记入 ans，cnt 加一 */ }
}

代价对比：迭代版固定枚举 59049 个方案、每个方案 10 次取模，约 6×10⁵ 次操作；递归 + 区间剪枝在 n = 11 时只访问 166 个节点，n = 20 时 50101 个。同一个答案，工作量差了三个数量级——差别就在“把不可能的整棵子树挡在门外”和“枚举完再判断”。

这一节的 6 个典型错法（附症状）

WA，第一行少了一个数字：在出口直接 cout 方案，忘了总数要打在最前面。题目要求先给总数，所以必须先把方案存进表再统一输出。

WA，最后一格永远没被填：出口写成 if (step == 10)，于是第 10 格还没定案就记录，n = 11 时会输出一堆只有 9 个数的行。正确的出口是 step == 11。

WA，方案成片消失：上界剪枝写成 sum + 3 * step < n。剩下的格子数是 11 - step，写成 step 会让后半段的界算得偏小，把合法方案一起砍掉。

WA，顺序不对：候选值从 3 递减到 1。方案集合一个不差，但字典序变成倒序，第一行就不一样。

RE / 答案被踩坏：ans[9005][11] 开小（例如 ans[1000][11]）。n = 20 时有 8953 个方案，写越界会踩坏相邻的全局变量，症状是满屏随机数。

TLE：输出用 endl。n = 20 要打 8953 行、每行 10 个数，行行刷新缓冲区非常慢。

递归专属的三个坑（和本题无关，但每次写递归都会遇到）

RE（爆栈）：递归深度 10⁶ 却每帧还带一个局部数组。int t[1000] 让每帧多 4KB，25 层就吃掉 100KB，几千层就炸。

TLE（重复计算）：f(n) = f(n-1) + f(n-2) 直接递归，n = 40 时调用约 3×10⁸ 次。调用次数是 φⁿ 级别，不是 n 级别——这种“看着像 O(n)”的错觉是本组最大的坑。

WA（返回值类型太小）：递归结果一路 return 上来，中间任何一层用了 int，结果就在那一层被截断。阶乘 21! 就超 int，用 long long。

数学补给 · 递归树：节点数是时间，深度是空间

把每次函数调用画成一个点，它调用的三个子调用画成孩子，得到一棵递归树。树上三个量分别对应三个问题：

量对应什么烤鸡里是多少
深度 h最大栈帧数，决定会不会爆栈11（从第 1 格到第 11 格的出口）
节点总数函数调用总次数不剪枝 (3¹¹ − 1)/2 = 88573
叶子数候选方案个数3¹⁰ = 59049

节点数用等比数列求和：1 + 3 + 9 + … + 3¹⁰ = (3¹¹ − 1)/2 = 88573。叶子在最后一行（step = 11），共 3¹⁰ = 59049 个；每个叶子若直接输出 10 个数，输出量约 3×10⁶ 个字符——不剪枝时瓶颈已经从搜索转到输出。

剪枝改的是节点数，不改深度。两条边界 sum + (11−step) 与 sum + 3(11−step) 把“已经凑不出 n”的子树整棵砍掉。实测访问节点数（含被砍掉的那些调用本身）：

n = 20 是最坏的一档，因为“10 个 1~3 的数凑成中间值”的方案最多；即便这样也只访问 50101 个节点，是不剪枝时的 57%。而 n = 10、n = 30 这种贴着边界的输入，剪枝后只剩 31 个节点——边界给得越紧，砍掉的越多。

同一棵树也能写成递推式：T(k) = 3T(k−1) + 1，T(0) = 1，解得 T(k) = (3ᵏ⁺¹ − 1)/2。对照主定理的形式 T(N) = aT(N/b) + O(1)：a = 3、b = 3，于是 T(N) = Θ(N^log₃3) = Θ(N)，其中 N = 3¹⁰。也就是说节点数与“候选方案总数”同阶，这类枚举的最好复杂度就是 Θ(输出规模)，不可能再低。

空间：调用 88573 次，但栈深度只有 11，每帧约 48 字节，总共不到 600 字节。这就是本题用递归毫无风险、而 fact(10⁶) 立刻 RE 的原因——调用次数和栈深度是两个数，永远分开算。

最后一句留给下一节：n = 20 时那 50101 个节点里，有大量是“换个顺序走到同一个和”的重复状态。如果能让每个状态只算一次，指数就会掉成多项式——这就是记忆化。

挑战题 · 幂次方
洛谷 P1010普及-去洛谷做这题 ↗

任何一个正整数都可以拆成若干个 2 的幂之和。例如 137 = 2⁷ + 2³ + 2⁰。

现在约定写法：2⁰ 写成 2(0)，2¹ 写成 2，2ᵏ（k ≥ 2）写成 2( k 的表示 )，其中指数 k 也用同一套规则表示。多个幂之间用 + 连接，指数从大到小排列。例如 7 = 2² + 2 + 2⁰ 写成 2(2)+2+2(0)，137 写成 2(2(2)+2+2(0))+2(2+2(0))+2(0)。

输入：一个正整数 n（1 ≤ n ≤ 20000）。输出：一行，即 n 的表示，中间不加任何空格。

引导性提示（先只看这里）

先只做一层：把一个数拆成 2 的幂之和，指数从大到小排列。20000 < 2¹⁵，所以指数最大是 14。

指数本身也要用同一套规则表示——这就是递归：同一个函数，参数从 n 变成指数 i，规模严格变小。

0 次幂和 1 次幂是两种特例，不能套 2(...) 的格式；另外想清楚 + 只应该出现在什么位置。

想看思路了？点开完整思路

把 n 看成二进制位：第 i 位是 1，就说明 n 的式子里要出现 2ⁱ。指数从 14 扫到 0，天然满足“从大到小”。

定义 print(n)：输出 n 的表示（不带外层括号）。对每一位 i，若第 i 位为 1：先按需输出 +；再分三种情况输出这一项。

三种情况：i = 0 输出 2(0)；i = 1 输出 2；i ≥ 2 输出 2(，递归调用 print(i)，再输出 )。

为什么一定停：递归只在 i ≥ 2 时发生，而指数每次严格小于上一层，最多 14 层就降到 0 或 1，而这两种情况不再递归。所以既不需要显式出口，也不会爆栈。

为什么对：n 的每个二进制 1 位恰好贡献一个片段，片段之间用 + 连着；每个片段的指数表示由同一个函数、更小的参数给出。不重不漏。

总代价 = 递归树节点数 × 每个节点的 15 次循环。n = 20000 = 2¹⁴+2¹¹+2¹⁰+2⁹+2⁵，二进制只有 5 位是 1，树小到可以忽略，微秒级出答案。

#include <bits/stdc++.h>
using namespace std;

// 输出 n 的表示，不含外层括号
void print(int n) {
    bool first = true;                 // 是不是第一个片段
    for (int i = 14; i >= 0; --i) {    // 20000 < 2^15，指数最大 14
        if ((n >> i) & 1) {            // 第 i 位是 1，说明要写 2^i
            if (!first) cout << "+";   // 加号只出现在片段之间
            first = false;

            if (i == 0)      cout << "2(0)";              // 特例：0 次幂
            else if (i == 1) cout << "2";                 // 特例：1 次幂
            else { cout << "2("; print(i); cout << ")"; }  // 一般情况：指数递归展开
        }
    }
}

int main() {
    int n; cin >> n;
    print(n);
    cout << "\n";
    return 0;
}
关键片段拆解
片段作用
for (int i = 14; i >= 0; --i)从最高位往低扫，输出顺序天然符合“指数从大到小”。14 是因为 2¹⁴ = 16384 ≤ 20000 < 32768 = 2¹⁵。
if ((n >> i) & 1)取 n 二进制第 i 位。等价于 (n / (1 << i)) % 2，但位运算更短也不会溢出。
if (!first) cout << "+";加号只能加在两个片段之间。第一个片段前面加、或者末尾多一个，都是 WA。
if (i == 0) cout << "2(0)";0 次幂是约定出来的特例。若套一般格式，会输出 2()。
else if (i == 1) cout << "2";1 次幂直接写 2，不写 2(1)。这条最容易被忘，样例第一段就会对不上。
print(i);指数递归展开。只有当 i ≥ 2 才会走到这里，而 i 严格小于 14，所以最多 14 层，一定停。
bool first = true;用“是不是第一个”这一位代替“最后一个不加加号”的判断，省掉回头看的问题。
这题最容易错的地方
  • 漏掉 i == 1 的特例，输出 2(1)。
  • 漏掉 i == 0 的特例，对 0 递归，什么也不输出，得到空的 2()。
  • 加号加了两次：既用 first 判断，又在循环外补了一句，导致开头或结尾多一个 +。
  • 把循环写成 for (int i = 0; i <= 14; ++i)，输出顺序变成从小到大，与“指数从大到小”的约定冲突。

挑战 2 · Secret Cow Code S
洛谷 P3612普及/提高-去洛谷做这题 ↗

给定一个由大写字母组成的初始串 s（长度不超过 30），以及一个下标 N（N ≤ 10¹⁸）。

定义变换 F：把 s 后面接上“s 右旋一位”的结果——右旋一位指把最后一个字符搬到最前面。例如 s = COW 时，右旋一位得到 WCO，于是 F(s) = COWWCO。对这个新串反复做同样的变换，长度每次翻倍，得到一个无限长的字符串：

COW → COWWCO → COWWCOOCOWWC → …

任务：求这个无限长字符串中第 N 个字符（第一个字符的位置是 N = 1）。

输入格式：一行，一个字符串 s 和一个整数 N，中间用一个空格隔开。输出格式：一行一个字符。

样例
输入： COW 8 输出： C
引导性提示（先只看这里）

N 最大 10¹⁸，任何一个字符串都装不下它。所以不要造串，只跟踪“位置”这一个数。

长度翻倍以后，第 N 个字符要么还落在前一半，要么落在后一半；后一半是前一半右旋一位。两种情况都能把 N 换算成“上一层里的某个位置”。

右旋一位的对应关系最容易写错：新串的第 1 位是旧串的最后一位，新串的第 k 位（k ≥ 2）是旧串的第 k−1 位。把这个换算写对，规模每步减半。

想看思路了？点开完整思路

建模。设第 t 层串长 len = |s|·2ᵗ。目标位置 N 只在“某一层”里有意义，所以从大往小推：先把 len 翻倍到 ≥ N，再一层层往回收。

一层怎么降。当前串 = A + rot(A)，其中 |A| = h = len/2，rot 是右旋一位。若 N ≤ h，目标就在 A 里，位置不变；若 N > h，令 k = N − h，它是 rot(A) 的第 k 位，而 rot(A) 的第 1 位是 A 的第 h 位、第 k 位（k ≥ 2）是 A 的第 k−1 位，所以 N = (k == 1 ? h : k − 1)。收完这一层，len 减半。

为什么一定停。每轮 len 严格减半，走到 len = |s| 时位置就在原串里，答案就是 s[N−1]。轮数 = log₂(N/|s|) ≤ 60。

为什么对。每一层的换算都是“同一个字符在相邻两层里的位置对应”，是可逆的一一映射，所以沿着这条路收回去，落在原串上的位置唯一确定，不会串位。

两个量级坑。① N 与 len 都会翻到 10¹⁸ 附近，必须 long long；② while (len < N) len *= 2 在 len 已经 ≥ N 之后不能再翻，否则会溢出成长负数、死循环。

复杂度。O(log N) 时间、O(1) 空间，N = 10¹⁸ 时不超过 60 轮。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    long long n;
    cin >> s >> n;

    long long len = (long long)s.size();
    while (len < n) len *= 2;            // 先翻到一个"装得下 n"的长度
    long long base = (long long)s.size();

    while (len > base) {
        long long h = len / 2;           // 前一半 A 的长度
        if (n > h) {                     // 落在后一半 rot(A) 里
            long long k = n - h;         // 是 rot(A) 的第 k 位
            n = (k == 1 ? h : k - 1);    // 右旋：第 1 位是 A 的末位，其余整体后移一位
        }
        len = h;                         // 无论落在哪一半，规模都减半
    }
    cout << s[n - 1] << "\n";            // 位置是 1-based，字符串下标是 0-based
    return 0;
}
关键片段拆解
片段作用
while (len < n) len *= 2;先把长度翻到 ≥ N。翻完后 len 满足 N ≤ len < 2N，最多约 60 次乘法；用 long long 是因为 N 可以到 10¹⁸。
while (len > base)只要当前串还比原串长，就还能往回收一层。收到 base 时位置就落在原串里。
long long h = len / 2;前一半的长度。当前串一定是 A + rot(A) 的形式，两半等长。
if (n > h)只有落在后一半才需要换下标；落在前一半时位置根本不变，这是最容易被写复杂的一步。
n = (k == 1 ? h : k - 1);右旋一位的对应：新串第 1 位 = 旧串第 h 位，新串第 k 位 = 旧串第 k−1 位（k ≥ 2）。写成 n = k 就是把右旋当成了不旋转。
len = h;这一行必须写在 if 外面：无论目标在前一半还是后一半，规模都减半，这是 O(log N) 的来源。
s[n - 1]题目位置从 1 开始，string 下标从 0 开始。差这一格，字符会整体偏一位。
这题最容易错的地方
  • 把右旋当成左旋或直接复制：k == 1 时应当回到 h（前半段的末位），写成 1 就整条链都歪了。
  • N 或 len 用 int：N ≤ 10¹⁸，len 翻倍时直接溢出成负数，循环条件永远成立，TLE 或死循环。
  • 把 len = h 写进 if (n > h) 里面：落在前一半时 len 不减，死循环。
  • 样例只测 N 很小的情况：N ≤ |s| 时一轮都不循环，任何写法都对，必须用 N 很大的数据对拍。
