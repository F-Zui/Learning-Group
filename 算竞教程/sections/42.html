42 · 最短路：Dijkstra 与 Floyd

把 BFS 的队列换成按 dist 排序的小根堆：Dijkstra 靠“每次取 dist 最小的点”做到 O((n + m) log n)，Floyd 用三重循环一次算出所有点对。重点是懒删除、INF 的选法，以及 k 循环为什么必须最外层。
提高-预计 75 分钟DijkstraFloyd堆优化

第 26 节已经会用 BFS 求最短路了，但它有一条隐形前提：每条边的代价都相等。有了这条前提，“先到”才等于“最近”。题目一旦给出边权 3、7、1 这样的数字，这个前提就碎了 —— 走两步的路径可能比走一步的代价还小。

于是要换判据：不比“第几层”，比“当前累计代价谁最小”。把 BFS 的队列换成按 dist 排序的容器，就得到 Dijkstra；把“一次算一个源点”改成“一次算所有点对”，就得到 Floyd。本节就这两个。

Dijkstra 的全部正确性压在一句话上：每次取出当前 dist 最小的点，它的 dist 已经不会再变小了。边权非负是这句话成立的唯一理由。
算法解决什么复杂度对边权的要求什么时候用
BFS（第 26 节）单源O(n + m)全部相等（通常为 1）无权图、最少步数
Dijkstra（堆优化）单源O((n + m) log n)非负绝大多数单源题，m 到 10⁶
Floyd全源（所有点对）O(n³)允许负边，不能有负环n ≤ 300~500，或要任意两点距离
Bellman-Ford / SPFA单源 + 判负环O(nm)允许负边有负权边时（本节只提一句）

先记三个数字，它决定了你该选谁。① n = 10⁵、m = 2×10⁵ 时，一次堆优化 Dijkstra 约 (n + m)·log m ≈ 3×10⁵ × 18 ≈ 5×10⁶ 次操作，稳过。② n = 500 时 Floyd 是 1.25×10⁸ 次内层操作，约 0.3 秒，能过。③ n = 1000 时 Floyd 是 10⁹，必超时 —— 而同样规模下跑 1000 次 Dijkstra 是 10⁹ 级，也不行。所以“n 小用 Floyd”里的“小”是 500，不是 5000。

推导priority_queue 存 pair（堆里放 (距离, 点号)）覆盖：priority_queue / pair / greater / 懒删除需求 → 尝试 → 验证 → 定理
问题

BFS 的队列是“先入队先出队”。边权相等时这恰好等于“先到即最近”；一旦边权不一样，队头可能是一条代价 9 的路，队尾却躺着代价 1 的路 —— 顺序全乱了。

所以要换容器：每次都能取出“当前距离最小”的那条记录。还要能随时插入新记录（距离被改小时）。普通数组做不到快速取最小，queue 不排序，能同时满足这两条的是堆，也就是 priority_queue。

剩下的问题是：堆里那个元素，应该长什么样？

1尝试①：先把堆的接口定下来

priority_queue 只提供三件事：push 插入、top 看堆顶、pop 删堆顶。默认是大根堆（最大的在顶），要小根堆得自己给比较器。

签名
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;
pq.push({d, u});
验证 / 关键

三个模板参数一个都不能省：元素类型、底层容器、比较器。想换比较器就必须把容器也写出来 —— 这是 priority_queue 最反直觉的地方。三个参数得写全。

2尝试②：堆里放的必须是“一条记录”，不是“一个点”

只放点号 u 的话，取出来还得回表查 dist[u]，而堆没法按 dist 排序 —— 顺序由点号决定，等于没排序。所以要把“距离”一起打包，用 pair。Dijkstra 的堆里一个元素就是一条“到 u 的距离是 d”的记录，不是点本身 —— 同一个 u 可以有多条记录。

组成部分含义 / 格式要求
pair<int,int>把“距离”和“点号”打成一个元素。堆里一个元素就是一条“到 u 的距离是 d”的记录，不是点本身 —— 同一个 u 可以有多条记录。
第一个参数（元素类型）必须是 pair，因为堆里要同时带走距离和点号。只放点号的话，取出来还得回表查 dist，而 priority_queue 不支持按 dist 排序。
第二个参数 vector<pair<int,int>>底层容器。想换比较器就必须把它写出来 —— 这是 priority_queue 模板最反直觉的地方：三个参数得写全。
第三个参数 greater<...>比较器。greater 让“更小的”排在堆顶，于是 top() 是距离最小的记录，这正是“小根堆”。
pq.push({d, u})花括号直接构造 pair，等价于 push(make_pair(d, u))。
pq.top()取堆顶，返回 const 引用，不能直接改。要拆开用结构化绑定：auto [d, u] = pq.top();（C++17）。
pq.pop()删掉堆顶，返回 void。所以 top 和 pop 必须成对写，顺序不能反。
不能遍历、不能删任意元素只有 top / push / pop。Dijkstra 靠“重复入堆 + 取出时判旧值”绕开“修改已入堆元素”这个做不到的操作。
验证 / 关键

最后一行是理解 Dijkstra 的关键：堆不支持改已经进去的元素，所以“距离变小”这件事只能靠再 push 一份新的来表示。旧记录不删，留在里面，等它被取出来时再判断要不要用。

3尝试③：压三条进去，看谁先出来
示例
// 小根堆：(距离, 点号)，距离小的先出
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;

pq.push({5, 3});                     // 到 3 号点距离 5
pq.push({2, 7});                     // 到 7 号点距离 2
pq.push({2, 4});                     // 距离同为 2，点号小的在前

while (!pq.empty()) {
    auto [d, u] = pq.top();          // C++17 结构化绑定，拆成两个变量
    pq.pop();
    cout << u << "(" << d << ") ";   // 输出 4(2) 7(2) 3(5)
}
验证 / 关键

输出 4(2) 7(2) 3(5) —— 距离升序；距离相同的时候按点号升序（4 在 7 前）。这条“同距离看 second”的性质不影响答案，但决定了程序的确定性。

4尝试④：两个必须记住的细节
  • 元素类型和比较器必须匹配。距离用 long long 时整个写法都要改成 pair<long long,int> 配 greater<pair<long long,int>>，漏改一个就是满屏模板报错。
  • 同一个点会在堆里出现多次（每次 dist 被改小就 push 一份）。这不是 bug，是“懒删除”的代价，取出时用 if (d != dist[u]) continue; 过滤即可。
于是我们得到：

堆里的记录型写法：元素是 pair<距离, 点号>，比较器写 greater<...>，top() 给的就是“当前距离最小的记录”。

一句话记住：把“到哪个点、距离多远”打成 pair 塞进小根堆。这一句就是 Dijkstra 的全部数据结构，剩下的只是“弹出→验货→松弛→再入堆”。

追问 · 把这一步想透
  1. 如果每条边的权只有 1 和 2 两种，能不能不用堆，把它做成 O(n + m)？提示：把每条权为 2 的边中间插一个虚拟点，拆成两条权为 1 的边（拆点），再用 BFS。
    想好了？点开核对思路与解析
    能。把每条权为 2 的边 u→v 拆成 u→x→v，中间插一个虚拟点，两条边权都是 1；新图点数 n + (权 2 的边数)，边数不超过 2m，全是单位权，BFS 一遍 O(n + m)，常数约 2。常见错路：直接写 dist[v] = dist[u] + 2 还照用普通队列——队列按入队顺序出队，权 2 的边会让队列失去“按距离排序”的性质，答案就错了；权只有 0/1 时才有 deque 版的 0-1 BFS（0 压队头、1 压队尾），1/2 这组权重要拆点。
  2. Dijkstra 里什么时候可以提前退出？如果只关心“s 到 t 的距离”，弹出 t 的那一刻能不能停？换成“只关心 s 到某 k 个点的距离”呢？
    想好了？点开核对思路与解析
    只关心 s 到 t：弹出 t 的那一刻可以停，因为出堆顺序就是 dist 递增序，第一次弹出 t 时它的 dist 已经确定。只关心 k 个目标点：第 k 个目标点被弹出时停（用计数器），理由相同。常见错路：在“松弛成功”时判断 v == t 就 break——那时 dist[t] 还可能被后来的路径改小，答案是错的；同理“入堆即停”也不行，入堆只代表候选。
  3. 有 10⁵ 个点和 10⁵ 条边，但所有边的权都是非负整数且总和不超过 10⁶，能不能做得比 Dijkstra 更快？提示：桶排序式的 Dijkstra（Dial 算法），第 28 节的 0-1 BFS 是它在 W = 1 时的特例。
    想好了？点开核对思路与解析
    能，用 Dial 桶排序 Dijkstra。所有 dist 都落在 [0, 10⁶] 内，开 10⁶+1 个桶按距离分桶，从 0 扫到 10⁶，每个点出桶一次、每条边松弛一次，总代价 O(n + m + Σw) ≈ 10⁶，比堆版的 (n+m)log n ≈ 2×10⁶ 还快，常数也更小。0-1 BFS 就是 Σw = n 时的特例：只有两个桶，用 deque 把 0 权边压队头、1 权边压队尾，O(n + m)。常见错路：桶按“最大单边权”开而不是按“总权上界”开，越走越大的距离找不到桶；或者忘了同距离的点要一起处理，退化成普通 BFS。
推导greater 对 pair 的比较（字典序，first 优先）覆盖：greater<pair> / 字典序 / 负数法 / 自定义比较器需求 → 尝试 → 验证 → 定理
问题

上一步把 (距离, 点号) 塞进了 greater 的堆里，但还没解释为什么这样就变成小根堆。更实际的问题是：如果把两个字段写反了，程序还能跑、样例还可能过，只是慢了或者答案全错。

要弄清这件事，得先看 pair 的 > 到底在比什么。

1尝试①：pair 的比较规则是字典序

两个 pair 比大小，先比 first，first 相等才比 second。greater 把这个 > 拿去当“谁更大”的判据，于是“更大的”沉底、“更小的”浮到堆顶。

字典序与写反的后果
pair<int,int> a = {3, 9}, b = {3, 2}, c = {4, 1};
cout << (a > b) << " " << (a > c) << "\n";   // 1 0：first 相等时看 second；3 < 4 所以 a < c

// 所以小根堆里 {3,2} 先于 {3,9}，两者都先于 {4,1}
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;
pq.push({9, 3});        // ✗ 把点号写在了 first：堆按 9 排序，距离 3 根本没参与
pq.push({3, 9});        // ✓ first = 距离 3，second = 点号 9
// 错写法里 {9,3} 和 {3,9} 比的是两个 first（9 与 3），也就是两个"点号"
验证 / 关键

所以“更小的”排堆顶时，实际参与排序的是 first。这就是为什么 first 必须是距离。

2尝试②：first 只能是距离

堆顶 = 距离最小的记录，写成 {u, d} 就变成“点号最小的先出堆”，距离完全没参与比较，“取最小即确定”的依据当场消失。这是本节最隐蔽的错：样例能过，构造数据 TLE，加上 vis 就 WA。

组成部分含义 / 格式要求
字典序比较pair 的 > 是先比 first，first 相等才比 second。greater 把它倒过来用，于是“更小的”排在堆顶。
所以 first 必须是距离堆顶 = 距离最小的记录。写成 {u, d} 就变成“点号最小的先出堆”，距离完全没参与比较，“取最小即确定”的依据当场消失。
first 相同时比 second距离相同的两条记录按点号升序出堆。这只影响同距离点之间的先后，不影响答案。
为什么不能写 greater<int>元素是 pair，比较器必须能比较 pair。greater<int> 和元素类型对不上，报错会指到模板深处。
验证 / 关键

这一条判据很硬：元素类型和比较器必须同时改。距离换成 long long，两个模板参数里的 int 都要跟着换，漏一个就是满屏模板报错。

3尝试③：不想写三个模板参数的两条退路
  • 负数法：priority_queue<pair<int,int>> pq; 配 push({-d, u})，用负号把大根堆当小根堆用。少写两个模板参数，但每个 d 前都要加负号，漏一次就是灾难。
  • 自定义结构体：元素是自己写的 struct 时没有现成的 greater，要重载 operator< 或写函数对象（第 28 节），方向与 sort 的 cmp 相反。

两条退路都不是“更好的写法”，只是要知道它们存在 —— 读别人的题解时天天遇到。

验证 / 关键

负数法验证一下：{-5,3} 和 {-2,7} 比，-5 < -2，所以 距离 5 的记录反而先出堆 —— 大根堆配负距离，等价于小根堆配正距离。

4尝试④：两条容易忘的小事
  • greater 在 <functional> 里，bits/stdc++.h 已包含。
  • 记住一句话：堆里第一个字段永远是排序依据。Dijkstra 里它必须是距离。

比较器的使用规则：greater 让 pair 按字典序取“小”的一端放堆顶，而字典序先看 first。想让堆按距离排序，first 就只能是距离。

顺带记住它的两个替身（负号、自定义 operator<），以及那句总结：pair 按字典序比，greater 让小者居堆顶。

  1. 把 Floyd 的 (min, +) 换成 (max, min) 会得到什么？（提示：最大瓶颈路，答案是“路径上最小边权的最大值”。）为什么同一套循环换成 (max, +) 求最长路就不行了？
    想好了？点开核对思路与解析
    (max, min) 得到最大瓶颈路：让路径上最小的那条边尽量大（最大生成树上的路径就取到这个值）。它成立是因为 max 对 min 满足分配律，k 维滚动的前提（加入中转点不会让已有答案变差）也保持。(max, +) 求最长路不行：有正环时答案无界；就算排除正环，“最长简单路径”也是 NP-hard 的（Hamilton 路径可以归约到它），不可能有 O(n³) 的做法。常见错路：把 Floyd 的 min 直接换成 max 就交——在 DAG 上碰巧对，一般图上错得无声无息。
算法落地例题 · 单源最短路径（标准版）· 堆优化 Dijkstra覆盖：洛谷 P4779 / 堆优化 Dijkstra
需求

例题 · 【模板】单源最短路径（标准版） · 洛谷 P4779 普及/提高-

给定一个 n 个点、m 条有向边的带非负权图，请计算从 s 出发到每个点的最短距离。数据保证从 s 出发能到达任意点。

输入格式：第一行三个正整数 n、m、s；第二行起 m 行，每行三个非负整数 u、v、w，表示从 u 到 v 有一条权值为 w 的有向边。

输出格式：一行 n 个空格分隔的非负整数，第 i 个数表示 s 到 i 的距离。

数据范围：1 ≤ n ≤ 10⁵，1 ≤ m ≤ 2×10⁵，s = 1，1 ≤ u, v ≤ n，0 ≤ w ≤ 10⁹，0 ≤ Σw ≤ 10⁹。

样例
输入：
4 6 1
1 2 2
2 3 2
2 4 1
1 3 5
3 4 3
1 4 4
输出：
0 2 4 3
1① dist 的定义和初始化：极大值，不是 0
初始化
    const ll INF = (ll)4e18;           // 4e18 + 4e18 仍在 long long 内
    vector<ll> dist(n + 1, INF);
    dist[s] = 0;                       // 源点到自己是 0
    pq.push({0, s});
为什么

dist[v] 表示“当前已知的 s 到 v 最短距离”，和 BFS 里的 dis 是同一个东西，只是边权不再是 1，所以“第几层”换成了“累计代价”。dist[s] = 0，其余设成一个极大的数。

必须是极大值，不能是 0 —— 全 0 等于宣布“所有点都已经到达且距离为 0”，后面 dist[u] + w < dist[v] 一条都松弛不动，输出一整行 0。INF 还要满足两条：比任何可能的最短路都大，且 INF + w 不溢出 —— 4e18 加 1e9 远小于 long long 上限 9.22×10¹⁸。

只把源点入堆，不是把所有点都塞进去。堆里只该有“距离被更新过”的记录。

2② 弹出堆顶，先验货（懒删除）
取堆顶 + 懒删除
        auto [d, u] = pq.top();        // C++17：把 pair 拆成 d 和 u
        pq.pop();
        if (d != dist[u]) continue;    // 懒删除：这是 u 的旧记录
为什么

先取出再删除。结构化绑定等价于 ll d = pq.top().first; int u = pq.top().second;，但只调一次 top()。

懒删除：u 的距离可能被改小过好几次，堆里躺着好几份 (d, u)，只有 d == dist[u] 的那份是最新的。删掉这行答案仍正确，但过期记录也会去扫一遍出边，度数大的点被改多次时可能 TLE。

为什么取最小就能“确定”（正确性证明）。假设弹出的 u 的 dist 还不是真正的最短距离 d(u)。在 s→u 的真实最短路上，从 s 开始找第一个还没被确定的点 y。y 之前的点都已确定并松弛过，所以 dist[y] = d(y)。因为边权非负，最短路越往后越长，所以 d(y) ≤ d(u)；又因为 u 是当前未确定点里 dist 最小的，所以 dist[u] ≤ dist[y]。串起来：d(y) ≤ d(u) < dist[u] ≤ dist[y] = d(y)，矛盾。∎ “边权非负”只用在这一步，这是全节最值得记住的一句话。

3③ 松弛出边：三角不等式，新值入堆
松弛
        for (auto &e : g[u]) {         // 引用遍历，不复制 pair
            int v = e.first, w = e.second;
            if (dist[u] + w < dist[v]) {          // 绕 u 更快
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});            // 旧记录留在堆里，靠上面那行过滤
            }
        }
为什么

“松弛”就是三角不等式：if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;。BFS 里这一步是 dist[v] = dist[u] + 1，因为不用比也知道更优。

dist[u] 此刻已是最优值，所以只需检查“绕过 u 这一条边”是否有改善 —— 这正是“每个点只处理一次”的依据。push 的是 dist[v] 而不是 d + w（两者相等，但前者可读性更好，也不怕以后改写法）。

复杂度：每条边最多触发一次 push，所以最多 push m + 1 次，堆大小 ≤ m + 1，每次 push/pop 是 O(log m)。总复杂度 O((n + m) log m)，写成 O((n + m) log n) 也一样。朴素写法每次在 n 个点里线性找最小是 O(n²)，堆把这一步压到 O(log n)。

4④ 样例手推：输出格式也在这里定下来
输出段
    for (int i = 1; i <= n; ++i)
        cout << dist[i] << (i == n ? '\n' : ' ');
    return 0;
}
为什么

手推得到的答案 0 2 4 3 就是程序输出。出堆顺序 1(0) → 2(2) → 4(3) → 3(4)，每一步都能在表里看到“这一行只改刚松弛成功的那几格”。

两条图连起来看：结论是“取最小即确定”，代价是堆里会留下过期记录，所以必须验货。

5⑤ 完整程序
完整代码（C++17）
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, s;
    cin >> n >> m >> s;

    // 邻接表：g[u] 里每一项是 (终点, 边权)
    vector<vector<pair<int,int>>> g(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v, w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});        // 有向边，只加一次
    }

    const ll INF = (ll)4e18;           // 4e18 + 4e18 仍在 long long 内
    vector<ll> dist(n + 1, INF);
    dist[s] = 0;                       // 源点到自己是 0

    // 小根堆：first 是距离，堆顶永远是"当前距离最小的记录"
    priority_queue<pair<ll,int>, vector<pair<ll,int>>, greater<pair<ll,int>>> pq;
    pq.push({0, s});

    while (!pq.empty()) {
        auto [d, u] = pq.top();        // C++17：把 pair 拆成 d 和 u
        pq.pop();
        if (d != dist[u]) continue;    // 懒删除：这是 u 的旧记录

        for (auto &e : g[u]) {         // 引用遍历，不复制 pair
            int v = e.first, w = e.second;
            if (dist[u] + w < dist[v]) {          // 绕 u 更快
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});            // 旧记录留在堆里，靠上面那行过滤
            }
        }
    }

    for (int i = 1; i <= n; ++i)
        cout << dist[i] << (i == n ? '\n' : ' ');
    return 0;
}
为什么

邻接表存的是 pair<int,int>（终点 + 边权），所以不用 struct Edge；距离用 long long，虽然本题 Σw ≤ 10⁹ 用 int 也够，但换一道题（边权 × 点数）就会爆，统一 long long 省心。

输出是 (i == n ? '\n' : ' ')：n 个数一行，行末只换行、不多空格。多一个空格在某些严格比对的题上会 WA。

竞赛用法

看到什么想到它：单源、边权非负、要求“到每个点的最小代价”（最短距离 / 最少花费 / 最少时间），n 到 10⁵、m 到 2×10⁵ —— 就是堆优化 Dijkstra。要全部点对时（n ≤ 300~500）才换 Floyd。

复杂度：O((n + m) log m)。n = 10⁵、m = 2×10⁵ 时约 (n + m)·log m ≈ 3×10⁵ × 18 ≈ 5×10⁶ 次操作，稳过。

常见的坑：① dist 用默认值 0 初始化，一条边都松弛不动，输出一整行 0；② INF 取 1e9 太小（真实最短路超过就当成不可达）、取 INT_MAX 又会让 INF + w 溢出成负数；③ 删掉懒删除那行，答案对但 TLE；④ pair 写成 {u, d}，堆按点号排序；⑤ 忘记写 greater（大根堆），取的是最大距离；⑥ 用 int 存 dist，累加后溢出成负数。

  1. 如果图里有 0 权边，Dijkstra 还对吗？回到证明里看“d(y) ≤ d(u)”这一步 —— 它能扛住 0 权边，为什么扛不住负权边？只差一个等号还是不等号？
    想好了？点开核对思路与解析
    还对。证明里用的是“沿最短路越往后 d 越大”，0 权边让它相等但不减小，所以 d(y) ≤ d(u) 这一步仍然成立（等号不影响推导）。负权边才会让后面的点更小，不等式当场崩掉。准确的措辞是“边权 ≥ 0”，不是“边权 > 0”。常见错路：给 0 权边写特判，或者担心“同距离的记录会顶掉正确答案”——它们只会多弹几条，答案不变。

    想好了？点开核对思路与解析
    在松弛那一步分两支：dist[u]+w < dist[v] 时 cnt[v] = cnt[u]（更短的路出现，旧计数作废）；== dist[v] 时 cnt[v] += cnt[u]（同样短的另一条路，累加）。所以必须分开：小于要覆盖、等于要累加，写成同一支就会把“更短”和“同样短”混为一谈。相等时不能重新入堆——v 的距离没变，它的出边已经按这个距离处理过，重复入堆会让同一条路径被反复计数。还有一处例外要留神：有 0 权边时 dist 相同的点会互相贡献，必须保证同层按拓扑序处理，否则计数会漏。

    成立，前提仍是边权非负，但三处要改。① 懒删除的 if (d != dist[u]) 改成带容差：if (d > dist[u] + 1e-12) continue;，否则舍入误差会让过期记录过滤不掉。② 松弛比较 dist[u] + w < dist[v] 最好也留一个 eps，不然极小改进会反复入堆。③ 全程统一 double（或统一 long double），INF 取 1e18，别用 DBL_MAX——一加就变成 inf，比较全乱。常见错路：以为浮点下“距离相等”还能可靠判出来，用 == 当松弛条件，同层被反复处理。

1① 换一张表：f[i][j] 记 i 到 j 的距离

Dijkstra 解决“一个源点到所有点”。如果要所有点对的距离，跑 n 次 Dijkstra 是 O(n(m + n) log n)，n = 500 时约 8.5×10⁸，太慢；而 Floyd 是 O(n³) = 1.25×10⁸，反而更快。稠密图上，Floyd 常常是更优的选择。

思路是动态规划。定义 fk(i, j) = 只允许把编号 1..k 的点当作中转点时，i 到 j 的最短距离。从 k−1 推到 k 只有两种选择：不用 k，还是 fk−1(i, j)；用 k，就是 fk−1(i, k) + fk−1(k, j)。于是

fk(i, j) = min( fk−1(i, j), fk−1(i, k) + fk−1(k, j) )。

一个二维表 + 一行转移
long long f[N][N];                       // f[i][j]：i 到 j 的最短距离
// f_k(i,j)：只允许编号 1..k 的点当中转点时的最短距离
// f_k(i,j) = min( f_{k-1}(i,j), f_{k-1}(i,k) + f_{k-1}(k,j) )
f[i][j] = min(f[i][j], f[i][k] + f[k][j]);
为什么

这不是“把所有路径枚举一遍”：转移只从第 k−1 层来，每层只多允许一个中转点。k 这一维可以滚掉：算 fk 时 fk−1(i, k) 与 fk−1(k, j) 的值和 fk 的那两个值相同（最短路经过 k 本身不会变得更短，除非有负环），所以直接就地覆盖成二维数组即可。这就是为什么 k 循环必须写最外层 —— 它是 DP 的阶段维。

2② 初始化：自己到自己是 0，重边取最小

转移式只负责“更短就改”，初值必须自己摆好：对角线 0、其余无穷大，读入的边取 min。

初值三件事
const long long INF = (long long)4e18;
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= n; ++j)
        f[i][j] = (i == j ? 0 : INF);          // ★ 自己到自己是 0
for (int i = 0; i < m; ++i) {
    int u, v, w; cin >> u >> v >> w;
    f[u][v] = min(f[u][v], (long long)w);      // 重边取最小
}
为什么

三处都不能省：① f[i][i] = 0，漏了它经过自己的转移全部失效（INF + x 还是 INF），答案偏大；② 反过来用 0 初始化整个矩阵，会得到“任意两点距离都是 0”；③ 重边要取 min，直接赋值会让后读入的较大边覆盖掉较小边。INF 取 4×10¹⁸：INF + w 不溢出（2×4×10¹⁸ < 9.22×10¹⁸），且仍远大于任何真实路径。

3③ k 必须在最外层：它是 DP 的阶段维
Floyd 骨架
for (int k = 1; k <= n; ++k)                   // ★ 阶段：必须最外层
    for (int i = 1; i <= n; ++i) {
        if (f[i][k] == INF) continue;          // 剪枝：i 到不了 k，这一层白算
        for (int j = 1; j <= n; ++j)
            if (f[i][k] + f[k][j] < f[i][j])
                f[i][j] = f[i][k] + f[k][j];
    }
// 到这里 f[i][j] 就是 i 到 j 的最短路
为什么

k 放里层会错，给一个具体反例。4 个点、3 条边 1→3、3→4、4→2，权都是 1，正确答案 d(1, 2) = 3。若写成 for i for j for k：算 (i = 1, j = 2) 时需要用 f[1][4]，而 f[1][4]（要等 j = 4 才算）此刻还是 INF，于是 f[1][2] 永远停在 INF。这类错误的表现是“一部分点对正确、一部分是 INF 或偏大”，极难靠小样例发现。

4④ 白送的三件事：负权、负环、传递闭包

Floyd 的骨架不只算距离。把运算换掉，同一个三重循环还能回答“能不能走到”和“有没有负环”。

同一副骨架，换运算
// 传递闭包：把 min 换成 or、+ 换成 and，三重循环一个字不改
bool reach[N][N];
reach[i][j] = reach[i][j] || (reach[i][k] && reach[k][j]);

// 判负环：跑完看 f[i][i] < 0（正常应该等于 0）
for (int i = 1; i <= n; ++i)
    if (f[i][i] < 0) { /* 有负环，最短路没有意义 */ }
为什么

所以 Floyd 还白送三件东西：①允许负权边（只要没有负环）；②判负环 —— 跑完看 f[i][i] < 0，说明有负环；③传递闭包 —— 把 min 换成 or、+ 换成 and，得到的就是“i 能否走到 j”。

int main() {

竞赛用法

看到什么想到它：要任意两点间距离、n ≤ 300~500、图稠密（m 接近 n²）、要传递闭包（“能否走到”）、要在有负权边的图上判负环。

复杂度：O(n³)，n = 300 时 2.7×10⁷，n = 500 时 1.25×10⁸；空间 O(n²)。

常见的坑：① k 写进 i、j 里层，部分点对停在 INF 或偏大；② 忘记 f[i][i] = 0，经过自己的转移全失效；③ 用 0 初始化整个矩阵，得到“任意两点距离都是 0”；④ 重边直接赋值，没取 min；⑤ 有负环时还算最短路——此时答案没有意义，要先判 f[i][i] < 0。

模型：全源最短路（Floyd）O(n³)坑：k 必须最外层

需求：还是单源最短路，但图里出现了负权边。以三点图为例：1→2 权 2、1→3 权 5、3→2 权 −4，源点 1。真实答案是 d(2) = 1（绕 3 号点走），而带“弹出即确定”的 Dijkstra 会给出 2。

1① 反例跑一遍：2 号点弹得太早

Dijkstra 的执行顺序是：dist = [0, 2, 5]，先弹出 2 号点（dist = 2 最小），把它当最终值；再弹出 3 号点，松弛 3→2 得到 1 —— 但 2 号点已经处理完了，答案停在 2。

vis 锁死距离的那一刻就错了
// 带“弹出即确定”标记的经典实现
while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();
    if (vis[u]) continue;              // 弹出过就不再处理
    vis[u] = true;                     // 这一行让 2 号点的距离被锁死
    for (auto &e : g[u]) {
        if (vis[e.to]) continue;       // ★ 已定稿的点不再更新
        if (dist[u] + e.w < dist[e.to]) {
            dist[e.to] = dist[u] + e.w;
            pq.push({dist[e.to], e.to});
        }
    }
}
// 出堆顺序：1(0) → 2(2) → 3(5)
// 弹出 2 后 vis[2] = true；之后 3 想把它改成 1，会被 if (vis[e.to]) 挡掉
为什么

这一段描述的是带“弹出即确定”标记的经典实现（弹出后 vis[u] = true 并不再更新 u），本节 P4779 的代码没有这个标记，结论见第 ③ 步。两种实现要分开说，不能混着解释。

2② 坏在证明的哪一步：d(y) ≤ d(u) 要求边权非负

回到 Dijkstra 的证明：那句 d(y) ≤ d(u) 用的是“最短路越往后越长”，而这条性质只在边权非负时成立。有负边时，最短路可能越走越短，“先取出的最小点”就不再是确定的。

同一个反例，换成不等式看
// 反例数据（可以自己跑一遍）
vector<tuple<int,int,int>> e = {{1,2,2}, {1,3,5}, {3,2,-4}};
// 手算：d(1) = 0，d(3) = 5，d(2) = min(2, 5 + (-4)) = 1
// 弹出 (2, 2) 的时刻，堆里还有 (5, 3)
// 证明要的「弹出 u 时，所有还没定稿的 y 都满足 d(y) >= d(u)」不成立：
// y = 2 的最终距离 1 比 u = 3 的 5 还小
为什么

把结论记准确：Dijkstra 的正确性依赖边权非负，不只是“复杂度好看”。0 权边还扛得住（等号不影响推导），负权边一出现，不等式当场崩掉。

3③ 不加 vis 的懒删除写法：答案对，但退化到 O(nm)

还要说清楚一个细节，很多资料含糊过去：本节这种“懒删除、不加 vis”的写法，在负权图上最终仍会给出正确答案，因为每次距离变小都会重新入堆，等价于堆版的 Bellman-Ford —— 但复杂度从 O((n + m) log n) 退化成 O(nm) 量级，SPFA 的卡法能把它卡死。

懒删除：答案对，复杂度崩
while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();
    if (d != dist[u]) continue;        // 过期记录丢掉，但没有 vis 锁死任何点
    for (auto &e : g[u])
        if (dist[u] + e.w < dist[e.to]) {
            dist[e.to] = dist[u] + e.w;    // 变小就重新入堆
            pq.push({dist[e.to], e.to});
        }
}
// 负权图上仍会收敛到正确答案，但每条边可能被反复松弛
为什么

而只要你为了提速加上“弹出即确定”（if (vis[u]) continue; vis[u] = true;），负权图上就是彻底的 WA。所以两种写法的结论必须分开记：懒删除版错在慢，加 vis 版错在答案。

结论不变，只是理由更精确：Dijkstra 的复杂度保证依赖非负权，正确性在带“确定”标记的实现里也依赖它。有负权边时用 Bellman-Ford / SPFA，并且用它顺手判负环。

4④ 无向图 + 一条负权边 = 一定有负环

最后一个容易忽视的推论：无向图里只要出现一条负权边，就一定有负环（这条边来回走一趟，总权变成负数，可以无限刷小），此时最短路根本不存在。

负权无向边 = 免费刷负环
// 无向边 u—v 权 -3：正着走一趟 -3，反着走一趟又 -3
// 来回走 k 趟（每趟两条边），dist 每次减 6，可以无限刷小
// → 最短路不存在，任何最短路算法都给不出有限值
// 所以看到「无向图 + 负边」：要么题目保证没有，要么答案就是 -∞
为什么

所以看到“无向图 + 负边”，先判断题目是不是另有保证；没有保证就不要指望任何最短路算法给出有限值，答案要么是 −∞，要么题目本身不合法。

const int N = 100005;
const long long INF = (long long)4e18;
int n, m, s;
struct Edge { int u, v; long long w; } e[N];
long long dist[N];

int main() {
    cin >> n >> m >> s;
    for (int i = 0; i < m; ++i) cin >> e[i].u >> e[i].v >> e[i].w;
    for (int i = 1; i <= n; ++i) dist[i] = INF;
    dist[s] = 0;

    bool neg = false;
    for (int i = 1; i <= n; ++i)                 // n 轮：第 n 轮还能松弛就是有负环
        for (int j = 0; j < m; ++j)
            if (dist[e[j].u] != INF && dist[e[j].u] + e[j].w < dist[e[j].v]) {
                dist[e[j].v] = dist[e[j].u] + e[j].w;
                if (i == n) neg = true;
            }

    if (neg) { cout << "NEGATIVE CYCLE\n"; return 0; }
    for (int i = 1; i <= n; ++i) {
        if (dist[i] == INF) cout << "INF";
        else cout << dist[i];
        cout << " \n"[i == n];
    }
    return 0;
}
为什么

用样例跑：3 3 1 / 1 2 2 / 1 3 5 / 3 2 -4，输出 0 1 5，和手算的 d(2) = 1 一致。复杂度 O(nm)：n = 10⁵、m = 2×10⁵ 时是 2×10¹⁰，所以实战多用队列版（SPFA），但它最坏还是 O(nm)，出题人可以专门卡。

竞赛用法

看到什么想到它：边权可能是负数、要判负环、题目出现“负权”“收益/花费可正可负”这类字眼 —— Dijkstra 直接排除，换 Bellman-Ford / SPFA；稠密小图可以直接用 Floyd 判 f[i][i] < 0。

复杂度：Bellman-Ford O(nm)，SPFA 平均快、最坏 O(nm)；Dijkstra 只在非负权下 O((n + m) log n)。

常见的坑：① 给 Dijkstra 加上“弹出即确定”的 vis，再拿去跑负权图 → WA；② 无向图里出现负权边还指望最短路，其实一定负环；③ 判负环只跑 n−1 轮，漏掉第 n 轮；④ INF + w 溢出成负数，被当成更短的路；⑤ 有负环时还输出 dist，答案没有意义。

模型：负权最短路O(nm)坑：无向图负边必负环
本节的 8 个坑，每个都有具体症状

dist 用默认值 0 初始化（全局数组、或 vector<ll> dist(n + 1)）：所有点都“已到达且距离 0”，一条边也松弛不动，输出一整行 0 → WA。这是本节第一大坑。

INF 取得太小（如 1e9）：真实最短路超过 1e9 时会被当成“不可达”，输出 1000000000 → WA。INF 取 INT_MAX：INF + w 溢出成负数，负数被当成更短的路 → WA。

删掉 if (d != dist[u]) continue;：答案仍对，但过期记录也会去扫一遍所有出边，高度数点被反复更新时工作量成倍上涨 → TLE。

pair 写成 {u, d}（点号在前）：堆顶变成“点号最小的记录”，距离没参与比较，复杂度退化到 SPFA 级别，构造数据 → TLE；若你还加了“弹出即确定”的 vis，则直接 WA。

忘记写 greater（用默认大根堆）：每次取当前最大距离的点，和“取最小即确定”完全相反。小数据可能因为反复入堆而碰巧收敛，一旦加 vis 就 WA —— 这种“样例能过”的隐患最危险。

Floyd 的 k 循环写进 i、j 里层：部分点对停在 INF 或偏大 → WA，而且小样例常常是过的。

Floyd 忘记 f[i][i] = 0：经过自己的转移全部失效（INF + x 还是 INF），答案偏大 → WA；反过来，用 0 初始化整个矩阵会得到“任意两点距离都是 0” → WA。

用 int 存 dist：n = 10³、w = 10⁴ 时单程才 10⁷，看着够；但 n、w 各放大十倍就是 10⁹ 出头，再加一条边就溢出成负数 → WA。统一 long long，代价只是一点内存。

挑战题 · 邮递员送信
洛谷 P1629普及/提高-去洛谷做这题 ↗

邮局在 1 号点，要送 n − 1 件东西到 2..n 号点。城市里所有道路都是单行道，共 m 条。邮递员每次只能带一件东西，送完必须返回邮局。

求送完这 n − 1 件东西并最终回到邮局所需的最少总时间。

输入格式：第一行两个整数 n、m；接下来 m 行，每行三个整数 u、v、w，表示从 u 到 v 有一条耗时 w 的单行道。

输出格式：一行一个整数，表示最少总时间。

数据范围：1 ≤ n ≤ 10³，1 ≤ m ≤ 10⁵，1 ≤ w ≤ 10⁴，保证任意两点互相可达。

引导性提示（先只看这里）

每次出门的路线是 1 → i，回程是 i → 1，n − 1 次出差互不影响。所以总时间就是 Σ(d(1, i) + d(i, 1))，不要想成“一条大回路”。

d(1, i) 跑一次 Dijkstra 就全有了。d(i, 1) 要对 n − 1 个 i 各跑一次吗？想想上一节的反向建图。

把所有边方向掉个头，在反图上从 1 跑一次 Dijkstra —— 反图上 1 到 i 的最短路，就是原图上 i 到 1 的最短路。

注意答案的最大量级：单程最坏约 10³ × 10⁴ = 10⁷，累加 10³ 次就是 10¹⁰，必须 long long。

想看思路了？点开完整思路

拆开算。送第 i 件东西的过程是“1 → i，再 i → 1”，与其他件无关，所以总时间 = Σi=2..n ( d(1, i) + d(i, 1) )。两次 Dijkstra 就能得到全部 2(n − 1) 个值。

第一遍：正图。以 1 为源点跑 Dijkstra，得到 distA[i] = d(1, i)。

第二遍：反图。建一张把所有边反向的图，同样以 1 为源点跑 Dijkstra。反图上一条 1 → x1 → … → i 的路径，在原图上正好是 i → … → x1 → 1 的路径，长度相同。所以 distB[i] = d(i, 1)。

为什么不能只跑一遍。正图给出的是“从 1 出发到各点”，而“从各点回到 1”在有向图里是完全不同的问题（单行道，去得回不得）。对每个点各跑一次是 O(n m log n) = 10³ × 10⁵ 量级，会超时；反图把它压回一次。

复杂度。两遍堆优化 Dijkstra，O((n + m) log n)，n = 10³、m = 10⁵，约 2×10⁵ × 17 ≈ 3.4×10⁶ 次操作。

为什么不用 Floyd。n = 10³ 时 10⁹ 次内层操作，超时；而且我们只需要 1 到各点、各点到 1 这两批值，Floyd 算的 10⁶ 个点对里绝大多数用不上。

// 从 s 出发的单源最短路，结果写进 d[1..n]
void dijkstra(vector<vector<pair<int,int>>> &gr, int s, ll *d) {
    for (int i = 1; i <= n; ++i) d[i] = INF;   // 全部先当不可达
    d[s] = 0;
    priority_queue<pair<ll,int>, vector<pair<ll,int>>, greater<pair<ll,int>>> pq;
    pq.push({0, s});
    while (!pq.empty()) {
        auto [du, u] = pq.top();
        pq.pop();
        if (du != d[u]) continue;              // 懒删除：过期记录
        for (auto &e : gr[u]) {
            int v = e.first, w = e.second;
            if (du + w < d[v]) {
                d[v] = du + w;
                pq.push({d[v], v});
            }
        }
    }
}

挑战 2 · 牛的旅行 Cow Tours
洛谷 P1522提高-/提高去洛谷做这题 ↗

农场里有 n 个牧区，编号 1..n，每个牧区有自己的坐标，某些牧区之间有路直接相连。如果两个牧区能通过若干条路互相到达，就说它们属于同一片牧场（即连通块）。一片牧场的直径是这片牧场里最远的两个牧区之间的最短距离。

目前至少有两片牧场互不连通。现在要恰好修一条路，连接两个不同牧场里的牧区，使连通后的新牧场直径尽可能小。求这个最小直径。

输入格式：第一行一个整数 n（1 ≤ n ≤ 150）；接下来 n 行，每行两个整数 x、y（0 ≤ x, y ≤ 10⁵），表示牧区坐标；接下来 n 行，每行 n 个数字（0 或 1），给出对称邻接矩阵——第 i 行第 j 列为 1 表示 i、j 之间有直接道路。

输出格式：一行一个实数，表示新牧场直径的最小值，保留六位小数。

样例
输入： 8 10 10 15 10 20 10 15 15 20 15 30 15 25 10 30 10 01000000 10111000 01001000 01001000 01110000 00000010 00000101 00000010 输出： 22.071068
引导性提示（先只看这里）

两个概念要分清：牧区是最小单位，牧场是连通的牧区集合；直径是同一片牧场内最远两点的最短路。n ≤ 150，能不能一次算出所有点对的距离？

Floyd 之后，每个牧区到「自己这片牧场里最远那个点」的距离可以直接扫出来，记为 mx[i]；一片牧场的直径就是这片牧场里 mx 的最大值。

新修 i–j 之后，新直径只可能是三种情况之一：左牧场原直径、右牧场原直径、或者「先走到 i，跨过新路到 j，再往右边最远处走」。三者取最大，再对所有 (i, j) 取最小。

想看思路了？点开完整思路

① 全源最短路。n ≤ 150，Floyd 三重循环 O(n³) = 3.4×10⁶，一次算出所有点对的距离。直接相连的两点边长取欧氏距离，不直接相连的设成 INF。

② 分牧场。Floyd 跑完后 d[i][j] 仍然是 INF，说明 i、j 不同牧场；据此做一次 DFS 给每个点标上牧场编号。注意判据必须是「最短路还是 INF」，而不是「邻接矩阵上是 1」——后者只能看到直接相连。

③ 两个量。mx[i] = max{ d[i][j] : j 与 i 同牧场 }；dia[c] = max{ mx[i] : i 属于牧场 c }。两者都是 O(n²) 扫出来。

④ 枚举新路。对每一对不同牧场的点 i、j，新直径 = max( dia[ci], dia[cj], mx[i] + dist(i,j) + mx[j] )，取所有方案的最小值。dist(i,j) 是两点间的欧氏距离（新修的那条路）。

为什么新直径一定长这样。连通后的最短路只有两种形态：完全在某片老牧场内，或者跨过新路。跨过的那条一定形如 a → i → j → b，其中 a 与 i 同牧场、b 与 j 同牧场，长度 = d(a,i) + dist(i,j) + d(j,b) ≤ mx[i] + dist(i,j) + mx[j]。两个上界都是可达的，所以新直径就是这三项的最大值。

复杂度。Floyd 3.4×10⁶，标记与统计 O(n²)，枚举 O(n²)。n = 150 时总操作不到 10⁷，几十毫秒。

精度。全程用 double，最后统一输出六位小数；不要在中间转成 int 或 float 存距离。

#include <bits/stdc++.h>
using namespace std;

const int N = 155;
const double INF = 1e18;
int n;
double x[N], y[N];
double d[N][N];          // d[i][j]：i 到 j 的最短距离
double far[N];           // far[i]：i 到本牧场内最远点的距离
double dia[N];           // dia[c]：第 c 个连通块的直径
int comp[N];

void dfs(int u, int c) {  // 只沿“有路且连通”的边扩散，给连通块编号
    comp[u] = c;
    for (int v = 1; v <= n; ++v)
        if (comp[v] == 0 && d[u][v] < INF / 2) dfs(v, c);
}

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; ++i) scanf("%lf%lf", &x[i], &y[i]);

    char s[N];
    for (int i = 1; i <= n; ++i) {
        scanf("%s", s + 1);
        for (int j = 1; j <= n; ++j) {
            if (i == j) d[i][j] = 0;
            else if (s[j] == '1') d[i][j] = hypot(x[i] - x[j], y[i] - y[j]);
            else d[i][j] = INF;
        }
    }

    for (int k = 1; k <= n; ++k)                 // Floyd：n <= 150，O(n^3) = 3.4e6
        for (int i = 1; i <= n; ++i) {
            if (d[i][k] > INF / 2) continue;
            for (int j = 1; j <= n; ++j)
                if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
        }

    int cc = 0;
    for (int i = 1; i <= n; ++i)
        if (comp[i] == 0) dfs(i, ++cc);

    for (int i = 1; i <= n; ++i) {
        far[i] = 0;
        for (int j = 1; j <= n; ++j)
            if (d[i][j] < INF / 2 && d[i][j] > far[i]) far[i] = d[i][j];
    }
    for (int i = 1; i <= n; ++i)
        if (far[i] > dia[comp[i]]) dia[comp[i]] = far[i];

    double ans = INF;
    for (int i = 1; i <= n; ++i)                 // 枚举新修的那条路的两端
        for (int j = 1; j <= n; ++j) {
            if (comp[i] == comp[j]) continue;    // 必须连两个不同牧场
            double cur = far[i] + hypot(x[i] - x[j], y[i] - y[j]) + far[j];
            if (dia[comp[i]] > cur) cur = dia[comp[i]];    // 新直径不会小于原来的两段
            if (dia[comp[j]] > cur) cur = dia[comp[j]];
            if (cur < ans) ans = cur;
        }

    printf("%.6f\n", ans);
    return 0;
}

dfs(i, ++cc)分牧场靠一次 DFS，判据是 d[u][v] < INF/2（最短路存在），不是邻接矩阵上的 1。
if (far[i] > dia[comp[i]]) dia[comp[i]] = far[i];牧场直径 = 场里所有 far 的最大值。far 是「到本场最远点」，两者差一层 max。
if (comp[i] == comp[j]) continue;题目要求新路连接两个不同牧场。同一牧场内修路不改变直径，却会让答案变小。
if (dia[comp[i]] > cur) cur = dia[comp[i]];新直径必须同时不小于两片老牧场的直径——新路只是多了一条选择，不会让老距离变短。漏掉这一项答案偏小。
printf("%.6f\n", ans);六位小数。double 有 15~16 位有效数字，n = 150、坐标 10⁵ 时精度足够。
这题最容易错的地方
  • 把「牧区」当成「牧场」：n 是牧区数，牧场数是连通块个数，两者不是一个量。
  • 用邻接矩阵判连通块：绕两个点才连上的牧区会被漏掉，牧场数偏大、直径偏小 → WA。
  • 枚举 i、j 时不做牧场判断，或让 i == j：同一片牧场里的点对也参与了取最小，答案偏小。
  • 新直径只算 far[i] + dist + far[j]，忘了跟两片老牧场的直径取最大：样例就会差一截。
