09 · 字符串进阶：数字、进制与格式

把字符串当“数字的另一种写法”：用 to_string / stoi / stoll 在两个方向搬运，用秦九韶与除基取余做任意进制互转，用 find / substr / reverse 切段，并且记住 19 位这条硬红线。
⭐ 已学范围普及-预计 60 分钟to_string进制转换find/substr

上一节把字符串当字符数组用：下标、遍历、字符分类。这一节换个看法——把字符串当成数字的另一种写法。同一个值 255，10 进制写作 255，2 进制写作 11111111，16 进制写作 FF。三串字符，一个数。

  • 数字 → 字符串：to_string、sprintf。拼输出、算位数、补前导零。
  • 字符串 → 数字：stoi、stoll，或者自己写秦九韶循环。
  • 定位与切段：find 找分隔符，substr 切开，reverse 就地翻转。
判断标准只有一条：这个数能保证不超过 19 位吗？能，就用 long long 中转；不能，就全程 string，一个字符都别进数字类型。
推导to_string：把一个数摊成字符串覆盖：to_string / 数字转字符串 / 位数需求 → 尝试 → 验证 → 定理
问题

想把一个数的每一位拿出来处理、想把它拼进一句话、想算它有多少位——可数字在内存里是二进制，取位只能靠 / 10 和 % 10 反复做，负数还得多一步处理。

1换一个表示：不用数字，用字符串

同一个值 255，10 进制写作 255，2 进制写作 11111111，16 进制写作 FF。三串字符，一个数。既然要对“写法”动手，就先把它变成字符串。

验证 / 关键

变成字符串后，“第 i 位”就是 s[i]，“位数”就是 s.size()——全都变成上一节学过的字符操作。

2一个函数覆盖三种重载

编译器按实参类型自动挑重载：整数版、长整型版、浮点版。

签名
string to_string(int x);
string to_string(long long x);
string to_string(double x);
组成含义 / 格式要求
参数任意算术类型，编译器按实参自动挑重载。
返回值string。位数就是 .size()，第 i 位字符就是 s[i]。
double 版本固定 6 位小数，宽度和位数都管不了——要格式就别用它。
效率比 sprintf 慢 2~3 倍，循环 10⁶ 次以上要掂量。
验证 / 关键

返回的是新字符串，原数字一点没变；两个结果只能 + 拼接，s1 - s2 编译不过。

3验证：位数与格式
示例
int a = 42;
string s1 = to_string(a);                     // "42"，长度 2
string s2 = to_string(123456789012345678LL);  // 18 位
cout << s1 + "!";                             // 42!：+ 是拼接
cout << s2.size();                            // 18：位数 = 长度
验证 / 关键

to_string(1.0) 得到 "1.000000"，不是 "1"——浮点版本固定 6 位小数，做不了“去掉多余的 0”。

于是我们得到：

to_string 把数值变成它的十进制写法，位数直接看 size()。

注意

to_string(1.0) 得到 "1.000000"，不是 "1"。

两个结果只能 + 拼接，s1 - s2 编译不过。

推导stoi / stoll：把字符串读成数覆盖：stoi / stoll / base 进制 / 越界异常需求 → 尝试 → 验证 → 定理
问题

题目给的是一串字符，可你要做加减乘除。自己写循环 x = x*10 + (c-'0') 当然行，但遇到“这个串是 16 进制”“只想读前几位”就得再加一堆判断。

1要的不只是“转成数”，还要能指定进制和停止位置

标准库的 stoi 一次满足三件事：解析、指定进制、报告停在哪。

签名
int stoi(const string& s, size_t* pos = nullptr, int base = 10);
组成含义 / 格式要求
s要解析的串，允许前导空格与正负号。
pos可选。传 &p 就把“停在哪个下标”写进 p。
base可选，2~36。写 16 就能直接读 "7f" 得 127。
停在哪遇到不属于该进制的字符就停，不报错："123abc" 得 123。
抛异常超出 int 范围时抛 std::out_of_range，进程终止，评测显示 RE。
示例
string s = "  -12345abc";
size_t pos;
int x = stoi(s, &pos);                 // -12345，pos = 8（停在 'a'）
int y = stoi("7f", nullptr, 16);       // 127
int z = stoi("11111111", nullptr, 2);  // 255
验证 / 关键

“遇到不认识的字符就停”是把双刃剑：解析半截字符串很方便，但也就没人告诉你“后面还有东西”。

2位数超过 10 位，就换 stoll

int 只有 10 位，long long 有 19 位；两者的接口一字不差，只是返回类型不同。

签名
long long stoll(const string& s, size_t* pos = nullptr, int base = 10);
组成含义 / 格式要求
三个参数含义与 stoi 一字不差，只是返回值换成 long long。
上限9223372036854775807（19 位）。值一旦超过它就抛 out_of_range，所以 19 位也不能乱填。
怎么选≤ 9 位用 stoi，10~18 位用 stoll，19 位对照上限看，≥ 20 位不转数字。
示例
long long a = stoll("9223372036854775807");   // 19 位，正好 LLONG_MAX
// stoll("9223372036854775808")  → 抛 out_of_range
string big = "12345678901234567890";          // 20 位，只能留在 string 里
验证 / 关键

20 位的 18446744073709551615 连 unsigned long long 都装不下。题目给出 20 位以上的数字，等于明示这道题考字符串。

3验证：异常是 RE，不是 WA

越界时抛 std::out_of_range，程序直接终止——评测机显示 RE，连输出都没有。怕它炸，就自己写秦九韶循环：x = x * 10 + (c - '0')，永远不会抛。

验证 / 关键

反过来说：只在“确定位数够”时用 stoi/stoll，是竞赛里更省事的选择；不确定就自己写。

于是我们得到：

stoi/stoll 把串解析成数，能指定进制、报告停止位置，越界抛异常。

注意

只认 int 范围。11 位的 "99999999999" 就抛异常。

怕异常就自己写 x = x * 10 + (c - '0')，绝不会炸。

追问 · 把这一步想透
  1. 给定 10⁵ 个长度不超过 20 的数字串，要求按数值排序。直接用 sort 比字符串为什么错？先比长度、再比字典序为什么对？有前导零时这个方案会怎样？
    想好了？点开核对思路与解析
    直接 sort 比字符串比的是字典序：“9” > “10”（'9' = 57 > '1' = 49），位数不同时结果和数值完全对不上。先比长度、长度相同再比字典序，对无前导零的数是对的：位数多的一定大，位数相同则字典序等价于逐位数值比较。
    有前导零时这个方案就错了：007 和 10，长度 3 > 2 会判 007 更大，而实际 7 < 10；要么先去前导零，要么按“去掉前导零后的长度”比。常见错路是用拼接比较 a + b < b + a——那是“拼成最小数”的排序，不是数值比较；或者用 stoll 转，20 位直接爆。
  2. 洛谷 P1601（高精度加法）为什么不能写成 cout << a + b？把理由压成一句话。
    想好了？点开核对思路与解析
    因为 C++ 的整数类型最多 19 位，P1601 的两个加数是几百位，没有任何内置类型装得下；而 a + b 在两个 string 上是拼接，“123”加“456”得“123456”，根本没做加法。一句话：位数超过 19，就只能自己逐位模拟竖式加法。
    常见错路是换 long long 或 __int128 再试——128 位也只有 38 位十进制，500 位差着一个数量级。
推导reverse：就地翻转一段区间覆盖：reverse / 左闭右开区间 / 原地修改需求 → 尝试 → 验证 → 定理
问题

把一串字符倒过来，手写也不难：首尾两个下标往中间靠，交换。可每写一次就要重新处理边界（长度奇偶、空串、区间是左闭右开还是闭区间），而且 swap 很容易写错。

1这个动作标准库已经实现了

反转的本质是“第 i 个和第 n−1−i 个交换”，标准库把它做成一个模板函数，给首尾两个迭代器就行。

签名
reverse(s.begin(), s.end());      // 需要 <algorithm>
验证 / 关键

s.end() 是末字符的下一个位置，所以区间是左闭右开 [first, last)——这是 C++ 迭代器区间的统一约定。

2返回值与适用范围

它是原地修改，不产生新串，也不返回任何东西。

组成含义 / 格式要求
区间左闭右开 [first, last)。s.end() 是末字符的下一个位置。
返回值void。原地修改，不产生新串。
数组也能用reverse(a, a + n) 反转 int 数组。
复杂度O(n)，每个元素交换一次。
验证 / 关键

“原地”意味着原串被改了：如果后面还要用原顺序，就得先复制一份。

3验证：两个编译期错误
示例
string s = "hello";
reverse(s.begin(), s.end());   // s 变成 "olleh"
cout << s;                     // 先反转，再输出

int a[5] = {1, 2, 3, 4, 5};
reverse(a, a + 5);             // 5 4 3 2 1
验证 / 关键

cout << reverse(...) 是编译错误（no match for operator<<），不是 WA；只给一个迭代器参数也编译不过——它要首尾两个。

于是我们得到：

reverse 就地翻转 [first, last)，返回 void，别往 cout 里塞。

推导find / substr：先定位，再切一段覆盖：find / string::npos / substr / 起点与长度需求 → 尝试 → 验证 → 定理
问题

一个串要被分隔符切成两段：小数点在哪儿？分数线在哪儿？不知道位置，就没法切；知道了位置，还得把两段各自取出来。这是两个动作，不是一个。

1第一个动作：找位置（find）

find 返回“首次出现的下标”，找不到时返回一个特殊值 string::npos。

签名
s.find(要找的东西, 起点 = 0);     // 返回 size_t
组成含义 / 格式要求
参数子串或单个 char：s.find('.')、s.find("to")。
起点从哪个下标开始找；想接着找就传 上次位置 + 1。
返回值首次出现的下标；找不到返回 string::npos，不是 -1。
npossize_t 的最大值 2⁶⁴−1。判断写 != string::npos，别写 < 0。
示例
string t = " to be or not to be ", w = " to ";
int cnt = 0;
size_t p = t.find(w);
while (p != string::npos) {
    ++cnt;
    p = t.find(w, p + 1);      // 从下一位继续，否则原地死循环
}
cout << cnt;                   // 2
验证 / 关键

漏掉 +1：find 每次返回同一个下标，死循环，评测 TLE。把结果存进 int 再和 npos 比也不行：npos 截断成 −1，< 0 的判断永远为假。

2第二个动作：切一段（substr）

substr 接“起点 + 长度”，省略长度就取到结尾。注意第一个参数是起点，不是长度。

签名
string substr(size_t pos = 0, size_t len = npos) const;
组成含义 / 格式要求
pos起点下标。pos == size() 合法，得空串。
len取几个字符；省略就取到结尾，写大了自动截断，不报错。
pos 越界pos > size() 抛 out_of_range → RE。
最常用取 [l, r) 这一段写 s.substr(l, r - l)。
示例
string s = "123.456";
size_t p = s.find('.');        // 3
string a = s.substr(0, p);     // "123"
string b = s.substr(p + 1);    // "456"，取到结尾
string c = s.substr(2, 5 - 2); // "3.4"
验证 / 关键

s.substr(p + 1) 在 p 是末字符时返回空串，合法。但拿 find 的返回值直接当 substr 起点——找不到时 npos + 1 是个天文数字，pos > size() 抛异常 → RE。

3验证：两个边界各试一次

① 找不存在的字符：find 返回 npos，判断必须写 != string::npos；② 空段：substr(size()) 返回空串，不崩。

验证 / 关键

这两个边界决定了切段程序在“没有分隔符”和“分隔符在末尾”时会不会崩——而这两种输入恰恰是评测数据的常客。

于是我们得到：

find 负责定位（找不到给 npos），substr 负责按“起点+长度”切段。

注意

漏掉 +1：find 每次返回同一个下标，死循环，评测 TLE。

把结果存进 int 再和 npos 比，npos 截断成 -1，看似能过；换成 < 0 的判断就永远为假。

第一个参数是起点，不是长度——这是最常见的错法。

1把格式写成一个字符串

printf 家族的思路：格式串里 % 开头的是占位符，其余字符原样输出，值按顺序填进去。sprintf 只是把结果写进一个字符数组，而不是屏幕。

宽度、补零、进制统统写在格式串里，一次说完。

验证 / 关键

%03d 的 3 是宽度、0 是“左边补 0”；这两个信息在 to_string 里根本无处安放。

签名

算法落地进制转换：先落到十进制，再长出来覆盖：洛谷 P1143 / 秦九韶 + 除基取余
需求

例题 · 进制转换 · 洛谷 P1143 普及-

输入三行：第一行整数 n（2 ≤ n ≤ 16），表示原数的进制；第二行一个 n 进制数，n > 10 时用大写 A~F 表示 10~15，且它的十进制值不超过 10⁹；第三行整数 m（2 ≤ m ≤ 16），表示目标进制。

输出这个数在 m 进制下的写法，m > 10 时同样使用大写 A~F。

样例
输入：
16
FF
2
输出：
11111111
1三行输入其实是三个词
读入
int n, m;
string s;
cin >> n >> s >> m;                  // 三行输入；cin 按“词”读，换行自动跳过
为什么

三行被当成三个“词”。s 是 string，遇空白就停，正好读完整个 n 进制数。n 进制与 m 进制之间没有逐位对应关系（2↔4/8/16 是例外），十进制是唯一的中转站。

2数码表 + 秦九韶：n 进制 → 十进制
秦九韶
string digit = "0123456789ABCDEF";   // 数码表：下标即数值，够用到 16 进制

long long dec = 0;
for (int i = 0; i < (int)s.size(); ++i) {
    int d = (int)digit.find(s[i]);   // 'F' 在表里的下标是 15
    dec = dec * n + d;               // 旧值升一档，再加新的一位
}
为什么

把“数值→字符”做成一张表：digit[15] 就是 'F'，digit.find('F') 就是 15——正查反查都用这张表，比 if-else 短、比 switch 快。

秦九韶每读一位做一次“乘 n 加 d”：第 i 位最终被乘了 nk−1−i 次，正好等于它的位权。FF：0×16+15 = 15，15×16+15 = 255。

3除基取余：十进制 → m 进制
除基取余
string res;
if (dec == 0) res = "0";             // 特判：否则 while 一次不进，输出空行
while (dec > 0) {
    res += digit[(int)(dec % m)];    // 余数就是当前最低位
    dec /= m;                        // 砍掉最低位，下一位升上来
}
reverse(res.begin(), res.end());     // 低位先产生，倒过来才是正常写法
为什么

余数天生是“最低位”：6 % 2 = 0、3 % 2 = 1、1 % 2 = 1，按 0、1、1 的顺序出来，可答案是 110——所以最后那次 reverse 不是装饰。

dec == 0 必须特判：输入 0 时循环一次不进，res 保持空串，会输出一个空行。这是本题唯一的数据边界。

4输出结果
输出
cout << res << "\n";
return 0;
为什么

输出不带前导零、不带空格；大小写由数码表决定，表里是大写，输出就是大写。

5拼成完整程序
完整代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    string s;
    cin >> n >> s >> m;                  // 三行输入；cin 按“词”读，换行自动跳过

    string digit = "0123456789ABCDEF";   // 数码表：下标即数值，够用到 16 进制

    // ① n 进制 -> 十进制，秦九韶
    long long dec = 0;
    for (int i = 0; i < (int)s.size(); ++i) {
        int d = (int)digit.find(s[i]);   // 'F' 在表里的下标是 15
        dec = dec * n + d;               // 旧值升一档，再加新的一位
    }

    // ② 十进制 -> m 进制，除基取余
    string res;
    if (dec == 0) res = "0";             // 特判：否则 while 一次不进，输出空行
    while (dec > 0) {
        res += digit[(int)(dec % m)];    // 余数就是当前最低位
        dec /= m;                        // 砍掉最低位，下一位升上来
    }
    reverse(res.begin(), res.end());     // 低位先产生，倒过来才是正常写法

    cout << res << "\n";
    return 0;
}
为什么

整段就两个循环：一个从左到右乘加，一个从低到高取余，中间靠一个 long long dec 衔接。题目保证十进制值 ≤ 10⁹（10 位），所以 long long 很富余。

竞赛用法

题型特征：题面给“n 进制 / m 进制”“A~F”“数码”“0x”，先想“秦九韶进来、除基取余出去”。

复杂度：O(k)，k 是数的位数；本题 k ≤ 10 位。进制互转本身是线性的。

常见坑：字符忘了减 '0'（'7' 的 ASCII 是 55）；除基取余忘 reverse（输出 011）；0 不特判（输出空行）；用 find(c) < 0 判没找到（size_t 无符号，条件永远为假）。

自测：16 / FF / 2 → 11111111；2 / 1011 / 10 → 11；10 / 0 / 16 → 0；再用回环验证：把输出当输入转回去，应还原原串。

模型：进制转换 / 数码表O(k)，k 为位数坑：忘 reverse / 0 特判 / size_t 无符号
追问 · 落到代码上再想一遍
  1. P1143 保证“十进制值不超过 10⁹”，所以 long long 中转很安全。若把这条保证删掉、改成“位数不超过 10⁵”，你的秦九韶还成立吗？除基取余会卡在哪一步？
    想好了？点开核对思路与解析
    秦九韶的“形状”还成立，数值不成立：中间量 dec 会涨到 10^(10⁵) 量级，long long 在第 20 位就溢出，换更大的类型也没用。于是“求完整数值”这条路断了，除基取余第一步 dec % m 就卡住——它需要完整的 dec。还能救的是“只需要部分信息”的版本：求余数时写 r = (r * n + d) % m，中间值永远小于 n·m。
    常见错路是把类型从 int 换成 unsigned long long 再试，20 位照样爆；或者以为“位数多只是慢一点”，其实是根本存不下。
  2. 判断一个 20 位正整数能否被 3 整除，可以全程用字符串。提示：秦九韶不必保留整个数，只保留那部分有用信息就够——推广到 7、13 呢？
    想好了？点开核对思路与解析
    循环是 int r = 0; for (char c : s) r = (r * 10 + (c - '0')) % 3;，中间值最大 2×10 + 9 = 29，远在 int 内。原理是秦九韶对取模同态：只保留余数，乘 10 加下一位再取模，结果与原数取模相同。推广到 7：中间值最大 6×10 + 9 = 69；到 13 是 12×10 + 9 = 129，都安全。
    常见错路是先 stoll 把 20 位转成数再取模（第 20 位就抛异常），或者某一步忘写 %，中间值照样爆 long long。
这一套能解的五类题
  • 回文：复制一份再 reverse，与原串比较；或双指针首尾对扫。
  • 位数 / 数位统计：to_string(x).size() 得位数，遍历字符串得每个数位。
  • 按数值排序：先比长度、再比字典序；数字位数超过 19 时这是唯一可行的比法。
  • 带分隔符的数据：日期 2024-03-15、分数 700/27、坐标 3.5 —— find 定位，substr 切段。
  • 任意进制输入输出：秦九韶进来，除基取余出去；密码题、颜色题、编号题都是它的变体。
19 位红线：什么时候不许用数字类型

long long 最大 9223372036854775807，19 位。超过它一步，“string → 数字 → string”这条链就整条断掉——20 位的输入必然如此，19 位的也得先和上限比一比。P1143 只保证十进制值 ≤ 10⁹（10 位），所以 long long 很富余；而本节挑战题把长度给到 20 位，同一个算法必须换成纯 string 版本。

但不进数字类型 ≠ 不能算：只要最终要的是余数、位数、某一位这类只依赖低位的信息，秦九韶就能只保留这部分状态往下跑，中间值永远不超范围。所以看到“输入是一个很长的数字串”，第一个问题永远是：我到底需要它的哪一部分信息？

位数超 19：只保留需要的那部分
string s = "12345678901234567890";       // 20 位
// long long x = stoll(s);                   // 抛 out_of_range → RE

int r = 0;                                   // 求这个数 mod 7
for (int i = 0; i < (int)s.size(); ++i)
    r = (r * 10 + (s[i] - '0')) % 7;         // 中间值最大 6*10+9 = 69
cout << r;                                   // 1
怎么验证你的进制转换是对的

进制题的答案没法靠“看起来像”判断，交之前用三个办法自检，每个都不到一分钟：

  • 回环验证：把输出的 m 进制结果再当输入转回 n 进制，应当逐字符还原原串。转两次还一样，基本就对了。
  • 对拍小数据：取 n = 10、m = 2，把 0~100 逐个跑一遍，与计算器或 Excel 的 DEC2BIN 对照。
  • 边界四连：0、1、最大数码（n−1）、n 本身（应写成 10）。这四组能打掉九成的 WA。

这三招不只对进制题有用：凡是“有明确逆运算”的题（进制互转、加解密、编解码）都能用回环验证。

进制数码一位能表示典型场合
20 12位运算、状压 DP、集合的子集
100~910所有读入输出、日常计算
160~9 A~F16内存地址 0x7ffd、颜色 #FF8800、哈希
360~9 A~Z36短链接、编号压缩：位数能省一半
看到“数字 / 进制”的题，先回答三问

最大可能多少位？≤ 9 位 int，≤ 18 位 long long，19 位踮脚，≥ 20 位一律 string。

需要整体数值吗？要就转数字；只要某位、某段、某个余数就全程字符串。

输出有固定宽度、前导零、大小写要求吗？有就用 sprintf 或数码表。

输出格式最常见的三种要求

十六进制大小写：数码表写成 "0123456789ABCDEF" 或全小写，一行切换。

固定宽度补零：sprintf(buf, "%05d", x)；to_string 做不到这件事。

去掉多余前导零：从下标 0 起跳过 '0'，但至少保留一位，否则 0 会变成空串。

这一节最容易踩的 7 个坑

把 20 位数喂给 stoll：抛 std::out_of_range，进程直接结束，评测显示 RE，连输出都看不到。

字符忘了减 '0'：写成 dec = dec * n + s[i]，'7' 的 ASCII 是 55，答案偏到天边。

除基取余忘了 reverse：6 转 2 进制应输出 110，你会输出 011，带前导零，WA。

用 s.find(c) < 0 判断没找到：size_t 无符号，条件永远为假。一律写 != string::npos。

拿 find 的返回值直接当 substr 起点：找不到时 npos + 1 是个天文数字，pos > size() 抛异常 → RE。

在循环里写 res = to_string(i) + res：每轮都要整体搬移整串，10⁵ 轮就是 O(n²)，本地跑得动、交上去 TLE。正确做法是往后追加、最后 reverse 一次。

dec == 0 不特判：输入 0 时 res 是空串，输出一个空行 → WA。

自己动手复现

关掉页面，把 P1143 的代码从零敲一遍提交。第一组数据用 16 / FF / 2，输出应为 11111111。

再打两个边界：2 / 1011 / 10 应得 11；10 / 0 / 16 应得 0（专打特判）。

改一改：把数码表换成全小写 "0123456789abcdef"，输出立刻变小写十六进制；但输入也得跟着变小写——同一张表既要用 find 查字符、又要用下标取字符，大小写必须一致。用 16 / ff / 2 验证。

再改一改：把表扩成 36 个字符 "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"，代码一行都不用动，输入 36 / Z / 10 就得到 35——这就是表比 if-else 划算的地方。

最后一改：把秦九韶换成“倒着扫、第 i 位重算 n^i”的直白写法，用 18 位输入数一数两种写法各做多少次乘法。

数学补给 · 位权、秦九韶与位数公式

设 n 进制数从高到低是 dk−1, …, d0，它的值就是各位乘自己位权的和：V = dk−1·nk−1 + … + d1·n + d0。

秦九韶把它改写成嵌套乘法：V = ((…(dk−1·n + dk−2)·n + dk−3)…·n + d0。把括号一层层拆开，每一项的系数与 n 的次数都和上式相同，两者等价。

差别只在代价：直白写法每位都要重算一次 ni，乘法 0+1+…+(k−1) = k(k−1)/2 次，k = 18 时是 153 次；秦九韶一次乘加一位，18 次。

除基取余的正确性来自带余除法：V = q·m + r，0 ≤ r < m，所以 r 一定是 m 进制写法里的最低位，q 是“砍掉最低位”后的数。对 q 重复同样的推理，位就从低到高被逐位剥出，因此最后必须倒序。

位数估算：k = ⌊logn V⌋ + 1。十进制 19 位对应 2⁶³−1 = 9223372036854775807；同一个值写成二进制要 63 位，写成十六进制只要 16 位——基数越大，位数越少，36 进制因此能把编号压到一半。

顺手把“19”推导一遍：2¹⁰ = 1024 ≈ 10³，于是 2⁶³ = (2¹⁰)⁶·2³ ≈ 10¹⁸×8 = 8×10¹⁸，精确值是 9.223×10¹⁸，刚好落在 10¹⁹ 以下——所以 long long 装得下 19 位、装不下 20 位；unsigned long long 是 2⁶⁴ ≈ 1.84×10¹⁹，正好 20 位，再多一位也装不下。

最后解释那个例外：2、4、8、16 之间可以直接换，不必经过十进制，因为 16 = 2⁴、8 = 2³——一个十六进制位恰好对应 4 个二进制位。所以 FF 逐位查表就得到 1111 1111。十六进制在底层代码里流行，正因为它对人可读（8 位一组）对机器整齐（4 位一组）。

挑战题 · 数字反转（升级版）
洛谷 P1553普及-去洛谷做这题 ↗

给定一个不含负号的实数 s，把它的各个数位反转。s 可能是整数、小数、分数或百分数。

整数：所有数位对调。小数：整数部分、小数部分各自反转，小数点不动。分数：分子、分母各自反转，分数线不动，不约分。百分数：只反转数字部分，% 保留。

反转后的最高位不能是 0（0 本身除外）；小数部分末尾的 0 要去掉，若只剩 0 则保留一个 0。

输入格式：一行，一个实数 s，各段长度最多 20 位。输出格式：一行，s 的反转数。样例：600.084 得 6.48，700/27 得 7/72。

引导性提示（先只看这里）

四种情况互斥，判别靠串里有没有 %、.、/ 这三个字符，不需要猜数据类型。

整段串里已经有全部信息。先想清楚：能不能把某一段转成数字再反转？数据范围允许吗？

真正要动脑的不是 reverse，而是删零：哪一端是“无意义的 0”，四种情况各不相同。

想看思路了？点开完整思路

① 依次 find('%')、find('.')、find('/')，命中哪个就是哪一类，都没命中就是整数。

② 用 substr 在分隔符两侧切开，左右两段各自 reverse。

③ 左段（整数部分、分子、百分数的数字）去掉反转后开头连续的 0，至少留一位；右段若是小数部分，去掉反转后末尾连续的 0，也至少留一位；若是分母，按整数规则去掉开头的 0。

④ 拼回去：a + "%"、a + "." + b、a + "/" + b，整数直接输出 a。全程在 string 里流动，一个字符都不进 long long。

为什么小数部分要删末尾的 0：600.084 的小数段 "084" 反转得 "480"，末尾那个 0 由原数的前导 0 变来，是无意义的 0，答案要求 6.48 而不是 6.480。

还是不会？点开题解代码与拆解
参考代码
#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    cin >> s;                       // 整行只有一个串，不含空格

    size_t p = s.find('%');
    if (p != string::npos) {                    // 百分数：只动数字部分
        string a = s.substr(0, p);
        reverse(a.begin(), a.end());
        int i = 0;
        while (i + 1 < (int)a.size() && a[i] == '0') ++i;  // 去前导零，至少留一位
        cout << a.substr(i) << "%\n";
    } else if ((p = s.find('.')) != string::npos) {        // 小数：两段各管自己
        string a = s.substr(0, p), b = s.substr(p + 1);
        reverse(a.begin(), a.end());
        reverse(b.begin(), b.end());
        int i = 0;
        while (i + 1 < (int)a.size() && a[i] == '0') ++i;  // 整数段去前导零
        int e = (int)b.size() - 1;
        while (e > 0 && b[e] == '0') --e;                  // 小数段去末尾零
        cout << a.substr(i) << "." << b.substr(0, e + 1) << "\n";
    } else if ((p = s.find('/')) != string::npos) {        // 分数：分子分母都按整数
        string a = s.substr(0, p), b = s.substr(p + 1);
        reverse(a.begin(), a.end());
        reverse(b.begin(), b.end());
        int i = 0, j = 0;
        while (i + 1 < (int)a.size() && a[i] == '0') ++i;
        while (j + 1 < (int)b.size() && b[j] == '0') ++j;
        cout << a.substr(i) << "/" << b.substr(j) << "\n";
    } else {                                               // 整数
        reverse(s.begin(), s.end());
        int i = 0;
        while (i + 1 < (int)s.size() && s[i] == '0') ++i;
        cout << s.substr(i) << "\n";
    }
    return 0;
}
关键片段拆解
片段作用
size_t p = s.find('%');先单独算一次，后面三个分支复用 p。用 size_t 接，别用 int。
(p = s.find('.')) != string::npos赋值表达式的值就是 p，少写一行，也保证 p 只在这个分支里有意义。
s.substr(0, p) / s.substr(p + 1)分隔符左边取 [0, p)，右边从 p+1 取到结尾，两段长度互不影响。
while (i + 1 < (int)a.size() && a[i] == '0') ++i;去前导零，但下标最多走到最后一位：保证 "0" 这类串不会被删成空串。
int e = (int)b.size() - 1; while (e > 0 && b[e] == '0') --e;小数段规则相反：删末尾的 0，同样留最后一位。e 是最后一个保留字符的下标。
b.substr(0, e + 1)取 [0, e]，长度是 e+1 而不是 e。差一错就在这里。
a.substr(i)只给起点，取到结尾——删完前导零剩下的正是答案。
i + 1 < (int)a.size()size() 是 size_t（无符号），与 int 比较会有警告，显式转 int 更保险。
这题最容易错的地方
  • 用 stoll 读整数部分：输入能到 20 位；即使是 19 位的 9223372036854775808，也已超过 LLONG_MAX，直接抛 out_of_range，评测 RE。
  • 删零删成空串："0" 反转后还是 "0"，无条件删前导零会输出空行 → WA。循环条件里必须有 i + 1 < size()。
  • 小数段照抄整数规则去前导零：600.084 会输出 6.480 而不是 6.48。小数段要删的是末尾的 0。
  • 拼回分隔符时手抖：cout << a << b 少了小数点，输出 648，只差一个字符，判 WA。
  • 四个分支用四个独立 if 而不是 else if：同一串可能被输出两次，答案多出一行。
