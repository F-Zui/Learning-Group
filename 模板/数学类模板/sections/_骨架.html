先用 2~4 段把「为什么需要这个对象」讲清楚：一个反例、一个算不出来的量、一个旧工具的失效点。动机写足了，后面的定义才不像空降。

二从需求推到定理

推导在知道「某某定理」之前需求 → 尝试 → 验证 → 定理
问题　先给一个具体到能手算的需求：要求什么、已知什么、卡在哪一步。
1
第一步做什么（枚举 / 试错 / 观察小例子）

写出你实际动手的过程：算了哪几个数、画了哪张表、发现了什么规律。允许出现失败的尝试。

观察　把这一步得到的事实单独点出来：它为什么值得注意。
2
第二步：把观察变成一个可检验的猜想

解释「为什么可以这样想」，并把猜想写成一句可以判断真假的话。

为什么　这一步用到了哪条已有结论（定义、上一节的性质），不要写「显然」。
3
第三步：验证猜想（反证 / 构造 / 最小性 / 代数变形）

这里承担「逐步证明正确性」的职责：把关键的不等式或构造写清楚。

验证　检查边界：等号什么时候成立？条件能不能放松？
于是我们得到：把刚才推出来的结论写成一句话，紧接着才是下面的定理与正式证明。
定理（结论的短名）

在 …… 的条件下，必有 ……。

证明

先把思路用一句话说完，再动手；跳步的地方单独点明依据。

…… 故结论成立。∎

读法

把上面的形式陈述翻译成一句人话或一幅图像。这是学生真正记住的部分。

易错

写出最常见的那个错用：条件漏掉会怎样、符号弄反会怎样。

1这一步做什么（对应定理的哪一步）

为什么　解释这一步的动机与构造理由，以及“为什么可以这样”。
2第二步做什么

继续用同一组数字往下走。

if (b % g == 0) { /* 可解 */ }
